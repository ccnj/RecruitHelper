# osengine — 鼠标轨迹引擎(自 hiBoss 搬入)

本目录只做一件事:**把「从这儿移到那儿」变成一份带时刻的坐标序列**。

它不碰 OS、不碰时钟、不等待、不发出任何东西。按时刻把计划播出去是脑进程
`client/service/internal/handinput` 的事。

## 目录里哪些是上游的,哪些是我们的

| | 来源 | 纪律 |
|---|---|---|
| `vendor/*.mjs` | hiBoss,**逐字复制** | **一行不改。** 连注释一起搬,那是纪律的载体 |
| `vendor/*.d.mts` | 我们写的 | 只声明实际调用的导出 |
| `plan.ts` | 我们写的 | 唯一对外入口 |

`vendor/` 里四个 `.mjs` 的上游位置不同,同步时要分别去取:

- `route.mjs` / `engines.mjs` ← `hiBoss/lab/engine/mouse/`
- `route.bjh.mjs` / `press.bjh.mjs` ← `hiBoss/lab/probe/baseline/`

后两个在上游被定性为「研究设备」,但**运行期必须有**:没有路由池生成不出窗口,
没有按压池 `pressMs` 就只能是常数——而常数是零误伤的机器签名。

### 为什么坚持一行不改

将来 hiBoss 换引擎或重采基线时要能对得上。改过的文件对不上,而对不上就意味着
那边的判别器跑分不再能说明我们真机跑出来的东西。**需要什么就在 `plan.ts` 里包一层,
不要进 `vendor/` 动手。**

`.d.mts` 是这条纪律的门禁:上游一改签名,编译期当场红。

## 版本钉子

`plan.ts` 的 `OSENGINE_SOURCE` 记着搬入时的上游 commit 与池子日期。

**池子换了轨迹就变了**,而跑分是对着某一版池子做的。同步上游时必须一起改这个常量,
否则「我们跑的」与「那边验的」是两个东西,而且不会有任何报错。

## 起点必须现读,不能用记忆里的值

`planMove` 的 `from` 必须是**光标此刻真实所在**,由 Go 侧现读系统坐标、再经当前
标定反算成 CSS。

理由是一条容易踩反的性质:Go 的 `Snap`(CSS→系统) 与 `ToClient`(系统→CSS) 用的是
同一份标定,互为逆运算,所以**不管标定多离谱,起点都落在光标现在所在的地方**,
误差只体现在终点打偏——那由落点判据抓。

而用记忆里的 CSS 值就没有这个抵消:标定一被修正,那个记忆值立刻错位,错位量正好
等于修正量。冷启动时那是一百多到两百多像素的一次干净瞬移,也就是评分台里最差的形状。

## 这里没有什么

- **打字那半**(`compose/`、`pinyin-pro`、TIP 管道):第一段的靶子都不打字,整体后置。
- **`observe.mjs` 与合帧模型**:那是离线预测与对账用的。生产输出的是 `points`,
  合帧由浏览器自己做。
- **判别器与评分台**:研究设备,永远留在 hiBoss。

## 范围提醒

第一段拿智联当靶子跑通链路,验的是「能点中、标定会收敛、耗时多少、五段编排的接缝
在哪」。它**不**验「像不像人」——那套基线与判别器不是对着智联采的,结论只能等 BOSS 真机。
