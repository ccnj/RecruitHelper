## 2. 已冻结的平台事实

### 2.1 当前目标不是“列表第一张卡”

- 推荐列表本身没有唯一选中语义；首卡只在本轮被用作不发送的代表性结构探针，不是产品目标裁决。
- 真人点开简历后，可见 `.new-shortcut-resume__modal` 数量为 1；该弹层和内部唯一公开动作表面可定义“当前候选人”。
- 详情弹层实际挂在 `body` 下，不被任何 `[role=listitem]` 包含，公开 DOM containment 不能绑定来源卡。
- 页面内 URL `resumeNumber` 与 20 个 `listitem.__vue__._props.source.resumeNumber` 比较时恰好命中 1 个；该命中 source 的 `userMasterId` 非空，且在 20 个 source 中也恰好唯一。`resumeNumber` 只允许在同一次 MAIN-world 读取中作详情到来源卡的瞬时连接键，永不返回、持久化、作为 Candidate 身份或失败降级值。
- 正式 `candidate.readCurrent` 必须要求详情弹层唯一；零个或多个都失败，不滚动、不选首卡、不自动打开别人。

### 2.2 职位引用的权威组合

- URL `jobNumber` = 当前来源卡 Vue owner 的 root route query `jobNumber` = 同一 owner 的 Vuex `talent.activeJob.jobNumber`；轻刷新后三者继续相等。生产读取只走这三处字面来源，不扫描运行时对象图。
- 可见 active job title 与 talent active job title 字面归一后相等；标题只是展示和绑定校验，不作身份。
- candidate search-condition active job 在当前页面与上述三者不相等，是可达的陈旧状态，不得用作 `positionRef` 或动作授权。

### 2.3 招呼动作是两步拓扑

1. 当前详情内唯一“打招呼”是 `button[type=button]`。
2. 第一击只打开唯一 `.ai-greeting-modal`，弹层内有两个 `.ai-greeting-modal__option`。
3. 无 AI icon 的选项可独立选中，其唯一 edit icon 展开唯一 textarea；正文可精确写入和读回。批次 6 真机补证：该 icon 在选项已选中但指针未悬停时仅被 CSS 隐藏，DOM 中仍恰有一个，人工悬停后显露的是同一节点。它只允许在 attempting 前作为可逆准备入口调用一次；调用后未出现唯一可见 textarea 即以 `sideEffect=none` 停止。
4. footer 只有一个最终“发送”标准按钮；该按钮才是候选人可见的不可逆动作。
5. “设置为默认，不再弹出”是独立复选项；M4 不点它，不改账号级设置。

本轮只点击第一击和弹层内的选项/编辑/关闭控件，从未点击最终“发送”。关闭后当前详情仍显示“打招呼”；复开后默认复选项仍未选中，探针正文不存在。

### 2.4 既有会话的候选人与招呼正证

- IM URL session 只匹配一条 session 记录；该记录的 `userId`、`typeUserId`、`peerPartnerId` 归一后相等。
- 同一会话的简历详情 candidate userId 与 session userId 相等，jobNumber 也相等；这说明建联后可以用平台 userId + 职位引用确认唯一会话。
- 历史招呼行的 raw `type` 是字符串 `custom`，数字 `131` 在 content envelope 的 `type`；正文位于 `greetingText`。平台文档不得误写成“raw type = 131”。
- 该行有稳定 `idServer`、`status=success`且 `from` 为当前 staff；这四项叠加正文 hash 才能作为已发招呼正证。
- timelineMap 的键与容器 `sessionId` 等于 `conversationRef`；消息行自身的 `sessionId` 字段在当前 9 条样本中全部不等于 conversationRef，不得用作会话绑定证据。
- 轻刷新前后，conversation、peer、job、招呼 `idServer` 与正文的脱敏指纹全部相等；本文不保存这些指纹值。

## 3. MAIN-world 发送前身份探针

### 3.1 公开层边界

- 当前详情弹层、对应候选人卡、URL 与动态后 outerHTML 均没有 `userMasterId/userId`；
- 页面初始化 JSON 含职位和登录用户状态，但不含当前未建联候选人 userId；
- 姓名、头像 URL、可见顺序与列表 `data-index` 均不是平台 userId；
- 因而公开 DOM 只能确认“真人当前打开了唯一详情”，不能单独产出 Candidate 主键。

### 3.2 一次性脱敏探针结果

甲方于 2026-07-20 单独批准一次 MAIN-world 身份事实探针，边界为只读、不发送、原始 ID 不落任何持久记录、不进 contract/capability、不留生产代码。执行结果：

1. 推荐窗共有 20 个 listitem，20 个 `listitem.__vue__._props.source.userMasterId` 均为非空值；探针只在页面内把代表值转成字符串参与摘要，原值从未返回浏览器外。
2. 页面内生成随机会话盐，以 `SHA-256(会话盐 || 原值)` 得到摘要 `121bfa79d01d5a2d160c06a19c674b613465d7097ec676dbe080ef304a29c3fd`；同页静置后的第二次读取与首次摘要相等。
3. 轻刷新后使用同一临时会话盐扫描新的 20 个 listitem，20 个身份值仍全部可读，目标摘要恰好命中 1 次。
4. 会话盐和摘要只存于一次性标签页的 `sessionStorage`；原始 ID 只存在于函数局部变量。探针页关闭后会话盐随页销毁，临时截图已删除，工作区和产品代码均无探针残留。
5. 后续补齐“详情→来源卡”缺口时，公开 DOM containment 已确认不成立；MAIN world 内以 URL `resumeNumber` 对 20 个 source 的 `resumeNumber` 作一次瞬时比较，结果恰好唯一，且命中 source 的 `userMasterId` 在同窗也恰好唯一。探针没有把 `resumeNumber` 当作身份、输出字段或降级值。
6. 同一补充探针定位到来源卡 Vue owner 的 root route query 与 Vuex `talent.activeJob` 两个职位来源；它们与 URL `jobNumber` 相等，足以让生产实现使用固定字面路径，无需保留通用对象图扫描器。

补充探针的首次路径诊断输出曾把 Vuex 动态 map key 带入一条本地临时命令结果，违反了“原始 ID 不落持久记录”的探针边界。发现后立即将该结果原位收窄为布尔事实、截断 SQLite WAL，并对数据库主文件/WAL/SHM 做残留片段复核，结果为零；临时诊断代码随后从工作区和插件构建中移除。该偏差不改变平台事实，但作为探针边界事故在此留痕，生产实现禁止返回对象路径或通用运行时扫描结果。

结论：`userMasterId` 在本轮真实页面上满足未建联候选人主键所需的非空性和轻刷新稳定性，可以作为智联 `platformUserRef` 的生产感知来源。它仍是高脆平台私有数据源，只回答“当前是谁”，不得参与动作接口授权互证；正式实现必须把唯一可见详情与其来源卡绑定后才返回 `candidate.readCurrent=ok`。任何读取失败、空值、重复、详情绑定不唯一或页面结构漂移都必须失败关闭：不确认候选人、不建档、不招呼并转人工，禁止降级到 `resumeNumber`、姓名、头像或 DOM 位置。

该事实只授权批次 1 按规范先行落地既有立案中的 `candidate.readCurrent` MAIN-world 感知通道；不授权新增通用注入机制、额外 capability 或其他 effectful 动作。
