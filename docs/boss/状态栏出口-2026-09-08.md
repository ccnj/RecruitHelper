# 状态栏出口(2026-09-08)

甲方 2026-09-08 立案并当日裁决:客户端加一条 OS 级半透明状态栏,主窗最小化或收进托盘时仍可见,透传一切鼠标事件,不影响浏览器与 OS 注入。本文是开工前冻结的出口,实现按本文落地;真机验收结果追记在文末。

## 1. 裁决要点(甲方 09-08)

1. 状态栏分**客户版**与**开发版**两种渲染,同一个窗、同一条取数路径,只是画的字段多少不同。
2. 开发版的开关放诊断台,**持久化**(甲方明示,推翻执行方"重启即回客户版"的建议)。
3. 注入进行中"请勿触碰"信号**不做**。
4. 开发版展示最近几条命令账本;巡检期间连续同名只读命令折成一行带次数(只改小窗,不改脑)。

## 2. 窗口

- Electron 第二个 `BrowserWindow`:`transparent`、`frame:false`、`alwaysOnTop`、`skipTaskbar`、`focusable:false`、`resizable:false`、`hasShadow:false`,Windows 上 `type:'toolbar'` 不进 Alt+Tab;建窗后 `setIgnoreMouseEvents(true)`;用 `showInactive()` 显示。
- 位置:主屏工作区顶部居中;尺寸固定(宽 640、高约 220),内容顶端对齐,客户版只画顶部一条约 36 像素的横条,其余区域透明。固定尺寸是为了两种模式切换时**不调用任何窗口级 API**(不 resize、不 show/hide、不重设置顶)。
- 只在启动时建一次,与主窗生命周期无关;主窗关闭即隐藏、托盘退出的逻辑不变。
- 加载 `client/ui` 的第二个 Vite 入口 `overlay.html`,共用同一个 preload(管理 token 只在内存中)。

**为什么必须只建一次、不能动焦点**:BOSS 的打字是 OS 注入进 Chrome 的焦点窗口,小窗若在运行期抢一次焦点,键序就落空;回读闸会拦住(方向是少发),但白白废一轮。`focusable:false` + `showInactive()` + 运行期零窗口级调用,是这条出口的硬约束。

## 3. 客户版(默认)

一条 36 像素横条:

| 位置 | 内容 | 来源 |
|---|---|---|
| 左 | 插件连接圆点;断线红点并显示"插件未连接" | `/app/overview` runtime 的插件连接投影(与产品首页"Chrome 插件"同一条) |
| 中 | 首页那句状态:七种标题之一 + 一句提示,颜色随语气 | `/app/overview`,经 `data.ts` 同一份 `homeStatus` 推导 |
| 右 | 今日打招呼、换微信、已约面 | `/app/overview` statistics |

脑联系不上时整条变灰,显示"客户端未就绪"。每 5 秒轮询一次。

## 4. 开发版

顶部一行与客户版相同;向下多两段:

- **最近命令**(固定五行,最新在上,不滚动):时刻、原语名、候选人姓名、状态(进行中/成功/失败+错误码/suspect)、耗时。有副作用的原语亮一档,只读灰一档;连续同名只读命令折成一行带 `×N`。来源 `/admin/ledger?limit=12&brief=1`,每 3 秒。
- **摘要一行**:当前批次采集/已发/失败(取 `/app/overview` funnel stages);插件心跳延迟、契约一致、journal 积压(`/admin/hands/health`);待裁决条数(`/admin/suspects`)。每 5 秒。

**不放**:聊天正文(账本 `summary` 在发消息时就是正文)、args、guards、结果体。要看现场去诊断台。

## 5. 开关

- 脑侧单行表 `StatusBarSetting{DetailEnabled}`,零值 false;`GET/POST /admin/statusbar/settings`。安装、升级、迁移、重装都不会把它翻成开(零值语义,与现场数据上报开关同款)。
- 诊断台「开发工具」页加一张"状态栏"卡,一个"详细模式"开关。入口仍是主窗 Ctrl/Cmd+Shift+D 加口令。
- 小窗每 5 秒读一次该设置决定画哪种模式;主进程不参与,无 IPC。
- **显示开关(2026-09-08 当日追加,甲方裁决"默认 BOSS 下打开、智联下关闭")**:同一张表加 `Visible` 三态列——空串=没人拨过、跟平台默认(BOSS 开,其余含快照缺席关);`on`/`off` 是诊断台拨过之后的明示值,此后不再看平台。三态而非 bool,因为默认值取决于绑定平台,平台在装机后才知道还可能换。脑按 `jobconfig.Source.CustomerPlatform()`(与产品面「开始」同一来源,快照缺席按智联)算出实际值随 GET 返回 `visible/visibleSource/platform`;POST `{visible}` 落明示值。小窗页面读到 `visible` 为真才画,读到之前与关着时整页空白——窗仍在,透明且穿透,对智联客户等于不存在;主进程不参与。诊断台同一张卡加「显示状态栏」开关,旁注当前是平台默认还是手动。
- **位置档位(2026-09-08 当日追加,甲方"做")**:同一张表加 `Position` 列(封闭枚举 top/bottom/topLeft/topRight/bottomLeft/bottomRight,空串按顶部居中),同一个端点 POST `{position}`,同一张诊断台卡加一排单选。主进程建窗前用管理 token 问脑一次档位(1.5 秒超时,读不到按顶部);运行期人改档位后,小窗页面在下一轮轮询读到新值,经 preload 的 IPC 让主进程 `setBounds` 挪一次——这是建窗之后唯一允许的窗口级调用,只由人改设置触发,窗不可聚焦故不动焦点;几何没变不调。页面在读到脑里的值之前不通知主进程,免得拿默认值把刚按库建好的窗挪回顶部再挪回来。贴底边的档位内容改为贴窗底、圆角翻到上面。

## 6. 脑侧改动(全部不碰业务逻辑)

1. `/admin/ledger` 加 `limit`(1～50,默认 50)与 `brief=1`(不带 args、guards、resultBody)两个查询参数。理由:该接口固定回 50 条并附完整结果体,readList 的返回体动辄几百 KB,小窗每 3 秒轮询扛不住。
2. `StatusBarSetting` 表与两个设置端点。

## 7. 边界核对

- **"两端禁止测试模式分支"**(大方向第 3 条)管的是命令生产与分发路径。两种模式走同一条取数路径、只是渲染字段不同,与诊断台本身同一性质;诊断台已于 2026-08-07 裁决保留在客户环境。
- **候选人姓名上屏幕顶层**:开发版与诊断台同属 `/admin` 明文面(「开发者诊断台明文边界」),同机、同 token、同口令闸。区别只在常驻可见,远程协助时对方屏幕也看得到。甲方知情,默认关。
- **前端不落盘**:小窗不把任何响应写入 localStorage/IndexedDB/日志。
- **截图不入镜**:webhook 截图走标签页截图(`captureVisibleTab`),不是屏幕截图;手服务不读屏幕像素。
- **鼠标穿透与 SendInput**:`WS_EX_TRANSPARENT` 窗口不参与命中测试,真人点击与注入点击都穿过去。系统行为,Windows 真机验一次。

## 8. 出口四项

1. **最小出口**:小窗 + 两种模式 + 开关 + 账本精简参数 + 定位与折行的单测;Mac 开发机看效果,Windows 真机验穿透与焦点。
2. **必须立即阻断**:打字期间小窗抢焦点。
3. **允许人工兜底**:远程桌面或无 GPU 加速下透明窗变黑底(只难看);Chrome F11 全屏之上是否可见;多显示器只在主屏。
4. **审查一轮**;后置项:招呼命令的 args 是候选人引用不是会话引用,账本目标名可能解析为空(那行只显示原语名),看真机需不需要补 `cmdTarget`。
