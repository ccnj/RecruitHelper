# 考古探针:`debug.osScroll` 与 `debug.osClick`(2026-09-03)

甲方 2026-09-03 晚定的两件事:① BOSS 的列表翻页、历史回读到顶、截图拼接全卡在没有滚轮注入;
② 考古不再用 Claude Chrome 插件的 CDP 点击(没有 OS 轨迹、不够拟人,当日两次风控都是它触发),
改为 Claude 经客户端诊断台派调试原语,走生产同一条 OS 注入链去指着页面 DOM 滚与点。

本文记这两条探针的落点、怎么用、收场怎么读、哪些还没真机验。契约 note 是权威,本文只是导览。

## 一、四层落点

| 层 | 落点 | 做什么 |
|---|---|---|
| 手服务(Go) | `handinput.Injector.Wheel` 两端实现;`/handinput/scroll` 播 `ScrollPlan{ticks:[{at,dy}]}` | 只播不算。Windows `MOUSEEVENTF_WHEEL`、一格 ±120;darwin `CGEventCreateScrollWheelEvent2` line 单位、一格 3 行。播前核对光标仍在最后注入落点(与 Click 同一条判据),不在即 409 |
| 插件排版器 | `osscroll.ts` `composeScrollBurst / composeScrollPause` | 一簇 3~8 格、簇内间隔对数正态(中位 55ms)逐格放慢 8%、簇间停顿 250~700ms;越界重采不夹取 |
| 插件编排 | `osscroll.ts` `runOsScroll`;`osinput.ts` `ClickPlan.action='land'`;`boss.ts` `bossOsScroll / bossOsClick` | 先经 osProbe 那条闸链把光标**落到**容器/元素上(前台、授权、标定、落点确认、命中测试),再滚或点 |
| 脑侧 | `/admin/osscroll`、`/admin/osclick`;`dispatch.OsScroll / OsClick`;两条生产者门禁 | 唯一派发入口。selector 在脑侧不透明、原样转交;index 缺省即"没给" |

契约:`debug.osScroll@1`、`debug.osClick@1`,intrusive、`platformSideEffect=none`、预算与 osProbe 同款。

## 二、怎么用(诊断台 / Claude)

鉴权与 `/admin/osprobe` 同一把 admin bearer。`platform` 与 `accountRef` 取已绑定的 BOSS 账号。

```bash
# 把消息区往上滚 1200px(拉历史)
curl -s -X POST http://127.0.0.1:17872/admin/osscroll \
  -H "Authorization: Bearer $ADMIN" -H 'Content-Type: application/json' \
  -d '{"platform":"boss","accountRef":"<accountRef>","selector":".chat-message-list","direction":"up","distancePx":1200}'
```

```bash
# 只把光标落到第 3 行会话上(不点);把 mode 换成 click 才会按一下
curl -s -X POST http://127.0.0.1:17872/admin/osclick \
  -H "Authorization: Bearer $ADMIN" -H 'Content-Type: application/json' \
  -d '{"platform":"boss","accountRef":"<accountRef>","selector":".geek-item","index":2,"mode":"move","expectText":"…"}'
```

参数:

| 端点 | 字段 | 说明 |
|---|---|---|
| 两者 | `selector` | CSS selector,≤256 字元;在 isolated world 以 `querySelectorAll` 定位 |
| 两者 | `index` | 可选。**不给**时命中不唯一即拒、不猜第一个;给 0 与不给分得开 |
| osscroll | `direction` | `down` / `up`(W3C deltaY 口径:down 让 scrollTop 变大) |
| osscroll | `distancePx` | 1~20000,一次调用最多滚这么多;滚过头一点不反向补 |
| osclick | `mode` | `move` 只落不点;`click` 至多按一次 |
| osclick | `expectText` | 可选,≤256。给了就与元素 `textContent`(去首尾空白)逐字相等才动;点前最后一次命中测试再核一遍 |

返回 `{msgId, status, result}`,`result.data.outcome` 是收场,`detail` 是判定现场(每簇的 scrollTop 观测 / 靶子签名 / 落点偏差)。

## 三、收场怎么读

| outcome | 含义 | 该做什么 |
|---|---|---|
| `scrolled` | 累计像素达到 distancePx | 读页面 |
| `edge` | 容器已到顶/到底(含一格没滚就在边上、没有可滚内容) | 到顶了页面会自行拉历史,等它拉完再叫一次 |
| `stuck` | 一簇下去纹丝不动又不在边上;或**方向反了** | 光标不在容器上/页面拦截/滚轮没送到;方向反了 = 注入器符号与本机不符,改注入器那一处负号,不换方向重试 |
| `landed` / `clicked` | osClick 两种模式的成功收场 | — |
| `refusedByGate` | 定位失败(none/ambiguous/out_of_range/offscreen/bad_selector)、文本不符、前台/授权/标定/命中测试/手服务光标核对任一未过 | 看 detail;不重试 |
| `handServiceUnavailable` | 脑没起来或本平台没有注入实现 | — |

全部收场都**不重试**:原语内不重试是内核。

## 四、防线与例外

- **selector 进 args 是 debug.* 命名空间的显式例外。** 大方向 2 禁止 selector 进协议语义,理由是脑要平台无关;这两条的用途就是让考古者指着任意 DOM,靶子枚举做不到(每个新靶子都要改契约、换代插件)。脑对该字符串零解释、零分支、不落业务表;只在这两条 debug 原语上如此,生产原语 args 仍不得携带 selector。
- **click 模式是本战役唯一会点东西的探针。** 四道防线缺一不点:selector+index 命中唯一;expectText 相等;点前最后一次命中测试(落点像素上是该元素或其后代,且文本仍相符——列表重排后同一 index 会指到别人);元素可见部分 ≥24px。它是考古工具,不是对不可逆控件的授权——只对可逆或已裁决的控件用 click。
- **滚轮不是候选人可见动作**,但页面会因此自行拉历史或下一页——那是页面自己的请求与节奏,符合「手对平台零出站」。
- 脑侧零业务生产者由 `osscroll_producer_test.go`、`osclick_producer_test.go` 钉住,与 osProbe 那道同款。

## 五、拟人参数是定的,不是量的

没有真人滚轮基线。簇长、簇内间隔分布、减速比、簇间停顿四个数只按"甩动成簇、簇内减速"两条直觉定,
常量在 `osscroll.ts` `SCROLL_BURST`。真机跑过之后拿 `bossInputCounters` 里滚轮相关计数的形状回来校。

## 六、尚未真机验证

| 项 | 平台 | 判据 |
|---|---|---|
| 滚轮方向符号 | macOS | 首次 osScroll 若报 `stuck` 且 detail 含「方向反了」,改 `inject_darwin.go` `Wheel` 的负号 |
| 滚轮方向符号 | Windows | 同上,改 `inject_windows.go` `Wheel`;微软口径正=向上,理论上不会反 |
| UIPI 静默失败 | Windows | 管理员浏览器下 SendInput 返回 0,`/handinput/scroll` 回 500「SendInput 只发出 0 个事件」 |
| TIP 空闲态透传 | Windows | 自研输入法切到我们时,滚轮不经键盘路径,理论上不受影响;真机确认一次 |
| 每格像素 | 两端 | detail 里每簇 `a→b(+n)` 除以格数;闭环自适应,只是记个数 |
| 埋点形状 | BOSS | `bossInputCounters` 滚轮计数增量 = 格数;无安全验证跳转 |
