# 键盘线段二验收 · Windows 真机首验

2026-09-01。客户端基线 `c159759`，TIP 源码 `hiBoss@6e60bff`。

**整条线通了。** 三条文案全部 `matched=true`——键序、上屏词、回读逐字相同。
自研 TIP 存在的唯一理由(从根上消掉候选词随机性)在真机上兑现。

## 三条文案

| 文案 | 键 | 排版 | 滞后峰值 | TIP | 回读 |
|---|---|---|---|---|---|
| 你好，方便加个微信聊聊吗 | 82 | 1 次重采 7 词 1ms | 13us | 7/7 | 逐字相同 |
| 岗位是Java后端，Base深圳，方便聊聊吗？ | 128 | 3 次重采 12 词 8ms | 585us | 12/12 | 逐字相同 |
| 薪资20到30万，3年经验 | 66 | 1 次重采 11 词 1ms | 172us | 11/11 | 逐字相同 |

三条都停在草稿状态,一次发送都没有。

### 第一条把 macOS 那次的病治好了

```
mac  期望「你好，方便加个微信聊聊吗」  实得「你好，方便价格微信聊聊吗」
Win  期望「你好，方便加个微信聊聊吗」  实得 逐字相同
```

段一在 mac 上七词错一个且是同音异形(`jiage`),说明切分、上屏键、组字周期全对,
只有候选词那一层不同——**而那正是自研 TIP 唯一要解决的**。现在解决了。

### 后两条堵的是两个「在 mac 上原理上验不了」的洞

**英文段。** 上游 2026-09-01 放行英文时**全部是离线证据、零真机**,而 macOS 上
结构性验不了:走系统输入法的话 `b,a,s,e` 会被当拼音处理,上屏的是汉字——
不是"选错候选词",是结构性不同。现在 `Java`、`Base` 大小写都对,
坐实了「按什么键」与「出什么字」分开这个设计。

**数字。** 上游自记的活账:真微软拼音下数字走 `insertText`(type1),而 TIP 的
classify 把空格、数字、OEM 标点键一律当上屏键吃掉走 composition(type2);
2026-08-23 那份真机计划里**一个直接数字段都没有**。`20` 还会被拆成 `2`、`0` 两段。
现在 `20`/`30`/`3` 全对。

### 排版器的闭环自验第一次在真机上可见

混排那条 **3 次重采**。排版器把自己算出的计划合成成事件流、再量一遍参数,
与真人基线对不上就换种子重来(最多 40 次)。两份不合格的形状被它自己否掉了。

## 时钟:Windows 比 macOS 好一个量级

```
macOS  5839us      Windows  13 / 172 / 585us      上游 Windows  790~2490us
```

`clocksrc_windows.go`(QPC)在真机上头一次跑,量级与上游对得上。
这也印证了当初那条判断:**不能用 `time.Now()` 测**——它在 Windows 上粒度 15.625ms,
量什么都是梳状,三种等待策略会被一律报成量化、结论完全相反。

## 鼠标线:冷启动收敛正常,但瞄准准头仍未验

```
只移不点  landed · 试了 2 趟 · 落点偏差 122px · 标定就绪 · 滞后 598us · 3574ms
```

两趟收敛,与上游「实测两趟就够」一致;122px 是**第二趟学的时候**的偏差,
学完即 armed,不是命中精度。

**`reversibleToggle`(真点一次)尚未跑过**,而键盘那三条都是 `焦点=在`、
根本没走点击。所以 **Windows 上"瞄准某个元素点下去"的准头至今零真机**——
那是鼠标线唯一还缺的验收判据。

## 这一趟改掉的两个 bug

**一、管道建一次就不能关。** 第一条命令全绿,第二条**整条 6ms、一个键都没发**。
6ms 是线索:等 TIP 的超时是 8 秒,所以它压根没走到等待,是建管道当场失败。
三条撞在一起——go-winio 建监听用 `FILE_CREATE`(同名管道有实例就建不出)、
关监听只关监听句柄(已接受的连接还开着)、而 TIP「连上就一直连着」。
根因是照搬了上游 `play.go` 的形状:那是一次性 CLI,"每次"等于"每进程",
永远撞不上第二次;我们的脑是常驻的。修复 `e56c138`。

**二、失败时不说原因。** 手服务把「起管道失败(…):拒绝访问」放在响应体里,
插件在非 2xx 分支直接扔掉,现场只有「手服务返回 500」。
「错误收敛必须留痕」禁的正是这个。修复 `c159759`。

⚠ **第一个修复的真机确认取决于那两条是不是连着跑的**:若中间重启过客户端,
它仍未被证伪过的路径覆盖。下次连点三次即可确认。

## 还缺什么

1. **鼠标 `reversibleToggle`** —— 鼠标线唯一缺的判据(见上)
2. **管道修复的连跑确认** —— 同一个脑进程里连点三次
3. **埋点那一段没跑** —— 操作单第 5 段。整条键盘线的**目的**是让 BOSS 的
   `_ZP_CNT_` 不上报输入异常,而"打对了字"只是前提,不是目的
4. **半角标点仍拒绝** —— 上游有意保留(真输入法直接上屏 type1,TIP 会当上屏键
   吃掉走 type2,是真实行为差异)。我方文案是 AI 生成的,半角完全可能出现
