## 二、真实耗时(2026-08-28,macOS,智联 IM 真实页面)

| 趟 | attempts | 落点偏差 | 标定 | planMs | elapsedMs | lagMaxUs |
|---|---|---|---|---|---|---|
| 冷启动 | **2** | 121 | 就绪 | 1964 | 7276 | 22660 |
| 热标定 | **1** | **0** | 就绪 | 2097 | 2156 | **23** |
| 热标定 | **1** | **0** | 就绪 | 13588 | 13651 | 651 |

跑完的手服务状态:`已标定 True 样本 4 残差 0px 可点击 True`。

**编排开销约 60ms**(`elapsed − planMs`,热标定两趟为 59 与 63)。四段的 HTTP 往返
加落点稳定等待合计可忽略 —— 时间几乎全部花在轨迹本身。

**单窗口时长 1964 ~ 13588ms**,方差来自路由池里的真人停顿(`maxDwellMs=3000` 截断下)。
上游给的单窗口 p99 是 23.5 秒,这三趟落在区间内。

**滞后是双峰的。** 热标定两趟是 23µs 与 651µs;22.7ms 那个离群出现在冷启动那趟。
本机另做过 13 趟专项测量,形态一致:多数趟最大滞后 28~54µs,约四成的趟冒一个
10~44ms 的单帧离群。**两个显然的嫌疑犯都排除了**:

	GOGC=off        离群照旧(28ms / 4.7ms / 2.1ms)   → 不是 GC
	LockOSThread    离群照旧(22ms / 10ms)             → 不是线程迁移

那是 OS 级调度抖动。`runtime.LockOSThread()` 仍然保留,理由是**方法上的**不是
"多一层保险":上游在 Windows 上量到的 0.79~2.49ms 是在它之下测的,我方若不加,
将来在 Windows 上量出差异时分不清是架构带来的还是这一行缺席带来的。

## 三、真机照出的 7 个缺陷(推演一个也拿不到)

这一节是本报告最值钱的部分。**七个全部是真机跑出来的**,静态审查、单元测试、
类型检查一个都没拦住。

### 1. NaN/Inf 让 `/handinput/state` 回 200 加空 body

样本不足两个时 `Piggyback.Residual()` 返回 NaN;零值标定的 `ToClient` 除以零得 Inf。
`encoding/json` 编不了它们,而老写法**先 WriteHeader 再 Encode** —— 200 已经发出去了,
错误无处可去,日志里一个字都没有。

修法不是"编码时兜住",是不让 NaN/Inf 进结构体(残差与光标坐标改可空指针,
**nil 而不是 0**:0 的意思是"拟合完美"和"光标在视口左上角",都是撒谎)。
`writeJSON` 改成先 Marshal 再写头 —— 这一条比第一条更要紧,它是**这一整类问题的形状**。

### 2. 平台失败逃出映射:什么都没做的失败被记成"副作用可能发生了"

IM 页面没打开时,手侧抛的是 `CTX_NOT_READY / pageAbsent / sideEffect=none`,
回到脑那边成了 `INTERNAL_HAND / sideEffect=possible`。原语没接住 `PlatformError`,
裸抛出去被兜底,而那条路的 sideEffect 默认是 possible。**方向正好反了。**

顺带发现 debug 那一族原语的接线此前**根本没有用例覆盖**
(`registerDebugPrimitives()` 都不在测试 bundle 里)。

### 3. 浮点撞契约整数:34.6 秒的数据丢在回程上

手服务算的滞后是浮点,而契约里**根本没有浮点类型**。第一次成功跑完 34.6 秒之后,
result 被 `$.data.lagMaxUs: 需要整数` 拦下,那一趟的数据全丢。
装配(含取整)因此收进 `osProbeContractData` 一处 —— 适配器不该知道哪些字段要取整。

### 4. 种子公式抄错了平台(最严重的一个)

**现象**:副屏上光标横扫了 34 秒。

**第一反应是错的**:照上游"混合 DPI 多屏……处置是回避"加了一道「副屏一律拒绝」。

**实测推翻了它**。真人手动移动鼠标两次,同时读页面 `clientX/clientY` 与 Go 侧
`CGEventGetLocation` 全局坐标,两点解出逐轴仿射:

	ScaleX = 1.000000   OffsetX = 2560.000   ← 精确等于 window.screenX,差 0.0
	ScaleY = 1.000000   OffsetY =  638.000   ← screenY(517) + 121(浏览器顶部高度)

而此前只有一份公式:`offset = screenX × dpr`,scale = dpr。**那是上游的 Windows 实测**
(SendInput 收虚拟桌面物理像素,150% 下不乘偏 227 物理像素)。**macOS 的 CGEventPost
收 point,而 `window.screenX` 报的已经就是 point** —— 多乘了一遍。

视口正中 (735,331) 于是被算到:

	真值            (3295,  969)
	旧种子          (6590, 1696)   ← 超出桌面右边界 2560 点
	macOS 正解种子  (3295,  848)   ← x 精确,y 差 121

主屏上 `screenX≈0`,乘不乘差别小,光标还落在屏幕里、还学得回来;副屏上 `screenX=2560`,
一乘就把光标甩出桌面 —— **观测不到落点就没有样本,没有样本标定就学不到东西**,
六趟重试全是瞎扫。

y 那 121 点是**设计内的**:上游本来就说 y 轴粗估天然错、交给搭车标定去学,
它小到光标还在页面上。x 那 2560 是致命的,因为它掐断了学习链条。

**结构上的改动**:`SeedCalib` 进 `Injector` 接口,各平台自己实现 —— 差异的根源就是
"本平台的注入 API 收什么单位",而那正是注入器自己的知识,不该由共享的标定层去猜。

**「副屏一律拒绝」已撤,并在代码里留了墓碑、用例反着写(断言副屏必须放行)**,
免得它被"顺手"加回来:它拿一个可修的 bug 换了一条永久产品约束,而我们控制不了
客户怎么摆屏幕。

### 5. 固定靶子永远张不开标定所需的跨度

**这一个是推演时发现的,没烧甲方的鼠标** —— 值得记一笔,因为它证明"动手前先推一遍"
不是仪式。

探针原先每趟都移向同一个点。第一趟落在靶子附近之后,后面每趟只挪一百来像素,
而搭车标定要求样本在**两个轴上各张开 200 CSS 像素**才解得出 scale(那个数从 `clientX`
的 ±0.5 取整噪声推出:两点相距 R 时 scale 的相对误差上界是 1/R,要落进 `snapScale`
的 0.5% 吸附容差就得 R > 200)。样本挤成一团,标定会一直停在冷启动直到把重试用完
—— 而每一趟都是一次真实的鼠标移动。

靶子改成视口里四个散开的点(22%/78% 两轴组合),相邻两趟跨度是视口的 56%。

### 6. 失效方向写反:观测不到落点时去重试

原先是 `continue`。观测不到说明光标压根不在页面上,再试只是让它再飞一圈:
没有观测就没有样本,没有样本就学不到东西。那 34 秒里六趟全是这个形态。改成停。

### 7. 落点没防污染:真人碰一下鼠标,垃圾就进了标定

**数据自己说的话**:两趟观测解出来的 `scale_y = -2.0`,而屏幕映射不可能是负的
—— 至少一个观测不是我们注入的位置。来源是运行期间鼠标被碰过:那一下也派发
mousemove,而且往往就是最后一个。

危害不是"这一次读错了",是它会被当成落点喂进搭车拟合,**越学越歪**,
而外表看起来一切正常:有样本、有残差、有状态码,没有任何一处报错。

判据是现成的:注入用绝对坐标,发完之后系统不该再动光标。所以喂标定之前现读一次,
对不上最后注入的那一帧就作废本次落点。**这条在生产上同样要紧** —— 客户机上
真人随手动一下鼠标是常态。

## 四、方法教训

**「错误收敛必须留痕」这条法条,是被自己的疏漏教会的。** 前三轮排障全在靠反推猜
根因,直到把判定现场(靶子、落点、视口、粗估、起点)打进 `detail` 才看见真相 ——
而那条宪法条款一开始就在那里。失败必须自带现场,不是等猜不动了才补。

**为验证 A 加的工具,可能把 B 的 bug 遮住。** 用 Claude 的 Chrome 工具读页面时,
浏览器顶部会多一条调试横幅,把内容整体下推 —— 实测视口从 1470x662 变 1470x718,
**56 像素**。横幅本身是常数、标定学得掉,但它在运行中开合就会让视口原点跳 56px,
标定等于在追一个会动的目标。处置是运行期间不碰那套工具,不是给代码加机制。

**`git checkout -- <file>` 对未跟踪文件无效。** 做变异验证时五次变异叠在了一起,
靠与上游逐字 diff 才追回来。未入库的文件做变异前必须自己备份。

**广域 `gofmt -w` 会改到无关文件。** 一次 `gofmt -w` 顺手重排了一个跟本轮无关的
既有测试,按"一因果一 commit"剔了出去。此后只格式化本轮自己的文件。

## 五、流程坑(两条,都已踩实)

**`BRAIN_DATA_DIR` 漏了会落到旧库。** 用 `pnpm start` 重启客户端时不带它,脑会落到
Electron 默认的 `~/Library/Application Support/recruithelper-client/data` —— 那是个
七月的旧库。当时没有任何业务动作(账号不当前、巡检未开),带上变量重启即纠正。

**插件跨契约自动换代验通了。** 契约变更后脑自动派 `debug.reload`,插件当场换代
(`previousBootId → bootId`,`ready: true`),全程 8 秒。这把「客户机跨契约真机升级首验」
这条挂账清掉了。本轮共发生 5 次,全部成功。

## 七、门禁清单(每条都做过变异验证)

| 门禁 | 守什么 |
|---|---|
| `handinput` 只被 `main.go` import | 脑不得直接指挥鼠标 |
| `handinput` 不 import 任何业务包 | 它不得长出"读一下工作流状态再决定怎么动" |
| purego 只出现在 `//go:build darwin` 文件 | Windows 发布产物零影响(实测构建图里 0 个包) |
| `ScaleGapOK` | 拦住"往 PlausibleScales 补一档"——补密会让带噪拟合被吸到相邻错档,而错档是个精确数字 |
| `dist/content.js ≤ 20000` 字节 | 守三张表那个架构。变异(从 content 侧真用引擎)当场红,体积 8543 → 94201 |
| `debug.osProbe` 无业务生产者 | 探针会接管鼠标,业务路径一律不得铸它 |
| osengine 与上游逐点一致 | 基准由 hiBoss **原始文件**生成,锁住随机数派生、参数、取整口径、抽 pressMs 的时机 |
