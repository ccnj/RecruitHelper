# 实发正文即事实：OS 打字发送族的判据放宽（2026-09-07 甲方裁决底稿；worktree 实施，合并前裁）

**甲方 2026-09-07 三步定案**：①招呼行身份不加契约字段、依赖自举（勿再提）；②精确闸不删、改「平台实际发出的是什么就认什么」（方案 B），加一道小的模糊地板挡灾难性错乱；③Windows 上 TIP 活动核对是硬闸，Mac 上不适用，Mac 因此能跑全流程。本文是规范先行的并列提交：旧约束 / 拟议文本 / 当前可达场景 / 收益与成本，外加出口四项。**实施在 worktree 分支 `claude/sent-text-is-fact`，做完不合并，等甲方命令。**

## 〇、起因

- 自研 TIP 与排版器可能遇到算不出键序的字元（emoji、扩展区汉字、未收录标点、制表符、竖线），一条招呼或回复因此整条停住。排版器上游自带 `sanitize` 档（摘掉打不出的字元、如实报出摘了什么），作者注释原话「dropped 必须回到脑，发出去的才是事实」，默认关闭，因为脑侧当时要求实发正文等于计划正文。
- Mac 开发机没有 TIP，系统拼音按候选上屏出同音错字，回读逐字相等闸拒发，第二刀在 Mac 上止于打字（2026-09-07 第六趟）。甲方要 Mac 能跑通「发送 + 正证 + 关窗 + 账本 + 巡检」。
- 真机数据：09-03 场景一 Mac 回复一例，期望 29 字、实得 28 字、编辑距离 3、相似度 0.90，同位逐字相等只有 0.28（掉一字后全错位），所以比对必须用编辑距离；第六趟三条错字样本因验证读补记 ok 覆盖了失败原文、手侧日志未落盘而丢失。

## 二、判据

| 判什么 | 只认这一两个 | 失效方向 |
|---|---|---|
| TIP 是活动输入法（Windows） | 手服务 `DriveWords` 等 8 秒无 TIP 连接即报错不打（**已有**）；打完 COMMIT 对账 `committed < planned` 即不发（**本次新增硬闸**，结构化字段回插件，不再只看一句人话） | 不发、不首击之外的任何动作，`none`（招呼首击已成则 `possible`） |
| 上屏没有灾难性错乱（地板，全平台） | 回读与目标（清洗后文案）字数差 ≤ 2，且编辑距离相似度 ≥ 0.7（起步值，Windows/Mac 各跑出数据再标定） | 不发，停在草稿 |
| 发送时编辑器内容未变 | 点击命中测试核「编辑器文本 == 刚被接受的回读文本」（逐字），不再核计划正文 | 不点 |
| 正文已发出（手侧即时正证） | 基线之外、方向 out、kind text、status 1/2、time ≥ 派发 − 5 s，多条取 mid 最大者；`sentText` 与 `contentHash` 取该行 | 零匹配 → `possible` 交验证读 |
| 正文已发出（脑侧验证读，`chat.sendMessage`） | 最近窗口内 out/text、time ≥ 派发 − 5 s、`sourceKey` 不属于账本既有行，取最新；正文与 hash 以该行为准 | 零匹配 → suspect 转人工 |
| 招呼已发出（脑侧验证读，`chat.sendGreeting`） | 不变：推荐卡关系已建立；实发正文不可知，账本行取计划正文（记录级，知情接受） | 不变 |

计划正文与实发正文不同时，手侧与脑侧各留一条留痕（只记字数、编辑距离、相似度、两个 hash，不记正文）；它是日后标定阈值与裁决地板存废的唯一数据来源。

## 三、出口四项

1. **最小可交付出口**：Mac 开发机从客户端「开始」跑 BOSS 完整流程，招呼正文经系统拼音（含同音错字）发出、快捷窗正证、关窗、账本 `greeted` + 实发正文行；沟通巡检里回复同款。契约 `sentText` 两处 optional 字段 + 手服务结构化 COMMIT 对账 + 脑侧接受实发正文 + BOSS 手侧地板与认行。智联零改动。
2. **必须立即阻断的损害**：多发（账本 idemKey、证词、至多一次点击不动）；错靶（账号、路由、目标绑定不动）；Windows 上 TIP 不活动时发出系统拼音错字（COMMIT 对账硬闸）；灾难性错乱（地板）。
3. **允许重试 / 人工兜底的失败**：零匹配 → 验证读 → suspect；地板不过 → 停在草稿、`none`/`possible` 照既有路径；清洗后空文案 → `none`。
4. **审查与后置**：一轮独立出口审查；后置——阈值真机标定、Windows TIP 首验、验证读补记路径的实发正文（记录级）、脑侧审计补记保留手侧原文（既有挂账）。

## 四、收益与成本

收益：一个打不出的字元不再停整条；Mac 可验到底；账本、自举、聊天上报与 AI 下一轮读到的是实发文本，幻影行消失。

甲方知情接受的代价：TIP 自己打错字只能事后从留痕看到；打字期间真人插手混出的文本若在地板之内会照发；同一窗口内真人或平台恰好插一条出站行会被记成我方正文（方向是少发，账本错一行）；验证读补记路径的招呼行正文可能与实发不同。
