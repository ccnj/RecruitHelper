# BOSS 取数通道决策：走 MAIN world 一次性读

**2026-08-28 甲方裁决。** 记录裁决、论证与支撑数据。

写这份文档的主要目的不是记结论，是**记否决了什么、为什么否决**——
因为这个论证在同一天里翻转过一次，而只留结论的话，
后来人看到「MAIN world 读 Vue 内部」会觉得脏、想改成「更干净的 API 调用」，
正好走回头路。

---

## 一、裁决

**BOSS 的消息取数走 MAIN world 一次性读**：由 background service worker 用
`chrome.scripting.executeScript({ target:{tabId}, world:'MAIN', func })` 按需读取，
读完即返回，页面里零常驻。

**不采用**：扩展自己调 BOSS 的 HTTP 接口。

## 二、问题：DOM 顶不掉消息身份

BOSS 的消息**服务端 id（`mid`）完全不在 DOM 上**——66 个 mid 与整页 `outerHTML`
比对命中 0，消息行只有 `data-v-*`。而 `mid` 是去重与账本的锚。

更糟的是 **DOM 是数据层的真子集，会整条漏行**：实测数据层 11 条 / DOM 9 行，
漏的是 `body.type=4` 的空内容系统行；已读标记也不全。

所以纯 DOM 路走不通，必须在「MAIN world 读页面已有的数据」与
「扩展自己去把数据取回来」之间选一个。

## 三、五条通道，逐条实测

| 通道 | 拿得到 mid | 结论 |
|---|---|---|
| **MAIN world 一次性读** | ✅ | **采用** |
| 扩展/content script 同源 fetch | ✅（超集） | 技术上通，**否决**，见第四节 |
| DOM | ❌ | 顶不掉身份，只作降级与交叉校验 |
| 本地存储 | ❌ | `indexedDB.databases()` 为空；localStorage 46 键无任何 mid |
| WebSocket 帧 | ✅ | 不可行：MV3 `webRequest` 看得见握手看不见帧；拆帧要么 patch `WebSocket`（持久化 hook，留痕），要么 `chrome.debugger`（弹 infobar） |

## 四、为什么否决 fetch —— 论证翻转的那一次

**最初的建议是 fetch**，理由是「DOM 会整条漏行，HTTP 接口是超集」。
甲方一句「isolated 调接口让我也很不舒服，这会不会反而扩大了暴露面」把它推翻了。

### 4.1 fetch 路会新增三层信号，全部朝服务端

1. **请求节奏对不上。** 页面自己只在人点开会话时才打 `historyMsg`。
   按巡检周期扫 N 个会话，就是「机器精度的等间隔、可能凌晨三点、与页面导航无关联」。
2. **缺整套仪式。** BOSS 页面每个交互都甩 `actionLog` 埋点，进会话前先打
   `bossEnter`、`geek/info`、`brandCard`。我们的 `historyMsg` 是**裸的**——
   前无埋点、后无伴随请求、没有 `Referer`。服务端日志里一眼货。
3. **`Origin: chrome-extension://<扩展ID>`。** 这不是「看起来不像人」，
   是一个**精确、稳定、可归因**的标识符，而且**全部客户共用同一个**——
   一旦被标记是整个机队同时被标记。

### 4.2 但决定性的不是这三条，是可测性

**我们能测前端检测，测不了后端检测。**

埋点观测（见 `plugin/src/base/telemetry/`）抓的是 BOSS 自己往外发的载荷，
所以「MAIN world 读留没留痕」是可以**持续观测**的。而 `historyMsg` 的暴露
落在 BOSS 的服务端日志里——那一面我们的可见度是零，而且永远是零。

信号强、可归因、我们看不见、全机队共享——这四条凑齐了。

再加损失不对称：

- MAIN world 读断了 → 立刻发现、fail closed、花一小时改判据
- fetch 路被标记 → 不是改代码能修的，是账号，而且可能是所有客户的账号

### 4.3 压垮它的一条：richness 这个理由本身不成立

BOSS 走的是 **OS 级键鼠注入驱动真实 UI**（见
[`第一段验收报告-OS注入链路-2026-08-28.md`](第一段验收报告-OS注入链路-2026-08-28.md)）。
在那个前提下：

> 我们点开会话 → **页面自己去打 `historyMsg`** → 页面填好 `list$` → 我们读。

数据一样全（`list$` 就是那个响应的归一化结果），网络上**一个字节都不多**，
headers、referer、埋点、节奏全是页面自己的。

**所以 MAIN world 读是免费拿到超集；自己调接口是花一笔可归因的暴露，
去买一份本来就到手的东西。**

唯一真需要自己调接口的场景是「不点开会话也要对账」——而那恰恰是最不像人、
最该被抓的行为。

## 五、MAIN world 足迹实测

用插件自己的 `executeScript` 实测（**不是 CDP**——两者注入机制不同，CDP 的数不作数）：

| 量什么 | 结果 |
|---|---|
| 连打两枪之间新增的 `window` 全局 | **0**（全局数三枪恒 332） |
| `func` 形式在 `performance.getEntries()` 的条目 | **0**（总条目三枪恒 205） |
| `files` 形式（从扩展加载 js）的条目 | **0** —— Chrome 对页面隐藏扩展注入的脚本加载 |
| 按数据形状搜整棵 Vue 树 | 282 组件，**0.9~1.2 ms**，五连打产生 0 个 `long-animation-frame` |
| 同一动作页面自己的 longtask | **86 ms**（比例约 1:57） |

对照 BOSS 已实证在查的清单：`Object.keys(window)` 差集（99003）、
`chrome.runtime` 可见性（550094）、设备指纹、本机端口探测、硬编码扩展 ID 探
`web_accessible_resources`、`isTrusted`——**一次性闭包读一条都够不着**。

**不需要给 zhipin 加 `content_scripts` match**：background SW 直接 `executeScript`
到目标 tab 即可，页面里零常驻，顺带绕开全文档 MutationObserver 撞 rAF 帧率那颗雷。

## 六、阳性对照：证明检测确实在跑

**一个刻意不留痕的探针没法自证跑过**——「零足迹」与「没执行」在观测上完全等价。
所以做了反向实验：用 `document_start` 的 MAIN world 内容脚本故意种一个可枚举全局
`__rhCanary_20260828`，然后刷页面。

**结果**：页面 21:55:17 加载，**21:55:27**（约 10 秒后）的上报里，
`800001` 的 `p6` 原样带出了这个名字。三件事同时得证——
他们的检测在跑、判据就是「可枚举 `window` 全局 ∉ 白名单 → 按名字原样上送」、
我们的埋点观测抓得住。

**意外发现：那份名单很脏。** 同一条 `p6` 里另有 12 个名字：

```
crashReport, viewport, initWarlockData, loadFallbackScript, loadLastbackScript,
apmVueErrorHandler, __originalFetch, litHtmlVersions, litPropertyMetadata,
litElementVersions, BOPI, __xbcw
```

其中 `crashReport`/`viewport`/`initWarlockData`/`apmVueErrorHandler` 是
**BOSS 自己页面的全局**——他们的白名单陈旧到盖不住自家页面。

这把单条命中的信号价值拉低了，但**没有归零**：一个稳定、独特、跨机队同现的名字
仍然可聚类。所以「别留全局」不放宽，只是理由从「会被抓」改成
**「别给跨机器可聚类的特征」**。

`__originalFetch` 在名单里，意味着有人 patch 了 `fetch` 并留了原引用——
「持久化 hook 会留痕」的现成反面教材。

**除故意种的金丝雀外，名单里没有任何一项来自我方插件。**
金丝雀已注销、页面已刷新清除。

## 七、执行方在此论证中说错的两处

留档，免得后来人以为这条路一开始就这么清楚。

**一、「Vue 内部 = 高脆」说过头了。** 那只对**按组件名**找的写法成立。
按**数据形状**搜（元素带 `mid`/`body`/`from|fromId` 的数组）不认组件名，
而形状就是 BOSS 的 IM 协议形状、和 HTTP 接口同一套——**两条路的失效模式高度重叠**。
把一个共有的风险算到了其中一条头上，比较做错了。

**二、押 `files` 形式注入会留 `resource` 条目，押错了。** Chrome 对页面
完全隐藏扩展注入的脚本加载，两种形式都是零条目。

## 八、知情接受的代价

**完整性判据从「已验证」换成「未验证」。** 被降级的 `c=100` 法
（返回不足 100 条即证明全量到手）是真机验证过的；接替它的 `isToTop`
**没观测过翻转**——测试账号最长会话 8 条、页大小 20，`isToTop` 一直是 `true`。
上生产前必须补验（需要一个 >20 条的会话）。

**「不点开会话就对账」这条能力放弃了。** 想要它就得自己调接口，
那正是本裁决否决的东西。

## 九、什么会推翻这个裁决

- **长期高频读被证明留痕。** 本轮只测了「空闲页面上读一次」，
  没测「按生产频率连续读数小时」。这个实验现在做不了——它要按生产读取频率跑，
  而频率取决于巡检设计，设计在本裁决之后。**顺序是 裁决 → 设计 → 频率实验，
  上生产前必做。**
- **埋点观测出现新码或全局名清单变长。** 那是我们对这条路的持续监测手段。
- BOSS 换掉 Vue、或把消息态挪出渲染层。

## 十、实现约束

走 MAIN world **可以**做的：一次性 `executeScript`、按数据形状搜、读完即返回。

**不许做的**（每一条都是已知会留痕的）：

- patch `fetch` / `XHR` / `WebSocket` 或任何内建 —— `Function.prototype.toString` 一验就露，
  且 `__originalFetch` 已在 BOSS 的上报名单里坐实
- 往 `window` 上挂任何东西 —— 直接进 99003 差集
- 声明 `web_accessible_resources` 带静态 URL —— BOSS 拿硬编码 ID 列表在探这个
- 在 MAIN world 里留 `setInterval` 或长驻引用 —— 周期性卡顿本身就是心跳
- 给 zhipin 加 `content_scripts` match —— 全文档 MutationObserver 撞 rAF 帧率

一句话分界：**读是隐形的，改和常驻是留痕的。**
