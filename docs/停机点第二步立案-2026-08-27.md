## 二、为什么做:三个真实病灶

**病灶一:真人插话挂人工,靠时间差定生死。** 现行判定:巡检建轮前扫描游标之后的账本行,只要我方出站与候选人输入并存,整个候选人挂 `interleavedOutboundBoundary` 人工(m5_v4_patrol.go:249-304)。真机案例(2026-08-12,候选人明杰):真人 16:31 手发文本+线下面试卡,16:34 候选人**接受面试**,16:38 巡检读到两边都在游标后 → 挂人工;主线停在 communicating、约面成功通知没进运营群——前后只差 40 秒。而只要巡检抢先读到过一次,同一条链完全能自动接住(纯我方尾巴逐条投影、真人手发的面试卡照样归一化成邀面事件推进到已约面)。**挂人工的唯一成因是时间差,不是能力缺失。** 甲方点名的开机场景是最坏子情形:停机期间两边消息攒在一起,开机首轮必然同时读到,100% 撞闸。

**病灶二:游标断案家族,第一步后从"冻死"变"原地打转",病根还在。** 无主行认领的真机战绩以自伤为主:195 个聚合里 49 个游标停在 system 行、40 个活跃档案一回复即锁死(0727 计划考古);2026-08-01"[微信交换成功]"无主行致验证读每秒空转 195 次;2026-08-03"可以直接给Ta打电话"系统卡致 22 人爆炸半径(8 冻结+13 待爆)。Q7 透明后缀只豁免了 system 行一类;每种新平台行为都要重新写死豁免规则,脆性无限增长。第一步把刑罚从终身冻结改成本轮跳过,但持久性矛盾者仍每轮跳过、原地打转,直到本案拆病根。

**病灶三:裁决即恢复不即时。** 您裁决 resolvedFailed("没发出去")后,机器不能在同一边界立即重新规划,只能"交给下一个自然触发点"(候选人新输入或时刻表)。代码注释自证这是游标约束所迫:"同边界重开轮受投影游标不可回退约束(轮身份=边界内容寻址,FreezeCommunicationV4Turn 要求边界在游标之后),故……不铸代次后缀"(m5_effect_resolution_recovery.go:14-16)。第一步完工报告已把"裁决恢复的即时性"登记为第二步消解项。

**规模背书**:体检口径,拆 turn/游标层可直接消灭约 134 个停机点(占应降级总数近一半)——本案摘除它们的裁决权(停止发病),第三步拆代码(尸体出门)。

## 三、方案一页纸

**1. 输入边界现算。** 每巡检轮从不可变消息账本直接算:锚 = 该会话最后一条我方出站(不分真人/系统,不分是否"认领过");本轮输入 = 锚之后的连续候选人消息(system 行不入锚也不入输入,现行 DialogueTurnCandidateMessages 语义保留);找不到任何出站行按来聊根处理。**推论:真人手发的出站行按构造就是新锚,天然免疫;无主行不再需要任何人认领;`interleavedOutboundBoundary` 扫描整个拆除。** 开轮不再要求游标连续、不再 CAS 游标、不再查 unclaimed。现算已有单点重建器可依托(reconstructCommunicationV4TurnBoundaryTx,m5_v4_turn_store.go:680-820,digest 自证防错锚)。

**2. turn 内存化。** 轮=每巡检轮现算的内存分组,用完即扔;AI 中间新鲜度重验删除(输入过时最多浪费一次 token);发送前保留一次终检(账本尾 CAS + guards,既有机制),失败方向 = 作废本批、下轮按最新账本重开。持久保留的只有三样:**动作事实行+链序**(多气泡"前项正证才发后项"的载体,体检判决必须保留)、**AI 调用 attempt 账**(5 次成本闸,必须跨重启存活,见 §六-2)、**裁决代次**(见 §四)。`collected/classified/adviceReady` 等轮生命周期状态、supersede/stalePlanned 全族概念随持久 turn 消亡。

**3. idemKey 派生根搬家**(唯一内核触点,详 §四)。

**4. "已回应至"水位落地**(决策 3,已批,固化性质)。每会话一个整数水位,仅静默收尾事务写入,消灭静默尾巴每轮重判(估算每人每天约 190 次多余调用);三条纪律钉死:只做下界永不做闸(不许相等比对/CAS/作停机条件,异常即当不存在按锚重算)、单写单向只增、水位压掉消息时记日志。"这批回过没有"由"动作行绑定该边界 + WAL 查重 + 水位下界"回答,不再问游标。

**5. 投影游标的去向(本案与第三步的分界)。** 本案把游标从**一切裁决路径**上摘下来:开轮、AI 边界重验、三道派发闸、时刻表四处等值闸、边界扫描——全部改为账本现算(判的问题不变:父项正证后无候选人新输入才发后项;Q7 透明后缀容忍照旧)。游标本体与业务事件投影机器(卡片跃迁→已约面等)**保留继续跑**,其推进规则由"认领制"简化为"顺序收编制"(过手行直接推进、业务事件按序应用、解释不了的行记日志不定罪);回执链重放/Corrupt 的拆除、V4State 现算、§12.4 契约破坏性修订,全部留在第三步。

**6. 不动面(一字不动)。** WAL/idemKey 唯一闸/手证词/发后正证/原语内不重试;guards 与 ExpectedTailSeq(侦察确认 dispatch 包生产代码零游标引用);suspect 冻结与人工裁决;存量 manualRequired 行零触碰(决策 1 硬边界);统一业务运行窗口;**手侧插件零改动、契约机器零改动**(不动 contract.v1.json、无 codegen、无硬切换——idemKey 的 `ik1:` 格式不变,变的只是脑内派生根)。

## 四、唯一内核触点:idemKey 派生根搬家

**现状链条(侦察核实,五环)**:账本边界内容寻址 → turnID = "turn-"+sha256(profileID+最后出站 seq/hash+每条输入 seq/kind/hash)(m5_dialogue_identity.go:136-176)→ ActionKey = turnID|kind[|card:seq][|bubble:n](v4_dialogue.go:643-664)→ ActionID → intentID = "intent-"+sha256(actionID)(同文件 231-240)→ idemKey = "ik1:{platform}:{accountRef}:{primitive}:{targetRef}:{intentID}"(m3_dispatch.go:635-637)。账本闸 = effect_intents 表 IdemKey 唯一索引 + 单写事务 CAS(m3_store.go:132-294)。

**关键侦察发现:turnID 今天本来就是边界指纹**——它不是数据库自增主键,而是边界内容的 sha256。所以"搬家"的实质**不是换键值形态,而是拆掉派生与校验链对持久 DialogueTurn 行的解引用**,并修剪指纹成员(去掉逐条输入的内容哈希、加入裁决代次)。

**拟议新配方**(规格先行批的实体内容,§五-1):

- 新根 = `bnd-v1` 域 sha256(档案 ID | 输入边界锚 | 裁决代次)。输入边界锚 = 本轮输入尾条候选人消息的服务端身份 sourceKey(身份战役成果:入站行经双重能力门槛保证有键;存量 NULL 行兜底见 §九 C3);来聊根沿用既有 inbound-root 版本化配方。ActionKey/intentID/idemKey 的派生**形式全部不变**,只换根。
- **三个必答坑的答案**(08-09 已讲解):①多条新输入取尾条身份、并一响应——同尾条=同边界=同键,天然防"同批输入二次送 AI 另铸新键";②文案不入键——重发=重新规划(决策 2),文案可变、位置不变、键不变;③裁决代次平时恒 0,每次 resolvedFailed 裁决在裁决事务内 +1——**这就是病灶三的解药**:同边界重新规划立即可行、键确定性区别于旧尝试,不再等下一个自然触发点。裁决代次是本案唯一新增持久状态(每档案一个整数),不参与任何闸、只入键。
- **版本域纪律**:按既有先例("版本域属于持久身份配方,未来变更必须换域而不能迁移旧 key",m6_sourcing_greeting_store.go:264-266)换 `bnd-v1` 域,存量 `turn-…` 键一律不迁移、按派发时契约解释。

**安全论证(为什么不开双发通道)**:

1. **同世界同键**:新根仍是持久账本内容的纯函数(消息行身份+档案+裁决代次全部落盘),同一世界状态任何时刻、任何重启后重算恒同键——账本闸拒绝后重算不出第二个键。
2. **闸本身零改动**:effect_intents 唯一索引、单写事务、ConversationEffectHead CAS、手证词、发后正证原样;§7.5 三道闸叠防结构不变。
3. **§7.4 不变式保全**:"自动生产者必须先持久化唯一业务动作事实,并从该事实主键确定性派生 intentId"——动作行仍先于 intent 落盘(见 §九 C1),变的是动作身份的配方来源;§8.4 的 |try{n} 干净失败重铸通则逐字成立(基础语义键不变、后缀铸新键)。
4. **在途处置硬边界**:切换版本内,已存在的 planned/在途/悬置行按旧键收束或按既有作废裁决(Q1/Q2/stalePlanned)作废,新键只用于新铸;绝不对同一逻辑动作先后用两个键派发——旧行要么已终局要么作废重铸,与契约硬切换同款纪律。

**受影响键面 / 不受影响键面**(侦察全量清单):
