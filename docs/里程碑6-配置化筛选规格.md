# 里程碑 6：配置化筛选规格

日期：2026-07-22

状态：甲方已批准《端到端业务主线计划》中的配置化筛选阶段；本文冻结正式批次的最窄确定性算法，不扩展到招呼语生成或发送。

## 一、出口与边界

本阶段只消费一个“采集已完成、统一评分已全部终局”的正式批次，读取该批冻结 revision 中的 `minScore / targetMin / targetMax / maleRatioLimit`，在一个 SQLite 事务中形成全员一次性筛选决策和稳定入选名单。

AI 不参与选人。本阶段不调用 provider、不调用手端、不生成招呼正文、不创建 greeting head / effect intent，也不发送消息。入选者建立 `selected` CandidateProfile，作为下一阶段招呼语生成的稳定业务对象；其余成员只留下明确落选事实。

## 二、范围与完整屏障

1. 入口只接受随机 `batchId`，账号、成员、职位与配置 revision 全部从批次反查，调用方不得覆盖。
2. 批次必须为 `completed + endedAt`，成员数等于采集目标；每个成员必须有唯一、`finishedAt` 非空且与 run revision/content hash 一致的评分调用。任一 pending/in-flight 或跨批材料立即拒绝，不能拿部分评分提前选人。
3. 查询只允许 `run.batchId = batchId`；同账号同 revision 的其他批次、未完成批次和 `batchId=NULL` 历史行不得进入。
4. 全批成员决策、入选 CandidateProfile 与批次筛选摘要在同一事务中提交。中途任一写失败必须全部回滚；重跑只能读取既有完整结果，不得产生第二份名单。

## 三、目标人数与排序

旧系统在 `targetMin..targetMax` 闭区间随机取目标人数。新系统保留同一范围分布，但把随机性构造为稳定函数：

`targetCount = targetMin + BigEndian.Uint64(sha256("selection-target-v1|" + batchId + "|" + revisionHash)[:8]) % (targetMax-targetMin+1)`

当上下限相等时直接取该值。目标人数与算法版本同时写入批次筛选摘要；同一批次重放永远得到同一目标，不依赖进程随机种子。

候选池按以下全序排列：

1. 合法评分降序；
2. `capturedAt` 升序；
3. 随机 `runId` 字典序升序。

旧系统的第二键 `lastActiveTime` 当前采集事实没有可靠来源，不猜造；`capturedAt + runId` 只负责打破同分并保证稳定，不表达候选人质量。

## 四、逐人确定性裁决

按全序遍历，每个成员固定得到一种 outcome：

- `scoringFailed`：评分不是成功终局或没有合法分数；
- `contactStateRejected`：采集时已不是未建联状态；
- `scoreBelowThreshold`：分数低于后台 `minScore`；
- `existingProfile`：同一人已被既有未淘汰档案占用，不创建新档案，也不占本批新选名额；
- `quotaFull`：新入选人数已达到稳定 `targetCount`；
- `maleRatioLimited`：候选人属于男性且本批男性入选数已达到 `floor(targetCount × maleRatioLimit / 100)`；
- `selected`：通过以上全部条件，创建唯一 `selected` CandidateProfile 并占一个名额。

`targetMin/targetMax` 是目标人数抽样范围，不是“最低必须选够”的成功门槛。合格人数不足时选择当前全部合格者，不降低最低分、不补采、不报错。

## 五、性别口径

1. 先读取简历基本信息中明确的 `性别=男/女`；没有该字段时，只承认平台展示名末尾精确的公开称谓 `先生/女士`。这是本地筛选事实，不进入 AI provider 输入、日志、管理响应或文档。
2. 不从姓名字形、头像、经历或其他自由文本推断。无法确认时记 `unknown`。
3. 为延续旧业务含义，只有明确 `male` 占男性名额；`female/unknown` 不占。批次摘要必须暴露脱敏的 unknown 数量，真实运行若出现大量 unknown，再以事实决定是否补采结构化性别，不在本阶段先造私有数据通道。
4. 男性上限只限制男性人数，不保证女性最低人数。达到男性上限的男性记 `maleRatioLimited`，不以笼统“名额满”掩盖原因。

## 六、持久化与管理投影

新增一条 `SourcingBatchSelection` 业务摘要，以 `batchId` 为主键，保存算法版本、冻结 revision、目标/阈值/男性上限、池/合格/入选/男性/未知性别计数和完成时刻。该行与逐人 `SourcingSelectionDecision`、CandidateProfile 均禁止物理删除。

管理端只返回批次随机引用、revision hash、算法版本、配置数值、聚合计数和完成时刻；不得返回候选人身份、姓名、逐人分数、简历、profileId 或名单明细。

## 七、停止条件

自动化门禁必须覆盖批次隔离、评分完整屏障、高分优先与同分稳定排序、低分/失败/已建联/已有档案、人数上限、男性上限、事务回滚和重跑幂等，并证明 provider、hand、greeting head、effect intent 与 effectful command 均未增加。

首个真实 3 人批次按正式后台配置得到完整筛选摘要和稳定 decisions/profiles，且零发送事实，即为本阶段出口。达到后单独提交脱敏冒烟记录，再进入“批量生成招呼语”。
