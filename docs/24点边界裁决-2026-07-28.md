# 24 点边界裁决（2026-07-28 甲方裁决）

本文件固化甲方对统一业务运行窗口 24:00 边界粒度的修订裁决。它修订 `AGENTS.md`「统一业务运行窗口（2026-07-25）」条款中"运行跨过 24:00"的收束粒度，其余窗口条款（`[08:00, 24:00)` 显式开始、`[00:00, 08:00)` 不可用、08:00 不自动恢复、开发期环境变量覆盖）不变。

## 背景与触发案例

2026-07-27 23:59 真实运行（turn-38f83a15…，拒绝挽留分支）：候选人拒绝后，三条挽留话术气泡分别于 23:59:48 / 23:59:54 / 23:59:58 发出并逐条取得服务端正证，最后一条气泡承诺"加个微信"；随后的换微信卡片动作按当时规则于 00:00:00 被日界闸挡下（planned 保留、intent 未铸造），候选人隔夜处于"承诺加微信但未收到请求"的可见中间态，次日恢复轨补发。该形态凡在 24:00 前约 20~30 秒内开始派发的回复链均可复现。

## 旧约束（2026-07-25 原文，被本裁决修订的部分）

> 运行跨过 24:00 时，已经开始的单个 AI 调用或手侧命令按既有账本/恢复纪律自然收束，随后工作流持久化为 `waitingDailyWindow`，不得开始下一候选人、下一阶段或新 effect intent。

即动作粒度：链内每个动作各自需要派发授权，跨点即停，业务单元（一个 turn 的气泡+卡片）可被时间边界劈开。

## 新裁决（权威文本）

运行跨过 24:00 时：

1. **不得开始下一候选人、下一阶段**，也不得为新候选人或新 turn 铸造 effect intent。
2. **已发出首条候选人可见动作的当前回复动作链继续收束到终局**：余下气泡与已获正证前提的卡片按既有交互节奏与安全轨逐项发送，视为当日运行的自然延续；接受数十秒级的跨点尾巴。
3. **尚未发出任何候选人可见动作的 turn 不跨点**：包括仍在 AI 调用或分类阶段的 turn，整体悬置至次日，候选人无任何感知。
4. **收束期间链内失败、断连、suspect 或转人工即止**，不为收束新增任何重试；残留的未派发 planned 动作一律作废（2026-08-02 甲方裁决，替代原“次日恢复轨自动续发”语义），次日按最新世界状态重新规划；已取得正证的前项照常保留、不回滚。
5. 既有 effectful WAL 的判定与收敛不算新业务授权，仍须继续（不变）。

### 边界定义

"链已开始" = 当前 turn 已有至少一个候选人可见动作取得派发（首条气泡已发出或已铸 intent）。链内推进指同一 turn 内、紧接前项正证后的下一动作派发；残留 planned 动作已按第 4 条作废，次日一切派发均来自按最新世界状态重新规划的新动作，须重新满足完整窗口与守卫条件，不属于链内推进（2026-08-02 修订）。

### 终态定案（连带裁决项）

- **沟通阶段**（stage=communication，含 full 与 replyOnly）跨日：当前链终局后，运行按跨日终局处理——`status=completed`、`end_reason=dailyWindowClosed`。次日须用户显式点击开始（新 run）；沟通连续性由业务账本（聚合与动作事实）承载，与 run 对象无关（2026-08-02 起残留 planned 不再续发）。此定案将既有实现（跨日 completed、空 end_reason）如实固化并补齐终局原因。
- **漏斗阶段**跨日：持久化为 `waitingDailyWindow`，次日显式恢复继续原批次（不变）。

## 被否决的备选

- **三种边界（暂停/结束/24:00）全部统一为候选人粒度**：否决。暂停是人工止损闸，必须保持动作间响应（能拦住链的后半截）；宪法"人工停止能力不删除"。
- **开链余量闸**（距 24:00 不足 N 秒不开始新链）：否决。启发式魔法数，甲方认为不够优雅；链粒度授权是构造性方案。

## 不变式（本裁决不触碰）

- 安全内核：WAL/idemKey/手证词/平台正证/manualRequired/suspect 一律不变，链内每个动作仍是独立业务动作事实，逐项走各自安全轨。
- 暂停（Pause）保持动作间止损语义：链收束期间用户点暂停，链在下一动作前即止。
- 结束（End）保持候选人间收尾语义（不变）。
- `[00:00, 08:00)` 不得派发任何新链；08:00 到达不自动恢复。
- 交互节奏与条件等待条款（2026-07-23）不变，链收束期间照常执行。

## 实现义务与观测

- 链内推进点不再做日窗口/日界复核，仍复核：上下文取消、账号显式停止/暂停、手换代、批次换代。
- 巡检轮不再以 24:00 wall-clock 超时取消等待中的调度；日界收束由链首/候选人边界的既有复核点承担。
- 巡检轮因日界收束终局时，错误码使用专属 `DAILY_WINDOW_EXPIRED`，不再落入 `BRAIN_INTERNAL` 兜底。
- 后置项（不入本轮）：脑侧 sentinel 错误的 `errorCode()` 兜底分类整体细化；账号 `paused_reason` 被跨日收尾覆盖为 `userPaused` 的观测语义；产品 UI 对"次日等待"状态的文案呈现。

## 风险预算（甲方知情接受）

- 每日至多一条链的候选人可见消息可能落在 00:00 后数十秒内。
- 隔夜可见中间态从"撞线必然发生"降为"仅异常中断（断连/失败/suspect）时发生"，不承诺根除；2026-08-02 起残留项不再由恢复轨补发，中间态由次日按最新状态重新规划的动作或时刻表自然收敛（甲方知情接受）。
