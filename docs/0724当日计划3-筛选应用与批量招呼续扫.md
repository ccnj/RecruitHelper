# 0724 当日计划 3：筛选应用与批量招呼续扫

日期：2026-07-24
状态：已完成；筛选应用与批量招呼续扫均已通过真机验收

## 一、目标

本计划清偿 M6 的两个既有待办：

1. 采集开始前，把本批后台职位配置中的“职位筛选”真实设置到智联推荐页，
   提交后回读确认，再开始读取第一份简历；
2. 批量招呼改为从页面顶部开始一次顺序扫描，后续候选人从当前位置继续，
   不再为每个人重复回到顶部。

本计划不改变入选名单、已生成招呼语、候选人稳定身份或既有发送安全轨道。

## 二、出口与风险预算

### 2.1 最小交付出口

- 后台筛选配置能够唯一映射到当前智联筛选控件；
- 正式脑手路径完成“逐项覆盖 → 确定 → 等待列表稳定 → 重新打开并回读
  → 取消关闭”；
- 回读与目标完全一致后，正式采集批次才进入第一份简历读取；
- 批量招呼只在整批开始时回顶部一次，随后沿当前页面向下扫描并发送遇到的
  待发送成员；
- 第一轮未定位成员最多再执行一次顶部兜底扫描，仍未定位则保留
  `pending/notLocated`；
- 自动测试、插件构建、契约生成检查和有人值守真机冒烟通过。

### 2.2 必须立即阻断

- 把后台职位 A 的筛选条件应用到职位 B；
- 筛选字段零匹配、多匹配、回读不一致或页面尚未稳定就开始采集；
- 按姓名、头像、`resumeNumber`、DOM 顺序或页面位置认领候选人；
- 同一招呼生成事实构造两个 effect intent，或绕过既有
  WAL、idemKey、witness 与页面正证轨道；
- 推荐流换代后沿用旧位置提示并据此错靶发送。

### 2.3 可接受失败

- 智联控件暂时不可见、加载超时或某个后台字段尚无可信页面映射；
- 当前推荐流中暂时找不到某位待发送成员；
- 尾锚因推荐流换代消失；
- 普通页面滚动、虚拟列表或稳定读取失败。

这些情况只允许停止、阻塞或保持 `pending`，不得猜测、降级身份或自动补发。

### 2.4 审查与明确后置

本计划最多一轮定向独立审查，只检查错职位采集、错靶发送、重复发送、
账本破坏与长期锁死。候选人离开当前推荐流后的直接平台 API 定位、其他平台、
“催”相关沟通、客户交付机制和无人值守 SLA 继续后置。

## 三、通用页面事实发现工作法

### 3.1 默认顺序

页面事实发现优先使用 GPT Chrome 控制能力直接操作当前已登录的真实页面：

1. 截图确认可见状态；
2. 读取目标区域的局部 DOM、标准属性、可见文字和父子关系；
3. 对比已选与未选状态；
4. 必要时做一次可逆点击，等待至少一秒后复读；
5. 使用“取消”等公开动作恢复未提交现场。

事实取得后再一次性写入 RecruitHelper 正式原语，最后通过真实脑手命令验证。
页面考古不得冒充生产验收。

### 3.2 通用适用边界

该工作法通常适用于：

- 可见 DOM、表单、弹窗、菜单、按钮与选中状态；
- 可逆的打开、切换、填写、滚动和取消；
- 页面提交后可见状态变化与列表稳定性；
- selector、控件层级及公开交互语义的快速考古。

以下事实不能只靠 GPT Chrome 观察宣告完成：

- Chrome 扩展 service worker 生命周期、权限和监听行为；
- isolated world 与 MAIN world 的真实执行差异；
- 脑手协议、命令序列化、deadline、取消和重连；
- witness、WAL、idemKey 与持久化恢复；
- 候选人可见副作用的正式正证与重复执行结果。

只有 GPT Chrome 无法取得实现所需的关键页面事实，或其执行环境与生产
MAIN world 确有差异时，才允许加入最小临时只读探针；探针采样后立即删除，
不得混入正式 capability 或长期调试契约。

## 四、批次一：筛选面事实门

先读取本批后台职位最近一次成功配置中的“职位筛选”，列出实际启用字段。
旧项目只提供候选字段和入口线索，当前智联页面才是实现依据。

在真实页面逐项记录：

- 后台字段、取值范围与“不限”语义；
- 智联分组的规范化可见标题；
- 控件类型：单选、多选、开关、数值、范围或级联选择；
- 选项的唯一定位方式；
- 已选与未选状态的公开证据，优先级依次为：
  原生 `checked/value`、标准 `aria-*`、可见勾选或当前值；
- 若只能读取样式状态，必须通过真实前后状态对比钉死，读不到时失败关闭；
- “确定”后的加载形态、推荐列表稳定形态；
- 再次打开筛选框后，已提交状态是否可由同一读取器完整恢复；
- 未修改时点击“取消”是否只关闭面板且不再次刷新列表。

产出不含候选人信息的筛选事实记录。事实门不能闭合的后台字段不得猜测实现；
是否允许暂时不支持该字段须另行裁决。

## 五、批次二：正式筛选设置与回读

### 5.1 定位与状态读取

定位顺序固定为：

`唯一可见筛选面板 → 规范化字段标题的唯一分组 → 分组内唯一目标选项或输入`

不得使用全局选项文字、`nth-child`、屏幕坐标或 Vue 内部对象认领控件。同一
分组内的“不限”只属于该分组。

首次设置、点击前复核和提交后二次确认必须复用字面同一份
`readFilterState()`，输出规范化完整状态。

### 5.2 设置流程

1. 脑冻结本批 `BackendJobID`、职位名称、配置 revision 与目标筛选状态；
2. 插件打开筛选框，不执行整体清空；
3. 对后台管理的每个字段逐项覆盖：
   - 单选当前值不同时才点击目标；
   - 多选只点击当前集合与目标集合的差异项；
   - 数值或范围写入后触发标准 `input/change` 并回读；
   - 后台表示无约束时，明确设置该分组的“不限”；
4. 相邻交互至少等待一秒并带随机量；元素就绪最长等待十秒；
5. 完整目标状态首次回读一致后，点击一次“确定”；
6. 等待加载结束，并要求首个推荐窗口连续两次稳定；
7. 再次打开筛选框，用同一 `readFilterState()` 逐项回读；
8. 完全一致后点击“取消”关闭，不再次点击“确定”；
9. 独立回读当前智联职位仍与本批职位绑定一致；
10. 以上全部成立后，才允许批次进入第一份简历读取。

设置或回读失败不得沿用页面原有条件继续采集。

## 六、批次三：页面驱动的批量招呼续扫

### 6.1 执行顺序

本批所有满足 `selected + greeting ok + 尚未绑定发送 intent` 的成员组成
待发送集合，以稳定 `platformUserRef` 为唯一页面匹配身份。执行顺序改为页面
出现顺序，只改变发送调度顺序，不改变入选名单、正文或筛选结果。

1. 整批开始时执行一次 `reset` 回到推荐列表顶部；
2. 从顶部读取稳定窗口；
3. 窗口内某张卡的稳定身份属于待发送集合时，事务内重新核对发送资格，
   再复用既有 `chat.sendGreeting@1` 正式轨道；
4. 取得终局后保持当前位置，继续向下读取；
5. 非目标卡片直接跳过，不为某个指定候选人无限向下搜索。

### 6.2 有限扫描边界

平台候选人近似无限，不使用“推荐列表到底”作为完成证据。第一轮扫描以本批
采集范围为边界：

- `batchTailAnchor` 取本批最后一位成功采集成员的稳定 `platformUserRef`；
- 第一轮遇到尾锚并完成其后一个稳定窗口，即认为已经覆盖原采集区域；
- 若推荐流换代导致尾锚消失，第一轮最多检查
  `2 × capturedCount` 个不同稳定候选人身份；
- 第一轮结束后，仍未定位成员最多触发一次 `reset`，从顶部按同一边界兜底；
- 第二轮仍未定位的成员保持 `pending/notLocated`，本次执行结束。

扫描位置、窗口摘要与尾锚都只是定位提示，不能授权发送。只有当前可见卡片
精确匹配稳定 `platformUserRef + positionRef`，并通过既有 greeting evaluator，
才可构造或执行候选人可见动作。

页面刷新、插件重载或推荐流换代会立即作废当前位置提示；系统不得主动刷新
页面来辅助定位。

## 七、自动化与真机验收

### 7.1 筛选

自动化至少覆盖：

- 单选已选/未选、无需重复点击；
- 多选集合差异；
- “不限”覆盖旧值；
- 数值与范围写入及回读；
- 字段零匹配、多匹配和状态不可读；
- 确定后列表稳定；
- 二次打开使用同一读取器精确回读；
- 二次确认点击取消且不产生第二次列表刷新；
- 回读失败时零简历读取。

真机选择一个后台职位，完成完整设置与二次确认；只在回读一致后采集少量
候选人，确认批次职位、筛选 revision 与采集事实一致。

### 7.2 招呼续扫

自动化至少覆盖：

- 整批只在开始时回顶部；
- 遇到多个待发送成员时从当前位置连续推进；
- 页面顺序与评分顺序不同时按页面顺序执行；
- 尾锚正常命中；
- 尾锚消失时按 `2 × capturedCount` 预算停止；
- 未定位成员只进行一次顶部兜底；
- 第二轮仍未定位时保持 pending 且零 effect intent；
- 已发送、非 selected、生成失败和错职位成员不进入发送；
- 重复管理请求、脑重启和插件重连零重复；
- 页面刷新或推荐流换代后旧位置提示失效。

真机使用一个小批次，至少连续命中并发送两位候选人，确认第二位没有先回顶部；
若现场确有未定位成员，验证最多一次顶部兜底且没有身份降级或重复发送。
