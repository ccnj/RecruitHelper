## 〇、系统是什么

替 HR 在智联招聘上干活的机器人：搜简历采集 → AI 按职位打分（不合格**淘汰**，全程未被打扰）→ 合格者发**招呼** → 大模型聊天 → 目标**约到面试**。约上后真人运营在微信接手。采集、打分、自动选人和招呼调度节律不在本规格内；除 M4 增加的“人工指定当前候选人 → 已选中”入口及招呼结果收束外，本规格仍自招呼发出起接管。

**巡检模型**：系统以巡检驱动，**每天由真人手动开启一次**（不早于 8:00），开启后每隔数分钟（运维参数，非精确调度）扫一遍全部活跃档案，最晚运行至 24:00。**一切时间门槛都是下界**——到期后的首次巡检执行；无巡检外的实时通道（"无条件同意换微信"等动作也于巡检到达时执行）；夜间及未开启时段到期的一切档位（含归档）自然顺延至下次开启后的首次巡检。单档案的巡检处理顺序：**先事件层 → 再对话分支（存在未回应真实文字时，时刻表不适用）→ 最后时刻表**。

系统只能感知智联站内；微信里发生的事（是否真加上好友）永不可知，故一切话术禁止"已加上/已通过"类完成断言。

## 一、术语

- **真实文字**：候选人自己生成的表达——打字、表情、图片、语音、文件都算；**主动发起换微信请求视同真实文字**。纯点卡片按钮（同意/接受/拒绝）不算。
- **正文**：我方的招呼、对话回复、挽留、收场——穷尽列举，此外（卡片、冷催、跟催、回执）都不是正文。
- **冷催**：催1（AI 追问）与催2（固定话术+换微信邀请）。全文"催"未加限定时专指冷催；跟催永远单独称呼。
- **对话轮**（判意向的单位）：巡检轮到该档案时，自我方上次已发消息以来候选人的全部消息合并为一轮，判一次意向；判后新来的消息属于下一轮。图片/语音等以"[候选人发送了图片/语音/文件]"占位进入判意向输入。
- **旧轮失效**：判定结果落库后、真实 effect intent 构造前若又观察到候选人新消息或真人出站消息，旧轮未发 action 显式标记为 `superseded/manualRequired`，不再自动执行。新消息属于下一轮，但 M5-A 冻结该档案等待真人，不自动合并、重写或连续发送；effect intent 已构造后的页面变化仍由既有 expectedTail/evaluator、验证与 suspect 收敛，业务层不得旁路取消后补发。
- **催1 计数轮**：自档案建立或候选人最近一条真实文字起，至下一条真实文字止。档案建立即存在初始轮——从未说过话的人也在一个轮里。
- **归档**：主线置"已结束"并记录原因（end_reason），同时**剩余冷催预算清零（含未打出的催2）**。任何原因的已结束都可被唤醒。
- **发过**：只算真正发出的。招呼后的沟通动作在**尚未构造真实 effect intent**的 AI 分类、建议生成或确定性计划阶段失败，只能在该 turn 已批准调用预算仍有余额时继续计算；已落库的分类不得重判，已冻结的合法建议不得重新生成。M5 P 档意向调用失败固定落 `neutral + llmFailureFallback` 后继续一次独立回复调用，回复调用失败则预算耗尽并立即转人工。**一旦真实 effect intent 已构造**，恢复与失败完全服从《协议规格-v1》：只有同 witness store 且 `report=unknown` 可重投原 `msgId`；`failed/sideEffect=none`、任意 receipt rejection、阴性验证与 `resolvedFailed` 均终局化原意图并把业务动作转人工，自动调度不得另铸；possible/confirmed/结果未知只进入验证、suspect 或人工裁决。只有唯一发送正证才算“发过”。**招呼阶段**仍只在平台明确业务拒绝并返回 `GREETING_REJECTED` 且 `sideEffect=none` 时由“已选中”进入“已结束（招呼失败）”；其他技术失败不推进主线，仍按既有验证、suspect 与人工裁决语义收敛。

## 二、实体与状态

**档案 = 人 × 职位**，沟通逻辑永远单档案视角。同人同职位重复采集：更新资料，不重置状态与预算。

主线状态跃迁表（全部跃迁，无其他）：

| 事件 | 跃迁 |
|---|---|
| 人工指定当前候选人（M4 有人值守入口） | → 已选中 |
| 插件采集入库 | → 已采集 |
| AI 打分完成 | 已采集 → 已打分 |
| 选人通过 / 不通过 | 已打分 → 已选中 / 已淘汰 |
| 招呼取得唯一发送正证 | 已选中 → 已招呼 |
| 平台明确业务拒绝（`GREETING_REJECTED` 且 `sideEffect=none`） | 已选中 → 已结束（招呼失败） |
| 候选人首次真实文字 | 已招呼 → 沟通中（招呼前的档案收到消息：**暂不响应，预留**——接入需插件端补采简历信息，见文末留白） |
| **实际发出邀面卡** | 沟通中 → 已邀面（仅文字提及时段不算；卡只可能发给说过话的人） |
| 点接受面试 | 沟通中/已邀面/**已结束** → 已约面（平台邀面卡不随归档失效，唤醒后或归档后点旧卡同样生效） |
| 归档 | 推进态 → 已结束 |
| 唤醒 | 已结束 → 沟通中 |

人工入口只有在 `candidate.readCurrent` 返回稳定候选人/职位身份且真人明确确认时才成立；单纯读取不建档。脑创建或收编“已选中”档案，不伪造“已采集/已打分”历史，并继续受本节“人级建档闸”约束；已有同一“已选中”档案只收编，不得借人工入口重置终态或绕过其他非“已淘汰”档案。除表中两种招呼结果外，其他招呼技术结果均不是主线跃迁事件：档案保持原状态，按验证、suspect 或人工裁决处理。

状态分三类：**推进态**（已采集→…→已邀面，漏斗与时钟在此运转）、**服务态**（已约面——活着，但只做"回消息+收号回执"，无时钟）、**归档态**（已淘汰不理；已结束可唤醒）。**沉默轨 = 已招呼、沟通中、已邀面**——时刻表只对这三个状态生效。

微信线：未邀请 → 已邀请 → 已换号，只进不退（候选人主动换微信时可由未邀请直跳已换号）。

**人级三规则**（档案之外的全部特判）：

1. **建档闸**：某人存在任何非"已淘汰"档案 → 其他职位永久忽略他。联系过的人一生只被追求一次；只有已淘汰者（必然从未被打扰）可被别的职位重新采集。
2. **拉黑**：推进态档案就地归档「拉黑」；服务态与归档态无操作。不做跨档案传播。
3. **微信号**：人级资产，重复收号重复通知，不去重。

## 三、四条公理

**公理1 · 相对时钟**：一切时间判断 = "距我方最后一条**已发**消息多久"。锚点随每条已发消息滑动（含冷催、跟催、回执），**也含真人在同一账号手动发出的消息**——人工插手自然滑动锚点、时钟顺延，系统不与真人抢话。（唯一例外：7 天兜底以我方最后一条**正文**为锚，见第四节。）

**公理2 · 打扰预算**（防止打扰过度的量化）：

- 消息分两类：**他驱动**（他说一句我们回一句：回复、挽留、收场、回执）免费不限量；**时钟驱动**（冷催与跟催）一律花预算。
- **冷催预算** = 催1×2 + 催2×1，档案终身，只减不增，无任何充值；**归档时剩余清零**。
- **跟催赠额** = 每张**实际发出的**邀面卡附赠 3 档。
- **判意向=拒绝 → 冷催预算即刻清零**（拒绝是清零最快的方式，不是"不催"的原理本身）；**不没收跟催赠额**——跟催是对卡的跟进，而卡只会出现在他自愿走回约面流程之后。沉默则让预算自然耗尽。
- 正反馈不充值：只有**真实文字**开启新的催1 计数轮；点卡、换号都不开轮。
- 约束二则：催1 每个计数轮至多 1 次；催2 需微信线未推进（物理条件：没法对邀请过/换过号的人再发邀请）。

**公理3 · 真实文字主宰对话**：真实文字一出，已到期未执行的冷催与跟催不再触发、当前卡的跟催组作废、计数轮重开，流程交回对话分支。**按钮不算说话**：纯点卡片不进对话（不判意向）、不开新轮、不动预算、不终止冷催；但按钮可改变事件层事实（状态跃迁、微信线推进、**作废所属卡的跟催组**——见事件表）并触发**回执**（固定话术或 AI 生成，视场景而定）。

**公理4 · 固定话术不重复**：每种固定话术对同一档案至多一次；跟催按"每张卡一组"，组内档位因开口或拒卡作废后**不复活**。话术文本与附带动作解耦：轮到该发但文本已发过 → 跳过文本、动作照做。拒绝流程的权威定义在第五节。

## 四、时刻表（沉默轨内的时钟行为）

**兜底最优先**：每次巡检处理任何沉默轨档案时，先查兜底——距我方最后一条**正文**满 7 天 → 立即归档「兜底归档」，**不论是否存在未回应消息或失败重试**，不参与下面的"最低一档"竞争。这是全系统唯一的失败安全网。

其余三行的门槛都是"距我方上一条已发消息"；每次巡检对一个档案只执行当前最低的一档，锚点滑动自然顺延其余；执行失败不算执行，下轮巡检重试。

| 档位 | 门槛 | 条件 |
|---|---|---|
| 跟催①②③（仅已邀面，每卡一组） | +10分钟 / +1小时 / +4小时 | 按序发、永不跳档 |
| 冷催 | +24小时 | 有可用催：催1 优先（余额>0 且本计数轮未发），否则催2（未发过、**未被清零**、线未推进） |

## 五、他说话了（对话分支）

**AI 权限边界**：AI 是纯建议层。判意向 AI 只能映射为 `interested | rejected | neutral` 建议；回复 AI 按现网旧格式返回必有 `话术_序列`，可选 `动作` 与 `会议时间:string`。脑只读取非空字符串话术，逐项 trim、丢空并保持原序；一个数组项就是一个候选消息气泡，不按标点或项内换行再次切分。非空项须为 `1～5` 个，每项都满足 `chat.sendMessage@1` 的 2048-byte 上限，且按换行连接后的整组文本仍不得超过 2048 bytes。`动作` 是封闭建议枚举，只允许缺失/空值/`无`、`发起线上会议`、`发起换微信邀请`，不得兼容别名或自由动作。`发起线上会议` 必须同时给出非空 `会议时间`。该字段只做首尾 trim；结果必须严格采用现有提示词格式 `M月D日HH:mm`（月、日不补零，时、分为两位，如 `7月14日14:00`），并与本 turn 已持久化冻结的 canonical 推荐时段列表逐项按同一格式渲染后恰好命中一项；不解析相对时间、别名或其他格式。唯一命中后，脑固定派生邀面参数：`startsAt` 为命中 canonical slot 的 Unix epoch 毫秒，`endsAt=startsAt+30分钟`，`method=wechatVideo`。`无` 与 `发起换微信邀请` 只能携带缺失或空 `会议时间`。本 turn 缺少 canonical 推荐时段列表（包括仅保存旧渲染文本的旧 turn）、字段非法、命中数为零或多项、未知动作、动作与时间组合非法、白名单外顶层字段、缺失或非法话术数组、越界话术项或整组文本，均使本次回复建议整体无效：整 turn 转人工，不创建任何正文或卡片 `CommunicationAction`，也不创建 effect intent。

通过输出契约只表示取得候选建议。脑还必须按已持久化主线、微信线、动作余额、卡片事实与本轮边界重新裁决：线上会议只在当前分支允许邀面且候选人已经说过话时可用；换微信邀请只在线未推进且一生一次的物理余额仍可用时可用。不满足业务前置的合法枚举建议不创建卡片 action，正文也不单独发送，整轮转人工，避免发送“马上发卡”等承诺后实际没有卡。AI 永远不能直接推进状态、创建 effect intent、选择重试或改变动作顺序；邀面状态和跟催赠额只在邀面卡取得唯一发送正证后推进，微信线也只在卡片动作或交换结果取得正证后推进。意向与回复是两次用途、预算和 invocation 各自独立的 provider 调用，不得合并 prompt、请求、输出或失败语义。

**M5-A 激活剖面**：只自动处理一个显式试运行、且已正式绑定 profile/conversation/后台职位的单轮普通文本。首条真实文字仍先按主线事实把“已招呼”推进为“沟通中”，不等待 AI；自动动作只开放 `interested/neutral → replyText`。`rejected` 只落分类并转人工，不执行固定挽留/收场、预算清算或换微信邀请；主动换微信、卡片、媒体、服务态、时钟动作及其他未激活能力也全部转人工。这只是阶段性能力削减，不改写本文完整目标行为，也不得用不完整动作冒充完整分支。模型文字中约定面试时段只算候选建议，真人负责后续发卡，不得推进“已邀面”或记录卡片成功。

**M5-B 激活剖面与组合动作**：M5-A 的能力削减在 M5-B 已知分支上解除，但安全内核不变。单个业务轮默认至多一个候选人可见动作；AI `话术_序列` 的 `1～5` 个消息气泡，以及以下“正文→我方新发卡片”固定组合，是本文批准的例外：AI 正文 + 邀面卡、AI 正文 + 换微信邀请、拒绝挽留正文 + 换微信邀请、催2正文 + 换微信邀请、面试接受确认正文 + 换微信邀请。整组 AI 建议必须在首发前一次性通过输出契约、业务前置与卡片资格裁决；随后只物化第一个动作。组合不是一个多动作原语：每个气泡和卡片各有稳定动作键、独立 WAL/idemKey/证词/正证，严格按数组顺序串行；前一个气泡取得唯一正证后才可物化下一个气泡，最后一个气泡取得唯一正证后才可构造卡片 effect。任一前项未确认、失败、suspect 或转人工时，所有后项停止且不得另铸同义动作；已经正证的前项不因后项失败而回滚或补发。暂停或跨日发生在下一项 WAL 前时保留不可变建议序列，恢复后重新核对当前会话、活动消息尾与 effect head/CAS，世界状态已经变化则转人工。

拒绝挽留正文沿用旧后台固定话术 `rejectWechat.messages` 的既有数组边界：经 trim 后的每个非空数组项就是一个候选人可见气泡，顺序不变，不按标点或项内换行再次切分；合法序列为 `1～5` 项，每项及整组均须满足正文长度约束。兼容字段 `message` 若存在，必须仍与原始 `messages[0]` 相等，不得借兼容回退改变数组边界。各气泡分别创建独立 action、WAL/idemKey、证词与正证，前一项取得唯一正证后才物化后一项；随后允许的换微信卡只依赖最后一个气泡。任一气泡未确认、失败、suspect 或转人工时停止全部后项，已取得正证的前缀不回滚、不补发。

**候选人主动换微信请求的接受→承接例外（2026-07-26）**：此事件仍先执行无条件接受，但只有 `chat.acceptWechat` 取得唯一正证、微信交换事实及权威联系方式收编在同一业务事务内完成后，才可跳过意向判断并创建一次 `reply` 用途的 AI 承接建议，继续推约面。接受未确认、失败、suspect 或收编失败时不得调用承接 AI、不得创建正文动作；AI/解析/正文发送失败不回滚接受事实，也不得再次点击接受。承接建议若含多个合法气泡，继续按上一段逐项发送；该例外不授权把接受与正文合并进同一原语、WAL 或 idemKey。

**职位配置路由（2026-07-24）**：新沟通轮及尚未物化的固定话术动作一律按 `conversationRef → CandidateProfile.BackendJobID → 该职位最近一次成功同步的 legacyJobConfig head` 解析职位配置。`ProfileAIContextBinding` 只保留为历史兼容与审计事实，不得授权、覆盖或阻断该路由；缺失 `BackendJobID` 或本地尚无该职位成功同步 head 时，本轮不得调用 AI 或构造候选人可见动作。创建 `DialogueTurn` 时冻结实际使用的 `revisionHash`；配置 head 后续推进只影响下一新轮，已创建 turn、已有 action 及其重放继续使用各自冻结的不可变 revision。

**职位文档与简历前置**：既有职位文档只作固定映射：`多轮沟通` 原文用于回复生成，`意向判断` 原文用于意向分类，`客户事实库` 原文作为事实上下文；不修改旧后台、不新增文档槽位、不以本地 sidecar 替换原文。`多轮沟通` 模板只支持 `{简历}`、`{推荐时段}`、`{对话历史}`，`意向判断` 模板只支持 `{回复}`、`{招呼语}`；每份文档出现自身白名单外活 token 都响亮失败，普通 JSON 花括号和输出示例不算输入 token。简历必须来自当前 profile 冻结的完整 IM 快照，历史来自正式活动消息账本并排除 retracted，推荐时段按冻结默认窗口生成并随 turn 固定；`{回复}` 来自本轮最后一条正式普通入站，`{招呼语}` 通常只来自唯一已发送招呼事实。唯一例外是本节已批准的“主动来聊候选人自动建档入口”：其第一轮由版本化主动入站事实根证明我方从未发送招呼，`{招呼语}` 固定渲染为“（候选人主动发起会话，我方尚未发送招呼语）”；该值是对真实缺席事实的中性描述，不得落成消息、发送意图或伪造招呼事实，第二轮起仍按活动消息账本中的真实我方正文处理。除该窄例外外，缺任一必要输入时不调用 AI，不填空、不猜值。

1. 先处理特殊事件：**他主动发起换微信 → 无条件同意**（于巡检到达时执行）、收号、通知运营；此动作视同真实文字（强意向，预算不动），AI 承接后继续推约面。
2. **判意向**（大模型动作一）：输入由三部分组成：原文 `意向判断` 提示词（只替换 `{回复}` 为本轮最后一条普通入站、`{招呼语}` 为唯一已发招呼事实）、本轮全部有序活动消息、本轮之前最近 20 条有序活动历史。后两者通过批次 0B 冻结的固定数据信封交付 provider，不新增模板 token，也不加本地行为指令；这明确替换“完整对话历史”的无界口径，前置确定性短路也必须扫描本轮全部消息。旧生产的简历投递 marker、拒绝模板正则与≤25 字短拒词都只属于候选规则，批次 0B 冻结的生产启用清单为 `enabledRuleIds=[]`，所以 M5-A 的每个非空普通文本轮都调用一次意向 provider，不猜测迁移任何旧条目。provider 的 `信号`/`signal` 只映射旧中文 `有意向/拒绝/中性`，`理由`/`reason` 只用于判错、不持久化；调用失败固定持久化 `neutral + llmFailureFallback`。分类一轮只落一次，随后才按分类决定是否作一次物理独立的回复调用：`rejected` 转人工，`interested/neutral` 继续；回复失败不产生第三次调用并立即转人工。发送失败只按“发过”条目的 intent 边界收敛，不重判、不重新生成。
3. 按结果分支：
   - **拒绝**（按话术标记判，无次数概念）：挽留未发过 → 固定挽留话术 +（若线未推进）换微信邀请，冷催预算清零；挽留已发、收场未发 → 固定收场话术 + 归档「拒绝」；都发过 → 一个字不发，静默归档「拒绝」。旧后台没有独立收场话术槽位时，新客户端使用本地不可配置默认值“好的，理解，感谢您的回复，祝您接下来一切顺利。”；该默认只服务本分支，不回写旧后台、不借用其他场景话术。
   - **非拒绝** → AI 生成回复（大模型动作二，带完整上下文与职位话术包）推约面，可提及时段或实际发出邀面卡（发卡才进"已邀面"并获跟催赠额；仅文字改时段无跟催）；也可**发起换微信邀请**——仅线未推进时动作可用（物理门槛与催2 同款），提示词须写明"约面永远优先；仅当意向不强、约面推进受阻时退而求其次发起邀请；邀请一生一次，禁止开场索要"。邀请被 AI 提前花掉的档案，催2 自然不再可用，冷催阶梯变为催1→36h 归档。**拒绝过的人回客套话（"好""嗯"）→ 只轻承接，禁止再推销**（提示词规则）。

## 六、按钮与事件（事件层全表）

| 事件 | 效果 |
|---|---|
| 纯点同意换微信（任何场景，含服务态与归档态） | 收号 + 通知运营 + 回一句固定确认语"好的，晚点加你"。回执滑动锚点（**一切时间门槛**重新起算），但不开计数轮 |
| 点接受面试 | 主线跃迁"已约面"，进服务阶段；发**固定确认语**（确认面试安排）+ **通知运营（约面成功）** + 自动发换微信邀请（若线未推进）。**已结束者点旧卡的接受同样生效**——平台上已存在约定面试，系统状态必须跟随平台真相（旧时段过期等问题由服务阶段/运营处理） |
| 点拒绝面试卡 | **作废该卡跟催组** + 触发一次 **AI 生成回执**（带完整上下文；意图限定：承接拒绝、可轻探原因或提议换时间、禁纠缠；每卡至多一次）。不判意向、不开计数轮、不动预算，锚点照滑；他若随后开口，真实文字规则全面接管。冷催与归档照常（归档原因仍按表取"沉默-邀面未答"，口径与事实略有失真，知情接受） |
| 被拉黑 | 推进态档案就地归档「拉黑」；已约面/已淘汰/已结束无操作 |

服务态（已约面）对一切事件只保留"收号 + 回执"，其余无操作——**本行优先于上表各行**。

## 七、服务阶段（已约面）

目标从"成交"变为"别搞砸"：**只回消息**——好回的直接答；不好回的（改期、取消、薪资细节、拿不准）一律引导微信（已换号→"留意好友申请，通过后微信细聊"；已邀请→"通过一下我发的邀请，微信上细聊"）。**引导话术不得包含"帮您反馈""我去问下"等我方后续动作的承诺**——系统不会做任何后续动作，只作纯引导。

不跑判意向、不推状态机；不催、不提醒、不归档；不自动改时间改状态；面试时间过后无动作。主动换微信请求照常无条件同意（见事件表）。

## 八、休眠唤醒

- **已结束**者发真实文字 → 直接当活人（回"沟通中"），无门控、次数不限；预算与话术标记不恢复——由于归档已清零剩余预算（含催2），**唤醒后永无冷催**（这是定理不是规则）；若聊回约面流程实际发出新卡，跟催照赠。
- **已结束**者点旧邀面卡"接受" → 直接进已约面（事件层跃迁，非对话唤醒，见事件表）。
- **已淘汰**者来消息 → 已读不回。

## 九、示例集（推演即答案；以下均设 AI 未曾自行发起换微信邀请）

**例1 · 全程装死**：我方回复后他消失。+24h 催1① → +24h 催2+邀请（线推进）→ +36h 归档「沉默-邀微未回」，剩余预算清零。一生共收 2 条冷催。

**例2 · 破冰型（催1② 的唯一路径）**：催1① 后 20 小时他回"最近忙"（中性）→ 新计数轮、到期档作废 → AI 回复 → 又沉默 24h → 催1② → 再 24h 催2 → 再 36h 归档。

**例3 · 主动换微信后消失**：他发起换微信（视同真实文字，开计数轮）→ 无条件同意收号 → AI 承接推约面 → 他消失 → +24h 催1① → 催1 本轮已用、催2 物理不可用（已换号）→ 无牌 → +36h 归档「沉默-已转微信」，运营持号在微信接力。

**例4 · 首次拒绝后的五个走向**：拒绝 → 挽留+邀请，冷催清零 →
① 沉默 → 36h 归档「沉默-邀微未回」；② 纯点同意 → 收号+回执 → 仍沉默 → 回执后 36h 归档「沉默-已转微信」；③ 回话再拒 → 收场+归档「拒绝」；④ 回话客套 → 轻承接 → 沉默 → 36h 归档；⑤ 回话有意向 → 照常推约面，此后**永无冷催**；若实际发出邀面卡，跟催三档照赠（跟催不是冷催）。

**例5 · 发卡与跟催**：发卡 → +10分钟跟催① → 他回"周四不行" → 该卡剩余跟催永久作废 → AI 换时段（仅文字则无跟催；实际发新卡才有新一组三档）。变体一：发卡后停机半天，恢复时只发跟催①（②的门槛是"距①满 1 小时"，天然不连发）。变体二：23:58 发卡，跟催① 顺延至次日开启后首次巡检。

**例6 · 点拒面卡**：沟通中说过一句话的人收到邀面卡后，点了"拒绝"按钮 → 该卡跟催组作废 + AI 回执一句（承接拒绝、轻探原因，锚点滑动）→ 他不理 → +24h 催1 → +24h 催2+邀请 → +36h 归档「沉默-邀面未答」（对拒卡者继续冷催与该归档口径均为知情接受；预算不清零——想清零请打字说"不"）。他若回话（"周四确实不行"），真实文字规则接管，AI 换时段重推。

**例7 · 服务阶段**：已约面者问"地址在哪" → AI 直接答；说"能改周四吗" → AI"改期的话麻烦您微信上跟我说一下哈"（纯引导，不承诺任何我方动作）→ 系统不改时间、不通知任何人，微信侧人工处理。

**例8 · 唤醒**：归档两周后他来"职位还在吗" → 回沟通中，判意向照常，推约面照常——冷催预算已在归档时清零（含催2），永无冷催；发新卡则跟催照赠。归档后来骂人 → 挽留收场均已发过 → 一个字不回，静默归档回去。

**例9 · 多职位**：职位 A 聊过已归档（已结束），职位 B 采集到他 → 建档闸，忽略。职位 A 打分淘汰（从未接触），职位 B 采集到 → 新档案从头走，预算全新。

## 十、打扰上界定理与哲学

> 任何档案一生：冷催 ≤ 3 条、跟催 ≤ 3×发卡数；一句"不"使剩余冷催立即归零；预算单调递减、归档清零、无充值路径。⟹ 打扰过度在本系统中被结构性抑制。（对外表述用可兑现口径："冷催终身不超过 3 条、候选人说不立即停止"，不使用"骚扰不可能"类绝对化措辞。）

哲学：宁可放过，不可骚扰；规则少到能背下来，其余一切行为都是推论。

有意留白：AI 生成话术的内部策略 = 提示词工程；除上一节本地拒绝收场默认外，各固定话术与跟催三档的文案 = 运营产出；判意向的短路模板（拒绝关键词、简历标记）= 配置产出；运营通知的渠道与格式 = 实现细节。

**主动来聊候选人自动建档入口（2026-07-26）**：对当前页面聊天列表发现、尚无 tracked 档案的真实候选人，只有同时读取到稳定平台用户身份、稳定会话身份和页面所示职位名称，且职位名称与本机最近成功同步的后台职位恰好唯一精确匹配时，才可用该后台 `Job.ID` 创建档案、绑定会话并进入既有 IM 简历补采；补采成功后按候选人主动消息进入“沟通中”并复用正常对话链。零匹配、多匹配、任一身份/职位读取失败或补采失败均转人工；不得按相似标题、当前默认职位、姓名、`resumeNumber` 或 DOM 位置猜测。自动建档本身不授权发送，第一条候选人可见动作仍须通过既有工作流窗口、消息尾核对和发送安全轨。
