# 0727 当日计划：未读插队气泡基线收敛

日期：2026-07-27  
状态：调度规则已获甲方裁决；事实与协议纠偏已由 `98dbac3` 固化，代码待按本文实施

## 一、事实、根因与目标

2026-07-27 现场确认：在智联“全部职位 + 未读”列表中打开一条会话后，该行
仍留在列表里，只是行上的未读气泡消失。此前实现假设“处理完未读后列表会
变空”，于是把稳定正数锁存为 `unreadPending generation`，等待
“空列表 + 总气泡为零”清除。这个出口在真实页面不可达，会造成同一批残留
气泡反复插队。

本轮只重整脑侧未读调度：

1. 以“上一次完整未读子轮结束时的侧栏总气泡数”取代 pending generation；
2. 普通全量扫描在每个新会话开始前比较当前稳定气泡数；
3. 需要插队时，从未读列表顶部到完成边界遍历一次；
4. 结束后切回全部列表顶部，建立新的普通扫描代际；
5. 复用已有列表 fingerprint 判断会话是否变化，不新增会话版本机制。

本轮不改插件页面原语、机器契约、消息归一化、沟通状态机、AI、发送动作、
WAL、idemKey、手证词或服务端正证。

## 二、出口宣言

### 2.1 最小可交付出口

完成后同时满足：

1. 脑只在进程内按 `platform + accountRef + principalFingerprint` 保存一份
   nullable 的“上次完整未读子轮结束气泡数”；稳定零值删除基线，进程重启
   自然失忆；
2. `filter=all` 首次领取及每个新会话领取前，在上一候选人动作链已经收束的
   安全边界检查：
   - 当前稳定值 `> 0`，且没有结束基线或与基线不同：插入未读子轮；
   - 当前稳定值 `> 0` 且与基线相同：继续普通扫描；
   - 当前稳定值为 `0`：清除旧基线并继续普通扫描；
   - 当前值缺失：不改变基线，不插队；
3. 每个未读子轮都从 `startAt=top` 开始，内部不递归插队；每个唯一
   `conversationRef` 至多领取一次，单个目标局部失败后继续后续目标；
4. 子轮只有完整到达列表完成边界后，才读取稳定总气泡数并写入结束基线；
   页面级失败、分页未完成、预算用尽或读数缺失都不得伪造完成基线；
5. 子轮结束后切回 `filter=all,startAt=top`，重建普通扫描的
   `checkedConversationRefs`；插队前的 checked 集合不跨新扫描代际；
6. 现有 `listHintFingerprint` 继续决定详情是否需要重读：提示未变则跳过，
   提示变化则读取权威线程。插队期间处理过的会话若又收到新消息，不会被旧
   checked 标记永久跳过。

### 2.2 必须立即阻断的损害

- 在候选人动作链、手命令或发送收敛中途切换列表；
- 相同残留气泡数在每个会话边界反复触发未读子轮；
- 未读子轮未完整结束却写入结束基线；
- 基线跨平台、账号或登录主体复用；
- `unread → all` 后继续使用插队前的 cursor 或 checked 集合，漏掉新消息；
- 为解决调度问题新增持久化恢复、会话版本、插件私有层守卫或发送旁路；
- 改变任何 effectful 动作的构造次数、WAL 或正证语义。

### 2.3 允许重试或由既有机制兜底

- 稳定气泡数暂时缺失：继续普通扫描，不改基线；
- 未读子轮页面级失败或未完整遍历：不写基线，也不围绕同一失败现场立即
  重入；按普通巡检间隔在下一次完整扫描重试；
- 单个未读会话定位、读取或幂等打开失败：记录本子轮已尝试并继续下一条；
- 进程重启丢失基线：当前正数最多多触发一次未读子轮；
- 一个旧未读消失、一个新未读到达而总数恰好不变：本轮允许不优先插队，
  随后的普通全量扫描由既有 fingerprint 发现变化；
- 当前没有自然到达的新消息：自动化测试覆盖数值变化分支，真机不为制造样本
  额外发送候选人消息。

### 2.4 审查预算与明确后置项

实现后只做一轮独立定向审查，范围为：

- 安全边界是否真正在“领取新会话前”；
- 基线是否正确隔离、清除和失忆；
- 未读子轮失败是否可能紧循环；
- `unread → all` 是否重建扫描且复用既有 fingerprint；
- 发送安全轨是否保持零语义变化。

以下事项后置，不进入本轮：

- 基线持久化、跨重启恢复或管理 UI；
- 用会话级版本替代现有 fingerprint；
- 为总数相同的新旧未读抵消形态增加第二种传感器；
- 未读吞吐统计、支持包或第二平台适配；
- 与本根因无关的沟通分支、AI 或客户端页面修改。

## 三、现有机制处置

| 现有机制 | 本轮处置 | 理由 |
|---|---|---|
| `unreadPendingByPrincipal` / generation | 删除并替换为结束气泡数基线 | 旧状态依赖不可达的空列表出口 |
| 稳定 `unreadTotal` 采样与 snapshot | 保留 | 已解决连续 mutation 与 SW 现货快照问题 |
| `unreadAttemptedRefs` | 保留，作用域收窄为单个未读子轮 | 防止同一子轮重复打开同一会话 |
| `checkedConversationRefs` | 保留，但只属于一个普通扫描代际 | 筛选切换后必须重建，不能跨代际压掉新消息 |
| `listHintFingerprint` | 原样复用 | 已能区分提示未变与同一会话出现新变化 |
| `startAt=top/current` | 原样复用 | 子轮初始与切回 all 用 top，动作后同筛选续行用 current |
| 插件未读筛选与 `chat.openConversation` | 不改 | 当前问题是脑侧调度出口错误，不是页面动作缺失 |

不再寻找“未读列表为空”的 DOM selector，也不再为它增加插件探针。

## 五、实施批次与提交

### 批次零：计划检查点

1. 保存本文；
2. `git diff --check`；
3. 独立 docs commit；
4. 进入代码前确认工作区干净。

### 批次一：结束气泡数基线

1. 在 patrol manager 增加进程内、按平台/账号/主体隔离的结束气泡数；
2. 提供“当前稳定数是否允许插队”和“完整子轮结束后记录数”两个窄操作；
3. 稳定零值清旧基线，缺失值不改基线；
4. 先保留旧消费者以维持可构建，新增定向单测；
5. 门禁绿色后独立 commit。

### 批次二：切换巡检调度并删除旧 pending

1. 普通扫描首次领取及每个新会话领取前执行同一份插队判定；
2. 只在候选人动作链收束后进入未读子轮；
3. 未读子轮内部不递归，每次重建独立 attempted 集合；
4. 完整结束才记录稳定气泡数；失败不记录、不在同一普通扫描立即重入；
5. 切回 all 时使用 `startAt=top`，重建 checked 集合；
6. 删除旧 pending generation 状态、方法和对应死分支；
7. 保持 fingerprint 判断和发送调用路径原样；
8. 定向 Go 与 race 测试绿色后独立 commit。

### 批次三：审查与全量门禁

1. 按 2.4 做一轮独立审查；
2. 只修当前可达阻断项，每个独立修复单独 commit；
3. 执行：
   - `go test ./...`
   - `go test -race ./client/service/...`
   - `go run ./contract/codegen -check`
   - Windows `CGO_ENABLED=0` 交叉构建；
   - UI build 与 Electron 生命周期测试；
4. 确认工作区干净。

插件源码与机器契约未变时，不做无意义的插件重载；只重启正式客户端，让新版
脑代码生效。

### 批次四：真机收口

在业务窗口内观察一轮正式沟通巡检，至少确认：

1. 首次稳定正数会在安全边界进入未读子轮；
2. 子轮从顶部连续遍历，不要求行消失或列表为空；
3. 子轮结束记录气泡数，并切回全部列表顶部；
4. 相同气泡数不会在后续每个会话前重复插队；
5. 普通扫描仍会跳过 fingerprint 未变的会话，并重读提示已变化的会话；
6. 无重复发送、错靶发送或未收束动作被中断。

若现场没有气泡数变化样本，第 4 项由真机确认，第 5 项沿用既有真机事实并由
回归测试补齐；不为了凑样本扩大外部副作用。

## 六、回归矩阵

至少覆盖：

1. 无基线 + 正数：首次插队；
2. 当前正数 = 结束基线：跨多个候选人、跨普通轮都不插队；
3. `N → M` 且 `M > 0`：无论增加或减少都再次插队；
4. `N → 0`：清基线；随后 `0 → 正数` 再次插队；
5. 当前值缺失：不清基线、不插队；
6. 平台、账号或主体不同：基线互不复用；
7. 进程重启：失忆后最多多插一次；
8. 在途候选人动作未收束：只等待，不切列表；
9. 未读子轮内部：不递归插队；
10. 每个新未读子轮重建 attempted，同一子轮每个 ref 至多一次；
11. 单个目标局部失败后继续后续目标；
12. 页面失败、`complete=false` 未续完、预算用尽：不写完成基线；
13. 未读完整结束：记录稳定数并切回 `all,startAt=top`；
14. 返回 all 后重建 checked，旧 checked 不压掉新扫描；
15. fingerprint 未变：不重复 `readThread`；
16. 同一 ref 的摘要、未读、方向、类型或活跃提示变化：重新 `readThread`；
17. 新旧未读抵消且总数同值：不优先插队，但普通 all 扫描仍能发现变化；
18. effectful 构造、WAL、idemKey、证词与正证路径调用语义不变。

## 七、预计时间与停止条件

预计代码、测试和一轮审查约 **60～90 分钟**，客户端重启与真机观察约
10～20 分钟。

满足以下条件立即停止，不顺手扩题：

- 计划、基线状态、调度切换按独立因果提交；
- 旧 `unreadPending generation` 的生产代码已删除；
- 定向测试、全量 Go、race、codegen check、Windows 构建及客户端门禁绿色；
- 独立审查无当前可达阻断项；
- 真机确认“首次插队 → 完整遍历 → 记录结束数 → 回到 all 顶部 → 同值不重插”；
- 发送安全内核与候选人可见动作语义零变化。
