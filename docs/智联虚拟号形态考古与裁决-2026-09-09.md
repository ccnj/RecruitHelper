# 智联虚拟号形态考古与裁决(2026-09-09)

运营通知里的「手机号」一行此前只出真实号。2026-08-06 甲方裁决把 IM 简历侧栏的电话采进通知时,真机见到三种形态——真实号有「复制」按钮、无号整段空缺、虚拟号有显示文本但无复制按钮——当时裁决虚拟号视同无号。2026-09-09 甲方改判:虚拟号也进通知,并且把平台标注的「仅限 X 呼叫」与失效时间一起带上。本文固化这次的页面事实、裁决与出口。

取数路径:甲方在已登录的智联 IM 页手抓侧栏 `.new-resume-basic` 的展开前/展开后两份 DOM,本文按仓库纪律洗掉号码、姓名与头像地址,只留结构。没有加插件探针。

## 一、虚拟号形态的页面事实(真机已见)

电话盒 `.new-resume-basic__contact--phone--box` 的骨架(展开前;展开后只是两个 class 的差别,见第 3 点):

```
.new-resume-basic__contact--phone--box
├─ .new-resume-basic__contact--phone.hover-resume-basic__phone
│  ├─ .hover-resume-basic__phone--box            ← 候选人电话文本容器
│  │  ├─ .hover-resume-basic__phone--label       「电话:」
│  │  └─ div
│  │     ├─ span.im-resume-basic__phone--black   候选人虚拟号,11 位,按 3-4-4 空格分组
│  │     └─ .im-resume-basic__phone.is-retract   说明块
│  │        ├─ span > span.new-resume-basic__contact-tip-place  「虚拟号归属地:<城市>」+ 问号图标
│  │        └─ span                              「将在yyyy.mm.dd hh:mm后更新」
│  └─ .new-resume-basic__contact--virtualnumber.is-hidden        ← 虚拟号块(结构判别锚)
│     ├─ .virtual-number__text                   「仅限」+ span.virtual-number__text--phone.im-resume-basic__phone--black + 「呼叫」
│     │                                           ↑ 招聘方自己绑定的主叫号,平台遮挡形态(前三后四可见)
│     └─ …「修改」链接若干(display:none 或可见,与本能力无关)
└─ .new-resume-basic__contact--phone--button     「展开」
```

1. **结构判别锚是虚拟号块** `.new-resume-basic__contact--virtualnumber`。它在收起态带 `is-hidden` 但始终在 DOM 里。真实号形态的标志是 `.im-resume-basic__phone--copy` 复制按钮,遮挡形态的标志是 `.resume-button.get-phone` 「查看电话」按钮;虚拟号形态两者皆无。
2. **号码文本挂在候选人电话文本容器里**:`.hover-resume-basic__phone--box` 下第一个 `span.im-resume-basic__phone--black`。真机值是 11 位手机号带两处空格,去掉空白后符合脑侧既有的 `^1[3-9]\d{9}$` 判定(真机样本号段 18x)。
3. **展开/收起只切 class,不改内容**:展开后 `.new-resume-basic__contact--virtualnumber` 去掉 `is-hidden`、说明块去掉 `is-retract`、按钮加 `is-expend` 文案变「收起」。号码、主叫号、失效时间在收起态就全部在 DOM 里。读取不需要任何点击,仍是 readonly。
4. **失效时间是纯显示文本**:说明块末尾 `将在2026.09.11 15:20后更新`。格式 `yyyy.mm.dd hh:mm`,平台时区即客户机时区(中国),手按本地时区解析成毫秒。
5. **坑:招聘方主叫号与候选人号同 class。** 虚拟号块里「仅限 …呼叫」中间那个号也带 `im-resume-basic__phone--black`,它是招聘方自己绑定的主叫号(AXB 隐私号方案里只有绑定的 A 号能拨通 X 号),不是候选人的。选择器若不限定在 `.hover-resume-basic__phone--box` 内,会把招聘方的号当候选人号发到运营群——这是错靶级损害,与 AGENTS.md「不得返回招聘方自己的微信号」同一条红线。

**未确认、按优先级判别绕过**:真实号形态里会不会也常驻一个隐藏的虚拟号块,样本里看不出。手侧按「复制按钮 → 查看电话按钮 → 虚拟号块」的固定优先级判别,真实号永远从复制按钮走,这个不确定不影响结果,不另考古(记录级)。

## 二、裁决(2026-09-09 甲方)

1. 撤销 2026-08-06「虚拟号视同无号」。AGENTS.md 运营通知条与《协议规格-v1》2026-08-06 增量同批修订,增量段见规格「候选人虚拟号读取契约增量」。
2. 通知文案带「仅 X 可呼叫」与失效时间。真实号那行不变;虚拟号行形如:

```
手机号: 184xxxxxxxx(虚拟号,仅139****xxxx可呼叫,09-11 15:20后失效)
```

   主叫号按平台遮挡形态原样带出,不去揭示;失效时间解析不出就省掉那一段,主叫号读不到也省掉;虚拟号本身读不到仍是整行省略,与现在一样。过期的虚拟号照常展示,失效时间自己说明问题。

3. 契约与库:`ChatReadPeerPhoneData` 追加 optional `phoneKind`(枚举 real|virtual,缺省按 real 兼容旧手)、`virtualCaller`、`virtualExpiresAt`;脑侧电话观察事实行加种类、主叫号、失效时刻三列;同一候选人有真实号观察事实时真实号优先,虚拟号不顶掉真实号。面板姓名首字核对对虚拟号照常适用。两项附属事实的去处与号码同款收口(只进 webhook 正文与 /admin 诊断面)。

## 三、出口四项

1. **最小出口**:三个 commit——规格与契约(本文同批)、手侧读虚拟形态、脑侧观察行加列并改渲染。验收用诊断台「手动测试发送」贴一个虚拟号候选人的 sessionId 直发到群里看,不等真实事件。
2. **必须阻断**:招聘方主叫号被当成候选人号(选择器限定在候选人电话文本容器内,夹具里把主叫号放在容器外);虚拟号顶掉已有真实号(真实号优先);任何读取失败只缺号,不影响通知发出。
3. **允许降级**:失效时间解析失败、主叫号缺失都只省略对应段,不转人工不重试。
4. **审查与后置**:一轮定向审查看手侧选择器与渲染两处。记录级后置一项:真实号形态是否也常驻隐藏虚拟号块(第一章末段)。

## 四、甲方知情接受的代价

- 虚拟号有效期短(真机样本约两天),通知发出时可能已接近失效;失效时间写在正文里,由运营自行判断。
- 招聘方主叫号只有遮挡形态,运营若在别的号上拨打会打不通;正文里的「仅 X 可呼叫」就是提醒。
- 虚拟号轮换后旧号作废,系统不追踪轮换、不补发通知;下一次取证顺访若再读到新号会追加一行观察事实,消费方取最新。

## 五、彩排增补(2026-09-09 甲方同日裁决)

诊断台的运营通知彩排此前只截两张图、按库里已有事实现算正文,不读侧栏电话;「手机号」一行只有巡检取证顺访写过电话观察事实行才会出现,验不到手侧读虚拟号那一段。甲方选定:彩排也经 `chat.readPeerPhone` 现场读一次侧栏电话——只读,不派 `chat.revealPeerPhone`(揭示消耗平台查看权益,彩排不碰);读到且通过与线上同款的收编判定(格式、面板姓名首字核对)就只用于本次正文,**不落电话观察事实行**;读不到、遮挡形态或未通过判定,正文沿用库里已有的电话事实,并把原因回显给操作者。AGENTS.md 运营通知条的彩排段同批修订。读号放在两张截图之前,用的是页面的初始状态;预算 30s 落在既有 360s 总窗口的余量内。
