## 一、一句话

未读角标的**被动上报链**在 2026-08-10 之后只剩一个用途(正数拉前下一轮巡检),
而该用途**最多值 60 秒**[数据];`pageNavigated` 事件里的 `pageKind` 字段则**从头到尾
没人读**[已核]。建议一次性删掉这两段,顺带订正一处已经失效的注释。

### 3.1 未读数值上脑:四个消费点,全是展示或日志 [已核]

### 3.3 `pageNavigated` 事件里的 `pageKind`:解出来但没用 [已核]

`patrol/manager.go:468-477`:

```go
case protocol.EventPageNavigated:
    var data protocol.PageNavigatedEventData
```

### 3.4 唯一还活着的用途:拉前巡检,值多少 [已核 + 数据]

`patrol/manager.go:450-467`:角标事件正数 → `DirtyHint=true` + `pullForward`。

| 参数 | 值 | 位置 |
|---|---|---|
| 正常轮间隔 `PatrolInterval` | **2 分钟** | `patrol/types.go:333`(2026-08-04 甲方由 5 分钟调快) |
| 拉前目标 `CoalesceWindow` | 25 秒 | `types.go:338-340` |
| 最小轮距 `MinimumRoundGap` | 60 秒,**拉前跨不过去** | `types.go:342-343`,实现见 `manager.go pullForward` |

最坏情况(消息在一轮刚结束时到达):

- 有拉前:目标 `now+25s`,被 60 秒下限顶住 → 下一轮在 上轮 +60 秒
- 无拉前:下一轮在 上轮 +120 秒

**拉前买到的上限是 60 秒**,且随时间接近自然轮迅速衰减到零(消息在 +90 秒到达时
只快 5 秒)。

## 四、拟议改动

### 4.1 契约(五处,均为删除)

1. 删 `PingSensors` 及 `PingBody.sensors`
2. 删 `PageNavigatedEventData.pageKind`(保留 `at`)
3. 删 `events.unreadBadge` 条目(`contract.v1.json:1639`)
4. 删 `UnreadBadgeEventData`(`contract.v1.json:1204` 一带)
5. 删 `enums.unreadScope`(`contract.v1.json:1305`)——唯一使用者是上一条的
   `scope` 字段(`:1204`),随之释放 [已核]

**第 3–5 条是初稿的漏项**(2026-08-26 并行审查指出)。初稿 §4.2 删掉了 `unreadBadge`
的全部生产者、§5.3 也明说「拉前废止」,却把事件本身、其数据类型、其专用枚举与脑侧
handler 留在原地。照初稿落地会得到:契约里躺着一个永远没人发射的事件、脑里留着一个
永远不会命中的分支——**恰好违反本节自己引用的「逐项证明无生产者、无消费者」纪律**。

同 commit 重跑 `go run ./contract/codegen` 并提交两端生成产物。按「悬置决策·契约
append-only 冻结点」,当前开发阶段允许破坏性修订,但须逐项证明无生产者、无消费者、
无持久化/恢复路径引用——本文第三节即该举证。

### 4.6 **两个坑**

**坑一:`resyncStaleSensors` 只能删一半。** `sensorBridge.ts:325-331` 的条件是
「未读缺失 **或** 登录态未知 → 重新索要快照」。未读那一半随本次删除去掉,
**登录态那一半必须留**:`lastCanonicalLogin` 要先拿到一个非 unknown 的采样,
登录态变化事件才可能触发(`sensorBridge.ts:170-179` 要求 `previous !== null &&
previous !== Unknown`)。删过头 → 即时停机通道永久失效,而且**没有任何症状**。

**坑二:`UnreadStable` 消息整条删除,不是只删 value。** 该消息同时承载 ping 快照的
`value` 与事件用的 `emitEvent/prev`(`contentSensor.ts:124-130`);事件本身随本次
裁决一并废止,故整条删。若甲方只批准删快照、保留拉前,则 `armBadge` 与
`readZhilianUnreadTotal` 必须保留,`contentDom.ts` 不能消失——**收益随之减半**,
见第五节。

## 五、收益与成本

### 5.1 收益

| 项 | 说明 |
|---|---|
| content script 的平台特定面 **4 件 → 1 件** | 只剩登录态解析;认站点退化为一个字符串,而 `hostMatch` 已在适配器上声明,白拿 |
| `contentDom.ts` 整个文件消失 | base 层不再持有该块平台 DOM 知识 |
| 多平台批 B 的一等危险消失 | 该文件有 2026-08-03 真机事故先例(选择器要求双类 → 零未读被读成读不到 → 插队被 `unreadRetryDeferred` 锁死);删除后剩下的选择器+解析是纯搬家,不再有两个消费者要协调 |
| 契约减 **1 个事件、1 个数据类型、1 个枚举、2 个字段** | `events.unreadBadge`、`UnreadBadgeEventData`、`enums.unreadScope`、`PingBody.sensors`(含 `PingSensors`)、`PageNavigatedEventData.pageKind`;规格事件类数五→四 |
| 脑侧减一份传感缓存、一个派生健康度与一个事件分支 | `SensorHealth` 与 `manager.go` 的 `EventUnreadBadge` 分支 |
| 清掉三处会误导人的失效描述 | `registry.go:129-132` 注释、`unreadBadge` 的 `brainMay`、规格 678 行的类数 |

### 5.2 成本

| 项 | 量级 |
|---|---|
| **候选人回消息后最多晚 60 秒被看见** | 上限 60 秒,平均更小;**不丢消息**,只是晚看见 |
| 诊断台失去未读数与 `sensorHealth` | 排障少一个眼睛。它今天不参与任何判断,但**确实是真实损失**。<br>**`pageHealth` 保留**(§4.3),故此项损失比初稿少一个 |
| **一次部署硬切换** | 契约变 → `contractHash` 变 → 按《协议规格-v1》§14:暂停派发 → 重启脑 → 重载插件 → 确认哈希一致 → 恢复 effectful。mismatch 状态禁发 effectful |
| 一批测试要跟着改 | 单元测试与端到端夹具里涉及 sensors/pageKind 的断言 |

### 5.3 风险与失效方向

- 删除面全部是「没有消费者的数据通道」,**不触碰任何安全内核**(账本闸、证词闸、
  平台回读闸、原语内不重试、发后正证一律不动)
- 坑一若踩中,失效方向是**掉登录后不能即时停机、要等下一轮巡检**——仍是「少做」
  方向,但会静默,故列为实施时的阻断级核对项
- 拉前废止后,新消息响应变慢属**时效**损失,不影响正确性
