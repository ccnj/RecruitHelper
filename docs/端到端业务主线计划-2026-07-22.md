# 端到端业务主线计划（2026-07-22）

> 状态：甲方已确认，作为后续实现、上下文恢复与范围裁决的持久依据。
>
> 目标：依次跑通“正式激活 → 后台配置同步 → 批量采集 → 统一评分 → 配置化筛选 → 批量生成招呼语 → 列表直接发送 → 完整沟通”。不得把最终业务重新收窄成逐人 `采集 → 评分 → 招呼` 的内联循环。

## 一、已冻结的总原则

1. 旧后台是职位业务配置的权威来源，旧后台本身保持不改。Go 脑侧负责激活和配置同步，Chrome 插件不连接旧后台。
2. 每个业务批次固定使用同一份不可变职位配置快照。采集条件、评分提示词、候选人筛选规则、招呼语提示词和后续沟通提示词均来自该快照，不在新客户端硬编码替代品。
3. LLM 的 `provider/model/base_url/key` 继续由新客户端本地配置，不从旧后台继承；插件永远不接触 key。
4. 候选人身份锚定 `platform + platformUserRef`，`resumeNumber`、姓名、列表位置与分页位置均不得成为身份依据。
5. “采集 150 份”“选前 80 人”都只是业务规模示例，不是代码常量。实际筛选必须服从后台配置；批次规模也应由明确配置或当次任务决定。
6. 每一阶段先完成最窄真实冒烟，变绿后立即独立提交，再进入下一阶段。

## 二、实施顺序

### 1. 激活旧后台正式兼容身份

- Windows 读取 `MachineGuid`，macOS 读取 `IOPlatformUUID`，生成：

  `SHA-256("recruithelper-machine-v1|" + 系统机器 UUID)`

- 每次启动都从当前系统重新读取并计算，不把可复制的本地记录当作机器真实性依据；原始机器 UUID 不上传、不进日志。
- 该 `machineId` 只用于旧后台授权与配置读取，不进入脑手协议，也不复活旧产品的机器身份契约。
- 用户输入后台下发的激活码，脑调用 `/api/v1/client/bind`；成功后持久化后台返回的 `licenseToken` 与必要客户信息，激活码不持久化。
- 本阶段只引入激活与配置面所需身份，不顺手接入 heartbeat、session、指标、任务、更新链等旧控制面能力。

**出口：** 后台认可当前安装为正式客户机器，重启后仍能使用同一身份。

### 2. 同步职位配置

- 使用正式 `machineId + licenseToken` 调用旧后台 `job-config(s)`。
- 把后台职位配置导入本仓库自有的不可变配置版本，并将目标后台职位与当前平台职位显式绑定。
- 至少完整收编职位筛选、打分、候选人筛选、招呼语、多轮沟通、意向判断、沉默追问、客户信息与固定话术等现有文档/配置；各阶段只消费自己已立案的部分，未消费部分仍无损保留。
- 成功后生产路径使用 `legacyJobConfig`，不再依赖当前冒烟用的 `localImport`。

**出口：** 数据库存在可执行的正式后台配置版本，评分和招呼语生成均能取得对应原文提示词。

### 3. 批量采集

- 按后台职位筛选条件连续采集一批候选人。
- 每位候选人打开详情、读取完整简历、持久化稳定 `platformUserRef` 与简历快照，随后立即关闭详情。
- 本阶段不评分、不生成招呼语、不发送消息。

**出口：** 一批候选人均形成可审计的独立采集事实，页面没有遗留已用完的简历详情。

### 4. 统一评分

- 对本批已采集简历统一调用 AI。
- 评分提示词及评分业务配置来自本批冻结的后台配置快照。
- 保存每位候选人的评分结果、配置版本与调用审计引用。

**出口：** 本批所有可评分候选人均获得可追溯评分或明确失败状态。

### 5. 配置化筛选

- 由确定性代码读取后台“候选人筛选”配置并选人，包括最低分、筛选人数下限、筛选人数上限、男性比例上限及后续已验证配置。
- AI 只提供评分，不自行决定最终动作名单；不得把“前 80”写死为业务规则。

**出口：** 产生一份绑定配置版本、可解释且稳定的入选名单。

### 6. 批量生成招呼语

- 使用后台“招呼语”提示词，为每位入选候选人生成对应正文。
- 生成结果先持久化并绑定候选人、职位与配置版本，再进入发送阶段。

**出口：** 每位待发送候选人都有唯一、可追溯的招呼正文或明确失败状态。

### 7. 在列表直接发送

- 回到候选人列表，手按稳定 `platformUserRef` 定位候选人卡片；分页、滚动位置等只能作为定位提示。
- 直接使用卡片上的“打招呼”入口，不为发送重新打开候选人详情。
- 发送仍走既有 WAL、idemKey、手证词与正证轨道，每位候选人每轮至多发送一条。
- 同一卡片由“打招呼”变为“继续沟通”可确认成功；页面无变化或读不到只能记“未确认”，永远不得反推为失败后重发。

**出口：** 入选名单能逐人定位并发送，成功与未确认状态均可审计，不制造重复发送。

### 8. 接入完整沟通

- 招呼后由 IM 巡检绑定对应会话与候选人档案。
- 使用同一后台配置版本中的多轮沟通、意向判断、沉默追问、客户信息与固定话术，接入既有确定性沟通状态机。
- AI 继续只负责分类或建议文本；状态推进、短路、停止与动作选择由确定性代码裁决。

**出口：** 从采集到后续沟通形成同一条可追溯业务链，覆盖沟通逻辑规格中的完整分支。

## 三、当前小目标顺序

2. 再把当前单候选人内联冒烟改成只负责采集的批次。
3. 随后依次实现统一评分、配置化筛选、招呼语生成、列表直接发送与完整沟通，不跨阶段重新耦合。
