# 0724 当日计划 4：批次零事实映射

日期：2026-07-25  
状态：完成

## 一、当前生产事实

1. M6 已经把采集、评分、筛选、招呼语生成和招呼发送拆成独立入口。招呼语
   生成只持久化 `SourcingGreetingInvocation`，不会接触手、创建
   `EffectIntent` 或自动进入发送；发送只能显式调用既有批次发送入口。
2. `SourcingBatch.TargetCount` 是创建后不可修改的批次事实。新产品完整流程固定
   传入 `30`；发现未终局批次时只恢复原值，不从
   `SourcingBatchSelection.TargetMin/TargetMax` 推导，也不覆盖历史目标。
3. 招呼发送的唯一业务来源继续是
   `selection=selected + greeting invocation=ok`。每个 invocation 只能绑定一个
   确定性 intent，最终仍走已有 WAL、idemKey、witness、正证、验证读与
   suspect 轨道。
4. 当前没有能同时表达 `full/replyOnly`、暂停、跨日等待与当前确认批次的持久
   工作流根；本批只允许新增一份最小脑侧运行事实，不在 React 中建立第二状态机。
5. 当前评分、招呼语生成和批量发送都是脑侧整批循环。三条路径开始下一候选人
   前必须字面复用同一个 `MayStartNextWorkflowMember`，不得在前端拆成逐人请求。
6. 现有账号 `EnabledDate/PausedReason` 是沟通 actor 的每日开关，不足以独立
   表达完整漏斗模式；新工作流可以调用它，但不得把“采集中”伪装成“沟通中”。
7. `/app/*` 是仅供同机最终用户 UI 使用的产品面，不进入脑手 contract，也不
   增加插件 capability。产品投影只读业务数据库事实；产品写入口只表达真人
   开始、暂停、恢复和确认整批发送的意图。

## 二、首页统计映射

| UI 指标 | 唯一事实来源 | 首版口径 |
|---|---|---|
| AI 评级人数 | `SourcingScoreInvocation` | 本地业务日内 `finished_at` 非空且 `status=ok` 的不同 run/profile |
| 候选确认人数 | `SourcingSelectionDecision` | 当日 `outcome=selected` 且已建立 profile 的不同档案 |
| 打招呼 | `CandidateProfile.GreetedAt` + 成功招呼 intent | 当日首次取得正证的不同档案；pending/suspect 不计 |
| 已约面 | `CandidateProfile.MainStatus` 与 V4 聚合动作事实 | 当日首次进入 `invited` 的不同档案；缺首次跃迁时返回不可用 |
| 累计招呼 | `CandidateProfile.GreetedAt` | 历史不同档案 |
| 累计已面试 | `CandidateProfile.MainStatus=interviewed` | 只有正式事实才计；当前无结果写入口不做猜测 |
| 累计已换微信 | `ContactAsset.Kind=wechat` | 已收编明文联系方式的不同档案 |
| 新回复 | 活动 `Message` | 当日真实 incoming 且未撤回的不同消息 |
| 新约面 | 邀面状态跃迁事实 | 无可靠首次跃迁时间时返回不可用 |
| 完成面试 | `CandidateProfile.MainStatus=interviewed` | 当日缺可靠跃迁时间时返回不可用 |

所有统计由 Go 查询层按档案去重后返回。无法可靠还原“首次进入状态”的历史
指标返回 `available=false`，UI 显示“—”，不得以列表长度或更新时间冒充。

## 三、七页只读字段

### 首页与侧栏

- 客户：授权源中的客户显示名与授权状态；未接入时显示“授权信息暂不可用”。
- 职位：当前 `legacyJobConfig` head 对应的 `BackendJobID`、职位显示名、
  revision 和最近同步时刻；普通 UI 不显示内部 ID。
- 手：在线、扩展版本、contract 是否匹配。
- 工作流：模式、状态、批次、阶段聚合、暂停位置和业务窗口。

### 候选确认

- 当前工作流唯一指向的批次；
- `profileId`、展示名、职位、评分、只读招呼正文；
- 生成与发送聚合及逐行终态；
- 不返回 `platformUserRef/accountRef/resumeNumber`。

### 四个状态页

- 统一从 `CandidateProfile`、`Candidate`、`Conversation`、
  `CommunicationV4Aggregate`、`Message`、`ContactAsset` 投影；
- 列表只返回 `profileId`、展示名、职位、统一业务状态、摘要、活动时刻和
  页面所需辅助字段；
- 详情返回本地已有简历摘要、活动消息、AI/动作与转人工摘要；
- 微信只来自权威 `ContactAsset`，没有就显示“尚未收编明文账号”。

## 四、运行与发送权利边界

1. `full`：恢复未终局批次，或新建目标为 30 的批次；依次推进到招呼语生成，
   然后写 `awaitingConfirmation` 并停止。工作流控制器没有招呼发送调用。
2. `replyOnly`：只开启既有沟通 actor，不创建、评分或推进 M6 批次。
3. `pause`：当前单成员自然收束，下一成员统一 evaluator 拒绝；已有 effectful
   WAL 继续按安全内核判定和收敛。
4. `resume`：只恢复原模式、原批次和现有未处理查询，不建立第二游标。
5. 本地时间 `[00:00,08:00)` 拒绝 start/resume/confirmation send；运行跨过
   24:00 后在当前单动作收束时写 `waitingDailyWindow`。08:00 到达不自动恢复。
6. 候选确认 POST 是新建首次招呼发送的唯一产品入口。一次确认只批准请求当时
   当前批次仍可发送的集合；技术失败、possible 或 suspect 不授权另铸新意图。

## 五、规范影响

- 统一运行窗口已经固化于 `AGENTS.md`，M6 列表发送规格也已同步；实现须删除
  当前采集入口“真人采集不受 08:00 门限制”的旧特殊口径。
- M6 正式批次规格已经冻结显式且不可修改的 `targetCount`；产品入口固定 30
  属于调用者口径，不改变底层批次模型。
- 本批不改变脑手 contract、原语、evidence、WAL、witness、验证或 suspect
  语义；无需修改 `contract.v1.json` 或 codegen 产物。
- 同机产品 UI 明文投影例外已在 `AGENTS.md` 获批，仍须使用 loopback 与
  preload 内存 bearer，且响应不得进入日志、浏览器持久存储、报告或导出。

## 六、已知诚实缺口

- 已面试与部分“首次状态跃迁”的历史日期缺少权威事实，首版显示“—”或空态。
- 客户授权信息与职位配置分别来自本地配置源和 brain.db，产品路由须在脑内
  合并，不能让前端自己拼接。
- Electron 当前窗口关闭会结束脑进程；七页与脑侧工作流可先完成，托盘化作为
  Electron 集成项单独验证，未完成前不得宣称“退出应用后仍运行”。
- 新工作流开始后仍依赖真实手、账号绑定、职位配置和 provider。缺一项时首页
  按钮应给出直接原因，不能以假运行状态代替。
