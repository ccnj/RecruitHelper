## 1. 当前结论

状态：**通过（M3 有人值守剖面）。信任边界重整的规格源、机器契约、codegen、实现与全量自动门禁已收口；甲方/Claude 独立 diff 审查通过。重整后首次真实发送观察到严格 +1，随后脑优雅重启、手自动重连，命令、意图、消息、outbox、journal 与 suspect 均未增生。**

旧 M3 路径曾完成协议、脑侧安全轨道、手侧持久证词、智联既有会话发送原语、产品 UI 和确定性故障矩阵，并在有人值守下真实发送成功一次。此前迭代修复了自动切会话越过 guards、错误使用列表在线样式、Sender 私有目标绑定、实时消息竞态和 barrier 后失败终局等问题。第五次真实命令又暴露出流程本身的缺陷：粗粒度 readonly 诊断显示 ready，但最终动作栈另有一套 DOM 消息尾判断；真实尾部包含 text/system/card 混合形状，DOM 选择器无法表达卡片语义，命令遂以 `ELEMENT_UNRESOLVED / sideEffect=none` 在平台点击前停止。这些都是旧路径历史，不证明当前重整实现已经通过。

2026-07-20 的第一轮重整删除了冗余 DOM 消息尾硬闸，并让生产 preflight 与 commit 字面调用同一 evaluator；旧路径随后真实成功一次。之后《防护成本预算》第 9 条进一步冻结动作信任边界：保留世界状态与标准公开动作语义，删除 Vue owner/component tree/model/engine/VNode/listener 私有互证；删除固定 250ms 双样本和会话版本 token；`targetBindingToken` 收窄为“各次读取仍是同一世界目标”；关联 form 仍只接受显式 `type="button"`，`disabled`/`aria-disabled` 不作硬闸。安全内核、原语内不重试和服务端后置核验不变。本报告后续把这次变更称为“当前重整”。

旧路径最终真实账本共有六条 `chat.sendMessage`：前五条均为 attempt 1、`sideEffect=none` 的安全失败，第六条为 attempt 1、`ok`。成功后脑侧 `origin=self` 恰好一条、effect intent 恰好一个成功终局、suspect 为零；手侧 `witnessReady=true`、`outboxPending=0`、`journalOpen=0`。随后脑优雅重启、手自动重连并重新核验身份，发送命令仍为六条、成功仍为一条、`origin=self` 仍为一条，没有新意图、重放或第二次平台点击。该 cohort 固定为历史 `n=6 / 动作前失败=5 / 成功=1`，不能直接换算成守卫假阳性率，也不能给当前重整背书。

## 2. 范围与边界

本里程碑只交付一条最窄真实副作用竖切：脑对已经 adopted 的既有会话创建一次稳定发送意图，手经 `chat.sendMessage@1` 执行一次自然文本发送，并在断线、Service Worker 重生、脑重启、result/ack 丢失与验证不完整时构造性地不双发。

没有混入新会话招呼、候选人采集、AI 回复、自动沟通状态机、第二平台、云端、授权、更新器、远程 JavaScript 或 program 交付机制裁决。插件仍编译到 `plugin/dist`，以 Chrome 开发者模式 unpacked 加载。

## 3. 已交付内核与当前重整目标

### 3.1 契约与生成物

- 激活 `witness/1`、`query/report`、journal/outbox 恢复语义和 `WITNESS_UNAVAILABLE`。
- 激活 `chat.sendMessage@1` 的 args、guards、data、evidence 与配对验证读。
- 成功后置条件严格限定为同一实时 Vuex timeline 的有序 last64 相对发送基线严格连续新增一条，且唯一新行方向为我方、类型为文本、正文指纹一致，同时具有新服务端消息 ID 和成功状态；输入框清空、点击完成、乐观气泡或客户端临时 ID 均不算成功。`chat.readThread` 只用于执行外的歧义恢复。
- effectful 命令缺 idemKey/guards、成功缺 evidence、失败缺 sideEffect 时在生成 validator 与运行边界响亮拒绝。

### 3.2 手侧

- base 独占持久 journal/outbox；attempting 在不可逆动作前落盘，committed 与 outbox 原子提交，ack 后才清理。
- 覆盖容量、损坏、TTL、store 世代、重复 cmd、query/report 五态与 Service Worker 重生。
- 后置条件已经观察但 committed/outbox 写入失败时，不发送易失 `ok`；保留 attempting、熔断 effectful 队列、断开连接并等待 query→验证收束。
- 熔断后，所有尚未开始的 witnessed effectful 命令永久隔离；只有同 msgId、同正文、完整新会话 query/report 后才可逐条恢复，普通 readonly 验证读仍能通行。
- 当前重整已实现：智联发送从唯一 live timeline 单次同步建立 baseline，删除固定 250ms 双样本和会话版本 token；preflight/commit 字面复用同一 evaluator，只核对账号、route/目标、动作窗口、唯一可见控件、composer、source keys、expectedTail 和收窄后的 `targetBindingToken`。DOM 不再证明 Sender 因果绑定，owner/model/engine/VNode/listener 私有互证全部删除。关联 form 仍要求有效 `type="button"`；`disabled`/`aria-disabled` 不再拦截。final 绿色后标准 click 至多调用一次，结果只由严格 +1 后置核验判定。自动门禁、执行侧静态复核、甲方/Claude 独立 diff 与真机验证均已通过。
- `chat.readThread` 在执行外的恢复验证中，只把带服务端 ID 且服务端状态成功的我方记录投影为可验证发送事实。

### 3.3 脑侧

- 持久化 EffectIntent、命令、验证子命令、人工 suspect 与 `origin=self` 消息账本；成功事实与意图终局在 SQLite 单写事务中推进。
- 新连接严格执行 outbox 补投→query→report→归类→恢复派发屏障。
- `attempting`、`sideEffect=possible`、证词缺失或验证矛盾均冻结账号串行域；验证读命中可补记成功，三轮仍不完整则转人工，不自动重发。
- late result、人工裁决和自有账本回撤存在明确竞态裁决，重复 result 不增生消息。
- 产品创建意图使用持久单调 `ConversationEffectHead` 和事务 CAS，不依赖 wall clock、rowid 或查询“最新”的偶然顺序；旧库确定性迁移，head 丢失/损坏和 generation 溢出均 fail-closed。

### 3.4 产品 UI

- 只允许 adopted 会话进入消息编辑器；恢复 latest intent 期间锁定输入。
- 权威 current 只在脑侧；浏览器会话存储不构成安全证明，也不承担意图恢复职责。
- POST 携带 `previousIntentId`；多标签或响应丢失导致的 409 会收编脑返回的 current，而不是创建第二意图。
- suspect 持续锁定并轮询。其他终局后的“我已确认，开始下一条”仅是 M3 有人值守验收 UI 的串行操作，不是后续自动调度或无人值守产品的规范性安全闸。

## 5. 确定性故障覆盖

以下故障链的核心内核覆盖延续自重整前；当前重整又重新运行了“跨语言代表性强故障 + 两端分层故障矩阵”。新增断言已覆盖删除私有互证、保留 form/type、删除 disabled/aria-disabled、单次 baseline、收窄且可独立归因的 target token、64 条滑窗和零重复 click。

### 5.1 真脑、真 WebSocket 的 M3 跨端强故障

合成页面边界不接触真实 Chrome，但其余链路均为生产代码：

`/admin/messages/send → 持久 EffectIntent/Cmd → 真 WebSocket → Connection → Dispatcher → WitnessStore → registerM3Primitives → 智联 program 控制流 → committed+outbox → result → 脑侧 WAL/消息账本 → ack`

测试只在 WebSocket 测试边界截获与本次合成正文指纹匹配的 M3 成功 result：第一次 result 已被脑持久化后，吞掉对应 ACK 并主动断链。正式 Connection 随后自动重连，welcome 后从 outbox 补投同一 result msgId；信封 session 改为新会话、attempt 加一，而 body/evidence 保持完全一致。脑命中 processed message 后回 `ack(duplicate)`，手清空 outbox。

最终断言：不可逆页面动作恰好一次；`chat.sendMessage` 根命令只有一条且 attempt 为一；intent/cmd 均为 `ok`；`origin=self` 消息恰好一条；补投前后 result msgId 相同；outbox 从已写入恢复到零；committed journal 保留且 attempting 为零；重连后再次查询不增生命令或消息。

该测试初次运行实际发现脑侧对重复 result 仍固定回 `ack(accepted)`，与协议“重复帧必须回 duplicate”不一致。现已让首次持久化回 accepted、processed message 补投回 duplicate，并增加真 WS 与 dispatch 层回归断言；手侧对两种 ACK 仍按协议等价清理 outbox。

### 5.2 分层确定性故障矩阵

以下矩阵由 Go 生产 dispatcher/store/session 集成测试和插件生产 Dispatcher/Witness/program 测试共同覆盖并通过：

- ack 前断线、ack 后执行前断线；
- attempting 写入前失败、写入后点击前死亡、点击后观察前死亡；
- committed 后 result 未发、result 已发但 ack 丢失；
- 同 boot 重连、新 boot Service Worker 重生、脑进程重启和双方连续重启；
- query/report/outbox 重复、乱序、丢失和超时；
- 验证读命中、连续不命中、窗口/游标不完整与账号身份变化；
- 相同历史文本、真人同时输入、会话切换、平台风控/验证码前置失败；
- committed/outbox 双写失败后的 dispatcher 熔断、FIFO 隔离与逐项恢复；
- 页面重载、多标签竞争、POST 响应丢失、系统时钟回拨、head 丢失/损坏和 generation 溢出。

上述故障下的共同断言为：平台可见发送次数不超过一次，脑侧 `origin=self` 消息最多一条；无法形成零副作用证明时进入 suspect，不能通过新 intentId、msgId 或新文案绕过冻结。

## 9. Guard cohort 与成本指标

旧 cohort 固定为：`n=6`、动作前失败 `5`、成功 `1`。它只能说明旧路径产生过五次零副作用终局和一次真实成功；动作前失败可能是真正拦截、实现缺陷或守卫假阳性，缺少逐守卫曝光分母，不能据此计算假阳性率，也不能把 `5/6` 标成“83.3% 假阳性”。
