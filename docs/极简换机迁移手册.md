# 极简换机迁移手册

2026-08-22 起草。给"把一个客户从一台 Windows 机器挪到另一台"与"一台机器换个客户跑"两件事用,只写必须做的步骤,不写保险步骤。事实依据见文末。

两种场景,下面分开写:

- **场景一**:客户 X 整个从机器 A 迁到机器 B(账本、历史都带走)。
- **场景二**:机器 A 上 X 的数据不要了,A 直接改跑另一个客户 Y。

## 先记住的五件事(两种场景都一样)

1. **业务数据只在一个目录。** `%APPDATA%\recruithelper-client\data`(即 `C:\Users\<用户名>\AppData\Roaming\recruithelper-client\data`)。账本 brain.db、截图 blobs\、AI 语料 ai-traces.db、模型 key、激活文件,全在这一个目录里;同级 `logs\` 是日志。其余都是机器级的、不随客户走:安装目录 `%LOCALAPPDATA%\Programs\RecruitHelper`、插件目录 `%LOCALAPPDATA%\RecruitHelper\plugin`、杀毒排除的注册表项、Chrome 里已加载的插件。
2. **授权绑机器,换机器一定要重新激活。** 机器码每次启动从系统 UUID 现算、不落盘、不可携带。激活只重写 `data\legacy-job-config.json` 这一个文件,不碰账本。
3. **卸载不清数据。** 卸载程序故意保留 `data\` 与插件目录。要清数据只能手动删目录。
4. **两台机器绝不能同时跑同一份账本**——候选人会收两遍消息。数据拷走之后,A 上那一份必须删掉,不能"留着以防万一"。
5. **一律在空闲时做。** 当天运行已结束、没有运行中或挂起的批次、没有待人工裁决;从托盘退出客户端(这样 brain.db 的 WAL 已回写),再动文件。

## 场景一:X 从 A 整体迁到 B

**A 上**

1. 托盘退出客户端。
2. 拷走整个 `%APPDATA%\recruithelper-client\data` 目录(连 `blobs\` 子目录;若还有 `brain.db-wal`、`brain.db-shm` 一并带上)。

**后台(我方做)**

3. 服务器数据库把 A 的绑定停掉(一条 UPDATE):

   ```sql
   SELECT id, machine_id, status, last_seen_at, app_version
     FROM machine_bindings WHERE customer_id = <X 的客户 id> ORDER BY id;
   UPDATE machine_bindings SET status = 'disabled', updated_at = now()
    WHERE id = <上面查出的 A 那一行 id>;
   ```

   为什么非做不可:管理后台生成的激活码每客户只允许 1 台 active 机器,A 不停,B 激活会被拒「授权机器数量已达上限」;X 原来的激活码已锁在 A 的机器码上,也不能复用。
4. 管理后台(<http://8.153.161.25/admin-web/>)→ 客户 X → 生成邀请码(30 天有效)。

**B 上**

5. 安装最新版客户端(不低于 A 上的版本)。启动一次,再托盘退出——这一步让它建好目录、把插件放到固定目录。
6. 用 A 拷来的 `data` 目录整个替换 `%APPDATA%\recruithelper-client\data`。
7. 启动客户端 → 激活页输入新码 → 核对界面显示「当前客户 X」「授权有效」。
8. Chrome:登 X 的智联招聘端;`chrome://extensions` 开发者模式从 `%LOCALAPPDATA%\RecruitHelper\plugin` 加载插件;客户端显示插件在线。
9. Clash 用**同一个节点**(IP 跟账号走)、向日葵、杀毒排除那段管理员 PowerShell——照 [新用户开机手册](新用户开机手册.md) 第二章做。

**A 上收尾**

10. B 跑稳之后(建议跑过一天),删 A 上的 `data\` 与 `logs\`。卸不卸载客户端随意。

迁完后台的观感:运行状态页上 B 是一台新机器,A 的面板留着但不再更新;聊天记录上报的游标随 brain.db 走,服务端按会话+序号 UPSERT,不会重复上传。

## 场景二:A 不要 X 的数据,直接跑 Y

1. 托盘退出客户端。
2. 想留 X 的历史,先把 `data\` 压一份到我方;不留就跳过。(服务器上只有聊天记录上报的正文与档案、14 天内的诊断包;截图与 AI 语料只在本机,删了就没了。)
3. 删 `%APPDATA%\recruithelper-client\data` 与同级 `logs\`。
4. 后台给 Y 生成激活码(Y 名下没有别的 active 机器即可)。
5. 启动客户端 → 激活页输入 Y 的码 → 核对「当前客户 Y」,职位是 Y 的职位。
6. 智联账号按实际归属处理:**换账号**就 Chrome 退 X 登 Y、Clash 换 Y 的节点、向日葵换 Y 老师的;**不换账号**(同一个智联号转给 Y 用)就这三样都不动。
7. 插件、杀毒排除不用动(同一个 Windows 用户的前提下)。

X 在 A 上的后台绑定**可以不停**:A 的 `data\` 一清,X 的授权文件没了,A 不会再以 X 的身份跑;代价只是 X 名下挂一台不再上报的幽灵机器,X 以后换机/加机撞到上限时再停。

不用做的:不用重装客户端、不用重新加载插件、不用重跑杀毒排除。

### 同一个智联号转给 Y 之后,X 的老候选人会怎样

不会被 Y 接着聊。两道既有的闸:入站建档要求会话上的职位名**唯一等于** Y 的某个职位名;即便撞名,采简历前查到该会话在账本里已有我方发出的消息(X 时期的招呼、回复读进账本后就算数)就拒,这个人停在"已选中、未采集",脑不回一句话。推荐页再刷到他们,卡片是「继续沟通」不是「打招呼」,也不会再招呼。表现为日志「沟通层跳过:候选人尚无沟通根」、审计 `resumeTargetConflict`、候选人列表里几个停着不动的名字——属预期,不是故障(与 2026-07-31「交接老人全部忽略」裁决同源)。

唯一的窄口子:X 时期我方**一句都没发过**的入站会话,且职位名恰好与 Y 的某个职位重名,Y 的脑会把他当成 Y 职位的主动投递者接手。要绝对避免,就让 Y 的职位名别和 X 的重名。

## 检查清单

场景一:

- [ ] A 在空闲时托盘退出,`data\` 整目录已拷走
- [ ] 服务器上 A 的 machine_bindings 行已 disabled,X 的新激活码已生成
- [ ] B 装的是最新版;`data\` 已替换;激活后显示「当前客户 X」「授权有效」
- [ ] B 的 Chrome 已登 X 的招聘端、插件已加载、客户端显示插件在线
- [ ] B 的 Clash 同节点、向日葵可连、杀毒排除已执行
- [ ] B 跑稳后,A 上的 `data\`、`logs\` 已删

场景二:

- [ ] A 在空闲时托盘退出;X 的 `data\` 按需压走后已删(含 `logs\`)
- [ ] Y 的激活码已生成;A 激活后显示「当前客户 Y」,职位是 Y 的
- [ ] 智联账号、Clash 节点、向日葵按账号归属处理完毕
- [ ] Y 的职位名与 X 不重名(同号换客户时)

## 事实来源

- 数据目录与卸载保留:`scripts/windows-run.md`、`client/electron/layout.js` 的 `resolveDataDir`、`scripts/installer.nsi` Uninstall 段。
- 机器码不可携带:`client/service/internal/machineid/machineid.go`。
- 激活规则(已用码锁机器、active 机器数 ≥ max_machines 即拒、管理后台生成的码 max_machines 固定为 1、`machine_bindings.status` 只允许 active/revoked/disabled):旧后台 `app/services/auth_service.py` 的 `bind_client`、`app/api/admin.py` 的 `create_invite`、`migrations/0001_schema.sql`。
- 老候选人不被接手:`client/service/internal/patrol/round.go` 的 `adoptInboundConversationProfiles`、`client/service/internal/store/m5_resume_store.go` 的 `inboundResumeTargetTx`(零出站闸)、`client/service/internal/store/m6_sourcing_selection_store.go`(「继续沟通」不选);裁决见 [交接日入站闸裁决-2026-07-29](交接日入站闸裁决-2026-07-29.md)。
