# 0724 当日计划：职位绑定与单会话冒烟

日期：2026-07-24

## 一、目标

以旧后台的职位 `Job.ID` 作为新系统职位业务路由的直接依据，依次打通：

1. 采集批次与候选人正式记录后台职位 ID；
2. 采集前按照后台绑定的职位，选择并对齐智联页面职位；
3. 评分、筛选、招呼语生成与多轮沟通均按后台职位 ID 获取最新配置；
4. 提供“单次精确处理此会话”入口，完成有人值守冒烟。

本计划只执行至批次五。批次五之后的自动巡检、批量沟通与其他扩展，另行讨论和立项。

## 二、关键口径

- `BackendJobID`：旧后台 `Job.ID`，是职位配置与业务路由的主依据。
- `PositionRef`：智联平台职位标识，只用于记录平台侧职位身份。
- `PositionTitle`：智联当前职位标题，用于核验后台职位与页面职位是否对应。
- `ContextID` 不再承担业务路由职责；如暂时保留，仅作为兼容字段。
- `RevisionHash` 只记录一次运行实际使用的配置版本，不冻结后续业务。
- 正常运行尽量使用后台最新配置；同步失败时使用本地最近一次成功同步的配置。

## 三、实施批次

### 批次一：从采集源头正式存储后台 Job.ID

1. 在采集批次与候选人档案中增加正式业务字段 `BackendJobID`。
2. 新采集任务在创建时即明确其后台职位。
3. 对当前已有数据，按既有 `ContextRevisionHash → JobAIContextRevision.SourceJobRef` 路径回填；只能唯一确定时才回填，无法唯一确定的记录列出并停止猜测。
4. 后续业务不得再依赖派生的 `ContextID` 决定职位配置。

完成判据：从采集批次到候选人档案，均能直接读出真实后台 `Job.ID`。

### 批次二：按后台绑定职位自动对齐智联职位后再采集

真实意图不是单独切换后台配置，也不是为了切换页面而切换页面，而是：

> 采集前先读取后台当前绑定职位的 `Job.ID + Job.Name`，再按照这个后台职位选择并对齐智联推荐页上的职位；确认智联当前职位与后台绑定职位一致后，才允许开始采集。

执行流程：

1. 脑读取后台当前绑定职位的 `Job.ID + Job.Name`。
2. 脑命令插件在智联推荐页打开“选择职位”，按规范化后的 `Job.Name` 做唯一精确匹配。
3. 若智联页面当前不是目标职位，插件选择该职位并等待页面与推荐列表稳定；若本来已经一致，则直接进入确认。
4. 使用既有采集窗口读取能力独立回读 `PositionRef + PositionTitle`。
5. 脑确认回读的 `PositionTitle` 与后台 `Job.Name` 一致后，持久化：
   - `BackendJobID`
   - `PositionRef`
   - `PositionTitle`
6. 以上步骤全部成功后，才创建或启动简历采集。

约束：

- 后台 `Job.ID` 留在脑侧，不进入插件的平台动作参数；插件只负责按目标职位名称操作智联页面。
- 职位名称只做 Unicode NFC、首尾空白清理与连续空白折叠，不做模糊匹配。
- 找不到目标职位、出现多个同名匹配、页面未稳定或回读不一致时，在读取第一份简历前响亮停止。
- 页面交互遵守全局等待纪律：交互之间至少等待一秒并带随机量；等待元素出现最长可放宽至十秒。

完成判据：每个采集批次都能证明“后台绑定职位 → 智联当前职位 → 已保存 BackendJobID/PositionRef/PositionTitle”三者一致，然后才开始采集。

### 批次三：评分、筛选、招呼语统一按 Job.ID 取配置

1. 评分提示词、候选人筛选条件和招呼语提示词均以 `BackendJobID` 查询。
2. 每次业务运行优先使用该职位最新成功同步的配置。
3. 后台同步失败时使用本地最近一次成功配置，不因版本冻结阻断主流程。
4. 实际使用的配置版本继续写入审计字段。

完成判据：同一候选人的采集职位、评分、筛选和招呼语生成均归属于同一个后台 `Job.ID`。

### 批次四：多轮沟通按候选人的 Job.ID 取最新配置

将沟通配置解析路径收敛为：

`conversationRef → CandidateProfile.BackendJobID → 该职位最新成功同步配置`

要求：

- 不再把首次招呼时的配置版本永久绑定为后续沟通依据。
- 既有 AI 上下文绑定只承担兼容和审计用途，不再主导路由。
- 不同候选人可以根据各自的 `BackendJobID` 使用不同职位的话术、固定语和沟通配置。

完成判据：任选两个绑定不同后台职位的候选人，系统能够分别解析到各自职位的最新沟通配置。

### 批次五：单次精确处理此会话并冒烟

增加正式的“单次精确处理此会话”入口：

1. 管理端指定当前网页聊天列表中的一个会话。
2. 脑本轮只处理该 `conversationRef`。
3. 完整复用生产路径：读取、账本对账、确定性状态机、必要时调用 AI、WAL/idemKey、发送与回读确认。
4. 执行完成即退出；其他候选人和会话在本轮不得推进。
5. 由真人在场完成至少一次真实会话冒烟。

完成判据：能精确选择一个真实会话，按其候选人的 `BackendJobID` 使用正确职位配置完成一次生产路径处理，且没有推进其他会话。

## 四、提交与停止纪律

- 每个批次保持一个清晰因果，门禁通过后立即独立提交。
- 进入下一批次前工作区保持干净。
- 批次五验收完成后停止，不顺手实现后续自动巡检、批量回复或新的调度机制。
