# 0724 当日计划 3：筛选面事实记录

日期：2026-07-24

状态：事实门通过；页面探测已取消全部暂存改动，正式原语后续真机验收通过。

## 一、材料与边界

本次使用 GPT Chrome 在当前已登录的智联推荐页做只读 DOM 观察和可逆交互，
并以本机最近成功同步的当前职位配置 revision 为目标材料。旧项目只用于列出
候选字段和 selector；以下结论均由当前真实页面重新确认。

仓库只记录字段、类型、布尔结论和平台结构，不记录候选人身份、展示名、简历
或推荐列表正文。探测期间没有发送招呼、聊天或卡片。

当前页面职位标题、URL 中公开 `jobNumber` 与本批配置绑定均为唯一且一致；
本机没有未终结的采集批次，不存在旧 `collecting` 批次绕过新筛选步骤的问题。

## 二、后台目标形状

权威材料是不可变职位配置 revision 中 `docType=职位筛选` 的文档正文，而不是
旧接口顶层 convenience projection。正文是六项数组，统一形状为：

```text
fieldKey
title
multiple
controlType
customMinAge / customMaxAge（仅自定义年龄）
options[]: label / action / selected
```

本次真实目标如下：

| fieldKey | 页面标题 | 目标 |
|---|---|---|
| `age` | 年龄要求 | 自定义 25–45 |
| `activeTime` | 活跃日期 | 3 天内活跃 |
| `careerStatuses` | 求职状态可多选 | 不限 |
| `educations` | 学历要求可多选 | 大专、本科、硕士、MBA/EMBA、博士 |
| `gender` | 性别要求 | 不限 |
| `filterTypes` | 人才范围可多选 | 过滤我已看过 |

该表记录的是事实门探测时所用 revision 的具体样本，只用于证明字段、控件和
读写形态。正式实现不把这些值写死：每个采集批次都从其冻结的后台最新
revision 严格转换目标。后续真机验收所用 revision 已变更为年龄 30～55 岁、
本科及以上并同时过滤“我已看过”和“同事已聊”，原语按新值完整回读成功。

旧页面仍显示经验、薪资、院校、专业和职类等其他分组，但当前后台文档没有管理
这些字段。本批不得读取页面旧值后猜测接管，也不得把它们扩进正式支持集合。

## 三、当前页面结构

### 3.1 入口与面板

- 推荐页：`/app/recommend`；
- 当前职位：唯一可见
  `.job-pane__item--active .job-pane__item-job-title`；
- 筛选入口：唯一可见
  `a[zp-stat-id="talent-recommend-filter-click"]`；
- 打开面板：唯一可见
  `.km-modal.km-modal--open.km-modal--right`；
- 确定：面板内唯一
  `button[zp-stat-id="rsmlist-confirm"]`；
- 取消：面板内唯一可见、文字精确为“取消”的按钮。

筛选分组均有唯一字段 class：

```text
.filter-item-age
.filter-item-activeTime
.filter-item-careerStatuses
.filter-item-educations
.filter-item-gender
.filter-item-filterTypes
```

每组同时有可见标题。正式读取必须同时核对字段 class、规范化标题和允许的选项
全集；零匹配、多匹配或选项集合漂移均失败关闭。

真机实现前冒烟补充确认：三个多选组的标题节点原文包含字面后缀“可多选”，
分别为“求职状态可多选”“学历要求可多选”“人才范围可多选”；该后缀是当前
唯一标题节点的一部分，不是独立子节点。正式页面事实与测试夹具均按原文核对。

### 3.2 控件与选中状态

- 年龄、求职状态、学历和人才范围使用
  `.recommend-checkbox-group__item`；
- 选中项表现为 `recommend-checkbox-group__active`，未选中项表现为
  `recommend-checkbox-group__inactive`；
- 活跃日期和性别使用 `.km-radio`；
- 选中项表现为 `km-radio--checked`；
- radio 的原生 `input.checked` 在真实交互后会同步，但重新打开既有状态时曾
  出现 wrapper 已选中而 input 仍为 false，因此不能单独以 input 属性否定
  可见选中状态。

样式 class 是当前页面唯一能完整覆盖六组既有状态的事实源，属于有真实
前后对比支撑的感知通道。读取不到时必须失败关闭，不得默认“不限”。

单选点击真实证明为旧项取消、新项唯一选中；多选真实证明为逐项独立切换，
选择具体项会取消“不限”。因此正式设置可以只点击当前集合与目标集合的对称差，
无需先整体清空。

### 3.3 自定义年龄

点击“自定义”会在年龄分组内显示：

```text
.recommend-checkbox-group__selector
  .filter-select-two__start .km-select
  .filter-select-two__end .km-select
```

下拉弹层为 `.km-popover.filter-select-two__popover`，可见选项是
`.km-option`。下限全集为“不限、16–50、55、60、65 岁”；选择下限后，
上限只显示不小于下限的年龄及“及以上”。

真实选择 25 岁下限后，“自定义”成为唯一年龄选中项，上限暂时显示“及以上”；
再选择 45 岁后，同一分组回读为 `25岁 / 45岁`。随后点击取消并重新打开，
页面完整恢复原已提交年龄，证明探测没有落地。

## 四、提交、稳定与二次回读

推荐列表当前公开结构为：

```text
.recommend-list__left div[role="listitem"]
  .recommend-item.recommend-resume-item[data-index]
```

本次在不改变已提交筛选值的情况下点击一次“确定”：

1. 面板关闭；
2. 可见列表的规范化 DOM 摘要发生变化，证明提交触发了推荐流刷新；
3. 一秒后与再后一秒读取的卡片数量和摘要完全一致；
4. 没有发现可作为权威信号的专用 loading overlay，因此正式实现不能依赖
   某个 loading class；
5. 再次打开面板，用与首次相同的六组读取口径得到完整已提交状态；
6. 点击“取消”关闭后，可见列表数量和摘要保持不变，证明二次确认不会触发
   第二次刷新。

正式稳定判据应对当前公开列表窗口生成仅留在手内的摘要，只向结果返回摘要与
数量等非正文证据；要求至少间隔一秒的连续两次读完全一致，最长等待十秒。
摘要只用于确认页面稳定，不得替代 `platformUserRef` 身份或授权任何发送。

## 五、实现结论

1. 后台六项原始 JSON 必须先在脑侧转换成强类型平台中立目标；未知字段、重复
   字段、未知选项、单选零选/多选、年龄范围非法或“不限”与具体值并存均拒绝。
2. 现有 `candidate.selectSourcingPosition`、`candidate.readSourcingWindow`
   与 `candidate.readSourcingTargetResume` 的规范明确禁止点击筛选确认，
   不能通过扩张其中一条原语实现。
3. 需要先按 `AGENTS.md` 第 12 条批准并新增独立
   `candidate.applySourcingFilters@1`，再进入代码实现。
4. 新原语的唯一接线点是职位选择成功之后、首次窗口读取和
   `BindSourcingBatchPosition` 之前。失败时批次保持 `preparing` 并阻塞；
   恢复时重新做幂等覆盖，无需新增持久游标或 `filterApplied` 字段。
5. `move=current` 的窗口读取还需补足与 reset/next 一致的连续稳定采样；
   不应把一次瞬时 DOM 读取冒充筛选后的稳定窗口。
