# 0724 当日计划 4：客户端七页核心 UI

日期：2026-07-24  
状态：甲方已批准；夜间独立执行中

## 一、目标

以老项目客户端的七页信息架构、导航顺序与主要视觉语言为基础，为新项目交付
一版普通用户可直接使用的客户端 UI：

1. 保留首页、候选确认、沟通中、待面试、已面试、已换微信、配置七个页面；
2. 只有首页与候选确认页能够改变业务运行状态；
3. 首页提供完整流程、仅多轮回复、暂停、恢复四类控制；
4. 完整流程自动执行采集、评分、筛选、招呼语生成，随后必须停在人工确认闸；
5. 候选确认页只有在用户全选并点击发送后，才允许真实发送招呼；
6. 招呼成功后由脑自动纳入多轮回复，不再要求用户额外启动一次；
7. 首页人数统计、总账面、今日面试与今日活动面板按老项目布局和名称呈现，
   但数据由新项目业务事实重新计算；
8. 客户当前绑定职位在侧边栏与首页常驻展示；
9. 现有值班巡检台、账本、suspect、协议帧与开发配置不删除，收进隐藏的
   开发者诊断入口。

本计划复刻的是用户已经形成习惯的页面结构与视觉语言，不恢复旧 Electron、
Python 服务、旧 IPC、`resumeNumber` 身份设计、Native Messaging、
electron-updater 或旧项目已经过时的业务调度。

## 二、产品口径

### 2.1 七页导航固定

侧边栏顺序固定为：

1. 首页；
2. 候选确认；
3. 沟通中；
4. 待面试；
5. 已面试；
6. 已换微信；
7. 配置。

页面名称、顺序、左侧导航、全局搜索位置和候选人详情抽屉尽量延续老客户端，
以降低既有用户迁移成本。

### 2.2 只有两个业务写入口

业务状态写入口只有：

- 首页：开始完整流程、仅运行多轮回复、暂停、恢复；
- 候选确认：全选并发送本批已生成的招呼语。

沟通中、待面试、已面试、已换微信为只读业务页。搜索、筛选、展开详情和复制
微信号属于本地查看便利，不改变业务状态。

配置页第一版只展示普通用户需要理解的配置与连接状态；激活、模型密钥、插件
重载、账本裁决等开发期写操作继续保留在隐藏诊断入口。首次激活页是进入七页
应用前的门禁，不计入七页导航。

### 2.3 完整流程含人工招呼闸

“开始完整流程”的业务含义固定为：

```text
按后台绑定职位对齐平台职位
→ 采集
→ 评分
→ 按后台规则筛选
→ AI 生成招呼语
→ 等待候选确认
→ 用户在候选确认页全选并点击发送
→ 逐候选人走既有 WAL / idemKey / witness / 页面正证发送轨
→ 成功者自动进入多轮回复
```

“开始完整流程”表示启动整条业务流程，不表示绕过人工发送闸。生成招呼语完成
后，任何定时器、重启恢复、页面轮询、管理端重复请求或候选人列表刷新，都不
得自动开始招呼发送。

### 2.4 仅多轮回复

“仅运行多轮回复”只启动已有候选人和已有会话的沟通巡检：

- 不创建采集批次；
- 不读取推荐列表；
- 不评分；
- 不筛选候选人；
- 不生成招呼语；
- 不发送首次招呼；
- 继续复用确定性沟通状态机、AI 建议层和既有安全发送轨。

### 2.5 暂停与恢复

- 暂停只阻止新的业务派发，已经进入手侧执行的单个命令自然收束；
- 暂停后不得开启新采集、继续下一位评分、发送招呼或处理下一段对话；
- 恢复必须从同一运行模式、同一批次与同一持久进度继续；
- 恢复不得重新创建采集批次、重新生成已完成招呼语或重新发送已确认招呼；
- 脑重启、UI 关闭和 Electron 页面重载不得把暂停变为运行，也不得把运行模式
  从“仅多轮回复”偷换成“完整流程”。

### 2.6 漏斗与沟通是两条可并行状态

首页分别展示：

- 候选漏斗状态：空闲、采集中、评分中、筛选中、生成招呼语中、等待人工发送、
  发送中、已完成、失败；
- 沟通引擎状态：未运行、运行中、已暂停、需要人工。

完整流程会启动候选漏斗并开启沟通引擎；等待本批候选确认时，既有候选人的
多轮回复仍可继续。仅多轮回复只启动沟通引擎。

### 2.7 夜间独立执行授权

甲方在 2026-07-25 睡前明确授权执行方按本计划连续开工，并要求执行期间不要
因局部阻断停下等待甲方在线裁决。

执行纪律固定为：

1. 某一页面、字段、接口或批次遇到事实缺口时，先判断是否只影响局部；
2. 能隔离的局部阻断必须以诚实空态、只读降级、禁用局部按钮、保留既有实现
   或明确后置项隔离，不得让它阻塞其他无依赖页面和批次；
3. 记录阻断事实、临时处置、未完成范围与恢复入口，然后继续开发其余已批准
   内容；
4. 不为等待完整字段而伪造统计，不为等待写接口而放假按钮，不把未实现功能
   宣称为完成；
5. 每个独立绿色因果单元立即提交，避免局部失败污染已经完成的成果；
6. 夜间结束时交付实际完成清单、门禁结果、诚实后置项和可继续执行的下一步，
   不以“遇到疑问”代替可独立完成的工作。

“跳过阻断”只授权隔离问题并继续其他工作，不授权绕过以下红线：

- 未经候选确认自动发送招呼；
- 错职位、错候选人或重复候选人可见副作用；
- 绕过 WAL、idemKey、witness、页面正证或 suspect；
- 破坏业务事实、物理删除业务行或伪造成功状态；
- 需要新增候选人可见能力却没有规格、契约与事实依据。

只有继续任何剩余工作都会直接造成上述不可逆损害，且已经没有可独立推进的
安全批次时，才允许整项停止；此前不得因普通实现困难、缺少低频字段、页面
样式偏差或一个批次暂时失败而等待甲方。

## 三、视觉与共用结构

### 3.1 视觉方向

直接复用老客户端企业蓝、白色侧栏、浅灰背景、卡片、列表、抽屉、筛选条和
统计面板的视觉语言，不重新发明一套陌生设计。

可迁移的旧代码仅限展示层与确定性纯函数：

- 主题变量与绝大多数组件样式；
- Sidebar、CandidateRow、Drawer、ConfirmModal、Toast 的布局；
- 七页标题、筛选条、空状态和列表结构；
- 面试时间显示等纯格式化逻辑。

不迁移旧 store、旧领域类型、旧 preload、旧 Electron 主进程与旧 Python API。
旧源码中的 Unicode/emoji 图标改为内联 SVG 或 CSS 图标，以符合本仓库源码
禁用 emoji 的约定。

### 3.2 全局布局

```text
┌──────────────┬─────────────────────────────────────────┐
│ 客户名称      │ 页面标题 / 页面说明                      │
│ 当前绑定职位  │                                         │
│              │ 页面主体                                 │
│ 七页导航      │                                         │
│              │                                         │
│ 全局搜索      │                                         │
│ 版本          │                                         │
└──────────────┴─────────────────────────────────────────┘
```

侧边栏客户区域常驻展示：

- 客户名称；
- 当前绑定职位名称；
- 未绑定时显示“尚未绑定职位”。

当前职位不只藏在配置页。首页顶部另设职位状态条，展示职位名称、后台同步状态与
运行环境；未绑定或当前配置不可用时，完整流程按钮不可用并给出直接原因。

### 3.3 四个状态页共用一套实现

沟通中、待面试、已面试、已换微信对用户仍是四个独立页面，但内部共用一个
`CandidateStagePage`：

- 同一个候选人查询投影；
- 同一个搜索与筛选栏；
- 同一个 CandidateRow；
- 同一个详情抽屉；
- 同一套加载、空状态与错误状态；
- 只通过页面配置决定筛选条件、状态标签、辅助字段和文案。

不得复制四份列表、四套 API 或四套候选人状态映射。

## 四、七个页面

### 4.1 首页

首页从上到下固定为以下区域。

#### A. 欢迎区

- 客户名称；
- 当前日期和星期；
- 当前绑定职位状态条。

#### B. 今日任务

空闲时显示：

- 主按钮“开始完整流程”；
- 次按钮“仅运行多轮回复”。

运行中显示：

- 当前模式：完整流程或仅多轮回复；
- 当前状态；
- “暂停”。

暂停后显示：

- 暂停前模式；
- 暂停位置；
- “恢复”。

不在本计划增加“强制终止并清空进度”“重新来一批”或其他破坏性控制。

#### C. 流程进度

候选漏斗按真实业务顺序展示：

`采集 → 评分 → 筛选 → 生成招呼语 → 等待确认 → 发送招呼`

每段至少展示：

- 当前阶段；
- 已完成数量；
- 待处理数量；
- 失败数量；
- 最近失败原因的用户可理解文案。

沟通引擎单独显示运行状态和最近一次巡检时间，不伪装成候选漏斗中的一次性
步骤。

招呼语生成完成后：首页显示“待确认 N 人”与“前往候选确认”，但首页不提供
发送按钮。

#### D. 今日数据

保留老系统四项面板和顺序：

1. AI 评级人数；
2. 候选确认人数；
3. 打招呼；
4. 已约面。

新系统统计口径固定为：

- AI 评级人数：本地业务日内完成有效评分的不同候选人数量；
- 候选确认人数：本地业务日内通过后台筛选并进入候选确认列表的不同候选人
  数量，不要求已经发送；
- 打招呼：本地业务日内取得唯一发送正证的不同候选人数量，pending、suspect
  和仅点击按钮均不计；
- 已约面：本地业务日内首次进入“已约面”状态的不同档案数量。

#### E. 总账面

保留老系统三项面板：

1. 累计招呼；
2. 累计已面试；
3. 累计已换微信。

并显示“自 YYYY-MM-DD 开始”。起始日期取当前客户第一条有效候选业务事实，
不是安装日期或首次打开 UI 的日期。

统计口径：

- 累计招呼：历史上取得首次招呼发送正证的不同档案数量；
- 累计已面试：按新项目统一状态投影判定已经完成面试的不同档案数量；
- 累计已换微信：取得微信交换成功事实的不同档案数量。

#### F. 今天的面试

保留老系统“今天的面试”卡片，展示：

- 候选人；
- 所属职位；
- 面试时间；
- 面试方式；
- 当前确认状态。

第一版只读，不在首页发送会议号或修改面试结果。

#### G. 今日活动

保留老系统面板：

- 招呼；
- 新回复；
- 新约面；
- 完成面试。

若保留老系统“招呼 / 上限 100”的进度条，“100”只作为显示目标，不成为频控
或发送授权，不新增后台配额机制。

所有“今日”按客户端本地业务日计算，查询时刻和刷新时刻一并显示。前端不得
通过当前列表长度自行推算统计值。

### 4.2 候选确认

该页展示当前等待人工发送的批次：

- 当前客户与职位；
- 批次创建时间；
- AI 评分完成数；
- 后台筛选入选数；
- 招呼语生成成功、失败与待处理数；
- 候选人基本信息；
- AI 生成的招呼语；
- 当前发送状态。

工具栏包含：

- 全选；
- 取消全选；
- 已选择数量；
- “发送所选候选人”。

第一版固定为整批确认：

- 用户必须主动点击“全选”；
- 发送按钮仅在本批所有可发送候选人均已选中时可用；
- 生成失败、已发送、已有 intent 或不再符合发送资格者不进入可选择集合；
- 未全选时不发送任何候选人；
- 不因进入页面、刷新、轮询、重新打开客户端或恢复运行而自动勾选或发送；
- 第一版招呼正文只读，逐条编辑后置；
- 点击发送后，脑按既有资格核对逐人构造独立 intent，并走已有安全轨道；
- 一位候选人失败不得导致前面已确认发送者重发；
- 每行实时显示待发送、发送中、已发送、失败、suspect 或不再可发送；
- 全部可发送成员终局后，本批招呼阶段完成；已发送者自动纳入多轮回复。

系统暂停时可以查看和选择，但发送按钮不可用，页面明确提示先恢复运行。

侧边栏“候选确认”徽章显示当前等待人工发送的可发送人数。

### 4.3 沟通中

只读筛选建议：

- 全部；
- 已招呼；
- 已回复；
- 推约中；
- 等候回复；
- 需要人工；
- 沟通已结束。

列表展示：

- 候选人；
- 所属职位；
- 当前沟通状态；
- 最后一条消息摘要；
- 最后活动时间；
- 未读或需人工徽章。

详情抽屉展示候选人画像、简历摘要、消息与卡片记录、确定性状态、最近 AI
判断、动作结果和转人工原因。该页不提供人工发送、处理一次、恢复预算或裁决
suspect 的按钮。

### 4.4 待面试

只读筛选建议：

- 全部；
- 今天；
- 本周；
- 待候选人确认；
- 已确认。

列表展示候选人、所属职位、面试时间、面试方式、邀面卡状态和微信状态。
第一版不发送会议号、不改约、不取消面试。

### 4.5 已面试

只读筛选建议：

- 全部；
- 待回填；
- 已录用；
- 未录用；
- 爽约。

只展示当前数据库已有的真实面试结果；没有正式结果写入口时不得放一个只改
前端内存或假装成功的“回填”按钮。

### 4.6 已换微信

展示：

- 候选人；
- 所属职位；
- 微信号或“尚未收编明文账号”；
- 换微信时间；
- 当前沟通主线状态；
- 是否仍在自动沟通范围。

允许复制已经存在的微信号。复制只写系统剪贴板，不改变业务状态。没有真实
微信号时不得用候选人平台 ID、姓名或其他字段代替。

### 4.7 配置

普通用户第一版只读展示：

- 客户名称与授权状态；
- 当前绑定职位；
- 后台配置最近同步时间与状态；
- AI provider/model 已配置状态，不显示 key；
- 插件在线、版本与契约匹配状态；
- 客户端版本。

首次未激活时，在七页应用外显示独立激活页。开发期手工导入上下文、模型密钥
配置、插件重载、账号绑定、巡检诊断、账本、suspect、协议帧与调试原语派发
继续保留在隐藏开发者诊断入口，不混进普通配置页。

## 五、脑侧运行控制与 UI 投影

### 5.1 控制权仍在脑

React UI 只发出用户意图，不串联“采集完成后前端再调用评分”等业务步骤。
UI 关闭后，完整流程、仅多轮回复、暂停、恢复和等待候选确认都必须继续由脑
持久化和裁决。

优先复用现有账号运行态、M6 批次事实和沟通 actor。只有现有状态无法表达
`full / replyOnly` 模式及其暂停恢复时，才允许增加最小脑侧运行模式字段；
不得为 UI 建第二份业务状态机。

建议的本地管理面：

- `GET /admin/ui/overview`：客户、职位、运行模式、漏斗、沟通引擎、统计；
- `POST /admin/workflow/start`：`mode=full|replyOnly`；
- `POST /admin/workflow/pause`；
- `POST /admin/workflow/resume`；
- `GET /admin/ui/confirmation`：当前等待发送批次及候选人；
- `POST /admin/ui/confirmation/send`：当前批次整批人工发送；
- `GET /admin/ui/candidates?view=communicating|pending|interviewed|wechat`；
- `GET /admin/ui/candidates/{profileId}`。

具体路径可在实现时按现有 admin 命名收敛，但必须满足：

- 管理 API 继续使用 Electron preload 内存中的随机 bearer；
- UI 投影不是脑手 contract，不新增插件 capability；
- 所有候选人可见动作仍只能进入现有业务入口和安全发送轨；
- UI 投影只读数据库事实，不自己推进状态；
- 候选人主键使用 `profileId`，不恢复旧 `resumeNumber` 身份设计。

### 5.2 当前绑定职位

首页与侧边栏读取同一份脑侧职位投影：

- `BackendJobID`；
- 职位名称；
- 最近成功配置 revision；
- 后台同步状态；
- 运行环境。

普通 UI 默认只展示职位名称、同步状态和环境，不显示内部 ID。完整流程创建批次
前仍由脑使用 `BackendJobID` 并按既有职位选择、平台回读与绑定链核对；UI
显示的职位不得成为动作授权证据。

### 5.3 统计投影

首页统计由单一 Go 查询层返回，七个页面和首页不得各自维护一套状态映射。
所有人数先按档案去重，再按本地业务日或历史口径聚合。

实施前须建立并测试以下映射：

| 老首页指标 | 新系统事实来源 |
|---|---|
| AI 评级人数 | 当日成功评分终局 |
| 候选确认人数 | 当日筛选结果为 selected 并进入确认列表 |
| 打招呼 | 当日首次招呼正证 |
| 已约面 | 当日首次进入已约面 |
| 累计招呼 | 历史首次招呼正证 |
| 累计已面试 | 统一面试完成投影 |
| 累计已换微信 | 微信交换成功事实 |
| 新回复 | 当日真实入站候选人消息 |
| 新约面 | 当日首次进入已约面 |
| 完成面试 | 当日首次进入面试完成投影 |

无法由现有事实可靠计算的指标显示“—”并登记缺口，不得用当前页面行数、
消息文本猜测或旧库 SQL 冒充。

## 六、规范先行与事实门

当前 M6 已有独立“招呼发送运行”入口，历史规格与验收记录包含自动进入发送
阶段的口径。本计划改变了该业务权利：生成完成后必须等待人工确认。因此实现
前先做独立规范批次：

1. 清点当前 M6 生成完成后的所有自动发送触发点、启动恢复入口和管理 API；
2. 修订 M6 招呼发送规格，明确“人工确认是唯一新发送授权”；
3. 明确人工确认只批准当前批次当时仍可发送的成员，不批准技术失败后另铸；
4. 固化完整流程、仅多轮回复、暂停与恢复语义；
5. 证明既有 WAL、idemKey、witness、正证与 suspect 语义不变；
6. UI 管理 API 不进入脑手 contract；若实现确需新增插件能力，必须另行第 12
   条立案，不得借本 UI 计划自我授权。

采集目标数目前由既有正式入口显式传入；本计划不擅自决定它应来自固定值、
后台配置还是其他运行设置。批次零须核对当前正式来源。若没有已经批准且可由
首页自动取得的唯一来源，必须在创建完整流程控制器前停下提交甲方裁决。

## 七、实施批次

### 批次零：字段映射、事实门与规范修订

- 固化老首页统计面板与新表的逐项映射；
- 清点当前运行态、M6 各阶段和多轮沟通 actor；
- 查清完整流程采集目标数的正式来源；
- 按第六节完成规范先行；
- 产出 UI 只读投影字段表，不改生产运行。

完成判据：人工招呼闸、两种运行模式、暂停恢复、统计口径和职位投影均无文本
冲突；无悬空的自动发送入口。

### 批次一：七页视觉壳

- 迁移老 UI 主题、Sidebar 与七页布局；
- 用内联 SVG 替换 Unicode/emoji 图标；
- 当前 1768 行值班巡检台整体拆为开发者诊断页，先不改其业务逻辑；
- 七页使用真实空状态或本地非生产 fixture 完成渲染；
- 引入最薄 Zustand store，仅承担 UI tab、筛选、加载缓存和抽屉状态。

完成判据：Electron 1200×840 默认窗口下七页可正常切换，侧边栏不抖动，
诊断台仍可访问，构建与 TypeScript strict 通过。立即提交第一个视觉冒烟
commit。

### 批次二：统一 UI 只读投影

- 增加 overview、候选人列表、候选人详情与确认列表查询；
- 使用 `profileId` 和新状态机事实；
- 建立统计聚合；
- 接通当前客户与当前职位常驻展示；
- 加 Go 投影测试与前端 decode/API 测试。

完成判据：七页不读 SQLite、不调用旧 IPC、不按旧字段猜状态；首页所有可计算
数字来自单一查询层。

### 批次三：首页运行控制

- 实现或收敛最小脑侧运行模式；
- 接通开始完整流程、仅多轮回复、暂停、恢复；
- 完整流程自动推进至招呼语生成并停在人工闸；
- 接通漏斗与沟通引擎双状态；
- 接通首页统计、总账面、今日面试与今日活动。

完成判据：两种开始模式无串线；暂停后零新派发；重启与恢复继续同一模式和
批次；生成完成后候选人可见招呼为零。

### 批次四：候选确认人工发送

- 接通当前待确认批次；
- 实现全选、取消全选、选择计数与整批发送；
- 发送前逐候选人重新核对资格；
- 复用现有批量招呼定位与安全发送轨；
- 接通逐行发送终态和侧边栏徽章；
- 成功发送者纳入 tracked/多轮沟通。

完成判据：未全选、未点击发送、页面刷新、脑重启和重复 GET 均为零发送；
唯一一次人工发送请求对每位合格候选人最多构造一个 intent；重复 POST、断线
和恢复不产生重复候选人可见招呼。

### 批次五：四个共用状态页与详情抽屉

- 以同一个 `CandidateStagePage` 接通沟通中、待面试、已面试、已换微信；
- 接通页面筛选、全局搜索、状态徽章与详情抽屉；
- 四页保持只读；
- 文本、卡片、AI 建议和转人工原因只展示本地已有事实。

完成判据：同一候选人的状态在首页数字、侧边栏徽章、列表和抽屉中一致；四页
没有业务写入口。

### 批次六：配置、激活与诊断收口

- 独立激活页接现有旧后台激活链；
- 普通配置页只读接线；
- 当前诊断能力完整保留并隐藏到开发者入口；
- 清理旧 UI 中 updater、企微、旧 session、旧 IPC 和假按钮残留。

完成判据：普通用户不会接触 API key、账本裁决或调试原语；开发者仍能完成
插件重载、身份核验、provider 配置与 suspect 裁决。

### 批次七：自动回归与 Electron 真机验收

- 完成全部构建、Go、race、UI、Electron 与 Windows 交叉构建门禁；
- 在真实 Electron 窗口对七页截图核对；
- 使用小批次跑完整流程至等待确认；
- 证明点击发送前候选人可见招呼为零；
- 真人全选并发送一个小批次；
- 确认成功者进入多轮回复；
- 暂停、恢复、脑重启与 UI 重载各演练一次；
- 单独验证“仅运行多轮回复”期间 M6 各表与候选人可见招呼零增长。

完成判据：第九节出口全部成立后停止，不顺手补后置功能。

## 八、自动化测试重点

### 8.1 运行控制

- 完整流程只创建一个活动批次；
- 重复点击开始不创建第二批；
- 仅多轮回复不触碰 M6；
- 暂停后在途单动作收束、后续零派发；
- 恢复沿用同一模式与批次；
- 脑重启保持运行或暂停事实；
- UI 关闭不承担业务调度。

### 8.2 人工发送闸

- 生成成功后零自动发送；
- 未全选发送按钮不可用；
- 全选但未点击仍零发送；
- 页面轮询、刷新、重开与重复查询零发送；
- 重复发送请求复用同一批事实，不铸第二套 intent；
- 已发送、生成失败、资格漂移和已有 intent 成员不重复进入；
- 部分成功后恢复只处理尚无终局者；
- failed、possible、suspect 和正证继续服从既有安全内核。

### 8.3 统计

- 本地日期零点边界；
- 同候选人重复评分或多条正证只计一次；
- pending/suspect 不计成功招呼；
- 当日与历史口径不串；
- 首页、七页列表和侧边栏徽章使用同一状态映射；
- 无数据返回 0，有事实缺口返回“—”，不返回假数字。

### 8.4 UI

- 七页导航顺序、名称与 badge；
- 1200×840 默认窗口和较窄窗口；
- 加载、空状态、错误状态；
- 键盘焦点与按钮 disabled；
- 当前职位常驻且长名称不挤坏布局；
- 四个共用状态页不出现跨页字段或写按钮；
- 候选人详情抽屉不泄漏平台 ID、内部引用或 AI provider key。

## 九、出口与风险预算

### 9.1 最小完成出口

- 七页均使用真实新项目数据或诚实空状态；
- 首页四类运行控制真实有效；
- 完整流程能自动推进至人工招呼闸；
- 候选确认全选发送走既有安全轨；
- 首页老系统统计面板与当前职位显示完成；
- 四个状态页只读且共用实现；
- 现有诊断能力未丢失；
- 自动测试、Electron 真机与 Windows 构建通过。

### 9.2 必须立即阻断

- 未经候选确认自动发送招呼；
- 暂停后继续创建新业务派发；
- 恢复时重开批次、重生成或重复发送；
- 错职位采集、统计或发送；
- UI 绕过 WAL、idemKey、witness、正证或 suspect；
- 首页显示一个职位，脑按另一个职位运行；
- 旧 UI 假按钮向用户宣称成功；
- 候选人明文、平台身份或模型 key 进入普通日志和报告。

### 9.3 可接受失败

- 页面显示落后脑一个正常轮询周期；
- 低频详情字段暂缺并显示“—”；
- 某个只读列表暂时加载失败并允许手动刷新；
- 复制微信号失败后提示手工复制；
- 老 UI 的像素级细节存在小偏差；
- 当前有人值守阶段的普通窗口缩放瑕疵。

这些失败不得升级为重复发送、错靶、假统计或长期锁死。

### 9.4 审查预算

- 首个可运行视觉竖切绿色后立即提交；
- 后续一项因果一个 commit；
- 默认最多一轮独立集成审查；
- 只自动阻断未经确认发送、错职位、重复副作用、账本破坏、错版发送和长期
  锁死；
- 普通样式瑕疵与低频空态进入后置，不递归开启审查。
