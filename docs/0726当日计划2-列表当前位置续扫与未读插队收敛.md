## 一、现场结论

本计划承接 2026-07-26 智联 IM 真机巡检现场，只处理两个已经还原完整因果链的
问题：

1. **列表物理回顶**：脑在处理一个会话后需要废弃旧 cursor，并希望从当前物理
   位置建立 fresh 快照；插件却沿用 M2 语义，把空 cursor 解释为
   `scrollTop=0`。因此当前行为是“回顶、跳过本轮已检查前缀、找到下一人、再
   回顶”，逻辑上会推进不同会话，物理上却反复重扫，成本近似二次增长。
2. **未读插队过早退出且后续不再触发**：该链包含四个已经由源码与现场记录
   分别证实的缺口：
   - 两次真实未读子轮都在成功打开第一条未读后，因为 fresh 列表短暂出现
     `unreadCount=0` 的行而报 `ELEMENT_UNRESOLVED`，随后退回普通列表；
   - 同一扫描的 `unreadPassAttempted` 禁止重新进入，本来应防残留气泡自旋，
     但在子轮被假阴性中断后也阻止继续；
   - 内容脚本监听整个 document，每次虚拟列表 mutation 都会取消并重建
     800ms 气泡采样；持续滚动/重排可能让稳定采样永远得不到执行；
   - SW 重启要求现货快照时，内容脚本会因数值等于旧 `lastStableUnread` 而拒绝
     重报，新 SW 的 canonical 未读缓存可长期为 null。
3. **未读清空没有成功出口**：当前 DOM 列表读取在零行时一律抛
   `dom_list_items_missing`，即使“全部职位 + 未读”筛选已确认且页面正在展示
   可信空态，也无法返回 `{sessions:[], complete:true}`。因此若直接增加
   pending latch，它可能永远无法被明确清除。

本轮不把上述现象归咎于智联随机行为：

- 第一项是脑、contract 与手对“无 cursor”含义不同，属于跨层语义漏建模；
- 第二项是把“未读筛选已选中”之外的平台行级同步时序升级成硬闸，再叠加未读
  提示不是可靠电平信号，属于本仓库自己的调度与守卫边界问题。

## 二、出口宣言与风险预算

### 2.1 最小可交付出口

1. `chat.readList@1` 显式区分 fresh 扫描起点：
   - 新完整扫描、切换 `all/unread` 筛选时从 `top` 开始；
   - 打开会话或本轮动作收束后，旧 cursor 作废，但同筛选 fresh 从
     `current` 物理位置继续。
2. 同一扫描继续复用既有 `checkedConversationRefs` 与共享 `MaxPages`：
   已处理会话不重复领取，读取预算不因 fresh restart 重置。
3. `filter=unread` 的授权事实是平台公开筛选状态已经回读为
   “全部职位 + 未读”；窗口内个别行的 `unreadCount=0` 只进入观测，不再导致
   整个读取或打开动作失败。
4. 稳定正数未读提示在脑中成为本轮待处理电平，直到未读子轮真实收束前，不被
   单次 `nil/0` 采样静默清除；当前候选人动作链收束后的下一个安全边界即进入
   未读子轮。
5. 气泡采样不能被持续 DOM mutation 无限延期；SW 重启请求现货快照时，即使
   值与旧稳定值相同，也必须补给新 SW，但不得伪造重复业务事件。
6. “全部职位 + 未读”筛选已确认后，页面唯一、可见且稳定的公开空态可以返回
   `sessions=[]、complete=true`；没有可信空态的零行仍响亮失败。
7. 一旦进入未读子轮，就继续使用页面未读列表逐条处理；每个本轮唯一会话至少
   打开一次、至多尝试一次。单条局部失败或暂时零未读摘要不得中断后续会话。
8. 真机至少观察一个普通列表完整扫描与一个未读子轮：
   - 普通列表处理会话后不再物理回顶；
   - 未读子轮不会只打开第一条就退出；
   - 没有新增候选人可见消息、重复点击或错靶动作。

### 2.2 必须立即阻断的损害

- 复用打开会话前的旧 cursor 或旧 DOM 行；
- 新完整扫描从当前位置开始，导致顶部新消息永久漏读；
- 切换 `all/unread` 后从旧筛选的当前位置继续，混用两份列表；
- 因当前位置续扫而绕过完整 `conversationRef` 唯一定位；
- 未读插队打断尚未收束的候选人动作链；
- 未读提示或行摘要直接取得发送、建档、状态推进权力；
- 为本轮修复放宽 WAL、idemKey、手证词、服务端正证或 suspect 安全内核；
- 因单次 `nil/0` 采样永久丢失已经观察到的正数未读待办。
- 未经当前页面事实确认就把旧项目空态 selector 直接固化进生产实现；
- 把“页面暂时零行”无条件解释成“未读已经清空”；
- pending latch 没有可达的明确清除出口，导致每轮永久进入未读。

### 2.3 允许重试或人工兜底

- 当前物理窗口暂时没有可解析行：本轮按局部未就绪收束或继续下一次扫描；
- 单个会话移动、消失或身份不能唯一确认：记本轮已尝试并 fresh 继续，不猜目标；
- 页面筛选无法回读为目标公开状态：退出该未读子轮并保留待处理提示，下一完整
  扫描再试；
- 达到共享 `MaxPages`：本轮部分完成，下轮从顶部重新扫描；
- 插件重载、页面丢失或账号登出：继续使用既有终止与人工恢复语义；
- 未读气泡与未读列表暂时不同步：不得围绕同一页面状态形成紧循环。

### 2.4 独立审查预算与后置项

实现后只做一轮定向审查，范围仅限：

- `top/current` 是否在全部调用路径上使用正确；
- 旧 cursor 是否仍有复用路径；
- 未读待处理电平是否可能永久自旋或被静默清除；
- 单条未读局部失败是否仍会饿死后续会话；
- 是否意外改变发送与沟通状态机语义。

以下事项明确后置，不扩张本轮：

- 通用持久化巡检游标、跨重启续扫和优先级队列；
- 第二招聘平台抽象；
- 未读气泡 UI 展示、吞吐统计和支持包；
- 与本次两个根因无关的消息分支、AI 或客户端页面改造。

## 三、第 12 条规范立案

### 3.1 现有约束与缺口

协议规格 §12.6 已冻结：

- 打开会话后旧列表快照与 cursor 作废；
- 未读提示大于零时优先真实选择“全部职位 + 未读”；
- 同一未读轮每个会话最多打开一次；
- 同一完整扫描最多进入一次未读优先轮。

上述约束继续成立。当前缺口有二：

1. `ChatReadListArgs` 没有表达“新快照从顶部还是当前物理位置开始”，脑只能把
   两种语义都编码为空 cursor；
2. 实现把“未读筛选窗口的每一行都必须同步呈现正数 unread”作为硬闸；该要求
   不是协议冻结的公开筛选语义，真机已经观察到打开一行后的正常重排会短暂产生
   零未读行。

### 3.2 拟议规范文本

在协议规格 §12.6 的列表分页语义中追加：

> `chat.readList@1` 的 fresh 读取必须显式声明扫描起点。`top` 表示新完整扫描
> 或切换列表筛选后的首次读取，手须从当前筛选列表顶部建立新快照；
> `current` 表示打开会话或候选人动作收束后，旧快照与 cursor 已作废，但脑仍
> 在同一筛选、同一次完整扫描中继续，手须从页面当前物理滚动窗口建立新快照。
> cursor 只对产生它的同一快照有效；`current` 不授权复用旧 cursor。
> 省略扫描起点时按 `top` 解释，以维持已有调用的保守语义。

并把未读行级判断收窄为：

> 未读优先的页面授权事实是职位范围与未读筛选控件已经通过公开可见状态回读为
> “全部职位 + 未读”。筛选结果中单行 `unreadCount` 是低保真变化提示，不是
> 筛选是否生效、会话是否可打开或动作是否可执行的授权闸；个别行暂时为零不得
> 导致整窗失败，也不得由手静默过滤。脑仍须按 fresh 列表中的完整
> `conversationRef` 唯一处理每一行，并以本轮已尝试集合保证至多一次。

未读调度追加：

> 一旦稳定正数 `unreadTotal` 被脑观察到，脑须把它视为未读待处理电平，直到
> 一次未读子轮取得明确收束事实前，不得被单次缺失、零值或普通列表滚动静默
> 清除。待处理电平只授权在当前候选人动作链收束后的安全边界切入未读子轮，
> 不授权中断命令、重复点击、建档、状态推进或发送。未读子轮中单条局部失败只
> 结束该目标尝试，不能终止后续唯一会话；账号、身份和页面级失败继续服从既有
> 停止语义。

页面空态与传感补充：

> “未读列表完整为空”必须由已经回读为“全部职位 + 未读”的同一页面上，唯一、
> 可见且稳定的公开空态确认；只看到零行、DOM 缺失或读取异常不得推断为空。
> 气泡去抖是基础设施 QoS，持续页面 mutation 不得通过反复取消 timer 让采样
> 永久饥饿。新 SW 请求当前快照时，内容脚本可以强制重发与旧稳定值相同的现货
> 给 SW 缓存，但该快照不得再次上报成业务 `unreadBadge` 事件。

### 3.3 机器契约改动

`ChatReadListArgs` 增加可选字段：

```json
{
  "startAt": "top | current"
}
```

要求：

- 省略等价于 `top`；
- 只影响 fresh 读取；带 cursor 时不得同时声明 `current`；
- 字段保持平台中立，不出现 `scrollTop`、DOM、tab 或智联名称；
- 同一 commit 修改 `contract/contract.v1.json`、协议规格并运行 codegen，
  提交 Go/TypeScript 生成产物与 contract 测试。

甲方已在本计划开工指令中批准上述规范方向；按
“规范与机器契约先行 → 实现”执行，不由同批实现反向授权规范。

1. 删除 `readList(filter=unread)` 与 `openConversation` 对“窗口任一行
   unread=0”的动作前硬闸；
2. 保留并复用“全部职位 + 未读”公开筛选状态回读、目标唯一性和路由绑定确认；

4. 在 GPT Chrome 可用时优先只读确认智联当前公开空态；若连接不可用，只允许

6. 修正气泡采样：已有 timer 不因连续 mutation 反复延期；双读不一致则重新

7. `requestSnapshot` 可把同一稳定值补给新 SW 缓存，但不重复产生 event；
8. 脑侧把已观察到的正数未读锁存为账号身份代际作用域的非持久

9. pending 只在同 generation 的未读 complete 空页确认后清除；读取失败、单条

10. 子轮单个目标的局部失败加入本轮 attempted 集合后 fresh current 继续；
11. 当前候选人动作链未收束时只登记 pending，不中断；
12. 覆盖正数后 `nil/0`、混合零行、单条失败后继续、子轮成功收束、筛选失败保留
   pending 和新轮重新观察等测试；
13. 定向 Go、race、插件 strict 与单测绿色后按“页面边界、传感 QoS、脑侧
    latch”三个独立因果分别提交。

### 批次五：真机验收与事实回写

1. 普通扫描至少处理三个不同会话，观察打开后列表不回顶，滚动位置继续向下；
2. 新完整扫描重新从顶部开始；
3. 有稳定未读气泡时，在当前会话收束后的安全边界进入未读子轮；
4. 未读列表出现零摘要行时不退出，逐个打开本轮唯一会话；
5. 单个目标不可处理时仍继续后续未读，不发送测试消息；
6. 未读子轮收束后退出筛选并继续普通扫描；
7. 将命令数量、不同会话数、回顶次数、未读进入/退出原因以无 PII 口径回写

## 五、回归矩阵

至少覆盖：

1. fresh `startAt=top` 从物理顶部建立快照；
2. fresh `startAt=current` 保持当前物理窗口；
3. 省略 `startAt` 等价于 `top`；
4. 带旧 cursor 的读取不会因 `startAt=current` 获得复用授权；
5. 新完整扫描从顶部开始；
6. `all → unread`、`unread → all` 切换后从新筛选顶部开始；
7. 打开会话后不使用旧 cursor，并从当前位置建立新快照；
8. 已处理前缀不会重复领取，后续会话仍能获得机会；
9. 所有 fresh restart 共享 `MaxPages`；
10. 未读筛选窗口包含零未读行时不会整窗失败或静默过滤；
11. 目标 `conversationRef` 缺失、重复或路由换绑仍拒绝打开；
12. 正数未读后出现单次 `nil/0`，pending 仍保留；
13. pending 只在候选人动作链收束后的安全边界切入；
14. 未读子轮单条局部失败后继续下一条；
15. 同一未读子轮每个目标至多尝试一次；
16. 筛选状态无法回读时退出本次尝试但不静默清除 pending；
17. 子轮明确清空后才清除 pending；
18. 新正数未读最迟在下一安全边界获得处理机会；
19. 连续 DOM mutation 小于去抖窗时，气泡采样仍在有界时间内执行；
20. 新 SW 请求 snapshot 时，相同稳定值会补给缓存但不重复发业务 event；
21. 已确认空态返回空 complete 页，零行但无可信空态仍失败；
22. 清空期间到达新正数会推进 generation，旧子轮不得反向清除新 pending；
23. Manager 重启后 latch 自然失忆，但 snapshot 能让当前正数重新建待办；
24. 所有发送安全内核与沟通状态机既有测试保持绿色。

## 六、预计时间与停止条件

预计总计 **2.5～3.5 小时**，其中新增时间用于闭合未读空态、传感采样与
SW 重启快照，而不是扩张发送或业务范围：

- 计划与契约：20～30 分钟；
- top/current 实现与测试：30～45 分钟；
