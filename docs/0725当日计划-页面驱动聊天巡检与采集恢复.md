# 0725 当日计划：页面驱动聊天巡检与采集恢复

日期：2026-07-25  
状态：已完成（2026-07-25，自动门禁与真机验收通过）

## 一、目标

本计划解决当前 30 人批次停在 `preparing / 0/30` 的直接问题，并把沟通巡检
改成页面驱动：

1. 修正手侧执行预算到期后，因 JavaScript 定时器正常抖动导致
   `EXEC_TIMEOUT_HAND` 被误改写为 `INTERNAL_HAND` 的边界缺陷；
2. 沟通巡检以智联聊天页当前已有的会话列表为调度入口，按页面顺序处理；
3. 数据库只判断页面刚观察到的会话是否有变化、处于什么业务状态，不再先从
   数据库挑一个人，再让插件到上千条会话中全局搜索；
4. 页面当前行需要处理时，直接打开同一轮遍历已经观察到的该行，读取后进入
   既有确定性状态机、AI 建议层和发送安全轨道；
5. 页面/API 单次条件等待最长 10 秒，未就绪只结束本轮观察，不允许占用手侧
   通道四分钟；
6. 页面驱动改造同时收口任务交接：切换到新采集批次后，旧巡检迟到结果仍须
   入账并收束自身；旧任务的局部失败不得反向暂停新批次，账号登出、错账号等
   对当前世界仍成立的全局事实继续沿用既有停机语义；
7. 全部插件改动完成后只重载一次，再恢复当前尚未读取首个推荐窗口的 30 人
   批次。

## 二、已确认事实与本轮边界

### 2.1 当前事故事实

- 一个智联 IM 页加一个智联推荐页是正常现场，不是故障原因；
- 当前完整流程已创建 30 人采集批次，批次仍为 `preparing`，尚未采集成员；
- 旧沟通巡检在新批次创建前已经派发 `chat.readThread`；
- 该读取耗尽 240 秒预算，定时器实际在预算后约十毫秒触发；
- 原本正确的 `EXEC_TIMEOUT_HAND` 因 `execMs` 超过契约字段上限，被二次改写
  为 `INTERNAL_HAND / manualOnly`，随后账号进入 `handManualReview`；
- 产品工作流仍显示 `running / sourcing`，因此首页形成“正在采集 0/30”的
  假运行状态；
- 历史正常 `chat.readThread` 通常只需数秒，当前四分钟不是合理业务耗时。

### 2.2 已拍板取舍

- 不单独优化旧的“按数据库目标全局翻找聊天列表”路径；
- 10 秒读取边界随页面驱动巡检一起落地，不为即将退出的旧调度路径单独补丁；
- 任务交接问题不是本轮前置独立机制，随页面驱动执行边界一并解决；
- 不新增通用取消框架、第二队列、持久化手侧业务状态或新的业务定时器；
- 既有 AI、沟通状态机、WAL、idemKey、witness、服务端正证和 suspect 语义
  保持不变。

## 三、出口与风险预算

### 3.1 最小交付出口

- 预算到期仍明确返回 `EXEC_TIMEOUT_HAND`，不会因数毫秒调度误差升级为
  `INTERNAL_HAND`；
- 一轮正式巡检只处理本轮从页面聊天列表观察到的会话；
- 数据库中存在、但本轮页面列表没有观察到的会话，不得触发页面全局找人；
- 需要处理的会话从当前列表行直接打开，处理后继续页面顺序；
- 页面/API 单次等待在 10 秒内终局，失败时手侧执行槽能够释放；
- 新采集批次出现后，旧巡检不再开启下一条命令，迟到的任务局部失败不暂停
  新批次；
- 自动测试、插件构建、Go 全量测试与真机只读巡检冒烟通过；
- 插件完成一次硬切换后，当前批次能够由用户显式恢复并开始采集。

### 3.2 必须立即阻断

- 打开或读取的会话不是当前页面行所示候选人；
- 页面行身份无法唯一确认，却降级按姓名、头像、列表位置或模糊文本匹配；
- 旧巡检结果丢失、不入命令审计，或破坏已有 effectful WAL 收敛；
- 页面读取失败被反推成“没有新消息”或授权自动发送；
- 页面驱动改造绕过现有状态机、AI 动作裁决或发送安全轨道；
- 插件重载发生在推荐批次已经读取首个窗口之后。

### 3.3 可接受失败

- 当前聊天列表暂时不可读、目标行在交互前发生重排或虚拟列表尚未稳定；
- 单次页面/API 等待 10 秒仍未就绪；
- 本轮只能处理部分页面会话，其余留待下一轮重新从页面观察；
- 当前有人值守阶段偶发可恢复的巡检失败。

上述情况只结束本轮或转入既有保守状态，不得全局搜索数据库目标、猜测页面行、
重复发送或伪造成功。

### 3.4 审查与明确后置

本计划最多一轮定向审查，只检查错会话、重复候选人可见动作、旧结果污染新
批次、执行槽永久占用和账本破坏。

以下内容后置：

- 为非巡检消费者设计通用的跨页面会话搜索能力；
- 多平台沟通列表抽象；
- 无人值守 SLA、巡检吞吐调优和长期性能统计；
- 与本次页面驱动无关的沟通分支扩展。

## 五、批次一：执行预算超时分类修正

1. Dispatcher 仍在原预算点触发停止，不延长 `execBudgetMs`；
2. `ResultBody.execMs` 使用契约允许范围内的诊断值；
3. 定时器晚触发时保留原始 `EXEC_TIMEOUT_HAND`、retryable 与 sideEffect
   语义，不再被结果 schema 校验改写为 `INTERNAL_HAND`；
4. 补充预算恰好到期、晚数毫秒触发和真正非法结果三类测试；
5. 门禁绿色后立即独立 commit。

本批修正的是错误分类，不把超时当成功，也不放宽任何命令预算。

## 六、批次二：插件端页面顺序巡检

优先复用 `chat.readList@1`、`chat.readThread@1` 与现有页面程序，不新增平台
专有脑侧语义。

1. `chat.readList` 从当前页面列表窗口读取有序会话摘要；
2. 脑从该次结果中选择需要处理的会话；
3. `chat.readThread` 只允许打开当前窗口内唯一匹配的已观察行；
4. 当前窗口不存在、身份不唯一或行已重排时，本轮返回未就绪，不启动全局
   `getSessions` 搜索兜底；
5. 读取当前会话历史时，每个关键页面/API 条件最长等待 10 秒；
6. 处理完成后，以本轮已观察身份集合去重并继续下一页面窗口；
7. 页面窗口换代、人工切换会话或草稿存在时，沿用现有保守失败语义；
8. 门禁绿色后立即独立 commit。

若现有原语数据形态不能表达“当前窗口读取”，先按 AGENTS.md 第 12 条提交最小
契约立案；默认方案是不改 contract，只改变智联 program 的生产实现。

## 七、批次三：脑侧页面驱动接线

脑侧调度顺序固定为：

```text
读取当前聊天列表窗口
→ 按页面顺序逐项与消息账本比较
→ 无变化则跳过
→ 有变化则直接处理该页面行
→ 读取消息并归一化为业务事件
→ 确定性状态机裁决
→ 必要时调用 AI 建议层
→ 必要时走既有发送安全轨
→ 继续当前列表窗口或下一窗口
```

约束如下：

- 数据库是事实账本与变化判断依据，不是页面导航目标来源；
- 不得查询数据库得出一个 `conversationRef` 后，要求插件从完整聊天列表搜索；
- 页面列表顺序决定本轮处理顺序，不另建候选人巡检队列；
- 当前轮次的已观察集合只存在脑侧调用栈，不新增持久化游标或第二账本；
- 每位候选人开始前继续复用现有工作流成员闸；
- AI、卡片、面试、微信和普通文本分支均复用现有状态机，不在本批另造分支。

接线与回归测试绿色后独立 commit。

## 八、批次四：任务交接与状态收敛

页面驱动巡检开始时冻结本轮观察到的活动采集批次 ID（允许为空）。每条手侧
命令返回并完成自身命令账本收束后，复读当前活动批次：

- 批次 ID 未变化：继续本轮正常处理；
- 批次 ID 已变化：旧巡检结束，不再开启下一条命令；旧任务的页面未就绪、
  超时和局部定位失败不得修改新批次的账号运行状态；
- 迟到结果若证明账号已登出、绑定账号不一致或其他对当前世界仍成立的全局
  停机事实，继续服从既有安全语义，不得因任务换代而静默忽略；
- 旧命令若已绑定 effectful WAL，仍按安全内核完成唯一意图的判定与收敛；
- 不新增数据库字段、协议 token、取消旁路或跨层恢复框架。

同时保证底层账号若已进入暂停，产品工作流不能永久显示“运行中”；应收敛为
可由用户恢复的状态，并保留同一采集批次和已有事实。

本批至少覆盖：

1. 旧只读/侵入式读取阻塞时启动新采集，启动请求无需等待旧命令四分钟；
2. 旧任务局部失败迟到后，新批次仍为 `preparing/collecting`，账号未被反向
   暂停；
3. 旧结果若证明账号已登出或错账号，仍能暂停当前运行；
4. 旧 effectful 命令仍完成原 WAL 收敛；
5. 底层真实暂停时首页不再假显示运行；
6. 用户恢复后继续同一批次，不创建第二批。

测试绿色后独立 commit。
