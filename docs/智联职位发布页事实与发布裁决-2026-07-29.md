# 智联职位发布页事实与发布裁决(2026-07-29)

本文是"发布职位到智联"能力的**事实门与裁决记录**,不是实现授权。第一节全部为 2026-07-29 经 Chrome 在真实登录态只读考察所得(按 AGENTS.md「页面事实发现顺序」,未新增插件探针);第二节为同日甲方裁决。实现另批立案,届时须按「增量交付、提交与停止纪律」第 1 条先冻结出口。

考察全程未点击「发布」按钮,未产生任何平台副作用;填入的表单内容均未提交,页面刷新即丢弃。

## 一、实机事实

### 1.1 发布页字段与后台「发布参数」对照

发布页 `https://rd6.zhaopin.com/job/publish`。后台 `documents["发布参数"]` 的 12 个必填字段与页面**逐项对得上**,页面另有两个后台未覆盖的选填项。

| 后台字段 | 页面控件 | 必填 |
|---|---|---|
| 工作性质 | 4 个 tab 按钮 | 是 |
| 职位名称 | input,带联想补全(可自由输入) | 是 |
| 职位描述 | `div.jqte_editor`(contenteditable 富文本,**非 textarea**) | 是 |
| 职位类别 | `div.job-subType-input` 弹层 | 是 |
| 最低学历 | 只读 input + 下拉 | 是 |
| 工作经验 | 只读 input + 下拉 | 是 |
| 最低月薪 | 只读 input + 下拉 | 是 |
| 最高月薪 | 选定最低月薪后才渲染 | 是 |
| 薪资月数 | 同上,默认「12个月」 | 是 |
| 工作地址 | 只读 input + 弹层,已预填公司默认地址 | 是 |
| 职位关键词 | 「+」按钮 → 弹层 | 是 |
| 招聘人数 | input,默认 1 | 是 |
| 对求职者展示 | checkbox(在招聘人数行) | 否 |
| 简历同步至同事 | 姓名/手机号/邮箱三输入 | 否 |
| 同步至我的邮箱 | checkbox | 否 |
| (后台无此字段) | 职位亮点 | 否 |
| (后台无此字段) | 职位福利 | 否 |

必填标记可由 DOM 类名 `km-form-item--required` 判定。

### 1.2 取值域(真机已见,下拉完整读取)

| 字段 | 取值 | 项数 |
|---|---|---|
| 工作性质 | 社招全职 / 应届校园招聘 / 实习生招聘 / 兼职招聘 | 4 |
| 最低学历 | 不限 / 初中及以下 / 高中 / 中专·中技 / 大专 / 本科 / 硕士 / MBA·EMBA / 博士 | 9 |
| 工作经验 | 经验不限 / 1年以下 / 1-3年 / 3-5年 / 5-10年 / 10年以上 | 6 |
| 最低月薪 | 1千以下 → 24万(1千至9千每千一档,1万至2.9万每千一档,3万起跳档) | 59 |
| 薪资月数 | 12个月 → 25个月 | 14 |

**值格式与后台一致**:后台存的就是页面选项的字面文本(`"2万"`、`"3-5年"`、`"大专"`、`"12个月"`、`"社招全职"`),填充时按文本精确匹配即可,无需单位换算。

### 1.3 联动与顺序约束

1. **薪资三段联动。** 空表单上薪资行只有「最低月薪」一个控件,DOM 中不存在(连隐藏的也没有)最高月薪与薪资月数节点。选定最低月薪后整行才渲染为 `[最低] － [最高] × [月数]`。
2. **最高月薪上限为最低月薪的 2 倍。** 实测最低选「1万」时,最高月薪可选项为 1.1万～2万共 10 档。**后台 `validate_publish_params` 不校验此关系**,运营可存入平台不接受的组合。
3. **职位类别由职位描述触发自动生成,不需要也无法手动预填。**
   - 只填职位名称、不填描述:等待 3 秒后类别仍为「请选择」;
   - 填入描述并失焦:约 2.5 秒后类别自动填充,并带「推荐」徽标与释义文案。
   - 因此**职位描述必须先于任何依赖类别的检查填入**,自动化中不能把描述放在最后。
4. **职位关键词弹层同样依赖描述。** 描述未填时点击「+」无任何弹层(早期考察一度误判为控件故障);描述填入后点击即正常打开。

### 1.4 职位关键词弹层(结构随职位类别变化)

弹层标题「选择职位关键词,为您推荐『更精准』人才」。**分组数量、分组名称与词库均随职位类别变化**,实测两例:

| | 储备总监(类别=储备经理人) | 财富传承顾问-法税(类别=财务咨询顾问) |
|---|---|---|
| 分组数 | 4 组 | 7 组以上,另有「更多」折叠 |
| 分组名 | 行业经验 / 工作方向 / 证书 / 其他招聘要求 | 行业经验 / 财务管理方向 / 咨询方式 / 管理咨询方向 / 市场调研方向 / 证书·职称 / 其他招聘要求 |
| 行业组词库 | 保险·银行·投资与资产管理·信托·金融科技/数字金融·社会事业与服务·基金·课外培训与资格考试·咨询服务·证券/期货 | 财务/审计/税务·法律·咨询服务·保险·商务服务业·投资与资产管理·银行·技术服务·专利/商标/知识产权 |
| 证书组词库 | 大学英语四级 / 大学英语六级 | FRM·会计从业资格证·CPA(专业阶段通过/全科通过/非执业会员/执业会员)·ACCA·AICPA·CPAA |
| 自动预选 | 预选「保险」(占 1/3) | 无预选(已选 0/11) |

**稳定事实(两例一致)**:
- 总配额 **11**,弹层底部显示「已选: x / 11」;
- 各分组有独立子配额(观察到 3 / 3 / 2 / 3);
- 每组均有「+ 自定义」入口,可输入词库外的词;
- 已选词条可取消(点击已选区词条的 ×,计数即回落)。

**不稳定事实**:分组结构、词库内容、是否自动预选,均随职位而变。因此**关键词的匹配结果无法离线预检**。

**复合词条**:词库存在 `财务/审计/税务`、`专利/商标/知识产权`、`金融科技/数字金融`、`证券/期货` 等以斜杠合并的词条。后台关键词数组中的 `税务`、`审计` 等单词不与之全等。

### 1.5 职位管理列表页

列表页 `https://rd6.zhaopin.com/app/job`。

- 职位名选择器 `a.job-item__title--jobname`,实测提取准确。
- 状态由顶部 tab 区分:**在线中 / 未上线 / 审核中 / 未过审**,tab 文本形如 `在线中 · 2`(无数字即 0),选中态为 `is-active`。
- 顶部「全部职位」下拉是**归属筛选**(全部职位 / 我发布的职位 / 协作给我的职位),**不是状态筛选**。要覆盖全部状态只能逐 tab 遍历。
- 每个职位卡片带操作:在线职位有「修改 / 下线 / 复制」等;未上线职位有「删除 / 修改 / **上线**」。
- **已下线的职位可直接一键「上线」**,不需要重新走发布流程。
- 分页默认每页 20 条;账号显示「可上线职位数 59 个」,存在超过单页的可能。

### 1.6 后台整包中一个职位的结构

`/api/v1/client/job-configs`(`includeDocuments=true`)下发的单个职位:

```
job:              { id, name, environment }
scoring / greeting / communication / intent / silenceFollowup:
                  { prompt, apiKey, model, baseUrl }   ← 每块均携带 provider 凭据
facts / fixedRules:      { content }
fixedPhrases:            { content, scenes: {...} }
documents:               { 11 个 doc_type → 原文 }   ← 发布参数在此
filters / candidateSelection / missingDocs
```

发布参数正文形态(字段名与类型):

```json
{
  "工作性质": "社招全职", "职位名称": "…", "职位描述": "…含 \\n 换行的长文本…",
  "职位类别": "…", "最低学历": "大专", "工作经验": "3-5年",
  "最低月薪": "2万", "最高月薪": "4万", "薪资月数": "12个月",
  "职位关键词": ["…", "…"], "工作地址": "默认", "招聘人数": 1,
  "对求职者展示": false, "简历同步至同事": null, "同步至我的邮箱": false
}
```

`工作地址` 实测取值为字面量 `"默认"`,不是地址文本,含义为沿用页面预填的公司地址。

## 二、甲方裁决(2026-07-29)

### 2.1 职位名来源

发布时填入平台的职位名称**必须取 `job.name`**,不得取 `发布参数.职位名称`。理由与完整条款见 AGENTS.md 相关约定与本仓库 memory;要点是 `job.name` 是系统的职位身份键(旧后台按归一化职位名去重,client/program 两侧按职位名把候选人匹配到职位配置),而发布参数中的职位名称无任何机制保证与之同步,漂移会导致平台职位与后台配置对不上号。

两者不一致时:**照常用 `job.name` 发布、不阻塞**,但须在表格/日志标出提示,让运营看得见 JSON 中该行未生效。

### 2.2 死字段

发布参数中以下两个字段**不参与发布**:

| 字段 | 原因 |
|---|---|
| `职位名称` | 按 2.1 走 `job.name` |
| `职位类别` | 平台按职位描述自动判定,人工不填 |

实测两例中自动判定结果均与 JSON 所写不同(`销售总监`→实际`储备经理人`;`财务经理`→实际`财务咨询顾问`)。预检报告须明确列出"以下字段不参与发布",避免运营误以为生效。

### 2.3 幂等口径

**不依赖任何后台或本地状态,以平台实时状态为唯一真相。**

- 发布前读职位管理列表,**只比对职位名**;
- **同名职位存在即不允许重发**,不区分在线中/未上线/审核中/未过审;
- 名字比对做**归一化**(至少统一全半角括号与空格)。归一化**只放宽匹配、不放宽发布**:判断是否已存在用宽松比较,真发时仍用原始 `job.name`。误判方向因此偏向"以为已存在而跳过",即少发。

不新增任何 client → 后台的写接口;后台不记录发布状态。

### 2.4 关键词处理

1. 打开弹层前**必须已填职位描述**;
2. 打开后**先清空全部已选**(消除平台自动预选带来的配额与不确定性);
3. 展开「更多」,取得全部分组与词条;
4. 对关键词数组逐项,在**所有分组**词条中做归一化后的**全等匹配**,**不拆分斜杠复合词条**(拆分会使 `税务` 命中 `财务/审计/税务`,顺带给职位打上财务与审计标签,超出运营本意);
5. 命中即点选该词条——**分组无须我方决策**,词条属于哪组由平台词库结构决定;
6. 未命中的词走 **「您还有哪些招聘要求？」组的「+ 自定义」**(该组无预设词条,语义上即兜底组);
7. 某组子配额占满时,按数组顺序取前 N 个,**其余丢弃并写入结果记录**,不转为自定义(转了语义即变);
8. 关键词匹配结果**不进预检**(词库随职位变化,无法离线判定),作为发布过程产出记录。

可离线校验的唯一关键词硬规则:总数不得超过 **11**。

### 2.5 客户端流程

1. 一个按钮「全部发布前预检」:手读取职位管理列表,回报平台现存职位名;
2. 客户端按 2.3 口径逐个校验,并附加确定性参数校验(薪资 2 倍上限、关键词总数 ≤ 11、必填齐全);
3. 二次确认弹窗,**默认全选所有可发职位**,可单独取消;不可发的显示原因;
4. 点击「确认发布(共 x 个)」后进入循环发布。

预检结论分三类:**可发布**(默认勾选)/ **平台已存在**(显示不勾选)/ **参数有问题**(置灰并写明原因)。

### 2.6 明确接受的风险

**预检快照与实际发布之间的 TOCTOU 不做防护。** 执行方曾建议每个职位提交前重查一次平台,甲方裁决**不考虑,概率太低**。据此,循环发布期间以预检快照为准,不再逐个复查。本条为知情接受,非疏漏。

## 三、后置项

1. **关键词规律统计(甲方 2026-07-29 提出)**:把平台弹层实际出现的分组与关键词,结合当次发布的 job,上报后台用于统计规律。**该项需要新增 client → 后台写接口,属于当前获准范围之外**,实施前须按「增量交付、提交与停止纪律」第 12 条并列提交旧约束/拟议文本/当前可达场景/收益与成本,获批后方可落地。
2. **职位改版同步**:平台列表每个职位均有「修改」入口。职位配置改版后应走编辑而非重新发布,否则平台会堆积同名职位。本轮不实现,设计上需为其留出位置。
3. **已下线职位的重新上线**:未上线职位卡片有「上线」按钮,较重新发布更合适。当前按 2.3 一律跳过同名职位,不做自动上线。

## 四、未验证事项

1. **发布成功后的可见后置状态形态未验证。** 考察全程未点击「发布」,因此不知道成功后是跳转、弹提示还是其他,也不知道新职位在列表中多久可见。按「成功=发后页面可见」内核,此项必须在实现前或首次真机验收时确定,预期正证为"职位管理列表中出现 name == `job.name` 的职位"。
2. **列表分页处理**:当前职位数未触发分页,超过 20 条时的翻页或每页条数调整未验证。
3. **关键词弹层「更多」折叠**的展开行为与其后的分组内容未逐一读取。
4. **富文本换行**:实测多行文本经真实键盘输入后,`div.jqte_editor` 内首行为裸文本节点、后续行各包一个 `<div>`,隐藏 textarea 同步含标签的 HTML。未验证特殊字符与超长文本(实测最长 194 字可见文本)的表现。
