# 评分与招呼语并行重试裁决（2026-07-28）

## 裁决

甲方原话："效率太低了，大模型生成时，我想改成每20个一批，并行处理，非429错误，最多重试三次，429错误重试次数无限（429是deepseek限速的报错）"；经方案往返后甲方裁决"（inFlight 续驱动）并入本轮"，并在阅看最终出口四项后下达"开工"授权。

据此，采集期两个纯建议类 AI 编排阶段——批次评分（`ScoreCompletedSourcingBatch`）与招呼语生成（`GenerateSelectedSourcingGreetings`）——由"串行 + 单人一次调用定终身"改为：

1. **并发池，上限 20。** 同一批次内成员并行调用 provider，同时最多 20 个在飞，完成一个补一个（甲方原表述"每20个一批"，经确认按等价的工作池语义实现）。批级互斥不变：同一时刻仍只有一个批次在评分/生成。阶段先后顺序不变：评分全批终局→筛选→生成→确认→发送，只是阶段内部成员并行。
2. **三档错误分类重试。**
   - 不可重试，立即终局：HTTP 400/401/402/422、请求构建失败、输入/输出预算阻断、payload 过大；
   - 有限重试：传输失败（超时、连接错误）、HTTP 500/503、模型输出解析失败、reasoning 用量异常——初次失败后最多再试 3 次，短退避；
   - 无限重试，仅 HTTP 429（provider 错误类 `rateLimited`）：指数退避 + 抖动、封顶 60 秒，不占 3 次预算，连续多次时向 stdout 响亮告警。
   依据 DeepSeek 官方文档核实（2026-07-28）：429 = "请求速率（TPM 或 RPM）达到上限"，并发超限亦返回 429；账户并发限额远高于 20。503/500 官方建议"稍后重试"，归入有限重试档；是否升格 503 为无限重试留待真机数据。
3. **每次尝试之间强制查闸**（ctx 停止、用户暂停、业务窗口）。闸关闭时不派发新成员、不发起新尝试，已在飞的 HTTP 自然收束；该成员**留在 inFlight 不写终局**，恢复后从剩余预算继续。任何成员不因暂停/关窗被烧掉机会。
4. **inFlight 续驱动（甲方明示并入本轮）。** 撤销原"预留后未终局的行不授权启动恢复重调"的保守语义：评分与生成两张调用事实表的 inFlight 行（`transportFailed` + FinishedAt=NULL）允许在复跑/重启后被同一编排器接手继续驱动，终局仍写回同一行。顺带修复既有的"进程崩在调用中途→批次永久停在未完成"卡死。依据：这两类调用无候选人可见副作用，重调本质安全，代价只是费用。
5. **账本形状不变。** 一人一行、一个终局、RunID 唯一索引、进度聚合、provider/model 冻结校验全部保留。预留行新增尝试计数（总尝试数、已耗预算尝试数），每次尝试开始先落库再发请求，崩溃保守计为已耗一次预算，3 次上限跨进程成立。

## 四问（防护成本预算第 10 条立案）

- **可达损失**：串行下几十人批次纯评分/生成墙钟各为分钟级，逐日发生；单次瞬时失败（超时/503/解析失败）把候选人永久打成无分/无话术，批内无补救入口，事后受推荐流连续性约束只能重采且不保证捞回同一人。
- **现有覆盖**：零。一次定终身，无任何重试或人工重打入口。
- **最小闭合**：并发池 + 预留与终局之间的重试驱动；不新增独立状态机、不改脑手协议、不碰发送内核；一切失败仍收敛为一行终局事实。
- **总代价**：两个编排器与两张表的改造 + 并发/重试/中断测试矩阵 + 两列增量迁移；最坏调用量约为现状 4 倍（429 请求未被受理且退避封顶，不无界烧钱）。

## 追踪身份（沿用追踪规格 §118 既有口子，不改规格文本）

每次真实 provider HTTP 尝试独立留痕：首次尝试沿用既有稳定裸 invocationID（单次成功场景与现状完全一致），第 N≥2 次尝试使用 `<裸ID>#a<N>` 的 attempt 身份。`brain.db` 终局行保留裸 ID 并记录尝试计数；brain.db 行与裸 ID trace 保持一对零或一关联，attempt 后缀行由业务规定的 attempt 身份解释。

## 安全边界（不变量）

- 发送阶段（`SendSelectedSourcingGreetings`）完全不动：串行、WAL/idemKey/手证词/服务端正证内核照旧。本裁决不授权任何 effectful 动作的重试。
- 脑手协议、插件、契约零改动；沟通阶段（回复/意图/沉默跟进）AI 调用不在本轮。
- AI provider 数据边界不变（请求内容不变，仅并行化）；`ai-traces.db` 原文边界不变，追踪写失败不阻断调用。
- 统一业务运行窗口语义不变：关窗后不开始新尝试，已在飞调用自然收束，成员留 inFlight 次日按用户显式恢复续跑。

## 实现落点

- `client/service/internal/store/models.go`：`SourcingScoreInvocation` / `SourcingGreetingInvocation` 增列 `AttemptCount`、`BudgetedFailureCount`；原"不授权启动恢复重调"注释按本裁决更新。
- `client/service/internal/store/m6_sourcing_score_store.go` / `m6_sourcing_greeting_store.go`：取件查询扩为"无调用记录或 inFlight"，新增尝试计数落库接口；Reserve/Complete 语义不变。
- `client/service/internal/patrol/m6_sourcing_scoring.go` / `m6_sourcing_greeting.go`：并发池（≤20）+ 三档重试 + 尝试间闸检查；公共池/重试逻辑抽为共享实现。

## 出口四项（甲方已批）

1. **最小可交付出口**：上述实现 + 单测覆盖并发上限、错误分类、闸中断留 inFlight、续驱动、崩溃预算计数；`go test ./...` 与 `-race` 绿；真机一轮采集→评分→生成验收通过（有人值守）。
2. **必须立即阻断的损害**：同一候选人双预留/双工作者；重试风暴打爆 provider；暂停/关窗/停止失效；任何触及发送内核或手侧的改动；HTTP 尝试无追踪痕迹。
3. **允许的失败/人工兜底**：预算耗尽成员终局失败、不阻塞批次，人工重采兜底；追踪写失败不阻断调用；极端 429 风暴下批次长时间停留，由人工暂停/结束裁决。
4. **审查与后置项**：冒烟绿即提交，一轮独立 diff 审查；后置项 = 503 是否升格无限重试（真机数据后议）、沟通阶段 AI 同构改造（另行立案）、并发数是否开配置面（另行立案）。
