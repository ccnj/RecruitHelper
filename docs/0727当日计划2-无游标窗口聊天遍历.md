# 0727 当日计划 2：无游标窗口聊天遍历

日期：2026-07-27  
状态：实现、门禁与部署硬切换已完成；真机业务观察待运行窗口内由甲方显式启动

## 一、现场事实与本轮裁决

2026-07-27 真机巡检中，脑在 04:33:17 打开一个普通会话并于约 1.2 秒后成功
读完；紧接着列表分页因 DOM 窗口轻微重排返回 `CURSOR_INVALID`。本轮随后以
`freshListPending` 收束，等待 60 秒，下一轮又固定从顶部开始。相同行为在
下一会话再次出现。

这不是候选人数据、AI、发送或 suspect 问题，而是旧模型把不断变化的虚拟列表
当成可冻结分页快照：

```text
读取窗口 → 生成绑定快照的 cursor → 页面轻微变化 → cursor 作废
→ 结束整轮 → 等待 60 秒 → 从顶部重开
```

甲方据此批准推翻列表 cursor/快照模型，改为：

```text
读取当前可定位窗口全部会话
→ 逐条按 fingerprint 跳过或打开处理
→ 本窗口处理完
→ 向下滚动小于一屏
→ 读取新窗口
→ 重复会话自然跳过，新会话继续处理
```

已确认的页面事实是：打开会话后列表行数与滚动位置保持不变。正式实现不再为
未经证实的“打开一条后列表行消失”假设，在每处理一人后重新读取整个窗口。
当前插件读取的是虚拟列表中已经加载且可由同一定位器操作的 DOM 窗口，通常
多于肉眼严格相交的几行；本轮保留这个字面一致的集合，不另造 viewport
过滤器。

## 二、出口宣言与风险预算

### 2.1 最小可交付出口

1. `chat.readList@1` 不再接受或返回列表 cursor，也不再计算跨命令
   page digest、offset 或连续重叠边界；
2. 新完整扫描、进入未读、退出未读都以 `move=reset` 选择目标筛选、回到顶部
   并读取当前稳定窗口；
3. 一个窗口内的全部会话按页面顺序完成“跳过或处理”决定后，脑才派发
   `move=next`；手向下滚动约 `0.7 × clientHeight`，保留约 30% 物理重叠，
   等页面稳定后返回新窗口；
4. 跨窗口重复 `conversationRef + fingerprint` 是正常现象并直接跳过；
   同一会话 fingerprint 变化后允许在同一完整扫描中重新领取；
5. `complete=true` 只表示到达当前物理列表底部，或普通列表命中既有
   8 天年龄截止；它不表示平台历史永久穷尽；
6. 普通列表继续使用既有列表 fingerprint：未变化则跳过，变化、待收编、
   空账本或到期对账才打开详情；
7. 未读列表复用相同窗口遍历器，但本次未读子轮中尚未打开的每个
   `conversationRef` 必须至少打开一次；业务状态可以跳过，幂等已读动作不能
   因普通 fingerprint 未变而省略；
8. 未读子轮到达 `complete=true` 后记录侧栏总气泡结束基线，切回
   `filter=all,move=reset`；普通扫描已决定过的 `conversationRef →
   fingerprint` 集合保留，同 ref 同 fingerprint 跳过、期间出现新 fingerprint
   则重新领取；后续是否再次插队继续按 0727 已冻结的气泡基线规则判断；
9. 单个目标的 `TARGET_NOT_FOUND`、未读打开未确认等局部失败只记录本目标已
   尝试并继续本窗口后续会话；账号、身份、筛选和页面整体不可用仍按既有
   页面级失败收束；
10. AI、沟通状态机、消息归一化、WAL、idemKey、证词与发送正证零语义变化。

### 2.2 必须立即阻断的损害

- 保存旧 DOM 节点并在页面换代后按位置盲点下一人；
- 以姓名、预览文本或列表序号代替 `conversationRef` 定位；
- 同一未读子轮因重叠窗口重复打开同一会话；
- 单条局部失败中止整批未读，或围绕同一失败目标紧循环；
- 未完整到达未读结束边界却写入气泡结束基线；
- 为遍历重构旁路任何发送安全轨或改变候选人可见动作次数。

### 2.3 允许兜底的失败

- 页面短时未稳定：条件轮询最多 10 秒，仍未稳定则结束当前页面读取，下一轮
  再扫，不推断消息失败；
- 向下滚动未推进且未观察到底：响亮记录页面级“窗口未推进”，不猜测到底；
- 重叠窗口造成额外 DOM 读取与重复 fingerprint 计算；
- 进程重启丢失本轮内去重集合：下一轮从顶部重扫，持久账本和 fingerprint
  最多让系统多核对一次；
- 同一扫描期间消息高速变化：变化后的 fingerprint 最迟由后续窗口或下一轮
  重新领取。

### 2.4 审查预算与后置项

实现后只做一轮独立审查，范围限于：

- `reset → 窗口处理 → next` 是否会漏掉窗口或产生紧循环；
- 普通 fingerprint 与未读 attempted 集合是否各自使用正确；
- 未读基线是否只在完整结束时写入；
- 发送与状态机是否保持零语义变化。

严格肉眼 viewport 过滤、滚动步长配置 UI、吞吐统计、支持包展示和第二平台
适配全部后置。没有真实失败证据时不增加窗口版本、持久恢复槽或新守卫。

## 三、第 12 条规范与机器契约修订

本批是首个真实客户安装前的破坏性契约清理，甲方已直接批准新遍历模型。按
规范先行顺序修改现有 `chat.readList@1`，不新增 @2 或新原语。

### 3.1 `ChatReadListArgs`

调整为：

```json
{
  "filter": "all | unread",
  "move": "reset | next",
  "stopOlderThanDays": "optional; 仅 all，省略默认 8"
}
```

- `reset`：切换并回读目标筛选，回到列表顶部，读取当前稳定窗口；
- `next`：要求筛选仍为目标值，向下滚动小于一屏，稳定后读取当前窗口；
- 删除 `cursor`、`startAt` 和调用方可调的 `maxSessions`；
- 单窗口固定最多 32 项，超过载荷边界响亮失败，不静默丢行。

### 3.2 `ChatReadListData`

保留：

```json
{
  "sessions": [],
  "complete": false
}
```

删除 `nextCursor` 及 `complete` 与 `nextCursor` 的条件规则。跨窗口重复会话是
脑侧去重输入，不是契约错误；单个窗口内重复稳定身份仍视为页面身份异常。

### 3.3 保留边界

- `chat.readThread` 的历史分页仍需要 `cursor/nextCursor`；
- `CURSOR_INVALID` 错误码继续服务线程等真实分页原语，只删除
  `chat.readList` 的生产者与专属说明；
- 历史 `CmdRecord.Args/ResultBody` 按派发时契约作为不可变审计快照，不参与
  新运行，不迁移、不物理删除；
- `listStart` 枚举删除前须证明无其他生产者、消费者或未来占位；
- 同一 commit 修改协议规格、机器契约、codegen 校验并重生成两端产物。

## 五、回归矩阵

至少覆盖：

1. reset 选择目标筛选、回顶并读一个稳定窗口；
2. next 向下约 70% 视口并返回自然重叠窗口；
3. next 到底返回 `complete=true`；
4. next 未移动且未到底响亮失败；
5. all 年龄截止返回 `complete=true`；
6. unread 禁止携带年龄截止；
7. 单窗重复 ref 拒绝，跨窗重复 ref 接受并跳过；
8. 普通同 fingerprint 只处理一次；
9. 同 ref fingerprint 变化后可以重新处理；
10. 同一窗口两个 dirty 会话按顺序全部处理后才 next；
11. 一个普通目标 `TARGET_NOT_FOUND` 后继续同窗下一人；
12. 插队检查只发生在新会话安全边界；
13. 未读一窗多条全部至少打开一次；
14. 未读跨窗重叠不重复打开；
15. 未读单目标局部失败后继续；
16. 未读未到底或页面失败不写结束基线；
17. 未读到底记录基线并以 all/reset 返回；
18. 线程 cursor 分页与 `CURSOR_INVALID` 原样可用；
19. 沟通状态机、AI 与全部 effectful 安全轨既有测试绿色。
