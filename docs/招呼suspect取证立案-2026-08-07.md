# 招呼 suspect 取证立案(2026-08-07 甲方裁决)

## 立案背景

戴相成03 客户机诊断包(2026-08-07)显示 696 次招呼中 37 次未成:22 条
resolvedFailed、4 条 suspect、11 条 USER_ACTIVE。三类成因经数据推定分别为
撞平台每日 100 条招呼上限(07-29 第 101 条起连续 21 条全灭)、平台未接受
发送(散发 5 条)、suspect 后弹窗未关连累后续候选人(08-06,11 条)。但
suspect 现场只有一句固定文案「本轮未取得同一目标的关系已建立正证」,三种
形态在账本里不可区分——撞上限的判据靠的是"恰好第 100 条"这个偶然证据,
不可复制。

## 甲方裁决

1. **取证批准开工**(出口四项经甲方确认):①招呼发送后轮询内捕获平台浮层
   原话与弹窗状态,拼进错误 message;②suspect 后派单帧截图,存本地 blobs
   与事实行,不上报。必须阻断项:取证任何失败改变原判定。允许失败项:
   选择器真机对不上、截图失败,空手而归不重试。
2. **平台页面文本可进 brain.log / handLog 与日志上报**(甲方原话「不用管
   这么严」,系在执行方陈述"会把候选人姓名泄到普通日志和实时上报"后作出,
   知情接受)。执行方固化范围为**取证/诊断用途的平台页面文本**:偶发夹带
   候选人信息不扫描、不过滤,口径与既有"不主动取、不滤掉"同构;不扩成
   "任何页面文本任何用途"。handLog.ts 的"不许塞页面文本"注释纪律保留未动
   ——本方案手侧走 result 正路,用不上 handLog。
3. **取证不得阻塞主线**:浮层捕获寄生在既有 20 轮×250ms 轮询里,零新增
   等待;截图只占该 suspect 成员自身收尾约 1~2 秒,异步派发、独立超时、
   失败即弃,批次照常推进(与 2026-08-05"单成员不确定不挡同批"同源)。

## 真机考古与拒绝判定(2026-08-07 同日追加)

甲方在自己账号上复现违规提示,执行方经浏览器读取真实 DOM,取得决定性事实:

| 事实 | 值 |
|---|---|
| 提示元素 | `.ai-greeting-modal__edit-error`(在 `.ai-greeting-modal__edit-area` 内) |
| 原文 | 「内容中涉及敏感词,请修改」,红色 `rgb(255,80,80)` |
| 节点常驻 | 无错时节点仍在,`innerText` 为纯空白 → 判据须 trim 后判非空 |
| 出现时机 | **点发送后**平台才校验;改动输入会清错误且不重校验 |
| 发送按钮 | 不置灰,照常可点 → 这是「点了却没发出去」的直接原因 |
| 弹窗 | 保持打开 → 08-06 三次拒绝连累 11 人被 USER_ACTIVE 跳过的根源 |
| 关闭控件 | `.km-modal__close-btn`(在 `.km-modal__header`) |

**同时暴露上一批取证的错误假设**:2.0.3 按「提示是页面浮层」设计并明确跳过
弹窗内部,真机实测一个字抓不到(只捞到左侧导航菜单当噪声)。已修正。

据此落地(commit 1e34fbd、b5ceb2e):读到错误位非空即平台明确业务拒绝,按
「可见后置状态原则」判 `GREETING_REJECTED/none`——契约 M4 就为此预留了该码,
脑侧原本全通:命令 failed、意图 failed、**档案 ended 防止重新招呼**、不进
验证轨、不 suspect、批次继续下一人。判定后关掉弹窗止住 USER_ACTIVE 连锁。
平台原话经新增的自由文本字段 `CandidateProfile.GreetingRejectReason` 投影到
客户端,显示成「沟通已结束:招呼失败——内容中涉及敏感词,请修改」。

甲方另据 659 条成功招呼零含「滚」字的统计,判定「滚」是触发词之一(08-06
三条 suspect 的文案都含「一年年往上滚」「越滚越厚」)。根治走后台招呼提示词
禁用该字,不做客户端违禁词库(平台词库私有、不可枚举,维护成本撑不过收益)。

## 挂账

- **真机首验挂账**:拒绝判定与关弹窗按真实 DOM 写就但零次真机出场(甲方页面
  上只读考古,未走我方脑手路径);`debug.capturePage` 同样零次出场。
  km-message 浮层扫描保留作兜底,仍未真机核对(高脆,脆断即空手)。
- **`.ai-greeting-modal__edit-error` 是平台私有类名**,与既有 `__edit-area`、
  `__option` 同族、同脆性等级。它读的是「平台对自己动作接口的公开业务结论」,
  按信任边界条款属合法守卫对象;脆断方向是读不到 → 回落原 suspect 轨,安全。
- **「连续 N 条全灭就停批」单独立案未做**:与 08-05"单成员不冻结同批"裁决
  有张力,待甲方裁决,不混入本批。
- 客户机需装新版客户端并换代插件后本取证才生效。
