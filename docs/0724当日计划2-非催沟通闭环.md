## 一、目标

在现有 M5-B 确定性沟通引擎基础上，优先完成所有不依赖时间推进的实时沟通
分支，并结合已经上线的“处理当前会话一次”入口完成集中真机冒烟。

本计划完成后的产品边界是：

- 候选人已经产生文字、简历、微信或邀面互动后，系统能够按
  `conversationRef → CandidateProfile.BackendJobID → 该职位最新成功配置`
  处理绝大多数已知实时分支；
- 每次真机测试可由真人先在智联打开目标会话，再只处理该会话一次；
- 所有候选人可见动作继续经过既有
  `CommunicationAction → EffectIntent/WAL → idemKey → witness → 平台正证`
  轨道；
- 未知平台事实或前置不完整时明确转人工，不猜测、不冒充成功。

本计划只调整
《M5-B集中开发与集中冒烟裁决-2026-07-23.md》的执行顺序，不修改
《沟通逻辑规格-v4.md》的业务语义。

## 三、实施批次

### 批次一：固定话术中央渲染器

1. 所有固定话术在事件 action 物化时经过同一渲染器；
2. 当前支持从本地候选人事实渲染 `{称呼}`；
3. 渲染完成后才计算最终 `ContentHash` 并进入动作/WAL；
4. 未知占位符、必要值缺失或仍残留未解析占位符时转人工；
5. 不在拒绝、微信或邀面分支分别维护局部替换逻辑；
6. 本批只提供公共渲染能力，不接入任何“催”动作。

完成判据：拒绝、微信回执和邀面回执均可复用同一渲染器，任何字面占位符都
不能进入候选人可见发送。

### 批次二：拒绝分支自动派发

1. 消除当前真实分支中的 `automaticDispatchNotConstructed`；
2. 拒绝正则族与已批准短语短路继续由确定性代码裁决；
3. 挽留、收场、归档及允许的后续微信邀请按 v4 既定顺序执行；
4. 固定正文使用批次一的中央渲染器；
5. 同一业务轮的正文与卡片组合继续遵守既有串行依赖和独立 WAL；
6. 重复处理同一会话不得重复构造 action、intent 或候选人可见消息。

完成判据：真实拒绝消息能形成唯一确定性结果；需要发送时走完整安全轨道，
不再因派发构造缺失转人工。

### 批次三：微信完整闭环

覆盖以下实时分支：

1. 候选人主动发起换微信请求；
2. 我方接受候选人的微信请求；
3. 我方主动发送换微信邀请；
4. 邀请 `pending/accepted/rejected` 状态投影；
5. 微信交换成功固定回执；
6. 可证明的候选人联系方式收编为本地 `ContactAsset`；
7. 重启、重连和重复巡检后零重复接受、邀请与回执。

事实门以 2026-07-24 真机样本为起点：候选人请求已读为
`wechatExchange/pending`；真人点击“同意”后，平台新增 system 消息而不是
直接把原卡片回读成 `accepted`。开工后先只读确认该 system 消息的原始类型
与稳定形态，再按平台枚举面纪律决定映射。

`chat.acceptWechat` 必须规格与契约先行；若当前事实不足以证明动作后的稳定
正证，则停在该能力事实门，不以按钮消失或推测冒充成功。联系方式不得进入
普通日志、审计 detail、管理 API/UI、文档或 AI 请求。

完成判据：微信请求、邀请、接受、拒绝、回执与联系方式收编均有确定性状态和
幂等恢复路径；未知形态保留原始类型并转人工。

### 批次四：邀面实时闭环

1. 普通回复 AI 只提供封闭的“发起线上会议”建议；
2. 确定性代码唯一命中 canonical 推荐时段；
3. 邀面参数固定为：
   - `startsAt = 命中开始时间`；
   - `endsAt = startsAt + 30 分钟`；
   - `method = wechatVideo`；
4. 邀面正文取得正证后，才允许发送邀面卡；
5. 覆盖邀面卡发送、接受、拒绝与未答状态；
6. 接受使用固定回执，拒绝使用规格规定的 AI 回执；
7. 本批不实现面试跟催 1/2/3。

完成判据：从普通对话建议到邀面卡及其即时结果全部进入生产安全轨道，AI
不能决定时长、方式、状态推进或自由动作。

### 批次五：非催分支集中真机冒烟

统一使用正式“处理当前会话一次”入口。真人先在智联打开目标会话，脑只处理
插件现场返回的 `conversationRef`，不读取列表、不搜索或切换其他会话。

至少覆盖：

1. 普通文字连续两轮：意向调用、回复调用和唯一真实发送；
2. 简历投递强意向；
3. 拒绝后的挽留/收场/归档；
4. 候选人主动换微信、我方邀请、接受/拒绝与固定回执；
5. 推荐时段、邀面卡、接受/拒绝与即时回执；
6. 服务态与未知类型转人工；
7. 同一会话重复执行、脑重启和插件重连后零重复。

候选人侧无法即时制造但已有真实历史样本的结果可固化为脱敏 fixture；本账号
能够制造的出站动作必须走正式脑手生产通道。文档、日志和验收报告不记录候选人
PII。

## 四、提交与审查纪律

- 一项因果变化一个 commit，第一条绿色竖切立即提交；
- 固定话术、拒绝、微信、邀面和真机验收分别形成清晰检查点；
- 契约改动与 codegen 产物必须在同一 commit；
- 自动化测试随实现持续运行，真实浏览器冒烟集中在已知分支接通后执行；
- 最多一轮集中独立审查，只修当前可达的重复发送、错靶、账本破坏或长期锁死；
- 普通页面失败、模型输出瑕疵和可恢复边缘问题记录后由重试或人工兜底；
- 批次五出口达到后停止，不顺手开始“催”、批量巡检或其他平台。
