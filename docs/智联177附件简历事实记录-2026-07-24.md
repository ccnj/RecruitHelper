# 智联 177 附件简历事实记录（2026-07-24）

## 1. 目的与边界

本记录只为关闭 `contentType=177` 的平台枚举事实门。探针发生在已登录的 wyl 智联 IM 页面，通过正式“处理当前会话一次”入口只读当前会话；未输入、发送或接受任何消息，文档不记录候选人身份、会话原始标识或简历正文。

## 2. 真机事实

同一条当前会话尾消息同时满足：

- 页面呈现为候选人发来的附件简历卡；
- program 在本轮读取时记录原始类型 `177`；
- 修正前 `chat.readThread` 将其保守归一化为 `system/system`；
- 该消息来自当前候选人、平台状态为成功，并具有稳定的服务端消息身份。

插件重载后的补充只读探针进一步钉死了页面运行时形状：

- 原始行 `type` 是字符串 `custom`，`content` 是字符串；
- 信封 `type` 是**数字** `177`，不是字符串；
- 原始 `row.text` 为空；
- 信封 `fallbackText` 是对象，`receiverText` 与 `senderText` 均严格等于“这是我的附件简历，请查收”，两侧 style 均为 `1`；
- 页面气泡与旧保守投影的规范正文为“您好，这是我的附件简历，请查收”。

插件重载后的 fresh `chat.readThread` 与初始时间线持有相同来源键、时间和消息身份，但历史接口投影提供规范正文，初始时间线投影提供 `fallbackText` 对象；这是同一平台消息的两种已见精确表示，不得要求二者同时存在。

旧日志库存中 30/30 条 `177` 均为同一附件简历语义与固定文案。库存只作形状交叉核对，本次真机事实才是启用映射的授权依据。

## 3. 获准映射

只有下列条件全部成立时，`177` 才归一化为候选人入站 `resumeAttachment` 卡片：

- 原始行类型为字符串 `custom`；
- `content` 是字符串，且信封 `type` 是数字 `177`；
- 解析后的自定义类型为 `177`；
- 发送者等于当前会话候选人；
- 平台状态为 `success`；
- 以下已见正文形状之一精确成立：
  - 历史接口消息正文严格等于“您好，这是我的附件简历，请查收”；或
  - 信封 `fallbackText` 是对象，双方文案严格等于“这是我的附件简历，请查收”，双方 style 均为 `1`。

任一条件不成立仍进入保守 `system` 分支，并保留原始类型到普通诊断日志；不得用“包含简历”等模糊文字猜测。

四条读取/动作前投影必须使用相同语义，并统一输出规范正文“您好，这是我的附件简历，请查收”：`chat.readThread`、发送正文基线、发送正文动作前 evaluator、发送卡片动作前 evaluator。否则同一页面在感知与守卫中会产生不同摘要。

## 4. 既有错误事实的处置边界

本次探针已经把该真机行按旧映射收编为 `system/system`。上线新映射后，不得物理删除、不覆盖来源身份，也不得让新旧摘要冲突后自行重试。恢复须在账号暂停时，以新 `chat.readThread` 正证为输入，严格核对唯一会话尾、同一来源键、正文、时间与无既有沟通副作用，再用一次性维护事务修正派生分类并留下脱敏审计。
