# 智联 177 附件简历事实记录（2026-07-24）

## 1. 目的与边界

本记录只为关闭 `contentType=177` 的平台枚举事实门。探针发生在已登录的 wyl 智联 IM 页面，通过正式“处理当前会话一次”入口只读当前会话；未输入、发送或接受任何消息，文档不记录候选人身份、会话原始标识或简历正文。

## 2. 真机事实

同一条当前会话尾消息同时满足：

- 页面呈现为候选人发来的附件简历卡；
- program 在本轮读取时记录原始类型 `177`；
- 修正前 `chat.readThread` 将其保守归一化为 `system/system`；
- 该消息来自当前候选人、平台状态为成功，并具有稳定的服务端消息身份。

插件重载后的补充只读探针进一步钉死了页面运行时形状：

- 原始行 `type` 是字符串 `custom`，`content` 是字符串；
- 信封 `type` 是**数字** `177`，不是字符串；
- 原始 `row.text` 为空；
- 信封 `fallbackText` 是对象，`receiverText` 与 `senderText` 均严格等于“这是我的附件简历，请查收”，两侧 style 均为 `1`；
- 页面气泡与旧保守投影的规范正文为“您好，这是我的附件简历，请查收”。

插件重载后的 fresh `chat.readThread` 与初始时间线持有相同来源键、时间和消息身份，但两条页面数据通道形状不同。一次性脱敏诊断确认：历史接口投影的信封 `type` 是字符串 `177`，解析后 `details.content` 是规范正文，原始 `row.text` 与 `fallbackText` 均不满足另一形状；初始时间线投影则是数字 `177` 与上述双方 `fallbackText`。这是同一平台消息的两种已见精确表示，不得要求二者同时存在，也不得把字段条件任意交叉组合。

旧日志库存中 30/30 条 `177` 均为同一附件简历语义与固定文案。库存只作形状交叉核对，本次真机事实才是启用映射的授权依据。

## 3. 获准映射

§2 记录的历史接口与初始时间线形态仍是真机事实样本，但不再作为两套业务
授权条件。旧写法把同一枚举在不同数据通道里的序列化与渲染细节误当成了
附件简历语义，造成了不必要的假阴性。

`177` 只有在下列世界状态全部成立时，才归一化为候选人入站
`resumeAttachment` 卡片：

- 原始行类型为字符串 `custom`；
- 信封 `type` 经窄归一化后为整数 `177`：只接受整数 `177` 或规范字符串
  `"177"`，不接受带空白、前导零、小数或相邻类型；
- 发送者等于当前会话候选人；
- 平台状态为 `success`；
- 行具有稳定的服务端消息身份。

经事实门确认的规范化枚举 `177` 本身就是“附件简历”业务语义。`content`
是对象还是序列化字符串、`fallbackText` 双方 style、双方展示文案以及正文
是否带礼貌前缀“您好”，只作为通道观察，不再参与业务授权；也不得改用
“包含简历”等模糊文字猜测未知类型。上述世界状态任一不成立时仍进入保守
`system` 分支，并保留原始类型到普通诊断日志。

四条读取/动作前投影必须使用同一窄归一化语义，并统一输出规范正文
“您好，这是我的附件简历，请查收”：`chat.readThread`、发送正文基线、
发送正文动作前 evaluator、发送卡片动作前 evaluator。否则同一页面在感知
与守卫中会产生不同摘要。

## 4. 既有错误事实的处置边界

本次探针已经把该真机行按旧映射收编为 `system/system`。上线新映射后，不得物理删除、不覆盖来源身份，也不得让新旧摘要冲突后自行重试。恢复须在账号暂停时，以新 `chat.readThread` 正证为输入，严格核对唯一会话尾、同一来源键、正文、时间与无既有沟通副作用，再用一次性维护事务修正派生分类并留下脱敏审计。

## 5. 其他观察

同一轮附近日志还出现原始类型 `368`。本次没有建立它与任何可见消息语义的唯一对应，因此不实现映射，继续保守并记录原始类型。

## 6. 恢复与真实强意向冒烟

新映射部署后，通过正式“处理当前会话一次”入口取得了一次新鲜完整读取。
快照允许含多条前置历史，但尾部附件简历卡必须唯一匹配旧行的来源键、正文与
平台时间。恢复前核对结果为：

- 会话物理账本和活动账本均只有两行：原始招呼与旧分类的附件简历；
- 旧附件简历消息行仍是 `system/system`，会话摘要则已被早先失败轮推进为
  `in/text` 的短文案形态，采纳边界停在招呼行；
- v4 只有一条 `systemNotice` 应用收据，revision 为 1、消息投影游标为 2；
- 不存在 dialogue turn、AI 调用、沟通动作、卡片跃迁、联系方式或时刻表等
  下游事实；
- 账号为 `userPaused`。

一次性本地维护事务只修改旧消息的派生分类、摘要与规范内容摘要，不改变
消息序号、来源键、正文、平台时间、方向来源、首次见到轮次和创建时间。旧
`systemNotice` 收据不删除，只把输入键改为确定性的归档键；聚合 revision 与
状态保持不动，消息投影游标从 2 回拨到 1，为正常的
`resumeSubmitted` 投影释放规范输入键。事务同时写入不含身份、正文和摘要值的
脱敏审计。

恢复首次执行成功；使用同一新鲜证明立即重放得到 `alreadyApplied`，所有事实
零增长。脑重启、插件重连并确认 `contractHash` 一致后，再经正式当前会话
入口处理该附件简历：

- 确定性代码按强意向跳过意向模型，只调用一次回复模型；
- 唯一回复通过既有 action、WAL、idemKey、witness 与平台正证轨道发送；
- 页面出现唯一新增服务端可见正文；
- 对同一会话再次执行后，活动消息、dialogue turn、AI 调用、沟通动作与
  effect intent 全部零增长；
- 验收结束后账号恢复 `userPaused`。
