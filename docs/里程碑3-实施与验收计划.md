# 里程碑 3 · 副作用安全轨道与既有会话发送实施计划

> 状态：执行基线，2026-07-19。
> 上游约束：`AGENTS.md`、`contract/协议规格-v1.md`、`docs/协议设计/A-独立推演.md`、`docs/协议设计/C-感知同步模型.md`、`docs/沟通逻辑规格-v4.md`。
> 真机许可：见 `docs/真实账号测试授权记录.md`。真实账号只做普通招呼/聊天范围内的最小验证；不记录账号、候选人、会话标识或聊天正文。

## 一、目标与边界

M3 只交付一条最窄但完整的真实副作用竖切：**脑对已经收编的会话产生一次明确发送意图，手安全执行 `chat.sendMessage`，系统在断线、Service Worker 重启、脑重启和结果丢失下仍构造性地不双发。**

本里程碑同时让协议中随首个 SX 原语到期的设施全部转正：

1. 手侧持久 journal/outbox 与容量、TTL、清理和拒绝门禁；
2. `query/report` 对账，以及“先补投、再询问、再归类、最后才恢复派发”的重连顺序；
3. effectful guards、idemKey、evidence 和 sideEffect 三值的运行时强制；
4. `chat.readThread` 作为配套歧义恢复读的验证闭环；发送执行期的即时后置观察只读同一实时 Vuex timeline；
5. 脑侧发送意图、会话账本、命令账本和人工队列的原子推进；
6. `chat.sendMessage` 的真实智联实现和一条自然消息的真机验收。

M3 不做新会话招呼、候选人采集、AI 回复、自动沟通状态机、第二平台、云端、授权、更新器、远程 JavaScript 或交付机制裁决。插件仍以编译进 unpacked 包的方式加载。

## 二、安全不变量

以下是不允许用“概率很低”换掉的完成条件：

1. **一个业务意图只有一个稳定 idemKey 和一个原发送 msgId。** 重连、脑重启和验证读不得重铸意图；只有 `report=unknown` 且证词库世代一致给出零副作用证明时，才允许重投原发送信封，不能换 msgId 伪装成新动作。同一意图的成功、suspect 或未裁决记录会冻结再次发送。
2. **不可逆动作前必须先有 attempting 证词。** journal 写入未被确认时不得点击发送；此时失败必须保证 `sideEffect=none`。
3. **成功只等于观察到稳定后置条件。** 点击按钮、输入框清空、乐观 DOM 气泡或只有 client `sendMessageId` 的 SDK 缓存行都不构成成功。发送执行期只认同一可信 live Vue root 的实时 timeline：按有限正 `time` 排序、server `idServer` 首行去重、取 last64 后，相对发送基线严格连续新增且唯一新增的一行必须是成功状态、方向为我方、类型为文本且正文指纹相符；`chat.readThread` 只用于执行外的歧义恢复。
4. **终局先持久化后发送。** SX result 先进入 outbox，再尝试经 WebSocket 上报；脑持久确认后手才删除 outbox。
5. **证词不是第二账本。** journal/outbox 只由 base 投递层访问，只含协议标识和协议消息，有固定 TTL/容量，整体丢失只增加人工频率，不能授权自主行为。
6. **结果未知不盲重发。** `attempting`、`sideEffect=possible`、验证不完整或平台状态矛盾时，一律冻结账号串行域并转验证/人工；不能因为重启、超时或 UI 操作自动换文案、换 idemKey 再发。
7. **验证读是唯一冻结例外。** 未知 SX 冻结该账号新的 intrusive/effectful；只有为消解它而执行的 `chat.readThread` 可占用该命令自己的槽位。
8. **脑不读 evidence 做业务分支。** 自动判定只读契约中的平台无关 data；selector、DOM、tabId、平台专有 ID 只用于 evidence 和脱敏日志。
9. **发送目标必须是 adopted 会话。** 账号身份、hand 绑定、会话跟踪状态、账本尾 guard 或用户静默条件任一不成立，都在不可逆动作前响亮失败。
10. **原语内部不重试。** 一次命令只允许一次不可逆尝试和有界后置观察；重试权只在脑的确定性状态机中。
11. **UI 重载不是新业务意图。** 产品入口在 POST 前只把 intentId 写入会话存储，并无条件从脑恢复该会话 latest intent；新意图创建以 `previousIntentId` 对不依赖 wall clock/rowid 的持久单调 head 做 SQLite 事务 CAS。响应丢失、页面重载、多标签竞争或系统时钟回拨只能恢复同一 current，终局经用户显式确认后才允许下一条。
12. **M3 发送不兼任切会话。** `chat.sendMessage` 只接受已由人打开且稳定的目标会话；自动切换会话以后单独做 intrusive 原语，不得与发送共用 attempting journal。发送前证据不能只证明“页面显示了这个人”；还必须把唯一 live Sender owner、当前 DOM 按钮及其唯一 DOM/VNode/component click listeners、Sender 的封闭会话模型投影和 engine target 收束为同一个结构性目标绑定。不得解析函数源码或猜测静态数据流；任何断点都零输入、零点击。

## 三、恢复状态机

新会话建立后，SX 恢复必须经过以下屏障，屏障完成前不得恢复该手的正常 effectful 派发：

1. 手补投持久 outbox；脑对已持久化 result 回复 ack；
2. 脑只对该手账本中的非终局/待对账命令逐条发送 query；
3. 手从内存与 journal 返回 report；脑在 SQLite 单写事务中归类；
4. 仅对拿到零副作用证明且未超过意图期限的命令恢复同一逻辑意图；
5. 所有待对账项收束后，才打开正常派发。

| 手侧 report / 已有结果 | 脑侧动作 |
|---|---|
| `done`，含完整 result | 按普通 result 的同一原子路径持久化；重复到达只重放 ack |
| `executing` | 继续等待，重置活性观察；不得再发一份命令 |
| `queued` | 原命令仍由手侧队列拥有；继续等待或显式取消，不得重投第二份命令 |
| `unknown` | journal 与内存均无证词且 `witnessStoreId` 与派发时一致时，才是零副作用证明；允许原发送信封最多重投一次 |
| `attempting` | 进入验证读；验证出目标我方消息则补记成功，否则验证封顶后转 suspect，不凭“暂未看见”盲重发 |
| result `failed/precondition_failed` 且 `sideEffect=none` | 按错误矩阵决定失败或同意图最多恢复一次 |
| result `failed` 且 `sideEffect=confirmed` | 按已发生记账，同时保留残余错误供人工处理 |
| result `failed` 且 `sideEffect=possible` | 进入验证读；无法确认则 suspect |
| 无 report 且意图期限到期 | suspect；不自动重发 |

`chat.readThread` 的验证必须覆盖发送前账本锚点之后的窗口。读到目标发送 fingerprint 才可补记成功；未读到只是一条负观测，不自动推导“平台绝对没有发送”，连续三轮仍不能确认就转人工。

## 四、分批实施

### 批次 X0：契约与生成门禁

- 激活 `query/report` 和首个 `chat.sendMessage@1`；
- 冻结 guards、send data、evidence、journal snapshot 与恢复 feature 的唯一 schema；
- codegen 生成 Go/TS 类型、常量、原语元数据和运行时 validator；
- effectful 缺 idemKey/guards、ok 缺 evidence、failed 缺 sideEffect 时必须在发送或受理边界响亮拒绝；
- 明确 `chat.readThread` 是本原语配对验证读，不再新增同义原语。

通过标准：规格、机器契约、生成物和双端 validator 没有重复手写类型；旧手不宣告能力时脑绝不派发 SX。

### 批次 X1：脑侧发送意图与恢复轨道

- 建立平台无关的发送服务入口，输入只包含账号键、conversationRef、自然语言文本和业务 intent；
- 在一个 SQLite 事务中校验 adopted、账号身份/绑定、域冻结和既有意图，创建稳定 logical intent、idemKey 与命令记录；
- result `ok/confirmed` 时原子追加 `origin=self` 的消息账本事实并终结意图；重复 result 不增生消息；
- 实现 pending-reconcile、query/report barrier、安全恢复授权、验证读和 suspect；
- 人工裁决入口在 outbox 补投与对账完成前不可用；迟到 result 赢，并撤销尚未执行的错误人工判断；
- 管理 API/UI 展示恢复状态、验证次数和人工队列，但不得提供绕过产品门禁的 effectful 调试入口；UI 在 reload/多标签下按会话恢复 latest intent，POST 由 `previousIntentId` 事务 CAS 防止同一次人工操作生成第二意图。

通过标准：表驱动测试覆盖恢复矩阵、事务回滚、迟到 result 与人工裁决竞态、同 intent 并发、域冻结和脑重启。

### 批次 X2：手侧证词与 `chat.sendMessage`

- base 独占 storage 访问，启动时清理 TTL、核容量并恢复 outbox；
- dispatcher 在入队前完成 msgId/idemKey 去重，命中 committed 时 duplicate ack 后重放结果，命中 attempting 时绝不再次执行；
- `beforeSideEffect` 是必须 await 的持久屏障；program 无权直接读写 journal/outbox；
- program 在真实页面核验账号、人已打开的目标会话、账本尾、输入框和用户活动 guards；发送组件适配器必须完整遍历并排除 destroyed/inactive/disconnected 组件，证明当前 DOM button、唯一 live Sender owner、唯一 DOM/VNode/component click listeners、封闭会话模型投影与 engine target 一致，关联 form 的按钮还必须显式为 `type=button`；禁止把 `Function#toString`、源码解析或静态数据流猜测作为授权证词；
- attempting 前从同一可信 live Vue root 双采样实时 timeline，冻结有序 last64 source keys、expectedTail、会话版本和 `hash(conversationRef, peerPartnerId)` 目标绑定 token；生产只读预检与 attempting 后的 commit 字面调用同一同步 evaluator 和同一组参数，DOM 只用于唯一控件定位与因果绑定，消息语义只认 live Vuex；commit 写入后由同一 evaluator 完整重投影 source keys，并复核硬截止、账号指纹、owner/model/listener 对象恒等、engine 会话版本和目标 token，绿色返回后立即唯一 click，任一变化都清理自动草稿且零点击；
- 文本输入与点击只执行一次；发送后仍只读同一实时 timeline，只有有序 last64 相对基线严格连续新增一条，且该唯一新行具有成功状态、新 `idServer`、我方方向、文本类型和相同正文指纹时，才生成 data/evidence 并提交 committed；
- 页面丢失、元素不确定、风控、验证码和后置条件超时按执行相位诚实返回 `none/possible/confirmed`；若后置条件已观察但 committed/outbox 双写失败，则不发送易失终局，保留 attempting、熔断已 accepted 执行队列，并经重连 query→验证收束；
- result 先持久化 outbox，发送失败留待重连补投；脑 ack 后幂等删除。

通过标准：插件单测覆盖写盘失败、容量满、TTL、重复 cmd、query 五态、点击前死亡、点击后死亡、committed 后死亡、result/ack 丢失和 SW 重生。

### 批次 X3：端到端故障矩阵

用正式 Dispatcher、真 Go 脑、生产 Connection/Dispatcher/program 接缝执行自动化故障矩阵。故障注入只存在于测试依赖中，不得形成生产“测试模式”。

至少覆盖：

- ack 前断线、ack 后执行前断线；
- attempting 写入前失败、写入后点击前死亡、点击后观察前死亡；
- committed 后 result 未发、result 已发但 ack 丢失；
- SW 同 boot 重连、新 boot 重生、脑进程重启和双方连续重启；
- query/report/outbox 各自重复、乱序、丢失和超时；
- 验证读命中、三轮不命中、截断/游标错误和账号身份变化；
- 相同文本历史消息、真人同时输入、会话切换、平台限流/验证码；
- 任一故障下“平台可见发送次数 ≤ 1”，且脑账本最多一条 `origin=self`。

### 批次 X4：真实 Chrome 最小验收

自动化全绿后，只对当前已登录且身份匹配的真实智联账号执行：

1. 选择一条已经 adopted、允许普通聊天的会话，并由人在智联页面打开它；
2. 确认路由、唯一可见编辑器、可信 Sender 结构链、engine target、实时 Vuex 双样本基线和目标绑定 token 同时指向该会话，且没有验证码、风险提示、账号错配或真人正在输入；左侧列表在线状态样式不作为发送目标证据；
3. 经正式脑端发送入口发出一条自然消息，默认文案为“你好”；
4. 页面确认仅出现一次，脑侧命令、意图和消息账本各只有一个终局；
5. 随后重连/重启并执行 readThread 对账，确认不产生第二次发送；
6. 停止当天 actor 和临时服务，不让真实账号继续自动运行。

真机不拿多个可见消息制造故障样本，也不在真实账号上做点击前后强杀。强杀、结果丢失等组合由确定性自动化 harness 覆盖；真实账号只证明真实页面的 guard、单次发送、实时 timeline 后置观察与恢复读成立。

## 六、停止条件

出现以下任一情况立即停止真实副作用测试并保留证据，不尝试“修一下再点一次”：

- Chrome 当前账号与脑绑定身份不一致或不可核验；
- 登录失效、验证码、风控、平台限制、付款或权限提示；
- 目标会话不是 adopted，账本尾无法与页面对齐，输入框已有真人未发送内容；
- journal/outbox 容量或持久化异常；
- 自动化故障矩阵、全量回归或隐私扫描未通过；
- 第一次点击后的后置条件无法确认。

最后一项只允许进入验证读和人工队列，不允许再点击一次。
