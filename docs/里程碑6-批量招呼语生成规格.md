# 里程碑 6：批量招呼语生成规格

日期：2026-07-22

状态：甲方已批准《端到端业务主线计划》中的“批量生成招呼语”阶段；本文把当前正式配置与既有 AI 纪律收窄为最小可执行语义，不进入列表定位或发送。

## 一、出口与风险预算

入口只接受一个已经完整筛选的正式 `batchId`。系统只为该批 `selected` 成员使用批次冻结 revision 中的后台“招呼语”原文生成正文，并把每位成员的唯一调用终局与正文业务事实持久化。

本阶段必须立即阻断：跨批或错 revision/profile/run 材料、非 `selected` 成员进入生成、同一成员重复调用 provider、非法输出被当作正文、API key 或候选人正文进入日志/管理响应。provider 的普通网络、预算、拒绝和解析失败允许形成明确终局，由后续人工或另行立案处理，不在本批自动重试。

独立审查限一轮。列表定位、平台页面动作、`CandidateGreetingHead`、`EffectIntent`、effectful command 与真实发送全部后置到“列表直接发送”阶段。

## 二、事实输入与模板

1. 本阶段只消费完整 `SourcingBatchSelection` 及 outcome 为 `selected` 的逐人决策；每条决策必须绑定仍为 `selected` 的唯一 CandidateProfile，且 run、profile、batch 的平台、账号、职位和 revision 全部一致。
2. prompt 只从批次不可变 `legacyJobConfig` revision 的“招呼语”文档取得。当前正式 revision 已确认 `usePlatformDefault=false`，两个活 token 恰为 `{career_state}` 与 `{resume_summary_json}`，且各出现一次。未来 revision 若为 `usePlatformDefault=true`，本入口响亮拒绝并重新裁决，不静默改用平台默认话术。
3. `greeting-input-v1` 把采集快照投影为旧客户端同形的中文对象：`基本 / 期望 / 自评 / 工作经历 / 教育经历 / 简历全文`。只保留页面实际观察值；`工作经验→工作年限`、`现居地→现居`；当前没有独立“简历全文”事实，固定为空串。招呼阶段沿用旧业务的完整结构化章节，不对自评、工作或教育正文静默截断；若渲染后越过 P 档输入边界，直接形成 `budgetBlocked` 终局。
4. `{career_state}` 取同一投影中实际观察到的 `求职状态`；缺失时填空串，不猜测。`{resume_summary_json}` 使用确定性 JSON。不得另行注入 `displayName`，但简历正文自身已经观察到的姓名、电话等自由文本按既有甲方授权可以随简历出站。
5. 除 prompt 与上述两项输入外，请求不得携带 platformUserRef、accountRef、positionRef、profileId、resumeNumber 或任何内部随机引用。provider/model/base_url/key 继续来自客户端本地配置，旧后台只提供业务 prompt。

## 三、模型调用与输出

1. 新增独立用途 `greeting`，仍走既有 OpenAI-compatible provider、`thinking=disabled` 和 P 档预算；不得借用意向或多轮回复的业务输出语义。
2. 每位入选成员在网络调用前先持久化唯一预留。唯一性锚定本批 selected run/profile；只有首次插入者获准调用 provider。成功、provider 拒绝、传输失败、预算失败、非法输出均为终局；HTTP 重跑和进程重启不授权第二次调用。
3. 当前正式 prompt 声明 JSON 输出。解析器只消费唯一、非空字符串键 `招呼语`；`需求点 / 需求点置信度 / 用到的简历事实 / 字数` 等分析字段丢弃，不持久化，不继承旧客户端 `greeting/content/text` 的宽松别名。
4. 正文先做 Unicode NFC 与首尾空白规范化，再通过既有发送正文边界：有效 UTF-8、非空、最多 2048 bytes。成功调用还必须通过非思考用量闸；任一正 reasoning token 或非空 `reasoning_content` 都改记 `invalidOutput/reasoningUsageUnsafe`，不保存正文。

## 四、持久化与恢复

新增 `SourcingGreetingInvocation` 业务事实，以 invocationId 为主键，并分别唯一约束 run 与 profile。保存 batch/run/profile 随机引用、revision、run content hash、provider/model、输入输出 hash、状态、合法正文、脱敏 token/费用/延迟/error class 及起止时刻。

正文属于本地建议业务事实，可以持久化；不得物理删除。普通日志、审计、管理 API 与验收报告只允许聚合计数、provider/model、hash、token、费用、时延和错误分类，不得返回正文、简历、prompt、候选人身份或逐人引用。

启动恢复把 `finishedAt=NULL` 的招呼调用收敛为 `transportFailed/processInterrupted`，不再次触碰 provider。完整终局可以重放读取；任何同一唯一键但 revision、content hash、provider/model 或输入 hash 不同的材料均响亮冲突。

## 五、批次编排与管理投影

批次按 `capturedAt ASC, runId ASC` 串行处理所有 selected 成员。入口在每次预留前重读批次筛选、逐人决策与档案状态；全部成员成功或失败终局后，批次招呼生成状态才是 `completed`。

管理端只返回 batchId、revision hash、selected/ok/failed/in-flight/pending 计数、冻结 provider/model、聚合 token 与费用、completed；不得返回 profile/run/invocation 明细或正文。重复 POST 对完整批次只返回既有聚合结果，provider 调用数与正文行数不增加。

## 六、自动化与真实出口

自动化门禁至少覆盖：批次未筛选或筛选不完整、跨批/revision/content/profile 绑定、非 selected 排除、输入投影与 token 白名单、唯一预留、成功/各类失败终局、非法/超长正文、非思考用量闸、中断恢复不重调、完整重放以及管理投影隐私，并证明 hand、greeting head、EffectIntent 与 effectful command 均未增加。

首个真实 3 人批次当前只有 1 位 selected。该成员用正式后台 prompt 生成 1 条合法正文，重复运行零增生，且全程零平台动作与零发送，即为本阶段出口。达到后单独提交脱敏冒烟记录，再进入“列表直接发送”。
