# 巡检单人错误隔离裁决（2026-07-27）

## 裁决

甲方原话："我希望轮询时某一个人不管发生了什么错误，都不能整个停掉，而是跳过继续跑下一个"；后续明确"我记得我想改这一点就是因为洪建辉出错，然后其他也停了……一人出错，跳过即可，不要影响其他人"，并批准出口四项后下达开工授权。

据此，巡检中**单个候选人处理失败不再停掉整个账号轮**：

1. 会话级错误只隔离当事人（会话打巡检隔离标记 + 有档案聚合则同时挂 manualRequired + 首次隔离留响亮审计），轮继续处理其他人。**洪建辉式源身份/哈希冲突从"暂停整个账号"改为"隔离该会话"**——这是甲方点名要改的场景，即使病因可能是全局的（解析语义变更会逐个命中带旧卡的人），甲方知情选择"逐个隔离多次解冻"优于"全账号停摆"。
2. 账号级信号维持全停：登录丢失、账号身份不符/不可确证、真人活动让位、日窗口到期、采集批次换代、进程退出。这些不是"某一个人出错"，是"接下来每个人都会失败或可能发错账号"。
3. 被隔离会话静躺等人工：人工解除标记前，巡检不再自动打开、对账或推进该会话（不消耗候选人闸、不做侵入式重读）。解除后允许下一次正常对账；再次失败会重新隔离。
4. 隔离动作本身写库失败时无法安全隔离，维持轮级失败。

## 错误分类表（不做字符串猜测）

| 判据 | 分级 | 处置 |
|---|---|---|
| 账号级信号（accountMismatch / loginRequired / identityUnverified / USER_ACTIVE / 窗口 / 换代 / ctx 取消） | 轮级 | 全停（既有语义） |
| 手侧 `TARGET_NOT_FOUND`、`POSTCONDITION_UNCONFIRMED` | 瞬时 | 本轮跳过（沿既有语义；retryable 描述命令不描述人） |
| 手侧 retryable = `yes` / `afterRecovery` | 瞬时 | 本轮跳过，下轮自然重试 |
| 手侧 retryable = `no` / `manualOnly` | 确定性 | 隔离该会话 |
| 脑侧例外：`ErrConversationVersionConflict`（与事件摄入的良性写竞争）、`ErrAdoptionSnapshotEmpty`（活页面观察异常） | 瞬时 | 本轮跳过 |
| 其余脑侧错误（源身份冲突、不安全修正、V4 投影冲突、状态机异常等）与一切未知错误 | 确定性 | 隔离该会话 |

默认方向的理由：把确定性误判成瞬时=每轮白错一次、永远静默；把瞬时误判成确定性=当事人被冻结+响亮审计、人工一步恢复。错误方向必须选"可见但要人动一下手"。

## 留痕

- 瞬时跳过：当场一行 slog（会话 ref + 错误类别）+ 轮收尾一条 `patrol_transient_skips` 汇总审计（条数 + ref:类别 列表，有界截断）。
- 隔离：`patrol_conversation_quarantine` 审计（仅首次打标写，避免每轮刷同一事实）+ 当场 slog。审计与日志只含 ref 与错误类别，无候选人身份、无正文、无等值键。
- 隔离原因固化在 `conversations.patrol_quarantine_reason`（`patrolQuarantine:<类别>` 前缀），聚合 manual_reason 同值。

## 安全边界（不变量）

- 隔离**不取消已发 effect 的 WAL 判定与收敛义务**：effect 恢复轨在 dispatch 层按 CmdRecord/手维度独立运行，不经过巡检的档案枚举；`DialogueTurnDispatching` 仍归持久恢复轨所有。
- 隔离/跳过前复核 `ensureDispatchAllowed`：手离线、账号暂停、窗口关闭、批次换代等环境级故障不得记到当事人头上，改按轮级失败处理。
- 安全内核（WAL/idemKey/手证词/服务端正证）不受本裁决影响；隔离只是"不再自动开始新的处理"，不回滚、不重试任何已有事实。

## 实现落点

- `client/service/internal/store/patrol_quarantine_store.go`：会话隔离标记（`patrol_quarantined_at` / `patrol_quarantine_reason`），幂等打标 + 人工解除方法。
- `client/service/internal/patrol/failure_scope.go`：分类器、`settleConversationFailure`、隔离动作、瞬时汇总审计。
- `client/service/internal/patrol/round.go`：全量与未读两个循环体接线；认领时跳过已隔离会话；`convergeReconcileFailure`（冲突→暂停账号）删除；`handleCommandFailure` 的 manualOnly 账号暂停只保留给账号/页面级命令（probe、readList 等）。

## 边界与后置项

- 批量 ensure 步骤（收编、V4 建根、采集上下文/简历复用）已各自容忍已知业务冲突（审计+continue）；其余未知错误属基础设施级（库故障会打到每个人），维持轮级失败，不属于"单人错误"。
- `manualCurrentConversation` 真人显式入口只处理一个人，无"跳过继续"语义，失败照常上报，不自动隔离。
- 解除隔离当前靠 `ClearConversationPatrolQuarantine`（store 方法，测试已钉）；面向甲方的解冻工具/入口后置，生产首次出现隔离时再按当时事实立案。
- 若未来发生"全局病因逐个隔离多人"的实况，重新评估是否需要跨会话聚类告警；本次不预建。
