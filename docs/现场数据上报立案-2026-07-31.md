## 2. 现状事实（本机实测，2026-07-31）

## 3. 撞上的旧约束（逐条）

### 3.1 云端出站白名单——必须加第五项

AGENTS.md 开篇列了四项获准出站：旧后台 bind/job-config、LLM provider、运营通知 webhook、客户端版本更新源，末尾一句「除此之外仍视为不连云端」。上报是第五项，没有别的解释路径。

两条现成通道都明确堵死了复用：旧后台那条写着「不得因此接入 verify/heartbeat/session/task/metrics/alert 等其他控制面或**上报接口**」；更新源那条写着「该通道单向只读，不得复用于**任何上报**、遥测、控制面或配置下发」。

（在同一台服务器上另开一个端点不算「复用更新源通道」，是新通道。但它仍然是第五项出站。）

### 3.2 `ai-traces.db` 的远程禁令——最重的一条

AGENTS.md「AI provider 数据边界」：

> `ai-traces.db` 原文不得经普通日志、`brain.db`、管理 API、验收报告或**任何远程渠道**暴露。

「任何远程渠道」没有留缝。要传 `ai-traces.db`，这句必须改。

### 3.3 候选人明文出本机——第一次

现有的两条明文授权都把边界收在同机，逐字如此：

- 「同机产品 UI 业务投影例外」：前端「不得把这些响应写入 localStorage、IndexedDB、普通日志、错误上报、**支持包或导出文件**」。
- 「开发者 SQL 控制台例外」：「边界仍然收在同机……不得进入普通日志、审计 detail、stdout、**支持包**、验收报告、运营通知 webhook、旧后台、AI 请求或**任何远程渠道**」。

微信号另有单独一条白名单，只允许存在于五个位置（原语 result、手侧 journal/outbox、`CmdRecord.ResultBody`、权威 `ContactAsset`、webhook 正文），并明确「不得进入 evidence、错误详情、stdout、普通日志、审计 detail、管理 API/UI、报告或 AI 请求」。

**「支持包」这个词在 AGENTS.md 里出现三次，三次都是禁止或后置**，其中一次直接写着「滚动日志、**支持包导出**、追踪清理与查看 UI 均后置，不属于本次授权」。本功能就是支持包导出。

### 3.4 截图 JPEG

「除本 webhook 外不得出本机」。`blobs/` 只有 724KB，但禁令是四条里最直白的。

### 3.5 日志本身——唯一没有阻力的一项

按规范，普通日志不含 key、聊天正文、简历正文、完整 prompt、候选人明文身份。`main.js:29-30` 的注释也重申了这点。**所以只传 `brain.log` 不触碰任何数据边界禁令，只需要「新增第五项出站」这一项授权。**

这是本立案里最重要的一个分界：三样东西的规范阻力差一个数量级，不该打包成一道是非题。

### 问题二：明文 http 怎么办

服务器是 IP、只有 http。旧后台明文传 key 甲方已知情接受（那是一个 key），但这次是**整库候选人明文过公网**，量级不同，单独拍板。

| 选项 | 成本 | 结果 |
|---|---|---|
| A. 就走明文 http | 0 | 候选人姓名/微信号/聊天正文/简历明文过公网 |
| B. 上传前用固定公钥加密 | 约 40 行，**零新依赖**（标准库 `crypto/ecdh` X25519 + AES-256-GCM） | 公网传密文；服务器上存的也是密文；私钥只在我方本机，解密在本地 |
| C. 服务器上 TLS | 自签证书 + 客户端固定指纹；IP 签不了 Let's Encrypt | 传输加密，但服务器上仍是明文落盘 |

**甲方裁决 2026-07-31：选 A，就走明文 http，不加密。** 执行方已陈述后果（候选人姓名、微信号、聊天正文、简历正文明文过公网，且在服务器上长期明文留存），甲方知情接受，与旧后台明文下发 key 同类处理。

**这个选择的直接后果，必须在实现与验收里当硬约束：** 问题三里「接收目录在 web root 之外」原本是三重保险之一，现在是**唯一的保护**。一次 nginx 路径配错、一次把上报目录挪进 `/srv/console/`，候选人全库就是公网可下载。因此该项列入第 6 节「必须立即阻断的损害」，并要求部署后实测验证——从外网 `curl` 上报目录必须拿不到东西，不能只靠配置文件看起来对。同理，服务器上的包是长期明文留存物，留存期限清理虽在后置项，但首个真实客户交付前必须重新裁决（已写入拟议文本）。

### 问题三：服务端接收怎么做（唯一不在本仓库的成本）

nginx 静态目录不能 POST，必须新增接收端。

| 选项 | 对旧后台的侵入 |
|---|---|
| A. 旧后台加 `client_reports.py` 接口 | 要放宽两条裁决；发布会重启给存量客户服役的进程 |
| B. 同机独立进程 + nginx location | 旧后台代码零改动，只 reload nginx |
| C. 完全独立，另开端口 | 对旧产品零接触，多一个对外端口 |

**甲方裁决 2026-07-31：选 A，在旧后台加接口。** 执行方已陈述代价（需放宽下述两条裁决；每次发布会重启 `console-server.service`，而该进程正在给 AutoZhilian 的存量客户服役），甲方知情接受。

**这项裁决要放宽的两条**，都在 AGENTS.md 开篇：

1. 「旧后台（xq-resume-backend）在客户交付前仍不改动」——加接口就是改动。
2. 「不得因此接入 verify/heartbeat/session/task/metrics/alert 等其他控制面或**上报接口**」——上报接口被逐字点名。`app/api/` 下现存的 `client_metrics.py`、`client_alerts.py`、`client_sessions.py`、`client_ai_model_logs.py` 正是这条列举的那几个，它们服务旧产品，本次仍不接入、不复用。

## 5. 若获批：技术方案

### 5.1 脑侧

新增 `client/service/internal/report`：

- **`brain.db` / `ai-traces.db` 快照用 `VACUUM INTO`**，不能直接读文件。两个库都是活跃 SQLite 且 `brain.db` 有 4MB WAL 未 checkpoint，直接拷会拿到不一致的库。`VACUUM INTO` 已在本机验证可用（SQLite 3.27+，glebarez 纯 Go 驱动支持）。
  - **副作用要说清楚**：`brain.db` 的连接池是 `SetMaxOpenConns(1)`，VACUUM 期间会占住那唯一连接，60MB 库大约几秒，这期间业务写排队。建议在没有活跃工作流时点这个按钮；几秒卡顿本身不会破坏任何账本，但值得在页面上写一句提示。
- **打包**：白名单收集 → tar+gzip。按裁决不加密。全程走临时目录，传完即删——本机临时目录里躺着一份候选人全库明文，收尾要确定性删除（含失败路径的 `defer`）。
- **上传**：一次 POST，写死超时（建议 120s），成功/失败原样返回给页面。**不建发件箱、不建重试队列**——AGENTS.md「新增跨层机制立法四问」明确禁止无证据的通用框架，这里失败了人再点一次就是了。
- **上传**：`multipart/form-data`，带上 `licenseToken` 与客户端版本。客户身份由服务端从 token 解析，客户端不自报客户名——比传 `jobconfig.CustomerName` 更可信，也少一个能被本机配置写歪的字段。

### 5.2 端点与页面

- `POST /admin/dev/report`，走既有 `/admin/*` loopback + admin bearer，与 SQL 控制台同轨。handler 不记录包内容。
- 诊断台第 7 页。`ConsoleSidebar.tsx` 加一项，`pages/` 加一个组件——`DevToolsPage.tsx`（108 行）是最省的参照。页面元素：一个按钮、一行进度、一行结果（包大小、耗时、服务器回执 id）。失败显示原因。

### 5.3 服务端（旧后台，不在本仓库）

在 `xq-resume-backend` 上按它自己的分层硬约定落位，分支 `dev-wmt-0703`（该仓库 CLAUDE.md：本方改动不动 `main`）：

- `app/api/client_reports.py` — 新 router，挂 `/api/v1/client/reports`，在 `routes.py` 注册。鉴权走 `licenseToken`（与 `client_auth.py` 同轨），**不是** admin token。
- `app/services/` + `app/db/*_repository.py` — 按该仓库约定，SQL 只许在仓储层。
- **上传实现照抄 `admin_releases.py:98` 那段**：1MB chunk 流式落盘、边写边算 sha256、DB 只存元数据不存文件本体。15–20MB 的包不该进 PostgreSQL。
- 新 migration 存元数据表（客户、客户端版本、上传时刻、字节数、sha256、落盘路径）。**必须幂等可重复执行**——该仓库 `scripts/migrate.py` 不记录已执行版本，每次全量重跑；编号从现有最大号往后排（历史上撞过两个 `0012_*`）。
- 新环境变量 `REPORTS_ROOT`，**默认 `/var/lib/console-reports`**，systemd unit 里显式设置。不要沿用 `UPDATES_ROOT` 的路径习惯（理由见问题三）。
- 测试按该仓库风格：unittest + 内存仓储替身，不连真 PostgreSQL。
