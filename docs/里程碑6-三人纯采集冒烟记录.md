# 里程碑 6：三人纯采集冒烟记录

日期：2026-07-22

## 范围与出口

本轮只验证正式旧后台职位配置下的最窄批量采集竖切：脑连续采集 3 个不同候选人，为每人保存稳定候选人人根与独立简历快照，随后关闭详情。采集阶段不得调用评分、选人、建档、招呼或 IM 对账。

本轮使用 `legacyJobConfig` 正式配置快照，配置修订摘要为 `cfbba4f16c895ea065cd1d3047a6ecd2941d93cddf14c698a35cbb720bb9752c`，包含 10 份后台文档。真机推荐页已切换到该配置对应职位。

## 实现检查点

1. `b7e34c3` / `7589fe4`：规格与实现统一为“采集结束即关闭本命令打开的详情”；只有确认弹框消失且 URL 已清除 `resumeNumber` 才返回成功。
2. `9d825eb`：采集事务只建立稳定 Candidate 人根，不提前建立 CandidateProfile。
3. `3f4e666`：actor 拆除逐人内联的评分、筛选和固定“你好”招呼，采集阶段只落采集事实。
4. `dbd2825`：纯采集轮完成一次采集后立即退出，不再继续进入 IM 列表或线程对账。
5. `8665863`：采集不再依赖推荐页恰好位于前台焦点；手在全部匹配标签中只接受唯一推荐页，零个或多个时停止，不猜测目标。

## 真机序列

1. 重载插件并确认手与脑 `contractHash` 一致。
2. 在唯一智联推荐页启动采集，冻结同一份后台配置修订。
3. 脑依次派发 3 次 `candidate.readSourcingResume`；每次均取得完整简历、原子写入采集事实，并确认详情已经关闭。
4. 第 3 条采集事实落库后立即暂停账号调度。
5. 通过只读聚合查询核对采集、评分、筛选、档案、命令 WAL 与副作用意图。

## 冒烟中暴露并修复的事实

- 初版纯采集路径仍会在采集后继续 IM 对账，导致推荐页被导航离开。修复后采集轮只执行一次采集并退出。
- 初版手只检查当前焦点标签；用户切到其他窗口时会把仍然存在的推荐页误判为缺失。修复后在全部匹配标签中寻找唯一推荐页，仍不放宽错靶边界。
- 以上早期失败均发生在读取或页面准备阶段，没有落入本批 3 条成功事实，也没有创建评分、档案或副作用意图。

## 结论与边界

“正式后台配置 → 3 个不同候选人 → 独立采集事实 → 详情逐次收口”的真实生产路径已绿，并且采集阶段已构造性隔离评分与发送。

本记录只证明当前推荐页首屏的小批量冒烟，不宣称已经具备 150 人正式批采能力。进入大批量采集前仍需独立实现批次实体/目标数、全批去重、职位绑定、后台筛选条件应用，以及虚拟列表滚动与耗尽语义；当前最多 32 项排除集合也不能作为正式批次去重机制。下一批次应先补齐这些批采基础，再进入统一评分。
