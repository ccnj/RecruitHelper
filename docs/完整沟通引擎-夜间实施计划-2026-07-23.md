# 完整沟通引擎：夜间实施计划

日期：2026-07-23

状态：甲方已在 Codex 任务中明确批准，允许按本计划夜间独立执行。

## 一、目标与最小出口

基于现有 M4/M5 实现继续扩展，不重写已经验收的候选人档案、消息账本、AI provider 与发送安全轨道。本轮建立可执行的主线：

`message ledger -> normalized business event -> deterministic communication reducer -> AI suggestion -> unique next action`

夜间完成出口：给定一段合法的候选人入站消息账本，系统能以平台无关、可重放、不重复构造动作的方式得出唯一下一步沟通决策；主要纯脑侧分支有自动化事件序列回归。

## 二、信任源与读取顺序

1. `AGENTS.md`：最高工程、安全、提交与文档纪律。
2. `contract/协议规格-v1.md`：脑手语义、证词、验证与 suspect 边界。
3. `docs/沟通逻辑规格-v4.md`：沟通状态、分支、时刻表、停止与归档的业务依据。
4. `docs/平台枚举面清点-v1.md`：本轮必读的平台消息枚举与真机/库存证据基线，不作普通参考材料降格处理。
5. M4/M5 计划、验收报告与批次事实记录：实现基线。
6. `docs/端到端业务主线计划-2026-07-22.md` 与 `docs/冒烟冲刺裁决-2026-07-22.md`：阶段衔接与当前风险预算。

旧项目代码、`to-check-logs` 和真实智联聊天只是考古与事实样本，不能覆盖本仓库规范。真实数据的 PII 不进入仓库文档、普通日志或验收报告。

## 三、架构边界

1. 智联 DOM、NIM 形状、`contentType/messageKind/cardType` 只存在平台 program 与证据中，不进入脑侧状态机分支。
2. 平台适配层先将原始消息收窄为小而稳定的平台无关业务事件；无充分证据的类型必须归为 `unknownPlatformEvent`，不得驱动自动副作用。
3. 状态机只消费归一化事件与仓库自有业务状态；AI 只输出分类或回复建议，不裁决状态跃迁或动作。
4. 任何可见发送仍通过现有 WAL、idemKey、手证词、动作后正证与 suspect 轨道。

## 四、已授权规则集

- 启用拒绝正则族、`RSM-01/02` 与 `SR-01/02/04`；优先级为简历标记、拒绝正则、短拒绝。
- `contentType` 字段缺席按普通文本处理，不创造 `null` 枚举。
- `99` 不沿用旧常量的 `READ` 语义。
- `105/ASK_FOR_WX` 识别为候选人主动请求微信，与 `99` 拒绝结果、`259/WX_CARD` 交换结果分开。
- `177/259/313` 只能在就地只读事实探针通过后新增显式平台映射；`343` 继续保守。
- 未见枚举不实现；进入保守分支时仍保留原始类型到 evidence 或普通日志。

## 五、执行批次与提交节奏

1. **差距清点。** 对照 v4、M5 和现有生产入口，列出已有能力、实现缺口与需裁决空白；先复用，不重写。
2. **归一化事件层。** 先建立平台无关事件词表、严格提升条件与 unknown 失效方向，再接智联映射与枚举 fixture。
3. **确定性归约器。** 实现主要事件到状态/下一动作的纯函数转移，包含明确拒绝、简历提交、普通文本、AI 失败与已终态短路。
4. **AI 建议与运行编排。** 复用已验收 provider/job-config 输入，将唯一沟通轮次接到建议、下一动作与既有发送意图，验证重放零增生。
5. **时刻表与沉默处理。** 只实现 v4 已冻结的时间和上界，不自行增加新打扰策略。
6. **集成回归与验收记录。** 用脱敏 fixture 覆盖事件序列、重复消息、脑重启、provider 失败、unknown 事件与终态输入。

上述每个独立因果单元在门禁变绿后立即创建本地 commit，进入下一单元前恢复干净工作区。不 push、amend、rebase 或 squash。

## 六、真机与旧日志授权的使用

- 可读取 `to-check-logs`、在已授权智联页面搜索真实历史与卡片，规则以 `docs/真实账号测试授权记录.md` 为准。
- 只在枚举、卡片入口、回执或状态转换的事实缺口真正阻塞时制造最小真实样本。
- 真机结果不明确时不补发、不重复点击；登录失效、验证码、风控、付费入口或账号变化时停止该真机分支，其余离线工作继续。
- 真实候选人是否在夜间回复不是完成出口；生产真实端到端冒烟可在白天用单个候选人补验。

## 七、停止与降级规则

只有以下情况停止相关分支，不因单一分支阻塞而结束整个夜间任务：

1. 实现需要修改现有可信规范、新增/改变协议权利义务，或需要甲方选择会实质改变产品行为。
2. 平台原始类型缺少真机证据，无法合法提升为明确业务事件。
3. 发现会造成重复/错靶外部副作用、不可恢复账本损坏、错版仍发送或需手工清库才能恢复的当前可达路径。

降级方向固定为 `unknown/manualRequired/no automatic side effect`，并在早间交付清单中记录事实、候选方案和待裁决点。

## 八、审查预算与早间交付

实现完成后最多一轮限定范围独立审查。只自动修复会导致重复/错靶副作用、账本损坏、错误状态推进或长期锁死的阻断项；优化与理论边缘项记录后不阻塞。

早间报告必须包含：

- 本地 commits 清单及各自因果。
- v4 分支覆盖矩阵和门禁结果。
- 真机/旧日志新增事实（只记脱敏结论）。
- 已降级分支、待裁决项与单候选人真机冒烟步骤。
