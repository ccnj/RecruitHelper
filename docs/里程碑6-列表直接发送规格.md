# 里程碑 6：列表直接发送规格

日期：2026-07-22

状态：甲方已确认《端到端业务主线计划》的“列表直接发送”阶段；2026-07-22 可逆真机事实门已经通过。本文把该授权收窄为当前正式批次的最小 effectful 竖切。

## 一、出口与风险预算

入口只接受一个已完成筛选和招呼语生成的正式 `batchId`。系统按稳定 `platformUserRef` 在推荐列表重新定位该批 `selected + greeting ok` 成员，直接使用列表卡片的“打招呼”入口，把已持久化正文送入既有 `chat.sendGreeting@1` WAL、idemKey、手证词和正证轨道。

本轮真实出口只要求当前批次唯一入选者发送一次并取得同卡“继续沟通”正证；成功后 profile 推进为 `greeted`，`conversationRef` 可由后续 IM 巡检补绑。必须立即阻断错人/错职位、同一生成事实产生两个 intent、绕过 WAL、覆盖既有弹窗或输入、契约错版仍发送，以及关系未确认时另铸意图。目标暂时不在可扫描窗口、窗口停滞、页面读取失败和普通动作前 UI 变化允许本轮停止后人工处理。

独立审查限一轮。批量日调度、频率限制、平台风控框架、列表耗尽证明、第二平台与完整沟通均不在本轮；本阶段不新增频控机制。事实门和自动化通过后应直接做一次有人值守真机发送，不再插入额外审查轮。

正式采集、评分、筛选、招呼语生成和列表发送共同服从仓库统一业务运行窗口：
只允许在客户端本地时间 `[08:00, 24:00)` 由用户显式开始或恢复。凌晨不得只跑
漏斗，也不得登记到点自动执行；跨过 24:00 时当前单个动作自然收束，随后停止
开始下一候选人或下一阶段。既有 effectful WAL 仍按安全内核完成判定与收敛，
但不得借恢复新建另一意图。08:00 后仍须用户显式恢复。

## 二、来源授权与唯一意图

1. 合法来源必须同时满足：selection 已完成；同批 decision outcome=`selected`；对应 `SourcingGreetingInvocation` 为 `ok` 且正文非空；run/profile/batch/revision/content hash 全部一致；profile 当前仍为 `selected` 且没有成功招呼、会话或结束事实。
2. 自动发送 intentId 只由招呼语 invocationId 按固定版本域确定性派生。同一 invocation 最多绑定一个 intentId；绑定字段属于业务事实，不物理删除。
3. 上述来源条件和“尚未绑定其他 intent”必须在创建 `EffectIntent + CmdRecord + CandidateGreetingHead` 的同一 SQLite 事务内重查并 CAS 绑定。管理端、actor 或 Dispatcher 的事务外预览不授权发送。
4. 既有人工 M4 入口保持可用，但不得伪造自动来源。自动入口一旦形成 WAL，即由既有恢复轨独占结果；同步 socket 错误、HTTP 重跑、脑重启或 actor 重跑都只能等待/读取同一 intent，不能换正文或另铸发送。

## 三、稳定列表定位

1. 脑只使用 `candidate.readSourcingWindow@1` 的 `platformUserRefs` 寻找目标。可从 `reset` 开始，再串行执行有界 `next`；每轮只比较不透明引用，分页、滚动位置和窗口序号都不是身份。
2. 目标进入当前窗口后，最终授权仍由手端同一 greeting evaluator 独立完成：账号身份已经由手注册绑定，当前页是公开 URL 中 `jobNumber === positionRef` 的推荐页；可见卡片中 `source.userMasterId === platformUserRef` 恰好一张；该卡恰有一个“打招呼”、零个“继续沟通”；页面没有详情或既有招呼弹窗。职位判定不得再向 Vue route/store 私有层追证。
3. 目标缺失、重复、职位不一致、窗口重复/停滞或达到脑侧扫描预算，只能返回未定位并停止。不得选首卡、按姓名/头像/职位标题匹配，也不得降级到 `resumeNumber`、DOM 位置或采集时的滚动坐标。

## 四、两步动作与正证

1. 真机已证明列表卡第一击只打开既有 `.ai-greeting-modal`，不改变关系。prepare 只可调用该可逆入口一次，并取得本命令独占的唯一非 AI 自定义 option、textarea 和未勾选默认设置；已有弹窗或输入一律动作前停止。
2. preflight 与 attempting 后的 commit 必须字面调用同一 evaluator 和同一组冻结参数。正文使用已持久化 `GreetingText`，通过 native setter 和 input/change 后精确回读；最后一份绿色结果后立即唯一 click footer“发送”，不再读取可变页面，不在原语内重试。
3. 即时成功只接受同一 `platformUserRef+positionRef` 卡片从唯一“打招呼”变为唯一“继续沟通”。toast、弹窗消失、输入清空、页面跳转、配额变化和无关卡片变化均不足以成功。
4. 即时未确认仍进入既有 `chat.readGreetingOutcome@1` 最多三轮验证；验证也只复读同一列表卡关系。无变化、目标卸载、读取失败或阴性永远不能推出未发送，最终只进 suspect/人工，禁止第二次招呼。

## 五、批次编排与管理投影

批次按已冻结 selection 顺序串行处理，当前一人成功后即退出真实冒烟。管理入口只返回 batchId、revision、selected/ready/pending/in-flight/sent/failed/suspect 聚合计数和 completed，不返回 profile/run/invocation/intent、平台身份、正文或页面位置。

管理 POST 可以开始或收编同一批；重复 POST 对已有 WAL 只返回同一聚合状态。没有合法来源、目标未定位或手/账号/contract/witness 不就绪时，不得创建 effectful 事实。

## 六、自动化与真实验收

自动化至少覆盖：跨批/revision/profile/run 拒绝、非 selected/非 ok 生成拒绝、来源到 intent 的事务回滚与双重唯一、稳定 intent 重放、列表 current/reset/next 定位、目标未见/重复/窗口停滞、列表 evaluator prepare/preflight/commit、已有弹窗、错职位、同卡关系正证、阴性不重发，以及管理投影隐私。

真实验收前构建插件并重载，确认脑手 `contractHash` 一致、witness/recovery 屏障收束、当前批次仍只有一条未绑定的 `selected + greeting ok`。随后只调用一次批次入口；成功时核对来源 invocation、唯一 intent/command/head、profile=`greeted`、同卡“继续沟通”和重复 POST 零增生。报告只写聚合、hash 与状态，不记录候选人身份或正文。

## 七、已登记后置优化（暂不实施）

- **批量招呼定位续扫。** 当前每个待发候选人都从推荐页顶部 `reset` 后向下定位，多人连续发送时会反复扫描同一段列表。后续优化为：前一人终局后保留当前推荐窗口，下一人默认从当前位置继续向下扫描；只有向下扫到尾部仍未命中时，才允许最多一次 `reset` 从顶部做全量兜底查找。
- 续扫位置只是定位提示，不是身份根据；命中后仍必须以稳定 `platformUserRef + positionRef` 完成同一套目标复核。兜底后仍找不到时继续记为未定位，不构造 effectful intent，不降级按姓名、DOM 位置或 `resumeNumber` 匹配。
