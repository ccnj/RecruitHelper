# 0727 当日计划 3：投影游标与轮边界解耦

日期：2026-07-27  
状态：甲方已批准开工；按 文档 → Commit 1 → Commit 2 → 一次性恢复 → 有人值守冒烟 顺序执行

## 一、现场事实与本轮裁决

2026-07-26 起两名真实候选人（钟女士、李先生档案）回复后系统不再应答。数据库核查确认因果链：

```text
我方出站(seq6) → 平台系统消息(seq7) → 巡检把 seq7 单独投影、游标推进到 7
→ 候选人回复(seq8) → 下轮重建边界要求"游标行必须是我方出站"
→ seq7 是 system → outboundBoundaryMissing → 档案永久 manualRequired
```

对照组（程女士档案）序列逐字相同，仅因候选人回复赶在巡检之前到达、系统消息与回复
落进同一边界而正常收尾。这是竞态，窗口宽度 = 巡检间隔。全库 195 个聚合中 **49 个
游标停在 system 行**，其中 40 个仍 `active`——候选人一回复即锁死。另有游标停在
`in` 行的同类入口（轮完成未发送后候选人再开口）。

根因不是缺一个判断，而是 `ProjectedThroughSeq` 一个字段同时承担三种语义：

1. 顺序投影指针 + 事务 CAS 令牌；
2. 轮边界出站锚（"候选人这轮说的话 = 我方最后发言之后的一切"）；
3. AI 历史渲染边界。

三者在纯一问一答里恰好相等，平台系统消息第一次把它们掰开。同一错误假设
（"游标行必须是我方出站"）在巡检重建、冻结事务、AI 重验链共五组点位重复出现。

## 二、出口宣言与风险预算

### 2.1 最小可交付出口

1. `ProjectedThroughSeq` 只保留语义 1：可停在 in/out/system 任意行；恒有
   `cursor >= anchor`（`v4_schedule.go` 既有校验不变）；
2. 轮边界锚改用 state 既有字段 `LastOutboundMessageSeq`：招呼根聚合创建/晚绑定时
   写入招呼 seq；存量 anchor=0 按 `messages.outbound_intent_id ==
   root_greeting_intent_id` 唯一索引确定性派生，派生失败维持
   `outboundBoundaryMissing`（该原因自此仅剩"锚不可解析"一义），不用 MAX(out) 猜测；
   主动来聊根 anchor=0 合法；
3. `dialogue_turns.history_through_seq` 列自此仅表示 AI 历史渲染边界，v4 轮恒等于
   `InboundFromSeq-1`；turn 身份 digest 内的同名字段值恒为锚 seq（代码
   `DialogueTurnIdentity` 硬编码 `lastOutbound.Seq`，不读表列），两者在锚与首条候选
   人输入之间有已投影系统消息时不相等——此定义同时是同批/分批到达同身份的幂等前提；
4. `InboundThroughSeq` 恒为候选人消息尾（direction=in 且 kind≠system 的最大 seq），
   不是边界尾；尾部未投影 system 行在轮收束后由既有非候选尾投影顺序消化，不永久跳过；
5. 冻结后重验链与冻结共用同一边界重建语义：锚由账本内 `InboundFromSeq` 之前最近一条
   有效出站确定性重建并经 digest 核对（找错必不匹配、保守失败），不透传表列；
6. 真人插话（边界含我方 out）仍 `interleavedOutboundBoundary` 挂人工，不放宽；
7. 40 个游标停在 system 的 active 档案不做数据处理，随本修复自动恢复处理能力；
8. 契约零改动、无新表新列、无新守卫、插件零改动。

### 2.2 必须立即阻断的损害

- 同一候选人消息被两个 turn 认领或二次送入 AI（防线：冻结事务游标 CAS + 确定性
  turn 身份唯一索引 + 未完 turn 检查，三者均不削弱）；
- 重建锚与冻结锚不一致却继续派发（防线：digest 核对）；
- legacy M5-A 试运行轨行为漂移（防线：共用验证器仅改 v4 分支，legacy 分支逐位不变）；
- 恢复步骤触碰消息、turn、游标或任何已发送事实。

### 2.3 允许兜底的失败

- 锚派生失败 → `outboundBoundaryMissing` 挂人工（真人可见、可裁决）；
- 重建 digest 不匹配 → `turnBoundaryChanged`/`inputBoundaryChanged` 挂人工；
- 冒烟期间任何非预期行为 → 停止解冻剩余档案，人在场即闸。

### 2.4 审查与后置

冒烟 commit 后默认一轮定向审查。后置项（各自独立立案，不混入本轮）：
平台系统消息语义映射（须按 `(99, innerType)` 二元组走枚举面事实门）、手侧
`msgb/msgc` 字段路径修复、混合卡片+文本轮次、微信被拒终结态、259 联系资产核查、
真人插话自动收敛、指纹/content_hash 影响。

## 三、设计与点位清单

### 3.1 被否决的替代方案

- **只改巡检层游标回溯**：存储层 `outboundTail != HistoryThroughSeq` 与 CAS 双断言
  仍拒绝，锁死换名不除根（codex 对审证实）；
- **区间重叠拒绝防重复认领系统**（codex 首版提出）：防的场景当前不可达——
  `superseded` 唯一写入点是七天归档（区间已在游标后）、边界变化走
  `inputBoundaryChanged` 不存在作废重建流、游标唯一回退路径（撤回）只回退到我方
  出站前。按防护成本预算三问不立，整套砍除；
- **system/in 都不推进游标**：`in` 不推进会使同批候选人消息在下轮重新入边界、
  另铸新 turn 身份二次送 AI，直接违反宁可少发红线。

## 四、回归测试清单

1. 同批 `out→system→in` 建轮成功；
2. 分批：先 `out→system` 投影（游标停 system）、重启，再收 `in`——建轮不挂人工
   （单批喂入测不出本缺陷，必须真实分两个巡检周期）；
3. 多条 system 后收到 in；
4. `[in, system]` 尾序：`InboundThroughSeq`=候选人尾，尾部 system 轮收束后投影；
5. 同批与分批产生相同 turnID、相同 `history_through_seq`、相同业务终态；
6. 连续两轮：turn1 完成未发送 → 再收 in → turn2 同锚不同身份，AI 历史含 turn1 入站；
7. 主动来聊第一、二轮（anchor=0 路径，含来聊根前置已投影 system 时
   `history_through_seq>0` 的 `sentGreeting` 回退）；
8. 存量 anchor=0：派生成功→继续；派生失败→维持 `outboundBoundaryMissing`；
9. 真人插话（边界含 out）→ interleaved 挂人工不变；
10. 并发冻结 CAS 一胜一败/幂等返回；重启+重复巡检零新增 turn/AI/action；
11. `out→system→in` 冻结后完整跑通 意向→回复→action 构造，不挂 `turnBoundaryChanged`；
12. `out→in→system` 完整跑通 AI 与发送前重验（含材料装载），随后 system 正常投影；
13. legacy 轨 turn 经共用验证器与材料装载旧分支，行为与现状逐位一致；
14. system 后场景多气泡序列：气泡 2+ 走依赖验证器照常派发；
15. 创建/晚绑定写锚、`v4_schedule` `cursor >= anchor` 校验回归。
