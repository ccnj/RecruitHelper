# 智联换微信与邀面卡事实记录

> 采样日期：2026-07-23（Asia/Shanghai）
>
> 探针边界：使用当前已登录的智联测试账号。一次“换微信”点击属于《真实账号测试授权记录》与《M5-B 集中开发与集中冒烟裁决》已授权的真实副作用；邀面编辑器只填写后取消，未发送第二条候选人可见消息。其余事实来自既有真实历史的只读巡检。临时探针只输出类型码、字段名、枚举值与存在性布尔值，采样后已从源码和插件构建中删除。
>
> 隐私边界：本文不记录候选人姓名、候选人自由文本、微信号、手机号、职位号、简历号、会话号或平台消息身份原文。

## 一、事实门结论

| 平台事实 | 真机结论 |
|---|---|
| 我方发起换微信 | `customType=105`、`direction=out`、`originType=1`、`status=success` |
| 对方接受我方换微信 | `customType=259`、`direction=in`、`originType=1`、`status=success` |
| 新版邀面卡 | `customType=355`、`direction=out`、`status=success` |
| 接受面试回执 | 普通 `in/text` 固定平台文案；当前样本未出现旧常量候选 `182` |

三种自定义消息均具有稳定服务端消息身份，足以继续按协议规格 §4.5 生成不可逆 `sourceKey`。当前样本没有通用 `requestId/id/cardId`；`355` 虽有 `interviewId` 字段，但本次没有记录原值，也没有证明它跨状态稳定。因此当前唯一已证实的消息级身份仍是由稳定平台消息身份生成的 `sourceKey`。

## 二、换微信卡

### 2.1 我方请求卡 `105`

真机探针只保留下列脱敏投影：

| 事实 | 值 |
|---|---:|
| 顶层 `type` | `custom` |
| 内层 `type` | `105` |
| 方向 | `out` |
| `originType` | `1` |
| `status=success` | `true` |
| 稳定服务端消息身份存在 | `true` |
| 独立卡片身份字段存在 | `false` |
| 微信号字段存在 | `false` |

结构字段候选为 `aiOperate/detail/icon/originType/pushContent/pushTitle/scene/staffContent/userContent`。点击当前聊天工具栏“换微信”会立即产生候选人可见副作用，不经过二次编辑器或确认弹窗。真实 DOM 结果为我方消息气泡，卡片根具有 `imc-wx-request` 形态。

这与既有候选人主动请求 `105 + originType=2 + direction=in` 是同一平台类型的另一条已证实分支，生产映射必须同时看方向与 `originType`，不得只凭类型码猜动作发起方。

### 2.2 对方接受卡 `259`

真机探针只保留下列脱敏投影：

| 事实 | 值 |
|---|---:|
| 顶层 `type` | `custom` |
| 内层 `type` | `259` |
| 方向 | `in` |
| `originType` | `1` |
| `status=success` | `true` |
| 稳定服务端消息身份存在 | `true` |
| 独立卡片身份字段存在 | `false` |
| 候选人微信字段存在 | `true` |
| 招聘方微信字段存在 | `true` |

结构字段候选为 `aiOperate/icon/originType/receiverText/receiverTitle/senderText/staffWeChat/userWeChat`。页面中它是新追加的入站 `imc-wx-request` 卡片，而不是已发 `105` 原消息的就地状态更新；因此当前真机成功交换应按一条新的 `in/card/wechatExchange/accepted` 消息归一化，不能等待 `105` 的 `CardTransitionFact` 才推进。

微信号属于本地业务资产，可以进入业务数据库；普通日志、审计、管理 API、文档和报告仍不得返回其原文。如何以平台无关结构把该资产交给脑、以及运营通知渠道，仍需在相应契约实现前按 AGENTS.md 第 12 条立案。

## 三、新版邀面卡 `355`

真机探针只保留下列脱敏投影：

| 事实 | 值 |
|---|---:|
| 顶层 `type` | `custom` |
| 内层 `type` | `355` |
| 方向 | `out` |
| `status=success` | `true` |
| `state` | `0` |
| 稳定服务端消息身份存在 | `true` |
| 独立卡片身份字段存在 | `false` |

结构字段候选包括 `interviewId/startTime/endTime/interviewType/interviewPlatform/state` 及职位、组织、展示文案字段。页面可见卡片根为 `imc-interview-new-card`，处于我方消息气泡；可见内容含“线上面试邀请”、时间、方式、查看详情和状态。

两个真实已接受历史样本的原始卡片 `state` 都仍为 `0`，而页面可见状态为“已接受”。因此本批**不授权**把 `state=0` 解释为 `pending`、`accepted` 或 `rejected`，生产感知只能先把 `355` 归一化为 `out/card/interviewInvite/unknown`。发送成功可由“基线后新增一条稳定身份的 355 我方卡片”取得正证；候选人接受则由紧随其后的普通入站固定回执归一化为业务事件。

当前样本中的接受回执是普通 `in/text`，固定平台文案为：

> 我已接受贵司的面试邀请，将准时参加面试

旧项目常量表候选 `182=INTERVIEW_ACCEPT` 在本次两段真机历史和旧库存接受记录中均未出现，不得实现。当前没有取得面试拒绝的真实类型或固定文案；拒绝继续保守转人工，不猜老常量。

## 四、邀面编辑器事实

工具栏“约面试”只打开编辑器，未立即产生副作用。当前编辑器已证实包含：

- 现场/线上类型；
- 日期选择器与时间选择器；
- 面试时长；
- 腾讯会议、钉钉、飞书、微信视频、电话面试；
- 联系人与留言；
- 取消与最终发送按钮。

同日补充的只读 DOM 探针进一步冻结：

- 当前会话唯一工具栏动作分别为
  `a[zp-stat-id="im_ask_for_wx_open"][type="button"]` 与
  `a[zp-stat-id="im_interview_invite_click"][type="button"]`，可见正文精确为“换微信”与“约面试”，且都位于唯一可见 `.im-session-detail` 内；
- 邀面编辑器根为唯一可见 `.km-modal__wrapper.interview-modal` 且包含 `.interview-form`；
- “现场面试/线上面试”切换会同步改变可见标题与选中图标；本次探针恢复并确认“线上面试”后才继续；
- 日期以 `.km-date-picker__label` 的 `YYYY-MM-DD` 可见文本回读；时间只提供五分钟粒度选项，选中值可从 `input[placeholder="请选择时间"]` 精确回读；
- 时长当前只提供 `15分钟/30分钟/45分钟/1小时` 四项，选中值可从 `input[placeholder="面试时长"]` 精确回读；
- “微信视频”选中按钮具有唯一可见 `is-checked` 状态；最终“发送”是编辑器内唯一 `type=button` 的可见发送按钮；
- 探针只切换和填写编辑器，最后点击“取消”；没有点击最终发送，也没有产生候选人可见消息。

本仓库现有“真机新版邀面卡”脱敏 fixture 对应当前页面的“线上面试 +
微信视频”样本，原始字段为 `interviewType=2`、`interviewPlatform=4`。本批只允许这组
当前数值形态映射为平台无关 `method=wechatVideo`；旧库存曾出现的字符串
`VIDEO/TENCENT` 对应腾讯会议，不得归入微信视频，也不建立其他字符串或数值猜测映射。

日期输入为只读公开文本框，选择日期后才出现时间选择；当前页面可选择到分钟。一次真实历史卡的方式为微信视频。最终发送动作尚未在本次事实门执行，因为同一候选人当前业务轮已先产生换微信请求卡，继续发送会违反“同一候选人同一业务轮至多一条可见消息”。现有历史卡足以固化出站形态；正式原语仍需在集中冒烟时选取新的合法业务轮走完整 WAL 与正证轨道。
