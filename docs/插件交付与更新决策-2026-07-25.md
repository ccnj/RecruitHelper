# 插件交付与更新决策（2026-07-25）

## 一、状态与范围

本文件记录甲方于 2026-07-25 拍板的 Chrome 插件最终交付方向，解除 `AGENTS.md` 原“program 交付机制”悬置项。

本裁决确定交付形态与更新激活边界，不宣称客户端侧的插件文件安装、原子替换、延迟重试和回滚能力已经实现。当前已经存在的是：

- `plugin/dist` 的 unpacked 构建产物；
- Chrome 开发者模式人工加载；
- 协议规格 §14.1 的 `debug.reload@1` 维护握手；
- 新 Service Worker 刷新已打开平台页，并以新 `bootId`、`contractHash` 和 ready 状态确认激活结果。

## 二、拍板结论

1. **唯一交付形态**
   - 不使用远程 JavaScript 或远程 program 下发；
   - 不制作、分发或自托管 CRX；
   - 不上架 Chrome Web Store；
   - 客户端发布物整包携带与该客户端版本配套的 Chrome MV3 插件。

2. **首次安装**
   - 插件放在客户端管理的固定本地目录，以开发者模式加载 unpacked 扩展；
   - 首次安装由我方人工远程操作，不开发客户自助安装向导；
   - 内部只保留最小远程安装清单；远程安装或售后成本显著上升时，再单独立项自助引导。

3. **后续更新**
   - 客户端可提前把完整新版插件准备到 Chrome 不会读取的独立暂存目录，不得提前覆盖正在使用的固定正式目录；
   - 进入业务安全窗口并确认没有未收束命令后，客户端校验暂存版本，原子替换固定正式目录，并紧接既有 `debug.reload@1` 激活；
   - `chrome.runtime.reload()` 只负责让 Chrome 重新读取磁盘文件，不承担文件下载或替换；
   - 激活成功仍以同一 `handId`、新 `bootId`、期望 `contractHash`、能力集和 ready 状态为准。

4. **业务安全窗口**
   - 客户端可以提前在独立暂存目录准备新版文件，但不得在推荐流仍被当前批次占用时改写正式目录或激活；
   - 禁止替换与激活的窗口从正式批次第一次读取推荐窗口开始，持续到该批最后一个计划招呼取得终局；
   - 评分、筛选、招呼语生成和人工确认虽然不一定持续操作页面，但后续招呼仍依赖原推荐流，因此同样属于禁止激活窗口；
   - 纯沟通、空闲或批次已经全部终局时，才可进入重载握手。

5. **最小延迟与重试**
   - 更新请求到达时可先完成独立暂存；替换正式目录前先检查业务阶段，再检查该手是否存在未收束命令；
   - 任一条件不满足时，不改写正式目录、不失效推荐流、不派发 `debug.reload`，只把本次激活视为延迟；
   - 在批次进入纯沟通阶段、客户端下次启动、用户准备开启新批次之前重新检查，并以低频周期检查作兜底；
   - “重试”只指尚未派发维护命令时重新评估激活条件。一旦 `debug.reload` 已派发，命令、result ACK 或新 hello 超时/歧义仍禁止进入通用自动重派链，按协议规格 §14.1 转维护处理。

6. **用户体验**
   - 普通用户不参与选择插件文件、点击 Chrome 扩展页重载或判断版本；
   - 更新被业务占用延迟时，产品只需表达“新版本已准备，将在本批任务结束后更新”；
   - 客户原本主动暂停时，更新完成后不得擅自恢复业务运行。

## 三、首个真实客户交付前的实现义务

以下是实现义务，不是本次文档批次已经完成的能力：

1. 使用不会随客户端版本变化的固定插件目录，并保持扩展身份稳定；
2. 新版先写入临时位置，完成 manifest、版本、文件完整性和期望构建摘要校验后，再替换正式目录；
3. 保留上一版完整插件作为失败恢复材料，避免半写入状态成为唯一副本；
4. 在客户端更新编排中实现第二节第 4、5 条的安全阶段检查与延迟重试；
5. 激活后等待新 hello；版本、契约或能力不符合预期时保持 effectful 禁派，并给出远程维护所需的无敏感信息诊断；
6. 冻结日常所需的必选 Chrome 权限；新增会触发用户确认的权限须另行评估，不得默认为无感升级；
7. 形成一页内部远程安装与恢复清单，但不建设客户自助安装向导。

## 四、明确不做

- 远程脚本热更、动态 program 下发或第二套插件代码通道；
- CRX、私有 update URL、企业策略强装或 Chrome Web Store 发布；
- 客户自助安装向导；
- 为低频“只手动重载插件、未刷新页面”场景新增推荐流真假换代识别机制；
- 把维护命令的超时或歧义交给普通命令自动重派。

## 五、重新立项触发条件

只有出现以下事实之一，才重新评估本交付方案：

- Chrome 明确阻止目标客户环境继续加载或运行该 unpacked 扩展；
- 人工远程首装、恢复或售后成本已经成为可量化的主要交付瓶颈；
- 客户环境进入统一管理的企业 Chrome，且现有方式相较企业策略产生明显更高的维护成本；
- 当前恢复路径无法把坏版本故障控制在可接受的人工处理范围内。
