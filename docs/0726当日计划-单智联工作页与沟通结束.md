# 0726 当日计划：单智联工作页与沟通结束

日期：2026-07-26  
状态：实现完成，等待自然业务切换验收

## 一、裁决与目标

本计划承接 2026-07-26 甲方现场裁决，并覆盖
[`0724当日计划4-客户端七页核心UI.md`](0724当日计划4-客户端七页核心UI.md)
中“漏斗与沟通并行”以及
[`0725当日计划-页面驱动聊天巡检与采集恢复.md`](0725当日计划-页面驱动聊天巡检与采集恢复.md)
中“一张 IM 页加一张推荐页是正常运行现场”的旧口径：

1. RecruitHelper 对单一账号只维护、驱动一张 canonical 智联工作标签页；
2. 完整漏斗与多轮沟通不并行占用页面，按业务阶段互斥切换；
3. 沟通中收到“再采一批”请求时，先完成当前候选人的本轮动作链，再切换推荐页；
4. 首页新增“结束本次任务”，第一版只在多轮循环沟通阶段可用；
5. 修复当前 IM 列表在实时增量重渲染后不可读、且真实页面失败阶段被吞掉的
   可用性缺陷。

“单一标签页”约束的是 RecruitHelper 自己选择和驱动的工作页。用户自行打开的
其他智联标签页不由系统自动关闭，也不得被选作并行业务工作面。

## 二、出口与风险预算

### 2.1 最小交付出口

- `chat.readList` 的 MAIN-world 页面失败能够返回具体、脱敏的诊断阶段，不再
  统一退化成“页面脚本未返回结果”；
- 当前 IM 页面实时重渲染后仍能以稳定平台身份读取当前可见列表窗口；身份
  不可唯一确认时响亮失败，不按姓名、头像、文本或列表位置猜测；
- 完整流程在最后一个计划招呼终局前只保留推荐工作面，不启动 IM 巡检；
- 最后一个计划招呼终局后，同一工作标签页切换到 IM，再启用循环沟通；
- 沟通中点击“再采一批”只登记待切换请求；当前候选人动作链收束后停止领取
  下一会话，同一标签页切换推荐页并创建新批次；
- 仅在工作流处于 `communication` 阶段时显示和接受“结束本次任务”；
- 结束请求不截断在途 AI、手侧命令、WAL 判定或组合动作链；收束后停止沟通、
  终局化当前产品运行并回到首页初始状态；
- 结束不删除候选人、简历、评分、消息、发送、联系资产或其他业务事实。

### 2.2 必须立即阻断

- 页面身份无法唯一确认却继续打开会话或发送；
- 推荐流中途被主动导航走，导致尚未终局的计划招呼失去定位现场；
- “再采一批”截断当前候选人的多气泡、邀面、换微信或 WAL 收敛；
- 结束后旧任务仍可构造新候选人可见动作，或新任务与旧在途动作交错；
- 为满足单页切换而绕过既有 WAL、idemKey、手证词、页面正证或 suspect。

### 2.3 允许重试或人工兜底

- 页面导航或 IM 列表当前轮暂时未就绪；
- 同一标签页切换失败并停留在原阶段；
- 当前候选人动作链尚未收束，待切换或结束请求继续显示“正在完成当前候选人”；
- 用户自行打开额外智联标签页；系统忽略它们，不自动关闭用户页面。

上述失败不得反推候选人可见动作失败，也不得授权自动重发。

### 2.4 审查预算与后置

本计划完成后只做一轮独立审查，范围限于错靶、重复发送、动作链截断、旧任务
污染新批次、推荐现场提前丢失和工作流永久锁死。

以下内容后置：

- 在漏斗的采集、评分、筛选、生成、等待确认或招呼发送阶段结束整项任务；
- 自动关闭用户手动打开的多余智联标签页；
- 无人值守吞吐优化与 IM 并行巡检；
- 与当前故障无关的通用页面身份框架。

## 三、单工作页阶段机

### 3.1 完整流程

```text
同一智联工作页切换推荐页
→ 采集
→ 评分
→ 筛选
→ 生成招呼语
→ 等待人工确认
→ 逐位发送招呼并完成各自 WAL / 正证收敛
→ 最后一个计划招呼终局
→ 同一工作页切换 IM
→ 页面就绪与账号身份复核
→ 启用循环沟通
```

评分、筛选和 AI 生成虽主要发生在脑内，也不在这段时间另启 IM 页面或沟通
巡检。等待人工确认期间同样保留推荐现场，不处理多轮消息；切回 IM 后从当前
页面列表重新观察并补齐积压消息。

### 3.2 沟通中再采一批

```text
用户点击“再采一批”
→ 持久化 pendingSourcingSwitch
→ 不再领取下一会话
→ 当前候选人的本轮 AI / 多气泡 / 卡片 / WAL 自然收束
→ 确认不存在该动作链的未收束副作用
→ 同一工作页切换推荐页
→ 创建并执行新的 30 人批次
→ 本批计划招呼全部终局
→ 同一工作页切回 IM
→ 恢复循环沟通
```

“当前候选人处理完成”以整轮动作链终局为边界，不以单条命令返回、AI 调用返回
或正文发送完成代替。待切换请求不得立即创建活动采集批次，以免现有 generation
边界在候选人动作链中间终止旧轮。

### 3.3 页面选择

- 系统运行期间只认一张持久化选择的 canonical 智联工作页；
- 活动漏斗优先把该页保持在推荐路由，沟通阶段把同一页保持在 IM 路由；
- 不因目标路由不同创建第二张后台业务页；
- 导航完成后继续执行当前账号身份和目标页面 ready 核对；
- 找不到既有智联工作页时才允许新建一张，之后持续复用。

## 四、沟通阶段结束

### 4.1 产品语义

- 暂停：保留当前运行、阶段和可恢复位置，之后继续同一任务；
- 结束本次任务：只在 `communication` 阶段可用，不再继续当前运行；
- 点击结束后立即关闭“领取下一候选人”的成员闸；
- 已经开始的当前候选人动作链及其 WAL 判定自然收束；
- 收束后停止账号沟通 actor，把产品运行正常终局并释放 active slot；
- 首页回到初始状态，重新显示“开始今日任务”和“只处理新消息”；
- 下次启动创建新的产品运行；既有候选人与业务事实继续保留。

产品运行可复用既有 `completed` 终态，但必须以本地审计事实记录
`reason=userEnded`，不得伪装失败，也不得物理删除业务行。第一版不在漏斗
阶段显示结束入口，因此无需终止半截采集批次、评分、候选确认或招呼发送。

### 4.2 UI

- 仅在 `communication` 阶段的运行或暂停状态显示次要按钮“结束本次任务”；
- 点击后确认：“结束后不能继续本次任务；已有数据和已发送消息不会删除。”；
- 有在途动作链时显示“正在结束”，期间不可再次开始新任务；
- 终局后自动刷新为首页初始控制。

## 五、IM 列表可用性修复

2026-07-26 现场事实：

- IM 页面已经完整加载，虚拟列表与滚动容器存在；
- `15:17:52` 最后一次成功读取列表窗口；
- `15:18`～`15:22` 批量招呼造成 IM 会话列表实时增量与重渲染；
- `15:27:30`、`15:30:43`、`15:35:43` 连续三轮在首次列表采集阶段失败；
- 失败发生在稳定等待和滚动之前，不是超时或滚动过慢；
- 当前 `mainReadListDOMWindow` 依赖行节点私有 `__vue__._props.source` 作为唯一
  身份入口；私有绑定缺失或形态变化会使整窗失败；
- 该函数未把内部 `dom_list_*` 失败转换为结构化 MAIN-world 结果，Chrome
  注入只返回空结果，导致真实失败阶段丢失。

修复顺序固定为：

1. 先把 MAIN-world 失败转换成脱敏、可序列化的阶段结果并补回归测试；
2. 通过当前真实页面确认具体失败阶段；
3. 在不猜姓名、文本或位置的前提下，补充稳定平台身份读取通道；
4. 单行异常不得静默丢弃；若无法唯一确认，整轮保持未确认并交下轮重试；
5. 通过正式 `chat.readList` 脑手路径验证当前窗口可读。

## 七、2026-07-26 实施结果

### 7.1 已完成

- 漏斗运行期间不再提前开启沟通 actor；计划招呼全部终局后才进入沟通阶段；
- 推荐→IM 交接优先把本轮唯一推荐页原地导航到 IM 并设为活动工作页；浏览器
  已有旧 IM 页时不再选回旧页，也不关闭用户页面；
- 沟通中“再采一批”和“结束本次任务”均持久化为待执行控制，只在当前候选人

  `reason=userEnded` 正常终局化运行；既有业务事实不删除；

- 修复了暂停与候选人边界 gate 的锁序反转，gate 返回后重新核对 actor 与 hand
