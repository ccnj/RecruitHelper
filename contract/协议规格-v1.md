## 1. 模型与公理

1. **脑是唯一账本。** 手随时失忆(SW 空闲约 30 秒被杀、页面导航杀 content script、浏览器重启),失忆是常态。手侧一切存储只能是"证词"——丢了只准退化为"更多转人工",不准导致错误的自主行为。
2. **语义方向永远脑→手;传输连接方向手→脑。** 手主动拨号、重连、发心跳,但协议语义上手没有主动权:只执行命令、只上报传感提示。
3. **语义传输无关。** 任何正确性不押在 WebSocket 特性上(连接即会话、帧有序、断开即边界都不作为正确性依据)。验收思想实验:换 MQTT 5 承载,语义零修改(A 卷 §13.2 已逐条核过)。
4. **外部副作用极贵。** 重复给候选人发消息=骚扰=封号风险。纪律:宁可少发;一切歧义不自动重发,只转人工。协议目标:让"多发"在自动逻辑下机制性不可能,让"少发+人工"成为歧义唯一归宿。
5. **契约单一源头。** 两端协议类型与运行时校验全部出自 `contract/` codegen(Go/TS 类型、常量、validator),禁止手写;关联字段在生成类型里非可空。CI 校验全部生成物一致。
6. **单一命令通道。** 测试页、调度器、将来的运营工具都只是脑体内的命令生产者;协议中不存在"测试命令"概念。手侧唯一入口是命令分发器。
7. **平台无关。** 命令与结果的语义字段一律意图级;DOM/selector/tabId/windowId/平台专有 id 只许出现在 evidence 与日志,脑逻辑不得读取 evidence 内容做分支。
8. **业务节奏全在脑。** 巡检、调度、重试、超时判定只存在于脑;分钟级延迟是业务规格明文允许的(`docs/沟通逻辑规格-v4.md` 巡检模型:每日真人手动开启,数分钟一轮,最晚至 24:00),协议不为秒级实时付复杂度。

环境基线:Chrome ≥ 116(活跃 WS 收发重置 SW 30 秒空闲计时);chrome.alarms 最小约 30 秒;脑=Electron 内常驻 Go 服务+SQLite。

## 2. 传输绑定与本地握手

### 2.1 连接 [M1]

- 端点 `ws://127.0.0.1:{port}/v1/channel`;默认端口 **17872**(明确不复用 17321),脑侧配置文件与手侧扩展 options 页均可改。文本帧,UTF-8,一帧一条 JSON 消息,不批量不拼接。
- 单帧硬上限 `limits.maxMsgBytes`(默认 256 KB,welcome 下发),按**完整 envelope 的 UTF-8 字节数**计算;通用 body 内联建议线 `inlineBytes`=32 KB。感知批次另冻结:单条消息内联文本 ≤2 KB、内联 `result.data` ≤64 KB、证据文字 ≤2 KB;更大完整内容只可走 `blob/1` Claim Check。未协商 blob 时必须在执行前或组装结果时响亮失败(PAYLOAD_LIMIT),禁止静默截断;收到超硬帧一律 PROTO_MSG_TOO_LARGE。
- 手侧重连退避:1s 起 ×2,封顶 30s,±30% 抖动;连接稳定 60s 后退避归零。chrome.alarms 看门狗(60s)发现"未连接且无在途尝试"即发起——它只是复活闹钟,不是心跳。runtime.onStartup/onInstalled 立即尝试。

### 2.2 本地可信握手与连接边界 [M1, 2026-07-17 修订]

威胁模型:用户明确把同机本地环境视为可信。协议防网页脚本误连与跨站 WebSocket,不试图防恶意本地进程;如果未来出现远程手、不可信本地多用户或云端监听,必须重新设计传输鉴权,不能把本节直接外推。

1. **只监听回环地址**:脑只在 `127.0.0.1` 监听固定端点,不得监听 `0.0.0.0`、局域网或公网地址。
2. **Origin 前置校验**:升级 WebSocket 前,脑只接受 `Origin` 以 `chrome-extension://` 开头的请求,其余请求直接拒绝。这是网页侧边界,不是对本地进程或某个特定扩展的身份证明。
3. **手自己出生身份**:插件首次运行以密码学安全随机源生成稳定、不透明的 `handId`(长度 1..128),写入 `chrome.storage.local`。每个 Chrome profile 天然拥有不同的本地实例 ID;SW/浏览器重启复用,清除扩展数据或重装后生成新值。`handId` 只用于手注册表、路由和单活接管,不是凭据,也不等于招聘账号绑定。
4. **零配对、零握手身份 token**:hello 的 `handId` 必填且不可空,没有 `auth`;welcome 不签发 `handId`、共享 token 或其他手身份凭据。不存在配对窗口、待确认连接、配对码、`paired_hands` 凭据表或配对管理 UI。§13 推迟的 `blob.token` 是会话作用域的 HTTP 数据面 capability,不参与 hello 身份判定,不得被当作配对机制。
5. **10 秒握手**:手发送 hello 后,脑完成 Origin、主版本和结构校验并立即回 welcome/bye;10 秒未收到响应,手关闭连接并进入正常重连退避。没有等待人工确认,因此没有握手期 pre-session ping 或 70 秒特殊超时。
6. **单活连接**:同 `handId` 的新 hello 顶掉旧连接(旧连接收 bye(SUPERSEDED));非当前物理连接来的任何消息丢弃并审计。当前物理连接上只有已 accepted 命令的 `progress/result` 可保留该命令创建时的旧 `session`;`ack/ping/event` 仍必须与当前会话一致。
7. **协议摘要不是签名**:`contractHash` 是契约文件公开字节的 SHA-256 摘要,在线握手层只用于漂移告警。它没有秘密材料,不是签名、MAC、口令或身份凭据;不匹配不得硬拒连接,在线协议门禁是主版本与逐项 caps/features。首客前破坏性硬切期间另按 §14 暂停 effectful,直至重启脑、重载插件并确认哈希一致。
8. 显式不做(防回潮):人工配对、共享 token、一次性配对码、二维码、旧扩展 ID 白名单、Native Messaging 发现、动态端口发现。若威胁模型改变,以新安全设计和相应协议版本处理,不得悄悄恢复旧字段。

本地明文 ws 可接受,依据是回环监听和用户声明的本地可信边界;wss 自签证书在该边界内零收益高摩擦,不做。

## 3. 消息信封 [M1]

信封 7 字段,冻结;扩展只发生在 body 内。

```json
{
  "proto": 1,
  "kind": "cmd",
  "msgId": "01JB2K3G8XF5N7Q9R0S1T2U3V4",
  "session": "s-01JB2K1AAAAAAAAAAAAAAAAAAA",
  "ts": 1768546201345,
  "attempt": 1,
  "body": { }
}
```

| 字段 | 类型 | 语义 |
|---|---|---|
| proto | int | 协议主版本。首客前可按 AGENTS.md 在同一主版本内硬切清理;兼容冻结后,跨原语的不兼容变更才递增主版本且当前主版本内只做加法。接收方始终必须忽略不认识的字段(must-ignore)。 |
| kind | string | 消息种类(§4)。不认识的 kind:命令方向 ack 拒绝(PROTO_UNSUPPORTED_KIND),上报方向记日志丢弃。 |
| msgId | string | 消息逻辑身份:唯一不透明串(建议 ULID,手侧 crypto.randomUUID 亦可),接收方不得解析其内容。**重传时不变**,是去重键与关联锚点。 |
| session | string\|null | 当前发送尝试所属会话(welcome 分配)。hello/welcome/bye 为 null。命令只在 session=手当前会话时可执行;已 accepted 命令在旧会话断开后仍可完成，首次产生的 progress/result 可以携带该命令的创建会话；同一上行信封跨会话补投时按下方重传纪律更新为当前会话。两者都只在该手当前物理连接上受理。 |
| ts | int64 | 发送方毫秒时钟,仅诊断;重传时更新。**永不**用于去重、排序或状态裁决。 |
| attempt | int | 同一 msgId 第几次发送,仅诊断(>1 说明投递层在重传)。 |
| body | object | kind 专属载荷。 |

所有线上 `int/int64` 都限制在 JSON/TypeScript 可精确表示的 safe-int53 范围(±9,007,199,254,740,991);Go/TS validator 使用同一 `safeInteger` 规则,防止跨端四舍五入后关联、deadline 或排序值分裂。

命名纪律:线上字段一律 camelCase;所有"指向另一条消息"的字段只有一个名字 **`ref`**,在生成类型里非可空——别名漂移与"回执丢关联 id"从构造上灭绝。

重传纪律:同一 msgId 重传时,信封可变字段为 ts、attempt、**session(跨会话重投时更新为手当前会话)**;msgId 与 body 不可变。

## 4. 消息种类

全集 13 种;M1 激活 8 种,S 批再激活 progress/event/cancel,X 批激活 query/report,至此 13 种全部激活。首客前破坏性清理规则见 §14;未知字段 must-ignore 的接收纪律不因冻结点前后而改变:

| kind | 方向 | 需对方 ack | 批次 | 用途 |
|---|---|---|---|---|
| hello | 手→脑 | 以 welcome/bye 作答 | M1 | 自报身份、bootId、能力、版本 |
| welcome | 脑→手 | 否 | M1 | 握手完成:分配会话、下发参数 |
| bye | 脑→手(手→脑方向 [远] 预留:优雅下线;v1 手侧终止一律直接关连接) | 否 | M1 | 拒绝握手/宣告关闭/顶替,带原因码 |
| cmd | 脑→手 | 是 | M1 | 下发命令 |
| ack | 双向 | 否 | M1 | 收妥回执:对 cmd=已解析入队;对 result=脑已持久化 |
| result | 手→脑 | 是 | M1 | 命令终局,唯一携带 data/error/evidence 之处 |
| ping | 手→脑 | 以 pong 作答 | M1 | 会话内心跳:SW 保活+半开检测+就绪度 |
| pong | 脑→手 | 否 | M1 | 心跳应答,带脑侧时钟 |
| progress | 手→脑 | 否(可丢) | S | 长命令阶段汇报,兼执行期活性;stage 为自由文本,禁止程序分支 |
| event | 手→脑 | **否(可丢)** | S | 传感提示。QoS0:无 ack、无重发、丢了无害(正确性在对账层) |
| query | 脑→手 | 以 report 作答 | X | 脑询问命令在手侧状态(歧义消解) |
| report | 手→脑 | 否 | X | 按手侧 journal/内存作答(state: unknown/queued/executing/attempting/done) |
| cancel | 脑→手 | 是 | S(随租约) | 尽力而为取消;ack 只确认请求收妥,与目标 result 赛跑时 result 赢 |

### 4.1 hello(手→脑)[M1]

```json
{ "body": {
  "handId": "h-7f3ak2m9qwe8rty0uiop", // 插件本地随机生成并稳定保存;不是凭据
  "bootId": "b-a83kd02m",         // SW 内存随机值,SW 每次出生新生成——手记忆连续性的唯一指示器
  "protoSupported": [1],
  "contractHash": "sha256:...",   // 公开摘要,仅漂移告警;不是鉴权签名
  "app": { "extVersion": "0.1.0", "browser": "chrome/126" },
  "caps": ["debug.ping@1", "chat.readThread@1", "chat.sendMessage@1"],
  "features": ["progress/1", "lease/1", "cancel/1", "witness/1"], // 独立协议特性开关(非原语)
  "witnessStoreId": "w-7d2f...", // [X] chrome.storage 证词库世代;清库后必须换值
  "outboxPending": 2,             // [X] 本次 hello 快照中等待补投的 SX result 数
  "journalOpen": 1                // [X] attempting 证词数;仅诊断,不承载业务判断
} }
```

**caps 会话不可变**:program 热更后手必须断线重连、以新 hello 重报能力(localhost 重连毫秒级,换来"会话内能力恒定"强不变量)。脑派发前查会话 caps,无能力的命令不派发、意图挂起并在 UI 呈现(能力缺口是运营事件,不是错误循环)。

**`witness/1` 是真实 SX 的硬门禁**:声明该 feature 时 `witnessStoreId/outboxPending/journalOpen` 三字段必须齐备;任一缺失即协议不就绪,脑不得派发真实 effectful。`witnessStoreId` 跨 SW/浏览器重启稳定,仅证词库首次初始化或整体丢失后换代;脑把派发时的值写入命令账本。换代后 `report=unknown` 不能证明零副作用,只能验证后转 suspect。三个字段也随 ping 搭车用于健康诊断,必须全有或全无;它们不使心跳变成业务账本。

### 4.2 welcome(脑→手)[M1]

```json
{ "body": {
  "session": "s-01JB2K1AAA...",
  "proto": 1,
  "hb": { "intervalMs": 20000, "graceMs": 50000 },
  "limits": { "maxMsgBytes": 262144, "inlineBytes": 32768 },
  "contractMatch": true,
  "now": 1768546200449,
  "sensors": { "badgeDebounceMs": 800, "badgeMinEmitIntervalMs": 5000,
               "navSettleMs": 500, "manualQuietMs": 45000 },  // [S] 传感参数由脑下发,手无自带策略数值
  "blob": { "endpoint": "http://127.0.0.1:17872/v1/blobs", "token": "bt-...", "maxBytes": 20971520 }  // [X]
} }
```

握手拒绝或会话关闭走 bye:`PROTO_INCOMPATIBLE` / `SUPERSEDED` / `SHUTTING_DOWN`。Origin 不合格在 WebSocket 升级前直接拒绝,不会进入协议帧。

### 4.3 cmd(脑→手)[M1]

```json
{ "body": {
  "name": "chat.sendMessage",
  "ver": 1,
  "context": { "platform": "zhilian", "accountRef": "acc-01",
               "expectedPrincipalFingerprint": "opaque-v1-..." }, // debug.* 或首次绑定前 probe.platform 可缺省;指纹只许相等比较
  "args": { "conversationRef": "c-5f6a", "text": "..." },
  "idemKey": "ik1:zhilian:acc-01:chat.sendMessage:cand-98a7:int-01JB2K2Z",  // 仅 effectful 携带
  "deadline": 1768546801345,      // 绝对过期时刻(脑钟):手出队时与不可逆动作前一刻双查,过期即回 result(expired)
  "execBudgetMs": 60000,          // 手侧单次执行预算,超时自行中止回 EXEC_TIMEOUT_HAND;上限 240000(MV3 5 分钟强杀留余量)
  "leaseMs": 30000,               // [S] 需 lease/1;5s..120s;progress 按脑接收时刻续租,绝不越过 deadline
  "guards": { "expectedTail": [ { "direction": "in", "contentHash": "..." } ] }
} }
```

`chat.sendMessage@1` 的 guards 词汇只冻结一项:`expectedTail` 为 1..5 条 `MessageAnchor`。手在**写 journal attempting 之前**定位指定会话并冻结一份当前线程窗口,又在**不可逆动作前最后一刻**以字面同一份 evaluator 重读当前世界;两次都必须精确以该锚结尾,且有序消息 source keys、账号身份、路由和 `conversationRef→peer` 目标绑定均未变化,否则 `GUARD_FAILED/sideEffect=none`。`composer.empty` 同为硬前置条件:页面已有用户未发送输入时必须在 attempting 前回 `USER_ACTIVE` 或 `GUARD_FAILED`,不得覆盖草稿;写入正文后还须确认当前唯一可见输入框的值精确等于待发正文。

动作前硬闸只核对两类对象:预期世界状态,以及被直接调用动作接口的公开标准语义。控件层只要求当前页面存在唯一可见 detail、输入框和发送按钮,三者满足 DOM containment;发送按钮若关联 form,其有效标准 `type` 必须为 `button`,避免一次 click 额外触发标准 submit/reset。原生 `disabled` 只会让标准 click 无效,`aria-disabled` 又不定义 click 抑制语义,二者均不作为多发/错靶/覆盖输入的安全硬闸。框架组件 owner/model、页面 SDK、渲染节点、监听器注册表、事件接线或 DOM 对象跨重绘恒等性等平台私有实现不得参与动作授权或降级为观测守卫。系统构造性保证自己的逻辑至多调用一次不可逆动作,并信任“一次标准 click 至多产生一次副作用且作用于界面所示对象”;若不接受该平台动作契约,只能削减能力或转人工,不得继续向私有实现内部追证。

preflight 与 attempting 后的 commit 必须调用字面同一 evaluator 和同一组冻结参数;commit 写入正文后仍由该 evaluator 重新核对世界状态。最后一份绿色结果后不得再读取页面、时钟或控件属性,必须立即执行唯一一次冻结的标准 click。guards 是条件写闸,不是验证结果;后置条件核验、配对 `chat.readThread@1` 与 suspect 只负责判定结果和收敛歧义,可以捕获并升级已经发生的伤害,不能补救或反向取代合法预防守卫。

手侧执行模型:**全局严格串行**,先 ack 入队,FIFO,深度 16,满则 ack 拒绝 QUEUE_FULL(背压)。只有协议/session/caps/schema/队列类问题走 ack(rejected)。命令在收帧时已经过 deadline 仍先 ack(accepted),随后从队列的“不可执行终局”分支回 result(expired),**绝不调用原语 handler**;accepted 后才发现页面、账号、用户或目标问题一律 result(failed)。

### 4.4 ack(双向)[M1]

```json
{ "body": { "ref": "01JB2K3G8X...", "status": "accepted" } }
```

- status:`accepted` / `rejected`(附 §10 错误对象,此层错误恒 sideEffect=none)/ `duplicate`。
- 对 cmd:accepted=已解析、schema 过验、已入执行队列(**不是**开始执行,更不是完成)。
- 对 result:accepted 与 duplicate **等价**——皆表示脑侧已持有该终局,手删除队列条目(否则补投会循环到 SW 死亡,挤占队列)。
- **去重不等于沉默**:重复到达必须重新 ack(duplicate);若该 cmd 已有终局,补发一份 result(replayed=true)——Stripe 式结果重放。

### 4.5 result(手→脑)[M1]

```json
{ "body": {
  "ref": "01JB2K3G8X...",
  "status": "ok",                  // ok | failed | canceled | expired(四者皆终局;拒收在 ack 层)
  "data": { },                     // ok 时与 dataBlobRef 恰有一个;内联按原语 dataSchema
  "dataBlobRef": null,             // blob/1:完整 data JSON 的 sha256 内容引用,取回验哈希后再跑 dataSchema
  "error": null,                   // failed 时必填,§10
  "evidence": [ { "type": "outboundMessageObserved" } ],  // chat.sendMessage ok 必填;对脑不透明
  "replayed": false,
  "execMs": 6890
} }
```

effectful 的 ok 定义为**观察到稳定后置条件**,"我触发了动作"、编辑器清空、乐观渲染或只有平台本地临时 ID 的缓存记录都不算(宪法原文)。生成的 `validatePrimitiveResult` 按具体原语强制 data/evidence schema;`chat.sendMessage@1` 必须在动作前冻结当前目标绑定的服务端消息基线,后续每轮观察仍须匹配该目标。只有相对基线**恰好新增一条**服务端确认记录,且该唯一记录为我方 `text`、`contentHash` 与发送正文相等时才可 ok。零新增、多新增、并发入站、明确失败与成功并存、目标换绑或读不清均只算阴性;歧义恢复只使用配套 `chat.readThread@1`。

目标绑定证词只表示本轮各次读取仍指向同一界面所示会话,不证明平台私有框架、SDK 或事件接线正确。系统构造性保证自己的逻辑对公开标准动作接口至多调用一次;平台把一次标准动作重复执行或送往其他目标属于被信任动作契约的违约。即时 observer、配对验证读与 suspect 可以发现并升级阴性结果,但不能撤销已经发生的伤害,因此任何阴性都禁止第二次动作。

正文 hash 与 `ThreadMessage` 文本采用同一算法:Unicode NFC、trim、所有 Unicode 空白串折叠为单个 ASCII 空格,再做 SHA-256 小写 hex。平台 ID 只在手内用于证词判定或脱敏 evidence，不进入脑侧业务 data；result/data/evidence 与手侧证词均不得回抄消息正文。

### 4.6 ping / pong [M1]

```json
{ "kind": "ping", "body": {
  "queueDepth": 1,
  "inFlight": "01JB..." ,          // 正在执行的命令 msgId,无则 null
  "contexts": [],                  // [S] 各账号上下文就绪度 { platform, accountRef, ready, reason }
  "sensors": null,                 // [S] 只运缓存现货(如 unreadTotal),禁止心跳到点反向拉取 DOM
  "witnessStoreId": "w-7d2f...", "outboxPending": 0, "journalOpen": 1 // [X] 仅计数诊断
} }
{ "kind": "pong", "body": { "now": 1768546220003 } }
```

ping 由完成握手的手发起,间隔 `hb.intervalMs`(默认 20s)±20% 抖动,一石三鸟:WS 活动保活 SW(<30s);手凭 pong 缺失(连续 2 次)检测半开连接并主动重连;携带就绪度供脑健康模型。**心跳不携带业务数据**——sensors 只是缓存读数转发,心跳变胖=健康信号失真。hello/welcome 之前没有会话心跳;握手由独立的 10 秒 helloTimeout 约束。

### 4.7 progress / 租约 / cancel [S]

三项分别用 `progress/1`、`lease/1`、`cancel/1` 协商;脑不得因手只支持其中一项就推断另两项。`chat.readList`、`chat.readThread` 等声明 `leaseMs` 的原语只有在三项所需能力齐备时才可派发。

```json
{ "kind": "progress", "body": { "ref": "cmd-msg-id", "stage": "page 3", "pct": 40 } }
{ "kind": "cancel", "msgId": "cancel-msg-id", "body": { "ref": "cmd-msg-id", "reason": "leaseExpired" } }
{ "kind": "ack", "body": { "ref": "cancel-msg-id", "status": "accepted" } }
```

- 租约从脑收到目标命令的 ack(accepted) 的本地单调时刻开始;每条**schema 合法、ref 指向仍在途命令、来自该手当前物理连接**的 progress 以脑接收时刻续到 `now+leaseMs`,但永不越过绝对 deadline。该 progress 可保留目标命令创建时的旧 session;旧物理连接、迟到、未知 ref、已终局命令的 progress 只记审计,不复活命令。`stage` 仅人读,`pct` 可缺省且范围 0..100,二者都禁止用于程序分支;合法 progress 与 ping 一样刷新手的 lastSeen。
- 租约 gap 到期代表本次物理尝试失联,不是业务终局:脑先发唯一 cancel,保留 1000ms 的有界 result 竞态窗;窗内目标 result 先到则 result 赢。竞态窗后仍无 result,readonly/intrusive 才按 §8 作废并进入 replacement chain,effectful 进入 suspect。竞态窗不延长绝对 deadline,progress 不能把 deadline 后移。
- cancel.body.ref 指向**目标 cmd**;cancel 自己的 ack.ref 指向**cancel 帧 msgId**。queued 目标直接移出执行候选并回目标 result(canceled);executing 目标在取消安全点前协作中止并回 result(canceled);越过安全点只记录取消请求,照常完成目标 result。ack(accepted) 只表示请求已收妥,不证明取消成功;无论竞态顺序,目标 cmd 的首个合法 result 赢并成为唯一终局。
- cancel.reason 是机器枚举:`leaseExpired | deadlineImminent | superseded | operator | shutdown`;不得用自由文本决定行为。`leaseExpired` 是当前自动生产值,`operator` 为未来显式人工取消来源预留,其余三值为 deadline 临界、命令替代和服务退出的确定性生命周期来源预留;手不按 reason 分叉取消语义,但日志保留来源。因此五值都是 cancel 控制面的正式词汇,不是可删化石。

### 4.8 query / report [X]

```json
{ "kind": "query", "msgId": "query-msg-id", "body": { "ref": "target-cmd-id" } }
{ "kind": "report", "msgId": "report-msg-id", "body": {
  "ref": "target-cmd-id", "witnessStoreId": "w-7d2f...", "state": "attempting",
  "result": null,
  "journal": { "ref": "target-cmd-id", "idemKey": "ik1:...", "state": "attempting", "startedAt": 1768546203000 }
} }
```

query/report 是 base 投递层对账,不是 program 原语,不进业务 FIFO、不触碰页面。query 的 `ref` 指向要询问的 cmd;report 的 `ref` 仍指向该目标 cmd而非 query 消息。report 可丢且无 ack;脑未收到可重新 query,手每次从当前内存/journal 重新构造 report。两者必须使用当前 session 和当前物理连接,不得跨连接采信。

| state | 强制字段 | 可以推出的事实与唯一动作 |
|---|---|---|
| `unknown` | `result=null,journal=null` | 当前内存和指定 `witnessStoreId` 的 journal 均无目标。**仅当 storeId 与派发时一致**才是“未越过 attempting 写点”的零副作用证明,允许安全重投原 msgId;storeId 换代/未知则不能证明,走验证后 suspect |
| `queued` | `result=null,journal=null` | 同一 boot 内仍排队、尚未写 attempting;等待原执行或 cancel,不得并发另发 |
| `executing` | `result=null,journal=null` | handler 正执行但尚未越过 attempting 写点;继续等待 result/下一轮 query,不得重发 |
| `attempting` | `result=null,journal.state=attempting` | 已持久写提交前证词,是否发生副作用不确定;冻结域并走验证,绝不重发 |
| `done` | 完整 `ResultBody` + `journal.state=committed` | 直接按 result 终局入账;ref 与账本命令、journal.idemKey 与账本 idemKey 必须逐项相等,不等即证词损坏并转人工 |

生成 validator 强制 `done` 的 result/journal 非 null、`attempting` 的 journal 非 null且状态匹配、其余状态禁止夹带二者,并强制所有内嵌 `ref` 等于 report.ref。attempting journal 只含 `ref/idemKey/state/startedAt`,**不得含 args、消息正文、guards 或业务决策输入**。

## 5. 确认层级:每层能推出什么 [M1]

| 层 | 信号 | 能推出 | 不能推出 |
|---|---|---|---|
| L0 | WS write 返回 | 字节进本端缓冲 | 对端收到 |
| L1 | ack(accepted) | 手收到、过验、入队 | 会被执行、会成功 |
| L2 | result 终局 | 手的终局判断+副作用标注+证据 | 平台真把消息投给了候选人 |
| L3 | 脑的业务核验(readonly/intrusive 对账回读)[X] | 逼近平台侧真相 | 绝对真相 |

端到端论证:低层确认永远不能替代高层核验。L1 缺失按投递问题处理(§7);L2 缺失按执行问题处理;L3 不通过**不自动重发,只转人工**。

## 6. 命令分类学 [M1 定义,S/X 逐批启用]

三类,契约静态声明,**按最坏实现定级**(声明从紧无害,从宽踩页面):

| class | 定义 | 重试/重派 | 排队 | idemKey | evidence |
|---|---|---|---|---|---|
| `readonly` | 不驱动页面、无平台侧效果的纯探测 | 自由重派(新 msgId 同 args),有轮次封顶 | 不进账号串行域 | 禁止 | 不需要 |
| `intrusive` | **业务只读或声明式幂等**,但驱动/占用页面;平台侧效果至多是一次性幂等的(已读回执、页面就位) | 同 readonly:自由重派安全 | **进账号串行域**(与 effectful 同队互斥,跨手生效) | 禁止 | 不需要 |
| `effectful` | 不可回滚、可叠加的外部副作用(发消息、发卡) | **永不自动重派**;只有 journal 在同一 storeId 下明确 `unknown` 的提交点前零副作用证明允许重投原物理命令;其余歧义→验证→suspect | 账号串行域 | 必填 | ok 必填且按原语 schema 强制 [X] |

归类判据(litmus,写进契约注释):执行两次与一次对候选人可感知世界无任何额外差别、且不发出任何业务内容→看是否驱动页面:驱动=intrusive,不驱动=readonly;否则=effectful。**拿不准=effectful**(与 sideEffect"拿不准标 possible"同一保守方向)。

intrusive 原语须另声明 `platformSideEffect: "none" | "idempotentReadReceipt"` 供审计。intrusive 单列的原因(C 卷 §4.2):判成 readonly,重派会踩掉同账号在途发送的页面;判成 effectful,"结果未知态的验证读"陷入循环依赖。

原语注册六要素:`name、ver、class、argsSchema、dataSchema、preconditions`;真实 effectful 另强制 `guardsSchema、evidenceSchema、verification{primitive,ver,maxRounds}`。这些元数据与 Go/TS 的 guards/evidence/result validator 一并由 codegen 生成,两端不得手写旁路。外加纪律第七条:**原语实现内部禁止自主重试**——原语=单次尝试+观察后置条件+诚实上报,重试决策归脑(旧系统"点击后重试一次"的修复移植时必须剥离内部重试,否则两层重试相乘)。

**debug 串行域**:debug.* 的 intrusive/effectful 命令进该手专属的 `debug` 串行域(每手一个,与账号域平行,规则同款);测试页命令同样经脑铸造意图行,idemKey 照常派生(§7.4 debug 形态)。

## 7. 投递保证、重传与幂等

### 7.1 选型 [M1]

- 命令通道:**至少一次投递 + 手侧去重 = 有效一次入队**。
- 执行语义:readonly/intrusive 至少一次(可重派);effectful **在歧义处降为至多一次**(宁可少发)。
- 上报通道:result 至少一次(内存队列重发直到脑 ack;[X] 起 SX 的 result 另有持久 outbox)+ 脑按 msgId 持久去重(processed 表 30 天)。
- 不追求恰好一次:两将军定理;QoS2 只保 broker-client 报文不重,应用崩溃照样重复,纯付费迷信。

### 7.2 重传规则(同 msgId)[M1]

**同一条存活的 localhost TCP 连接上永不重发帧**——loopback 不丢包;送达了没 ack 说明手内部卡死,再塞一帧只是多一条日志(B 卷 1.2)。规则:

1. ackTimeout(3s)内**无任何应答**(连 rejected 都没有)→ 判连接可疑 → **脑主动关闭连接**,触发手侧重连。本规则与反模式 19 只约束"无应答的帧"。
2. 帧重发只发生在**重连之后**,且仅当新 hello 的 `bootId` 与派发时记录一致(手记忆连续,去重表有效,重复投递被吸收);重发帧的 session 更新为新会话(§3 重传纪律)。
3. bootId 变了:readonly/intrusive 重新派发(新 msgId);无 `witness/1` 的 effectful 一律 suspect。真实 SX 按 §9 四阶段对账:只有 `witnessStoreId` 与派发记录一致且 report=unknown 时才获得“attempting 写点前死亡”的零副作用证明,可重投**原 msgId**;attempting、storeId 换代、report 缺失/损坏均先验证后 suspect,绝不盲重发。
4. **ack(rejected) 是应答,不是歧义**:对 readonly/intrusive,瞬态拒绝(QUEUE_FULL 退避后、STALE_SESSION 换会话后)允许同 msgId 再投,同一连接亦可(它有应答,不属"无应答帧重发");协议性拒绝(PROTO_*)记 rejected 终局。**真实 SX 不使用这条瞬态重投通道**:任何 receipt rejected(包括 STALE_SESSION/QUEUE_FULL)都终局化物理命令与原意图,之后只能由人确认并另铸新意图。真实 SX 的唯一自动恢复通道是§9 在与派发时相同的 `witnessStoreId` 下得到 `report=unknown`,然后重投原 msgId。

### 7.3 手侧去重与队列 [M1]

- **收帧管线顺序(固定,不许重排)**:信封/body 结构校验 → **msgId 去重**(命中即 ack(duplicate),有终局则重放 result,**不再看 session**)→ session 校验(**仅受理时刻生效**:已 accepted 的命令跨会话继续执行,其首次 progress/result 即使携带命令创建会话也照常入账；持久信封跨会话补投则更新为当前 session；脑侧始终以当前物理连接为不可放松的来源围栏)→ caps/features/原语版本 → args + guards schema → **deadline 时间分支**:若已过期,直接写去重表、ack(accepted) 并进入不占 FIFO 容量的终局队列回 result(expired);否则检查队列容量 → 写去重表并 ack(accepted) → FIFO 执行候选。**只有 ack(accepted) 的命令才进去重表**,被拒命令不入表(只为 readonly/intrusive 瞬态拒绝后同 msgId 再投留路;真实 SX 在脑侧已终局化)。deadline 的字段类型仍在 schema 阶段校验;时间已过永不因 QUEUE_FULL 改成 rejected,handler 调用次数必须为 0。
- **去重表:内存 LRU 256,作用域=SW 一次生命(bootId)**,键=msgId(idemKey 冗余记录),值含终局 result 缓存。命中即 ack(duplicate)+必要时重放 result。**严禁把这张 LRU 写入 chrome.storage**——普通投递层的同 id 重发只发生在 bootId 未变时,由内存去重吸收；真实 SX 另有且仅有 §9 的跨 boot 例外：同一 `witnessStoreId` 的 report=unknown 给出 attempting 写点前零副作用证明后重投原 msgId。该例外不依赖旧内存 LRU，而由 journal 入队前闸与脑账本共同围栏，不能推广为一般同 id 重传。
- 断线不弃队:已 accepted 的命令在 SW 存活期间继续执行(deadline 出队双查防僵尸);R/I result 进内存有界队列(50 条,result 优先),重连即冲,SW 死即丢(由脑侧 WAL 兜底);真实 SX result 必须先进入持久 outbox,不得降级到仅内存队列。
- 去重先于一切副作用:msgId 表与真实 SX 的 idemKey journal 查询发生在入队前。journal 命中 attempting 时绝不再进 handler;命中 committed 且 ref 相同则重放缓存 result;同 idemKey 却 ref 不同是脑账本闸失效的严重告警,保证零新副作用并转人工。

### 7.4 幂等键(idemKey)[M1 格式,X 启用]

```
ik1:{platform}:{accountRef}:{primitive}:{targetRef}:{intentId}    业务形态
ik1:debug:{handId}:{primitive}:{targetRef}:{intentId}             debug 形态(测试页命令同样经脑铸意图行)
```

- **脑生成、从业务意图行确定性派生**(intentId=脑 SQLite 意图主键)。同一意图无论重发多少次、脑重启多少次,键恒同——比 Stripe 随机键更强:把"忘了复用"这种人祸也灭掉。
- 粒度=意图,不是"候选人+动作"全局唯一(隔天跟进是新意图新键);粒度裁决权在脑业务层。
- 仅 effectful 携带;readonly/intrusive 禁止(避免假安全感)。

### 7.5 幂等三道闸 [X 全部就位]

1. **脑账本闸(权威)**:intents 表 UNIQUE(idemKey);派发前查账本,已有非失败终局或 suspect 冻结中的意图,拒绝铸造新命令。手侧全丢也拦得住。
2. **手证词闸(缩窗)**:§9 journal——SW 死于执行窗口的任意点,后果只可能是少发+人工,不可能多发。
3. **平台回读闸(L3)**:`chat.sendMessage` 动作前以 `expectedTail` 对当前目标绑定的服务端消息视图做条件写,动作后仍从同一目标绑定视图确认唯一新增的服务端消息后置条件;歧义恢复时使用 `chat.readThread` 回读。读到线程已变化即停手,只有唯一正匹配可补记成功,其余转人工。

重复发送需三道闸同时失效,而每道闸单独失效的后果都是"少发+人工"。

## 8. 命令生命周期、超时矩阵与 suspect [M1]

### 8.1 脑侧账本状态机(SQLite 持久)

**先记账后发送**:命令必先以 `queued` 落库(在途日志:msgId、name、class、idemKey、bootId@dispatch、deadline、状态)再进 socket。脑的账本永远是手所见命令的超集。

```
queued → sent → accepted → ok | failed | canceled | expired   (result 为准)
   sent --ackTimeout(无应答)--> (关连接,待重连按 §7.2 处置)
   sent --ack(duplicate)--> 视同 accepted
   sent --ack(rejected, 协议性 PROTO_*)--> rejected(终局)
   sent --ack(rejected, 瞬态 STALE_SESSION/QUEUE_FULL)--> readonly,intrusive: queued(待同 msgId 重投,非终局)
                                                         真实 effectful: rejected(终局;意图同步 failed)
   accepted --lease gap [S]--> readonly,intrusive: void(可铸 replacement)
                               真实 effectful: reconciliation gate(冻结,§9);无 witness: suspect
   任何非终局 --deadline+宽限 过 / bootId 换代 / 脑重启扫描--> readonly,intrusive: void(作废,巡检自然重派)
                                                            真实 effectful: reconciliation gate
   reconciliation --outbox/done--> result 终局
                  --same storeId + report=unknown--> 原 msgId 安全重投
                  --attempting/换代/缺报告--> 验证读唯一正匹配:ok;否则:suspect
人工裁决 suspect → resolvedOk | resolvedFailed(可由人铸新意图;自动逻辑不代劳)
```

**真实 SX 恢复的唯一性**:自动逻辑只能在同一 `witnessStoreId` 下收到 `report=unknown` 这一提交点前零副作用证明后,重投原 msgId。任何合法 `result=failed,sideEffect=none` 都终局化物理命令与原意图,`retryable=yes/afterRecovery` 只是手的建议值,不授权真实 SX 自动重投;任何 receipt rejected(包括瞬态 STALE_SESSION/QUEUE_FULL)同样终局化意图。若仍需发送,只能由人确认后另铸新 `intentId`/`idemKey`,不得复活旧意图或铸 replacement。

**迟到帧总则**:任何终局/void 状态收到迟到的 ack/result,一律审计,不静默丢弃;suspect 收到迟到 result 按 §8.3 法条 6 自动核销;void 收到 result 只审计不改账(它是"脑账本是手所见超集"断言的观测点)。

**物理命令与逻辑派发链分层** [S]:每个 msgId 的 rejected/void/ok/failed/canceled/expired 都先独立持久化。readonly/intrusive 需要安全重派时才以新 msgId 建 `replacementOf` 链；真实 SX **禁止**进入这条新 msgId replacement 规则，只能在 §9 获得零副作用证明后重投原 msgId，否则验证后 suspect。对 R/I，单条物理命令终局不等于逻辑等待结束:等待者只在整条 replacement chain 最终成功、失败或达到重派上限时唤醒,不得因中间 void/expired 提前返回,也不得永远只等原始 msgId。cancel/result 竞态仍以目标物理命令的首个合法 result 为准。

**脑重启恢复**:启动即扫在途日志,未终态 readonly/intrusive 作废;无 `witness/1` 的 effectful 沿 M1 降级为 suspect。真实 SX 保留非终态账本并立即冻结 idemKey/账号域,进入 §9 reconnect reconciliation gate；先等 outbox 补投,再 query/report。只有完整对账无法给出终局或零副作用证明时才经验证落 suspect。这样脑重启不会制造自动重发,也不会在 outbox 即将补投前抢跑人工裁决。

**脑对离线的手不排队命令**:巡检 tick 现算现发,手不在线本 tick 跳过;命令是状态的投影,投影留在脑侧。deadline 取短值(巡检类 ≤ 2×execBudget)。

### 8.2 超时矩阵(v1 裁剪版;[S]/[X] 逐列启用)

### 8.3 suspect 六法条 [M1 铺轨,X 已满负荷]

1. 触发:effectful 出现以下任一且 §9 对账/配套验证仍不能核销——deadline+宽限过仍无终局;result 带 sideEffect=possible;派发后 bootId 或 witnessStoreId 换代且无 result;脑重启扫描命中在途。冻结发生在对账前,但 suspect 终态只在对账结论后落下。
2. suspect 是**自动化的终态**:永不自动重试、永不静默;落审计,进客户端 UI 显著的 suspect 队列,有通知(v1 用 UI 告警面板+结构化日志;云端接入后加企微)。
3. **冻结幂等键**:人工裁决前,该 idemKey 拒绝签发任何新命令。
4. **冻结串行域**:该账号不派新 effectful/intrusive(debug 命令的冻结域=该手 debug 域);唯一例外是脑为消解该 suspect 下发的验证读,它占用被冻结命令自己的槽位 [X]。
5. 人工二选一裁决(确认已发生→补记完成;确认未发生→解锁允许**由人决定是否铸新意图**,自动逻辑不代劳),裁决落审计。**裁决入口前置条件**:手已重连且完成 outbox/query/report 与验证读仍无终局,或手离线持续 ≥ suspectManualDelayMs(默认 10 分钟)——对账未完成不许人裁,封死"人工误判与迟到 result 并发"的双发窗口。验证读封顶 3 轮；只有唯一正匹配自动核销成功,阴性不是“确认未发”,不得自动重发。
6. **迟到终局自动核销**:suspect 状态收到该命令的 result → 按 result 终局化、suspect 工单自动销案、落审计(与 cancel 的"result 赢"同构)——账本永远反映真相。

**配套立法**:今后任何业务 effectful 原语,必须与其配套验证读原语**同批交付**,缺验证读的 effectful 不准上线。

## 9. 手侧证词(journal / outbox)与恢复 [X 已激活]

### 9.1 存储形态与边界

chrome.storage.local 中只允许 base 投递层读写以下三类键；所有 DTO、枚举与 validator 均由 `contract.v1.json` 生成,plugin 不得另写接口:

```text
witness:meta       = WitnessStoreMeta{storeId,createdAt,schemaVersion=1,journalCount,outboxCount}
journal:{idemKey}  = JournalEntry{ref,idemKey,state,startedAt,committedAt?,result?,expiresAt}
outbox:{msgId}     = OutboxEntry{message:ResultEnvelope,createdAt,expiresAt}
```

`ResultEnvelope` 是完整的**已会话内** SX result 信封:`proto=1,kind=result,msgId,session(必填非空),ts,attempt,body:ResultBody`;outbox 的 key 必须等于 envelope.msgId,而 `body.ref` 指向原 cmd。`JournalEntry` 的 attempting 形态强制禁止 `committedAt/result`;committed 形态强制二者非 null且 `result.ref=ref`。`validateSchema` 在 Go/TS 两端同时执行条件字段、关联和 TTL 时间顺序校验。

与宪法“手不持业务账本”的边界是四道栅栏,缺一不可:

1. 键值只含协议标识符、时间与 result 协议消息；**不存 args.text、候选人正文、guards 或业务决策输入**。attempting 尤其只是一张“这把手术刀可能已经举起”的证词。
2. 仅 base 可见；program 只能经过 `beforeSideEffect`/完成回调请求投递层写入,无法查询、删除或绕过。
3. journal TTL 14 天、outbox TTL 7 天、各上限 512。只清理已过期记录,绝不逐出未过期记录腾容量；**任一 TTL 条目实际删除前必须先旋转 storeId**，删除/计数更新任一崩溃缝必须在下次读取时判 corrupt，不能留下同世代 `unknown`。任一表已满即在 attempting 和 handler 不可逆部分之前回 `WITNESS_UNAVAILABLE{reason:capacityExceeded},sideEffect=none`。
4. 允许整体丢失,但丢失必须表现为新的 `witnessStoreId`。`journalCount/outboxCount` 与条目增删一同维护；每次启动和关键读写都须复核实际 key 数，单条丢失、崩溃在删除中间或计数不符一律判库损坏/换代，不能在同一 storeId 下回答 unknown。脑看到换代只会增加验证/人工,绝不会把 unknown 当零副作用证明。手证词永远不能反向覆盖脑账本。

### 9.2 双写点与失败语义

真实 SX 的固定顺序如下,不得交换:

1. base 预检 feature、store 健康、journal/outbox 容量、idemKey 冲突；失败在动作前回 `WITNESS_UNAVAILABLE` 或相应 guard/context 错误。
2. program 完成页面、身份、`composer.empty` 与 `expectedTail` 核验后调用不可逆动作安全点；base 先写 `journal:{idemKey}=attempting` 并**等待 chrome.storage 写完成**。写失败回 `WITNESS_UNAVAILABLE{reason:writeFailed},sideEffect=none`,handler 的不可逆部分调用次数必须为 0。
3. 写成功后只允许一次物理动作。program 内部不得重试点击、键盘提交或网络发送。
4. 一旦越过 attempting 写点，本命令的**任何完整终局**（`ok`、`failed/none`、`failed/possible`或超时失败）都必须把 `journal=committed+完整 ResultBody` 与对应 `outbox=完整 ResultEnvelope` 放在**同一次 storage.set** 中再发送 result。`committed` 表示“该命令的终局已持久”，不等于“副作用已确认发生”；副作用真相仍由 ResultBody 的 `status/error.sideEffect` 表达。收到脑 ack(accepted/duplicate) 只删除 outbox，journal 保留至 TTL。越过 attempting 前的失败没有 journal，但仍须先进 outbox 再上报。
5. 后置条件未确认回 `POSTCONDITION_UNCONFIRMED/possible`，并按上一步原子持久这个失败终局。若 committed/outbox 双写失败，**不得用仅存于内存的任何终局绕过持久屏障**：保留 journal=`attempting`，熔断 dispatcher（不得继续 pump 已 accepted 队列），停止该连接的继续投递并由脑在重连 query 后进入验证读；同一 SW 内的重复 cmd 也只能回 duplicate ack，不能从内存重放易失 result。该分支既不得退回 `none`，也不得把易失事实伪装成可确认终局。恢复期只允许 query/report 与配套验证读推进；旧队列不得抢在恢复闸前重新获得页面执行权。

因此 SW 死于 attempting 写前=零副作用；死于 attempting 与 committed 之间=report attempting→验证/人工；死于 committed 后=outbox 补投或 report done。自动路径的方向始终是**可能少发,不能多发**。chrome.storage 回调与物理落盘之间是否仍有实现级窗口列入 §18 真机故障注入,不改变保守裁决。

### 9.3 重连四阶段(恢复闸)

手声明 `witness/1` 后,每次新会话在进入 normal 前严格经过以下四阶段；恢复期间脑冻结受影响账号的 intrusive/effectful 新派发,query/report 本身不占业务槽:

1. **outbox 补投**:手先按 hello 快照 `outboxPending=N` 补投这 N 条完整 result envelope,脑逐条持久去重并 ack。未收齐、损坏或计数漂移即证词链异常,不得越过闸门。
2. **query**:脑对该手账本中每条非终局真实 SX 逐条发 query(ref=cmd msgId)。脑必须使用命令派发时持久记录的 `witnessStoreId` 作比较。
3. **report**:手按 §4.8 从内存/journal 回 report。done 直接入账；queued/executing 继续等原执行；attempting、storeId 换代、缺失/损坏报告进入配套验证；只有同一 storeId 的 unknown 可证明没有越过 attempting 写点。
4. **安全重投并 normal**:对上一步唯一获零副作用证明的命令,只更新 session/ts/attempt并重投**原 msgId 与原 body**；不得铸新 msgId。其余命令必须已经 result 终局、正在等原执行、验证中或 suspect。全部分类落库后才解除恢复闸进入 normal。

同 bootId 重连也走 outbox→query 的恢复闸；bootId 只说明内存连续,不能替代持久 result 补投。query/report 可安全重复,迟到 report 只在当前物理连接、当前 recovery generation、目标仍非终局时采信,否则仅审计。

### 9.4 `chat.sendMessage@1` 配套验证读

验证原语固定为 `chat.readThread@1`,最多 3 轮。脑使用原命令 `conversationRef` 和 guard.expectedTail 构造读窗口；目标 hash 由原 args.text 按 §4.5 规范算法计算。只有在 expectedTail 之后**唯一**观察到 `direction=out,kind=text,contentHash=目标` 才自动补记 ok。以下情况一律不能推出“未发送”:锚缺失、零匹配、多个匹配、分页/页面/身份失败、证词库换代。它们全部落 suspect 转人工,**禁止自动重发**。

## 10. 错误对象与错误码 [M1]

```json
{ "code": "CTX_LOST_DURING_EXEC",
  "message": "仅人读,禁止程序分支",
  "retryable": "afterRecovery",        // yes | no | afterRecovery | manualOnly(建议值;脑矩阵是最终裁决;真实 SX failed/none 不因此自动恢复)
  "sideEffect": "possible",            // none | possible | confirmed(effectful 失败必填;拿不准一律 possible)
  "data": { },                         // 结构化细节,schema 随 code 入契约
  "evidence": [] }
```

v1 错误码全集由 `contract.v1.json.errorCodes` 生成;每码冻结 `phase=receipt|execution`。**receipt 码才有资格出现在 ack(rejected)**;execution 码说明命令已经 accepted,只能出现在 result(failed)。receipt 白名单固定为 PROTO_*、STALE_SESSION、QUEUE_FULL;“接收时已经过期”不是错误码,走 accepted→result(expired)。

| code | phase | retryable 默认 | sideEffect 可能值 | 说明 |
|---|---|---|---|---|
| PROTO_MALFORMED / PROTO_UNSUPPORTED_KIND / PROTO_UNSUPPORTED_CMD / PROTO_BAD_ARGS / PROTO_MSG_TOO_LARGE | receipt | no | none | 协议、caps/版本、schema、帧上限拒收 |

| CTX_NOT_READY | execution | afterRecovery | none | 页面不在/未登录/身份未 fresh probe;data.reason 复用 **notReadyReason**(含 identityUnverified)[S] |

| CURSOR_INVALID | execution | afterRecovery | none | cursor 过期或跨上下文误用;丢弃未入账聚合并从首页重启 [S] |
| TARGET_NOT_FOUND | execution | no | none | 仅留给未来非会话类目标;chat.* 禁止使用,不与上一码同义 [S] |

| PLATFORM_LIMIT | execution | manualOnly | none/possible | 风控/频控迹象 [X] |
| POSTCONDITION_UNCONFIRMED | execution | manualOnly | possible | 动作已做,后置条件预算内未观察到 [X] |
| EXEC_TIMEOUT_HAND | execution | R/I: yes;SX: manualOnly | none/possible | 手侧预算耗尽自行中止 |
| CANCELED_BY_BRAIN | execution | no | none | 取消诊断码;目标终局仍用 status=canceled [S] |

## 11. 健康模型 [M1 两级,S 起三级]

三个正交问题,三个信号源,禁止互推:

| 问题 | 信号 | 判定与动作 |
|---|---|---|
| 链路 | WS close / ping 到达 | **close=静默暂停派发**(SW 正常死亡是设计内常态,不告警不刷屏);连接开着但 ping 静默 ≥ graceMs(50s)=真异常(事件循环卡死/心跳代码坏),**告警**并关闭连接 |
| 行为能力 | ack/result 及时性 | 连续 3 个"关连接→重连→首命令仍 ackTimeout"周期(计数跨重连累计,任一 ack 正常即清零)→ HAND_WEDGED:告警转人工;每次关连接动作由 §7.2.1 完成,此处不重复 |
| 页面在场 [S] | ping.contexts[].ready + 传感链路 | ready=false → 该账号 CTX_MISSING:readonly 探测照发,intrusive/effectful 挂起等 ready;hb.sensors 持续 null 而页面声称在 IM 面=传感链路残废,能力级告警 |

派生态(脑侧手注册表):READY / DEGRADED / SUSPECT(断线<graceMs)/ DOWN。执行长命令期间 progress 兼任活性信号 [S],ping 与 progress 任一到达都刷新 lastSeen。

## 12. 感知与同步 [S](裁决定稿,C 卷全文为实施细则;C 卷成文于沟通规格 v3,巡检"每日手动开启"门控以 v4 与本节为准)

1. **轮询循环归脑**:巡检节律(**每日真人手动开启**后数分钟一轮,最晚至 24:00——沟通逻辑规格 v4)只存在于脑的账号 actor;手零自主循环、零业务定时器(允许:重连退避、alarms 复活闹钟、心跳、传感去抖的一次性 setTimeout ≤3s)。手对"巡检开没开"零感知——开关只是脑侧调度器的一个闸。
2. **感知三层栈**:event 提示(秒级,可丢)→ ping.sensors 缓存搭车(≤25s,可丢)→ **巡检对账命令(分钟级,唯一正确性来源)**。层 1/2 的值禁止进入任何业务判断,唯一权力=把下一轮巡检拉前(合并窗 25s、频控 ≥60s;**巡检未开启时段拉前失效**——含夜间与"当日尚未手动开启",提示只落脏标记,开启后首轮收割,v4 明确"开机首日集中催与归档是预期行为")——事件是油门不是刹车,徽章清零/闪空永不取消或跳过巡检。
3. **事件四类**(unreadBadge / pageNavigated / loginStateChanged / manualInteraction):字段、去抖与两次一致规则按 C 卷 §6.2 入契约;manualInteraction 开手动静默窗(默认 45s):窗内不派 intrusive/effectful,在途不撤销。
4. **同步机制**:脑持会话级账本锚尾(最近 ≤5 条 {direction, contentHash}),随 `chat.readThread` 首页下发,仅作滚动止损提示。单页最多 64 条且 compact data≤64KB;未到 anchor/顶部时回 `complete=false,nextCursor=opaque`,脑以相同 context/窗口参数带 cursor 续页,直至 `complete=true` 且 `anchorMatched || reachedTop`。各页内部按时间正序;首页是最新页,后续 cursor 页更老,聚合时依次**前插**且 cursor 保证页间不重不漏。手只在锚尾唯一命中时可裁掉锚前上下文;重复命中必须保留完整候选窗口。脑聚合成一份有界完整快照后,在快照任意连续片段中寻找账本后缀的最大重叠;同样最大长度有多解时取最靠后的起点(最少新增)并审计,随后才产出“本轮新增”投影,中间页不得入账或触发事件。零重叠→丢弃本轮聚合后 deep=true 从无 cursor 重启→仍零重叠按收编处理+审计,不静默吞。
5. **卡片=身份哈希+状态分离**:contentHash 只哈希卡片身份(cardType+关键参数),cardState(pending/accepted/rejected/expired)独立;按钮事件=对齐位置上的状态跃迁——旧卡跨轮重复触发机制性不可能,"已结束者点旧卡直进已约面"天然支持。
6. **列表=变更检测不是账本**:`chat.readList` 按最近活跃排序,单页最多 32 会话且 compact data≤64KB;`complete=false` 必带 opaque nextCursor,脑以相同 filter/stopOlderThanDays/maxSessions 续页,直到 8 天截止回 complete=true。脏判据=unread>0 ∪ lastMessage 摘要≠账本尾(后者兜住用户手动读走的假阴性)。不脏且无到期时钟→本轮零页面动作。
7. **收编边界**:每会话 `adoptedBoundarySeq`,边界前消息不触发事件、不进对话轮,仅作语境。
8. **多标签仲裁**:SW 维护 canonical 平台标签页;驱动命令与传感只在 canonical 执行/发射(manualInteraction 例外:任何平台页的用户输入都上报)。
9. **账号主体确证**:`probe.platform.data.principalFingerprint` 是平台无关、不透明、只许相等比较的登录主体指纹,不得暴露 Cookie/token/明文平台 userId,脑不得解析。首次真人绑定前尚不存在 `accountRef`,因此仅绑定流程发出的 `probe.platform` 可按原语元数据 `contextOptionalBeforeBinding=true` 省略 context；已绑定账号 actor 发出的 probe 仍必须携带完整 context,其余 [S] 原语无例外。真人绑定时脑保存指纹;之后每条 intrusive/effectful 命令在 context 携带 `expectedPrincipalFingerprint`。手在首次驱动页面前复读比较,并在返回任何账号数据或进入不可逆动作前再复核;不一致回 ACCOUNT_MISMATCH(sideEffect=none,manualOnly),不得交付跨账号数据。`nav.ensureSurface` 是 pageAbsent 时唯一恢复驱动例外,但身份一旦可见仍须在返回前复核。
10. **身份三态**:已绑定但 pageAbsent/contentScriptDead 暂不可观测时保留绑定,仅允许 probe/nav 恢复;新 session/boot 或健康过期时必须 fresh probe 一致后才放行驱动;明确 mismatch 或 logout→login 时绑定立即失效,只允许 probe,必须真人重新确认。登录态 `in` 本身永远不等于账号一致。
11. 原语四条:`probe.platform`(readonly,5s/30s)、`nav.ensureSurface`(intrusive,lease 30s)、`chat.readList`(intrusive,lease 60s)、`chat.readThread`(intrusive,lease 30s,兼任 [X] 验证读)。args/data 的 required、nullable、枚举、上下限均以 `contract.v1.json.schemas.types` 为唯一机器源;关键边界为列表页≤32、线程页≤64、每页 compact data≤64KB、cursor≤2KB、anchorTail≤5、摘要≤200 Unicode 码点。两种 data 都满足 `complete=false ⇔ nextCursor 非空`;列表 complete=true 时 nextCursor 必须空,线程还必须满足 `complete=true ⇔ anchorMatched || reachedTop`。opaque cursor 只许原样回传,不得解析、跨账号/会话/参数复用;CURSOR_INVALID 时脑丢弃本轮未入账聚合并从无 cursor 安全重启。任一条目本身超限则 PAYLOAD_LIMIT,不准伪造 complete 或裁剪字段。

## 13. 大载荷(blob)[X]

简历 HTML、截图和不可分页的大载荷走同一 Go 进程的 localhost HTTP 内容寻址端点(`PUT /v1/blobs`,`sha256:<hex>` 引用,单件 ≤20MB,30 天无引用 GC,token 会话作用域经 welcome 下发);WS 消息只携带 ref。完整原语结果 JSON 用 `result.dataBlobRef`,取回后先验 sha256 与大小,再按该原语 dataSchema 校验;单条消息的大文本用 message.blobRef。`data` 与 `dataBlobRef` 在 status=ok 时恰有一个。S 批在 `blob/1` 未激活期间先用 §12 的 cursor 把列表/线程结果切成每页≤64KB;单个不可再分条目超过 2KB 文本边界或整页仍无法表达时回 PAYLOAD_LIMIT,不准截断、发明字段或突破 256KB 帧上限。理由:控制面不被大帧队头阻塞(心跳纯度)、免 base64 税、传输无关(Claim Check 模式)。**blob 通道零协议语义**——不推进状态,不构成第二语义通道。

## 14. 版本与能力协商 [M1]

- **首客前例外**:第一次给真实客户安装前,可按 AGENTS.md 的四项删除举证、持久化兼容评估和硬切换程序,在当前 `proto`/原语版本内做破坏性清理。该许可只处理对外兼容形态,不允许削弱已经冻结的安全内核语义。
- `proto`:兼容冻结后的跨原语破坏性开关;兼容冻结后,当前主版本内一切变更是加法(must-ignore)。信封、kind 或跨原语公共结构不兼容时升级主版本并提供迁移/双栈方案。
- 原语粒度版本 `name@ver`:兼容冻结后,args/data/guards/evidence schema 不兼容变化=原语版本+1;脑按会话 caps 门控派发,支持双端灰度不同步。
- `contractHash`:在线握手仍仅作漂移告警(哈希对加法变更也变,普遍硬拒会把无害灰度变成瘫痪);真正的在线协议门禁是 proto/caps。首客前破坏性批次另受**部署硬切换栅栏**约束:暂停派发,重启脑并重载插件,确认哈希一致前禁止 effectful;这不是鉴权,也不把 mismatch 变成握手拒绝。
- codegen:`contract/` → Go(类型+校验+状态机常量+合法转移表)与 TS(类型+常量+校验);CI 校验两端生成物一致;禁止手写协议类型。

## 15. 反模式清单(明令禁止)[M1]

1. 两端手写协议字段/别名——唯一来源是 codegen,code review 见手写字段名即打回。

9. 追求协议级恰好一次(QoS2 迷信)。
10. 大载荷内联 base64 进 WS。
11. 过程式命令("点第 3 个会话")——命令必须声明式,这是 intrusive 可重派的构造前提。
12. 手侧批量聚合命令、自行排程——一 cmd 一 ack 一 result,节奏权 100% 在脑。
13. 无版本报文。
14. 心跳携带业务载荷/心跳到点反向采集。
15. 静默去重——重复到达必须重新 ack(+必要时重放 result)。

19. 同一条存活 TCP 上重发帧——ackTimeout 的唯一动作是重建连接。
20. 事件直接触发业务命令——事件唯一权力是调整巡检开跑时刻/静默窗/健康档。
21. retained 式"上线即收到陈旧命令"——脑对离线手不排队,命令现算现发。

生产 preflight 与 commit 必须字面调用同一同步 evaluator 和同一组参数。evaluator 在三个动作边界执行:attempting 前、写入正文前、输入事件后且唯一标准动作前;每次核对账号、界面目标、动作窗口、唯一可见控件、编辑器期望值、消息基线连续性、`expectedTail` 与目标绑定。守卫只核对世界状态和被直接调用动作接口的公开标准语义,不得遍历、互证或以平台私有框架、SDK、渲染层、事件层的一致性授权发送。

final evaluator 绿色后不得再读取可变页面状态,必须立即对当轮解析出的唯一控件调用一次公开标准动作;原语内不得重试。post observer 必须继续读取同一目标绑定的服务端消息视图,相对 baseline 只接受恰好新增一条服务端确认记录;该唯一记录还必须是我方 `text` 且正文 hash 相等。零新增、多新增、并发入站、明确失败与成功并存、目标换绑或读取失败均为阴性,收束为 `POSTCONDITION_UNCONFIRMED/possible`、恢复验证或 suspect,绝不补动作。各平台如何选择权威消息视图、稳定消息身份和公开动作接口,只写入该平台事实文档与 program,不进入本协议。
