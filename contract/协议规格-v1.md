## 1. 模型与公理

1. **脑是唯一账本。** 手随时失忆(SW 空闲约 30 秒被杀、页面导航杀 content script、浏览器重启),失忆是常态。手侧一切存储只能是"证词"——丢了只准退化为"更多转人工",不准导致错误的自主行为。
2. **语义方向永远脑→手;传输连接方向手→脑。** 手主动拨号、重连、发心跳,但协议语义上手没有主动权:只执行命令、只上报传感提示。
3. **语义传输无关。** 任何正确性不押在 WebSocket 特性上(连接即会话、帧有序、断开即边界都不作为正确性依据)。验收思想实验:换 MQTT 5 承载,语义零修改(A 卷 §13.2 已逐条核过)。
4. **外部副作用极贵。** 重复给候选人发消息=骚扰=封号风险。纪律:宁可少发;一切歧义不自动重发,只转人工。协议目标:让"多发"在自动逻辑下机制性不可能,让"少发+人工"成为歧义唯一归宿。
5. **契约单一源头。** 两端协议类型与运行时校验全部出自 `contract/` codegen(Go/TS 类型、常量、validator),禁止手写;关联字段在生成类型里非可空。CI 校验全部生成物一致。
6. **单一命令通道。** 测试页、调度器、将来的运营工具都只是脑体内的命令生产者;协议中不存在"测试命令"概念。手侧唯一入口是命令分发器。
7. **平台无关。** 命令与结果的语义字段一律意图级;DOM/selector/tabId/windowId/平台专有 id 只许出现在 evidence 与日志,脑逻辑不得读取 evidence 内容做分支。
8. **业务节奏全在脑。** 巡检、调度、重试、超时判定只存在于脑;分钟级延迟是业务规格明文允许的(`docs/沟通逻辑规格-v4.md` 巡检模型:每日真人手动开启,数分钟一轮,最晚至 24:00),协议不为秒级实时付复杂度。

环境基线:Chrome ≥ 116(活跃 WS 收发重置 SW 30 秒空闲计时);chrome.alarms 最小约 30 秒;脑=Electron 内常驻 Go 服务+SQLite。

## 2. 传输绑定与本地握手

### 2.1 连接 [M1]

- 端点 `ws://127.0.0.1:{port}/v1/channel`;默认端口 **17872**(明确不复用 17321),脑侧配置文件与手侧扩展 options 页均可改。文本帧,UTF-8,一帧一条 JSON 消息,不批量不拼接。
- 单帧硬上限 `limits.maxMsgBytes`(默认 256 KB,welcome 下发),按**完整 envelope 的 UTF-8 字节数**计算;通用 body 内联建议线 `inlineBytes`=32 KB。感知批次另冻结:单条消息内联文本 ≤2 KB、内联 `result.data` ≤64 KB、证据文字 ≤2 KB;更大完整内容只可走 `blob/1` Claim Check。未协商 blob 时必须在执行前或组装结果时响亮失败(PAYLOAD_LIMIT),禁止静默截断;收到超硬帧一律 PROTO_MSG_TOO_LARGE。
- 手侧重连退避:1s 起 ×2,封顶 30s,±30% 抖动;连接稳定 60s 后退避归零。chrome.alarms 看门狗(60s)发现"未连接且无在途尝试"即发起——它只是复活闹钟,不是心跳。runtime.onStartup/onInstalled 立即尝试。

### 2.2 本地可信握手与连接边界 [M1, 2026-07-17 修订]

威胁模型:用户明确把同机本地环境视为可信。协议防网页脚本误连与跨站 WebSocket,不试图防恶意本地进程;如果未来出现远程手、不可信本地多用户或云端监听,必须重新设计传输鉴权,不能把本节直接外推。

1. **只监听回环地址**:脑只在 `127.0.0.1` 监听固定端点,不得监听 `0.0.0.0`、局域网或公网地址。
2. **Origin 前置校验**:升级 WebSocket 前,脑只接受 `Origin` 以 `chrome-extension://` 开头的请求,其余请求直接拒绝。这是网页侧边界,不是对本地进程或某个特定扩展的身份证明。
3. **手自己出生身份**:插件首次运行以密码学安全随机源生成稳定、不透明的 `handId`(长度 1..128),写入 `chrome.storage.local`。每个 Chrome profile 天然拥有不同的本地实例 ID;SW/浏览器重启复用,清除扩展数据或重装后生成新值。`handId` 只用于手注册表、路由和单活接管,不是凭据,也不等于招聘账号绑定。
4. **零配对、零握手身份 token**:hello 的 `handId` 必填且不可空,没有 `auth`;welcome 不签发 `handId`、共享 token 或其他手身份凭据。不存在配对窗口、待确认连接、配对码、`paired_hands` 凭据表或配对管理 UI。§13 推迟的 `blob.token` 是会话作用域的 HTTP 数据面 capability,不参与 hello 身份判定,不得被当作配对机制。
5. **10 秒握手**:手发送 hello 后,脑完成 Origin、主版本和结构校验并立即回 welcome/bye;10 秒未收到响应,手关闭连接并进入正常重连退避。没有等待人工确认,因此没有握手期 pre-session ping 或 70 秒特殊超时。
6. **单活连接**:同 `handId` 的新 hello 顶掉旧连接(旧连接收 bye(SUPERSEDED));非当前物理连接来的任何消息丢弃并审计。当前物理连接上只有已 accepted 命令的 `progress/result` 可保留该命令创建时的旧 `session`;`ack/ping/event` 仍必须与当前会话一致。
7. **协议摘要不是签名**:`contractHash` 是契约文件公开字节的 SHA-256 摘要,只用于漂移告警。它没有秘密材料,不是签名、MAC、口令或身份凭据;不匹配不得硬拒连接,真正门禁是主版本与逐项 caps/features。
8. 显式不做(防回潮):人工配对、共享 token、一次性配对码、二维码、旧扩展 ID 白名单、Native Messaging 发现、动态端口发现。若威胁模型改变,以新安全设计和相应协议版本处理,不得悄悄恢复旧字段。

本地明文 ws 可接受,依据是回环监听和用户声明的本地可信边界;wss 自签证书在该边界内零收益高摩擦,不做。

## 3. 消息信封 [M1]

信封 7 字段,冻结;扩展只发生在 body 内。

```json
{
  "proto": 1,
  "kind": "cmd",
  "msgId": "01JB2K3G8XF5N7Q9R0S1T2U3V4",
  "session": "s-01JB2K1AAAAAAAAAAAAAAAAAAA",
  "ts": 1768546201345,
  "attempt": 1,
  "body": { }
}
```

| 字段 | 类型 | 语义 |
|---|---|---|
| proto | int | 协议主版本。不兼容变更才递增;主版本内只做加法,接收方必须忽略不认识的字段(must-ignore)。 |
| kind | string | 消息种类(§4)。不认识的 kind:命令方向 ack 拒绝(PROTO_UNSUPPORTED_KIND),上报方向记日志丢弃。 |
| msgId | string | 消息逻辑身份:唯一不透明串(建议 ULID,手侧 crypto.randomUUID 亦可),接收方不得解析其内容。**重传时不变**,是去重键与关联锚点。 |
| session | string\|null | 消息创建时所属会话(welcome 分配)。hello/welcome/bye 为 null。命令只在 session=手当前会话时可执行;已 accepted 命令的 progress/result 携带创建时会话,只要来自该手当前物理连接仍有效。 |
| ts | int64 | 发送方毫秒时钟,仅诊断;重传时更新。**永不**用于去重、排序或状态裁决。 |
| attempt | int | 同一 msgId 第几次发送,仅诊断(>1 说明投递层在重传)。 |
| body | object | kind 专属载荷。 |

所有线上 `int/int64` 都限制在 JSON/TypeScript 可精确表示的 safe-int53 范围(±9,007,199,254,740,991);Go/TS validator 使用同一 `safeInteger` 规则,防止跨端四舍五入后关联、deadline 或排序值分裂。

命名纪律:线上字段一律 camelCase;所有"指向另一条消息"的字段只有一个名字 **`ref`**,在生成类型里非可空——别名漂移与"回执丢关联 id"从构造上灭绝。

重传纪律:同一 msgId 重传时,信封可变字段为 ts、attempt、**session(跨会话重投时更新为手当前会话)**;msgId 与 body 不可变。

## 4. 消息种类

全集 13 种(契约 append-only);M1 激活 8 种,S 批再激活 progress/event/cancel,共 11 种:

| kind | 方向 | 需对方 ack | 批次 | 用途 |
|---|---|---|---|---|
| hello | 手→脑 | 以 welcome/bye 作答 | M1 | 自报身份、bootId、能力、版本 |
| welcome | 脑→手 | 否 | M1 | 握手完成:分配会话、下发参数 |
| bye | 脑→手(手→脑方向 [远] 预留:优雅下线;v1 手侧终止一律直接关连接) | 否 | M1 | 拒绝握手/宣告关闭/顶替,带原因码 |
| cmd | 脑→手 | 是 | M1 | 下发命令 |
| ack | 双向 | 否 | M1 | 收妥回执:对 cmd=已解析入队;对 result=脑已持久化 |
| result | 手→脑 | 是 | M1 | 命令终局,唯一携带 data/error/evidence 之处 |
| ping | 手→脑 | 以 pong 作答 | M1 | 会话内心跳:SW 保活+半开检测+就绪度 |
| pong | 脑→手 | 否 | M1 | 心跳应答,带脑侧时钟 |
| progress | 手→脑 | 否(可丢) | S | 长命令阶段汇报,兼执行期活性;stage 为自由文本,禁止程序分支 |
| event | 手→脑 | **否(可丢)** | S | 传感提示。QoS0:无 ack、无重发、丢了无害(正确性在对账层) |
| query | 脑→手 | 以 report 作答 | X | 脑询问命令在手侧状态(歧义消解) |
| report | 手→脑 | 否 | X | 按手侧 journal/内存作答(state: unknown/queued/executing/attempting/done) |
| cancel | 脑→手 | 是 | S(随租约) | 尽力而为取消;ack 只确认请求收妥,与目标 result 赛跑时 result 赢 |

### 4.1 hello(手→脑)[M1]

```json
{ "body": {
  "handId": "h-7f3ak2m9qwe8rty0uiop", // 插件本地随机生成并稳定保存;不是凭据
  "bootId": "b-a83kd02m",         // SW 内存随机值,SW 每次出生新生成——手记忆连续性的唯一指示器
  "protoSupported": [1],
  "contractHash": "sha256:...",   // 公开摘要,仅漂移告警;不是鉴权签名
  "app": { "extVersion": "0.1.0", "browser": "chrome/126" },
  "caps": ["debug.ping@1", "debug.switchWindow@1", "debug.slowEcho@1"],
  "features": ["progress/1", "lease/1", "cancel/1"]  // 独立协议特性开关(非原语)
} }
```

**caps 会话不可变**:program 热更后手必须断线重连、以新 hello 重报能力(localhost 重连毫秒级,换来"会话内能力恒定"强不变量)。脑派发前查会话 caps,无能力的命令不派发、意图挂起并在 UI 呈现(能力缺口是运营事件,不是错误循环)。

### 4.2 welcome(脑→手)[M1]

```json
{ "body": {
  "session": "s-01JB2K1AAA...",
  "proto": 1,
  "hb": { "intervalMs": 20000, "graceMs": 50000 },
  "limits": { "maxMsgBytes": 262144, "inlineBytes": 32768 },
  "contractMatch": true,
  "now": 1768546200449,
  "sensors": { "badgeDebounceMs": 800, "badgeMinEmitIntervalMs": 5000,
               "navSettleMs": 500, "manualQuietMs": 45000 },  // [S] 传感参数由脑下发,手无自带策略数值
  "blob": { "endpoint": "http://127.0.0.1:17872/v1/blobs", "token": "bt-...", "maxBytes": 20971520 }  // [X]
} }
```

握手拒绝或会话关闭走 bye:`PROTO_INCOMPATIBLE` / `SUPERSEDED` / `SHUTTING_DOWN`。Origin 不合格在 WebSocket 升级前直接拒绝,不会进入协议帧。

### 4.3 cmd(脑→手)[M1]

```json
{ "body": {
  "name": "chat.sendMessage",
  "ver": 1,
  "context": { "platform": "zhilian", "accountRef": "acc-01",
               "expectedPrincipalFingerprint": "opaque-v1-..." }, // debug.* 或首次绑定前 probe.platform 可缺省;指纹只许相等比较
  "args": { "conversationRef": "c-5f6a", "text": "..." },
  "idemKey": "ik1:zhilian:acc-01:chat.sendMessage:cand-98a7:int-01JB2K2Z",  // 仅 effectful 携带
  "deadline": 1768546801345,      // 绝对过期时刻(脑钟):手出队时与不可逆动作前一刻双查,过期即回 result(expired)
  "execBudgetMs": 60000,          // 手侧单次执行预算,超时自行中止回 EXEC_TIMEOUT_HAND;上限 240000(MV3 5 分钟强杀留余量)
  "leaseMs": 60000,               // [S] 需 lease/1;5s..120s;progress 按脑接收时刻续租,绝不越过 deadline
  "guards": { }                    // [X] 语义化前置断言,词汇随首个 SX 原语定
} }
```

手侧执行模型:**全局严格串行**,先 ack 入队,FIFO,深度 16,满则 ack 拒绝 QUEUE_FULL(背压)。只有协议/session/caps/schema/队列类问题走 ack(rejected)。命令在收帧时已经过 deadline 仍先 ack(accepted),随后从队列的“不可执行终局”分支回 result(expired),**绝不调用原语 handler**;accepted 后才发现页面、账号、用户或目标问题一律 result(failed)。

### 4.4 ack(双向)[M1]

```json
{ "body": { "ref": "01JB2K3G8X...", "status": "accepted" } }
```

- status:`accepted` / `rejected`(附 §10 错误对象,此层错误恒 sideEffect=none)/ `duplicate`。
- 对 cmd:accepted=已解析、schema 过验、已入执行队列(**不是**开始执行,更不是完成)。
- 对 result:accepted 与 duplicate **等价**——皆表示脑侧已持有该终局,手删除队列条目(否则补投会循环到 SW 死亡,挤占队列)。
- **去重不等于沉默**:重复到达必须重新 ack(duplicate);若该 cmd 已有终局,补发一份 result(replayed=true)——Stripe 式结果重放。

### 4.5 result(手→脑)[M1]

```json
{ "body": {
  "ref": "01JB2K3G8X...",
  "status": "ok",                  // ok | failed | canceled | expired(四者皆终局;拒收在 ack 层)
  "data": { },                     // ok 时与 dataBlobRef 恰有一个;内联按原语 dataSchema
  "dataBlobRef": null,             // blob/1:完整 data JSON 的 sha256 内容引用,取回验哈希后再跑 dataSchema
  "error": null,                   // failed 时必填,§10
  "evidence": [ { "type": "postcondition", "text": "..." } ],  // effectful ok 必填 [X 起强制];对脑不透明
  "replayed": false,
  "execMs": 6890
} }
```

effectful 的 ok 定义为**观察到后置条件**,"我点了按钮"不算(宪法原文)。

### 4.6 ping / pong [M1]

```json
{ "kind": "ping", "body": {
  "queueDepth": 1,
  "inFlight": "01JB..." ,          // 正在执行的命令 msgId,无则 null
  "contexts": [],                  // [S] 各账号上下文就绪度 { platform, accountRef, ready, reason }
  "sensors": null                  // [S] 只运缓存现货(如 unreadTotal),禁止心跳到点反向拉取 DOM
} }
{ "kind": "pong", "body": { "now": 1768546220003 } }
```

ping 由完成握手的手发起,间隔 `hb.intervalMs`(默认 20s)±20% 抖动,一石三鸟:WS 活动保活 SW(<30s);手凭 pong 缺失(连续 2 次)检测半开连接并主动重连;携带就绪度供脑健康模型。**心跳不携带业务数据**——sensors 只是缓存读数转发,心跳变胖=健康信号失真。hello/welcome 之前没有会话心跳;握手由独立的 10 秒 helloTimeout 约束。

### 4.7 progress / 租约 / cancel [S]

三项分别用 `progress/1`、`lease/1`、`cancel/1` 协商;脑不得因手只支持其中一项就推断另两项。`chat.readList`、`chat.readThread` 等声明 `leaseMs` 的原语只有在三项所需能力齐备时才可派发。

```json
{ "kind": "progress", "body": { "ref": "cmd-msg-id", "stage": "page 3", "pct": 40 } }
{ "kind": "cancel", "msgId": "cancel-msg-id", "body": { "ref": "cmd-msg-id", "reason": "leaseExpired" } }
{ "kind": "ack", "body": { "ref": "cancel-msg-id", "status": "accepted" } }
```

- 租约从脑收到目标命令的 ack(accepted) 的本地单调时刻开始;每条**schema 合法、ref 指向仍在途命令、来自该手当前物理连接**的 progress 以脑接收时刻续到 `now+leaseMs`,但永不越过绝对 deadline。该 progress 可保留目标命令创建时的旧 session;旧物理连接、迟到、未知 ref、已终局命令的 progress 只记审计,不复活命令。`stage` 仅人读,`pct` 可缺省且范围 0..100,二者都禁止用于程序分支;合法 progress 与 ping 一样刷新手的 lastSeen。
- 租约 gap 到期代表本次物理尝试失联,不是业务终局:脑先发唯一 cancel,保留 1000ms 的有界 result 竞态窗;窗内目标 result 先到则 result 赢。竞态窗后仍无 result,readonly/intrusive 才按 §8 作废并进入 replacement chain,effectful 进入 suspect。竞态窗不延长绝对 deadline,progress 不能把 deadline 后移。
- cancel.body.ref 指向**目标 cmd**;cancel 自己的 ack.ref 指向**cancel 帧 msgId**。queued 目标直接移出执行候选并回目标 result(canceled);executing 目标在取消安全点前协作中止并回 result(canceled);越过安全点只记录取消请求,照常完成目标 result。ack(accepted) 只表示请求已收妥,不证明取消成功;无论竞态顺序,目标 cmd 的首个合法 result 赢并成为唯一终局。
- cancel.reason 是机器枚举:`leaseExpired | deadlineImminent | superseded | operator | shutdown`;不得用自由文本决定行为。

## 5. 确认层级:每层能推出什么 [M1]

| 层 | 信号 | 能推出 | 不能推出 |
|---|---|---|---|
| L0 | WS write 返回 | 字节进本端缓冲 | 对端收到 |
| L1 | ack(accepted) | 手收到、过验、入队 | 会被执行、会成功 |
| L2 | result 终局 | 手的终局判断+副作用标注+证据 | 平台真把消息投给了候选人 |
| L3 | 脑的业务核验(readonly/intrusive 对账回读)[X] | 逼近平台侧真相 | 绝对真相 |

端到端论证:低层确认永远不能替代高层核验。L1 缺失按投递问题处理(§7);L2 缺失按执行问题处理;L3 不通过**不自动重发,只转人工**。

## 6. 命令分类学 [M1 定义,S/X 逐批启用]

三类,契约静态声明,**按最坏实现定级**(声明从紧无害,从宽踩页面):

| class | 定义 | 重试/重派 | 排队 | idemKey | evidence |
|---|---|---|---|---|---|
| `readonly` | 不驱动页面、无平台侧效果的纯探测 | 自由重派(新 msgId 同 args),有轮次封顶 | 不进账号串行域 | 禁止 | 不需要 |
| `intrusive` | **业务只读或声明式幂等**,但驱动/占用页面;平台侧效果至多是一次性幂等的(已读回执、页面就位) | 同 readonly:自由重派安全 | **进账号串行域**(与 effectful 同队互斥,跨手生效) | 禁止 | 不需要 |
| `effectful` | 不可回滚、可叠加的外部副作用(发消息、发卡) | **永不自动重派**;歧义→suspect 转人工 | 账号串行域 | 必填 | 必填 [X] |

归类判据(litmus,写进契约注释):执行两次与一次对候选人可感知世界无任何额外差别、且不发出任何业务内容→看是否驱动页面:驱动=intrusive,不驱动=readonly;否则=effectful。**拿不准=effectful**(与 sideEffect"拿不准标 possible"同一保守方向)。

intrusive 原语须另声明 `platformSideEffect: "none" | "idempotentReadReceipt"` 供审计。intrusive 单列的原因(C 卷 §4.2):判成 readonly,重派会踩掉同账号在途发送的页面;判成 effectful,"结果未知态的验证读"陷入循环依赖。

原语注册六要素:`name、ver、class、argsSchema、dataSchema、preconditions`(effectful 另加 `evidenceSchema`);外加纪律第七条:**原语实现内部禁止自主重试**——原语=单次尝试+观察后置条件+诚实上报,重试决策归脑(旧系统"点击后重试一次"的修复移植时必须剥离内部重试,否则两层重试相乘)。

**debug 串行域**:debug.* 的 intrusive/effectful 命令进该手专属的 `debug` 串行域(每手一个,与账号域平行,规则同款);测试页命令同样经脑铸造意图行,idemKey 照常派生(§7.4 debug 形态)。

## 7. 投递保证、重传与幂等

### 7.1 选型 [M1]

- 命令通道:**至少一次投递 + 手侧去重 = 有效一次入队**。
- 执行语义:readonly/intrusive 至少一次(可重派);effectful **在歧义处降为至多一次**(宁可少发)。
- 上报通道:result 至少一次(内存队列重发直到脑 ack;[X] 起 SX 的 result 另有持久 outbox)+ 脑按 msgId 持久去重(processed 表 30 天)。
- 不追求恰好一次:两将军定理;QoS2 只保 broker-client 报文不重,应用崩溃照样重复,纯付费迷信。

### 7.2 重传规则(同 msgId)[M1]

**同一条存活的 localhost TCP 连接上永不重发帧**——loopback 不丢包;送达了没 ack 说明手内部卡死,再塞一帧只是多一条日志(B 卷 1.2)。规则:

1. ackTimeout(3s)内**无任何应答**(连 rejected 都没有)→ 判连接可疑 → **脑主动关闭连接**,触发手侧重连。本规则与反模式 19 只约束"无应答的帧"。
2. 帧重发只发生在**重连之后**,且仅当新 hello 的 `bootId` 与派发时记录一致(手记忆连续,去重表有效,重复投递被吸收);重发帧的 session 更新为新会话(§3 重传纪律)。
3. bootId 变了:readonly/intrusive 重新派发(新 msgId);effectful **一律进 suspect**(§8),绝不盲重发。
4. **ack(rejected) 是应答,不是歧义**:瞬态拒绝(QUEUE_FULL 退避后、STALE_SESSION 换会话后)允许同 msgId 再投,同一连接亦可(它有应答,不属"无应答帧重发");协议性拒绝(PROTO_*)记 rejected 终局。effectful 的"永不自动重派"精确定义为**无终局信号的歧义下永不重派**——ack 层干净拒绝恒零副作用(去重先于 session 校验,重复帧永远走 duplicate 不会走 STALE),不属歧义。

### 7.3 手侧去重与队列 [M1]

- **收帧管线顺序(固定,不许重排)**:信封/body 结构校验 → **msgId 去重**(命中即 ack(duplicate),有终局则重放 result,**不再看 session**)→ session 校验(**仅受理时刻生效**:已 accepted 的命令跨会话继续执行,progress/result 带创建时会话照常入账;脑侧仍以当前物理连接为不可放松的来源围栏)→ caps/原语版本 → args schema → **deadline 时间分支**:若已过期,直接写去重表、ack(accepted) 并进入不占 FIFO 容量的终局队列回 result(expired);否则检查队列容量 → 写去重表并 ack(accepted) → FIFO 执行候选。**只有 ack(accepted) 的命令才进去重表**,被拒命令不入表(为瞬态拒绝的同 msgId 再投留路)。deadline 的字段类型仍在 schema 阶段校验;时间已过永不因 QUEUE_FULL 改成 rejected,handler 调用次数必须为 0。
- **去重表:内存 LRU 256,作用域=SW 一次生命(bootId)**,键=msgId(idemKey 冗余记录),值含终局 result 缓存。命中即 ack(duplicate)+必要时重放 result。**严禁写 chrome.storage**——同 id 重发仅发生在 bootId 未变时,内存作用域恰好与安全窗口重合,这是规则 7.2 与去重表的自洽点。
- 断线不弃队:已 accepted 的命令在 SW 存活期间继续执行(deadline 出队双查防僵尸);result 进内存有界队列(50 条,result 优先),重连即冲,SW 死即丢(设计内,由脑侧 WAL 与 suspect 兜底)。
- 去重先于一切副作用:msgId 表与([X] 起)idemKey journal 的查询发生在入队前。

### 7.4 幂等键(idemKey)[M1 格式,X 启用]

```
ik1:{platform}:{accountRef}:{primitive}:{targetRef}:{intentId}    业务形态
ik1:debug:{handId}:{primitive}:{targetRef}:{intentId}             debug 形态(测试页命令同样经脑铸意图行)
```

- **脑生成、从业务意图行确定性派生**(intentId=脑 SQLite 意图主键)。同一意图无论重发多少次、脑重启多少次,键恒同——比 Stripe 随机键更强:把"忘了复用"这种人祸也灭掉。
- 粒度=意图,不是"候选人+动作"全局唯一(隔天跟进是新意图新键);粒度裁决权在脑业务层。
- 仅 effectful 携带;readonly/intrusive 禁止(避免假安全感)。

### 7.5 幂等三道闸 [X 全部就位]

1. **脑账本闸(权威)**:intents 表 UNIQUE(idemKey);派发前查账本,已有非失败终局或 suspect 冻结中的意图,拒绝铸造新命令。手侧全丢也拦得住。
2. **手证词闸(缩窗)**:§9 journal——SW 死于执行窗口的任意点,后果只可能是少发+人工,不可能多发。
3. **平台回读闸(L3)**:发送前 guards(如"我方无先前消息")+ 发送后对账回读;读到已有我方消息即停手转人工。

重复发送需三道闸同时失效,而每道闸单独失效的后果都是"少发+人工"。

## 8. 命令生命周期、超时矩阵与 suspect [M1]

### 8.1 脑侧账本状态机(SQLite 持久)

**先记账后发送**:命令必先以 `queued` 落库(在途日志:msgId、name、class、idemKey、bootId@dispatch、deadline、状态)再进 socket。脑的账本永远是手所见命令的超集。

```
queued → sent → accepted → ok | failed | canceled | expired   (result 为准)
   sent --ackTimeout(无应答)--> (关连接,待重连按 §7.2 处置)
   sent --ack(duplicate)--> 视同 accepted
   sent --ack(rejected, 协议性 PROTO_*)--> rejected(终局)
   sent --ack(rejected, 瞬态 STALE_SESSION/QUEUE_FULL)--> queued(待重投,非终局)
   accepted --lease gap [S]--> readonly,intrusive: void(可铸 replacement);effectful: suspect
   任何非终局 --deadline+宽限 过 / bootId 换代 / 脑重启扫描--> readonly,intrusive: void(作废,巡检自然重派)
                                                            effectful: suspect(人工队列;迟到终局自动核销,§8.3)
人工裁决 suspect → resolvedOk | resolvedFailed(可由人铸新意图;自动逻辑不代劳)
```

**迟到帧总则**:任何终局/void 状态收到迟到的 ack/result,一律审计,不静默丢弃;suspect 收到迟到 result 按 §8.3 法条 6 自动核销;void 收到 result 只审计不改账(它是"脑账本是手所见超集"断言的观测点)。

**物理命令与逻辑派发链分层** [S]:每个 msgId 的 rejected/void/ok/failed/canceled/expired 都先独立持久化;需要安全重派时以新 msgId 建 `replacementOf` 链。单条物理命令终局不等于逻辑等待结束:等待者只在整条 replacement chain 最终成功、失败或达到重派上限时唤醒,不得因中间 void/expired 提前返回,也不得永远只等原始 msgId。cancel/result 竞态仍以目标物理命令的首个合法 result 为准。

**脑重启恢复**:启动即扫在途日志,未终态 readonly/intrusive 作废,未终态 effectful 全部 suspect——脑的任何一次重启,静默丢失降为"响亮的人工确认项"(在途 effectful 每账号恒 ≤1,量可控)。

**脑对离线的手不排队命令**:巡检 tick 现算现发,手不在线本 tick 跳过;命令是状态的投影,投影留在脑侧。deadline 取短值(巡检类 ≤ 2×execBudget)。

### 8.2 超时矩阵(v1 裁剪版;[S]/[X] 逐列启用)

| 故障点 | readonly | intrusive [S] | effectful [X 前用 debug.slowEcho 演练] |
|---|---|---|---|
| ackTimeout(3s 无 ack) | 关连接;重连后按 §7.2 | 同左 | 同左(bootId 变则 suspect) |
| **deadline+宽限(suspectGraceMs=5s)过仍无终局**(v1 脑侧唯一超时定时器就是 deadline;execBudgetMs 只是手侧自中止预算,不作脑侧定时器) | void 后重派 ≤2 次(退避 5s/15s),再败标手 suspect 告警 | void 后重派,轮次封顶 3;连续 3 轮超时→能力级告警→ensureSurface 自愈→再败转人工 | **suspect**(v1 无验证原语的降级);[X] 起先走验证读(封顶 3 轮)再落人工 |
| result: failed, retryable=yes/afterRecovery, sideEffect=none | 重派 | 退避重派,封顶 3 | 允许同 idemKey 重发 1 次 |
| result: failed, sideEffect=possible/confirmed | n/a(R 类恒 none) | n/a(intrusive 无资格声明非 none) | possible→suspect;confirmed→记"已发出",残余步骤人工 |
| deadline 过(未执行) | result(expired) 或脑侧直接 void | 同左 | 同左(expired 是安全终局:手执行前双查) |

### 8.3 suspect 六法条 [M1 铺轨,X 起满负荷]

1. 触发:effectful 出现以下任一——deadline+宽限过仍无终局;result 带 sideEffect=possible;派发后 bootId 换代且无 result;脑重启扫描命中在途。
2. suspect 是**自动化的终态**:永不自动重试、永不静默;落审计,进客户端 UI 显著的 suspect 队列,有通知(v1 用 UI 告警面板+结构化日志;云端接入后加企微)。
3. **冻结幂等键**:人工裁决前,该 idemKey 拒绝签发任何新命令。
4. **冻结串行域**:该账号不派新 effectful/intrusive(debug 命令的冻结域=该手 debug 域);唯一例外是脑为消解该 suspect 下发的验证读,它占用被冻结命令自己的槽位 [X]。
5. 人工二选一裁决(确认已发生→补记完成;确认未发生→解锁允许重派),裁决落审计。**裁决入口前置条件**:手已重连且完成补投仍无终局,或手离线持续 ≥ suspectManualDelayMs(默认 10 分钟)——对账未完成不许人裁,封死"人工误判与迟到 result 并发"的双发窗口。[X] 起在人工前插一道自动验证闸(readonly/intrusive 验证读,封顶 3 轮),suspect 台账与 UI 不变——先建台账不是弯路,是终态子集。
6. **迟到终局自动核销**:suspect 状态收到该命令的 result → 按 result 终局化、suspect 工单自动销案、落审计(与 cancel 的"result 赢"同构)——账本永远反映真相。

**配套立法**:今后任何业务 effectful 原语,必须与其配对验证读原语**同批交付**,缺验证读的 effectful 不准上线。

## 9. 手侧证词(journal / outbox)[X;M1 明确不做]

[X] 批次随首个真实 SX 原语引入,v1 骨架**不实现**:

- `journal:{idemKey}`:双写点——(a) 不可逆动作**前**写 `attempting`,(b) 观察到后置条件**后**写 `committed`+缓存 result。SW 死于任意点:死于 (a) 前=零副作用可重发;死于 (a)(b) 间=report 只会说 attempting→suspect 人工;死于 (b) 后=复活补投终局。**只可能少发,不可能多发。**
- `outbox:{msgId}`:SX 的 result/持久化待投,直到脑 ack 删除——脑重启窗口内 SW 也死时,SX 终局不失。
- 与宪法禁令 2 的边界(四道栅栏,缺一不可):键值全是协议标识符与协议消息,不含业务决策输入;仅 base 投递层可读写,program 不可见;有 TTL(journal 14 天/outbox 7 天)与容量上限(各 512,超限告警并拒新 SX);**允许整体丢失**——丢失只增加人工频次,绝不产生错误自主行为。它是投递层基础设施(证词),不是账本;任何"以手侧记录为准"的对账方向都是颠倒(反模式 16)。
- 随批激活 query/report:重连对账序列升级为 A 卷 §7.1 的四阶段(补投 outbox→脑逐条 query→手按 journal report→重投未 ack)。v1 无 journal,对账靠 bootId 一刀切(§7.2),不需要 query 回合。

## 10. 错误对象与错误码 [M1]

```json
{ "code": "CTX_LOST_DURING_EXEC",
  "message": "仅人读,禁止程序分支",
  "retryable": "afterRecovery",        // yes | no | afterRecovery | manualOnly(建议值;脑矩阵是最终裁决,手只能向保守收窄)
  "sideEffect": "possible",            // none | possible | confirmed(effectful 失败必填;拿不准一律 possible)
  "data": { },                         // 结构化细节,schema 随 code 入契约
  "evidence": [] }
```

v1 错误码全集由 `contract.v1.json.errorCodes` 生成;每码冻结 `phase=receipt|execution`。**receipt 码才有资格出现在 ack(rejected)**;execution 码说明命令已经 accepted,只能出现在 result(failed)。receipt 白名单固定为 PROTO_*、STALE_SESSION、QUEUE_FULL;“接收时已经过期”不是错误码,走 accepted→result(expired)。

|---|---|---|---|---|

| STALE_SESSION | receipt | yes(新会话重投) | none | 命令带旧会话 |
| QUEUE_FULL | receipt | yes(退避) | none | FIFO 深度 16 背压 |
| GUARD_FAILED | execution | manualOnly | none | 前置断言不成立 [X] |
| CTX_NOT_READY | execution | afterRecovery | none | 页面不在/未登录/身份未 fresh probe;data.reason 复用 **notReadyReason**(含 identityUnverified)[S] |
| CTX_LOST_DURING_EXEC | execution | R/I: afterRecovery;SX: manualOnly | none/possible | 执行中页面导航/关闭 [S] |
| USER_ACTIVE | execution | afterRecovery | none | accepted 后发现仍处于手动静默窗;脑等待恢复,手不自行重试 [S] |
| ACCOUNT_MISMATCH | execution | manualOnly | none | 当前登录主体与 expectedPrincipalFingerprint 不同;禁止驱动/返回数据 [S] |
| CONVERSATION_NOT_FOUND | execution | no | none | chat.* 指定会话不存在 [S] |
| CURSOR_INVALID | execution | afterRecovery | none | cursor 过期或跨上下文误用;丢弃未入账聚合并从首页重启 [S] |

| ELEMENT_UNRESOLVED | execution | manualOnly | none/possible | 疑似平台改版(selector 细节只进 evidence)[S] |

## 11. 健康模型 [M1 两级,S 起三级]

三个正交问题,三个信号源,禁止互推:

| 问题 | 信号 | 判定与动作 |
|---|---|---|
| 链路 | WS close / ping 到达 | **close=静默暂停派发**(SW 正常死亡是设计内常态,不告警不刷屏);连接开着但 ping 静默 ≥ graceMs(50s)=真异常(事件循环卡死/心跳代码坏),**告警**并关闭连接 |
| 行为能力 | ack/result 及时性 | 连续 3 个"关连接→重连→首命令仍 ackTimeout"周期(计数跨重连累计,任一 ack 正常即清零)→ HAND_WEDGED:告警转人工;每次关连接动作由 §7.2.1 完成,此处不重复 |
| 页面在场 [S] | ping.contexts[].ready + 传感链路 | ready=false → 该账号 CTX_MISSING:readonly 探测照发,intrusive/effectful 挂起等 ready;hb.sensors 持续 null 而页面声称在 IM 面=传感链路残废,能力级告警 |

派生态(脑侧手注册表):READY / DEGRADED / SUSPECT(断线<graceMs)/ DOWN。执行长命令期间 progress 兼任活性信号 [S],ping 与 progress 任一到达都刷新 lastSeen。

## 12. 感知与同步 [S](裁决定稿,C 卷全文为实施细则;C 卷成文于沟通规格 v3,巡检"每日手动开启"门控以 v4 与本节为准)

1. **轮询循环归脑**:巡检节律(**每日真人手动开启**后数分钟一轮,最晚至 24:00——沟通逻辑规格 v4)只存在于脑的账号 actor;手零自主循环、零业务定时器(允许:重连退避、alarms 复活闹钟、心跳、传感去抖的一次性 setTimeout ≤3s)。手对"巡检开没开"零感知——开关只是脑侧调度器的一个闸。
2. **感知三层栈**:event 提示(秒级,可丢)→ ping.sensors 缓存搭车(≤25s,可丢)→ **巡检对账命令(分钟级,唯一正确性来源)**。层 1/2 的值禁止进入任何业务判断,唯一权力=把下一轮巡检拉前(合并窗 25s、频控 ≥60s;**巡检未开启时段拉前失效**——含夜间与"当日尚未手动开启",提示只落脏标记,开启后首轮收割,v4 明确"开机首日集中催与归档是预期行为")——事件是油门不是刹车,徽章清零/闪空永不取消或跳过巡检。
3. **事件四类**(unreadBadge / pageNavigated / loginStateChanged / manualInteraction):字段、去抖与两次一致规则按 C 卷 §6.2 入契约;manualInteraction 开手动静默窗(默认 45s):窗内不派 intrusive/effectful,在途不撤销。
4. **同步机制**:脑持会话级账本锚尾(最近 ≤5 条 {direction, contentHash}),随 `chat.readThread` 首页下发,仅作滚动止损提示。单页最多 64 条且 compact data≤64KB;未到 anchor/顶部时回 `complete=false,nextCursor=opaque`,脑以相同 context/窗口参数带 cursor 续页,直至 `complete=true` 且 `anchorMatched || reachedTop`。各页内部按时间正序;首页是最新页,后续 cursor 页更老,聚合时依次**前插**且 cursor 保证页间不重不漏。手只在锚尾唯一命中时可裁掉锚前上下文;重复命中必须保留完整候选窗口。脑聚合成一份有界完整快照后,在快照任意连续片段中寻找账本后缀的最大重叠;同样最大长度有多解时取最靠后的起点(最少新增)并审计,随后才产出“本轮新增”投影,中间页不得入账或触发事件。零重叠→丢弃本轮聚合后 deep=true 从无 cursor 重启→仍零重叠按收编处理+审计,不静默吞。
5. **卡片=身份哈希+状态分离**:contentHash 只哈希卡片身份(cardType+关键参数),cardState(pending/accepted/rejected/expired)独立;按钮事件=对齐位置上的状态跃迁——旧卡跨轮重复触发机制性不可能,"已结束者点旧卡直进已约面"天然支持。
6. **列表=变更检测不是账本**:`chat.readList` 按最近活跃排序,单页最多 32 会话且 compact data≤64KB;`complete=false` 必带 opaque nextCursor,脑以相同 filter/stopOlderThanDays/maxSessions 续页,直到 8 天截止回 complete=true。脏判据=unread>0 ∪ lastMessage 摘要≠账本尾(后者兜住用户手动读走的假阴性)。不脏且无到期时钟→本轮零页面动作。
7. **收编边界**:每会话 `adoptedBoundarySeq`,边界前消息不触发事件、不进对话轮,仅作语境。
8. **多标签仲裁**:SW 维护 canonical 平台标签页;驱动命令与传感只在 canonical 执行/发射(manualInteraction 例外:任何平台页的用户输入都上报)。
9. **账号主体确证**:`probe.platform.data.principalFingerprint` 是平台无关、不透明、只许相等比较的登录主体指纹,不得暴露 Cookie/token/明文平台 userId,脑不得解析。首次真人绑定前尚不存在 `accountRef`,因此仅绑定流程发出的 `probe.platform` 可按原语元数据 `contextOptionalBeforeBinding=true` 省略 context；已绑定账号 actor 发出的 probe 仍必须携带完整 context,其余 [S] 原语无例外。真人绑定时脑保存指纹;之后每条 intrusive/effectful 命令在 context 携带 `expectedPrincipalFingerprint`。手在首次驱动页面前复读比较,并在返回任何账号数据或进入不可逆动作前再复核;不一致回 ACCOUNT_MISMATCH(sideEffect=none,manualOnly),不得交付跨账号数据。`nav.ensureSurface` 是 pageAbsent 时唯一恢复驱动例外,但身份一旦可见仍须在返回前复核。
10. **身份三态**:已绑定但 pageAbsent/contentScriptDead 暂不可观测时保留绑定,仅允许 probe/nav 恢复;新 session/boot 或健康过期时必须 fresh probe 一致后才放行驱动;明确 mismatch 或 logout→login 时绑定立即失效,只允许 probe,必须真人重新确认。登录态 `in` 本身永远不等于账号一致。
11. 原语四条:`probe.platform`(readonly,5s/30s)、`nav.ensureSurface`(intrusive,lease 30s)、`chat.readList`(intrusive,lease 60s)、`chat.readThread`(intrusive,lease 30s,兼任 [X] 验证读)。args/data 的 required、nullable、枚举、上下限均以 `contract.v1.json.schemas.types` 为唯一机器源;关键边界为列表页≤32、线程页≤64、每页 compact data≤64KB、cursor≤2KB、anchorTail≤5、摘要≤200 Unicode 码点。两种 data 都满足 `complete=false ⇔ nextCursor 非空`;列表 complete=true 时 nextCursor 必须空,线程还必须满足 `complete=true ⇔ anchorMatched || reachedTop`。opaque cursor 只许原样回传,不得解析、跨账号/会话/参数复用;CURSOR_INVALID 时脑丢弃本轮未入账聚合并从无 cursor 安全重启。任一条目本身超限则 PAYLOAD_LIMIT,不准伪造 complete 或裁剪字段。

## 13. 大载荷(blob)[X]

简历 HTML、截图和不可分页的大载荷走同一 Go 进程的 localhost HTTP 内容寻址端点(`PUT /v1/blobs`,`sha256:<hex>` 引用,单件 ≤20MB,30 天无引用 GC,token 会话作用域经 welcome 下发);WS 消息只携带 ref。完整原语结果 JSON 用 `result.dataBlobRef`,取回后先验 sha256 与大小,再按该原语 dataSchema 校验;单条消息的大文本用 message.blobRef。`data` 与 `dataBlobRef` 在 status=ok 时恰有一个。S 批在 `blob/1` 未激活期间先用 §12 的 cursor 把列表/线程结果切成每页≤64KB;单个不可再分条目超过 2KB 文本边界或整页仍无法表达时回 PAYLOAD_LIMIT,不准截断、发明字段或突破 256KB 帧上限。理由:控制面不被大帧队头阻塞(心跳纯度)、免 base64 税、传输无关(Claim Check 模式)。**blob 通道零协议语义**——不推进状态,不构成第二语义通道。

## 14. 版本与能力协商 [M1]

- `proto`:唯一破坏性开关;主版本内一切变更是加法(must-ignore)。
- 原语粒度版本 `name@ver`:args/data/evidence schema 不兼容变化=原语版本+1;脑按会话 caps 门控派发,支持双端灰度不同步。

## 15. 反模式清单(明令禁止)[M1]

1. 两端手写协议字段/别名——唯一来源是 codegen,code review 见手写字段名即打回。
2. 回执不带 ref——生成类型非可空,构造上灭绝。
3. DOM/selector/tabId/windowId/平台 id 进语义字段——只许 evidence 与日志;脑读 evidence 做分支同罪。
4. 用时间戳做去重、排序或状态裁决。
5. 手自主重试 effectful;原语内部重试同罪。
6. 把"WS 连着"当"手健康"、把"心跳在"当"页面在"。
7. 自由文本承载语义(error.message、progress.stage 上做程序分支)。
8. 第二条命令通道(任何"顺手加个 HTTP 接口直接叫手做事"直接否决;blob 无语义不在此列)。
9. 追求协议级恰好一次(QoS2 迷信)。
10. 大载荷内联 base64 进 WS。
11. 过程式命令("点第 3 个会话")——命令必须声明式,这是 intrusive 可重派的构造前提。
12. 手侧批量聚合命令、自行排程——一 cmd 一 ack 一 result,节奏权 100% 在脑。
13. 无版本报文。
14. 心跳携带业务载荷/心跳到点反向采集。
15. 静默去重——重复到达必须重新 ack(+必要时重放 result)。
16. 把 chrome.storage 当账本——手侧持久数据只有证词地位,冲突以脑为准、疑义转人工。
17. fire-and-forget 下发 effectful——每条 SX 账本行必须走到终局或 suspect。
18. 未知原语/指令默认回成功——默认分支必须是显式拒绝。
19. 同一条存活 TCP 上重发帧——ackTimeout 的唯一动作是重建连接。
20. 事件直接触发业务命令——事件唯一权力是调整巡检开跑时刻/静默窗/健康档。
21. retained 式"上线即收到陈旧命令"——脑对离线手不排队,命令现算现发。

## 16. v1(里程碑 1)实现清单与验收

**激活范围**:kind 8 种(hello/welcome/bye/cmd/ack/result/ping/pong);class 三枚举全部进契约;原语 3 条:

| 原语 | class | 说明 |
|---|---|---|
| `debug.ping` | readonly | 回显 args,证明通道 |
| `debug.switchWindow` | intrusive | 激活当前窗口下一个标签页,肉眼可见;练习 intrusive 排队 |
| `debug.slowEcho` | effectful(声明上,无真实副作用) | args:{ms, outcome: ok\|failed\|silent}——用真通道演练 ack、超时、suspect、幂等键冻结全路径,不等发消息原语才第一次踩轨道 |

**S 批契约增量(里程碑 2)**:激活 progress/event/cancel,独立 feature 为 progress/1、lease/1、cancel/1;激活四类传感事件、welcome.sensors、ping.contexts/sensors、opaque 账号指纹和四条平台无关原语(`probe.platform`、`nav.ensureSurface`、`chat.readList`、`chat.readThread`)。Go/TS 的 body/args/data/event 类型及运行时 validator 统一由 `contract.v1.json.schemas.types` 生成;unknown fields=must-ignore、contractHash=warn-only 是生成常量与测试门禁。

**验收项**(编号即测试用例):

1. 重连退避+alarms 复活;hello 10 秒无应答或协议拒绝后进入同一有界退避,不存在待配对状态。
2. 会话内心跳 20s±抖动;pong 缺失 2 次手主动重连;脑侧 close=静默、开着静默 50s=告警(两种"没消息"分开)。
3. 单活连接顶替(SUPERSEDED);非当前物理连接消息丢弃+审计;当前连接上已 accepted 命令的旧 session progress/result 可入账,ack/ping/event 不得越过 session 围栏。
4. 本地握手:只监听 127.0.0.1;Origin 前缀校验;手本地随机稳定 `handId` 必填;hello/welcome 不含 auth/issued;无配对窗口或凭据表;contractHash 只告警;hello 应答超时 10s。
5. 先记账后发送;脑重启扫描:readonly/intrusive 作废,effectful(slowEcho)转 suspect;手重连补投的迟到 result 自动核销该 suspect(法条 6 路径)。
6. ackTimeout→关连接;重连 bootId 未变→原 msgId 重发(session 更新为新会话)→手 duplicate ack(或补 result);bootId 变→effectful suspect。
7. suspect 六法条:UI 队列、幂等键冻结、串行域冻结(debug 域)、裁决置灰前置、迟到终局核销、人工二选一裁决、审计。
8. 分发器唯一入口;未知原语显式拒绝;deadline 出队双查;去重表命中重放 result。
9. 测试页与(未来)调度器共用同一信封、通道、派发器——协议观测台展示 hello 能力集、每帧原始报文、命令生命周期。
10. 契约 codegen:两端类型自动生成,CI 一致性校验,零手写字段;附加文档检查:规格 §17 参数表与 contract.defaults 逐项一致。

**显式推迟表**(触发条件即到期日):query/report+journal/outbox+验证闭环+evidence 强制+guards 词汇(首个真实 SX 原语,**与验证读同批**);blob/1 的 HTTP 实现(真机测量证明合法感知快照会超过 2KB/64KB 内联边界时立即提前,否则首个大载荷证据原语;未实现期间超限响亮失败);多手并发注册表(Android 手/多 profile 转正);MQTT 迁移(远程手/云端多租户)。远程或不可信本地通信一旦进入产品范围,必须先冻结新的身份与传输安全设计,本地可信握手不得直接复用。progress/租约/cancel、四类 event、sensors 搭车、静默窗和能力级健康已在 S 到期,不得再引用旧推迟条款。
