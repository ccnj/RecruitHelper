# 发布招聘助手新版本到自建更新源

把新版本发上更新源,所有已装客户端会自动发现、下载、校验并择机安装,不需要
人工再碰客户机。这是 2026-07-30 甲方裁决批准的第四项云端出站(单向只读静态
更新源),条款见 AGENTS.md「客户端版本更新源」。

## 零、这是对外动作

发布一落地,所有客户端最快十几分钟后就会开始下载安装。所以**每次发布都要
甲方当次明确授权**,不存在"顺手发一下"。`publish-update.sh` 末尾的 y/N 确认
就是这道闸;在非交互环境代答(`echo y |`)之前,确认本轮对话里甲方说过"发"。

## 一、机制(先懂再动手)

- 更新源是静态文件:`http://<服务器>/rh-updates/latest.json`(清单)+
  `pkg/RecruitHelper-<版本>-setup.exe`(安装包)。默认服务器 `8.153.161.25`,
  服务器目录 `/srv/console/rh-updates`。
- 客户端(脑内 `client/service/internal/selfupdate/`)每 15 分钟带抖动查一次
  清单(0.2.6 起即如此;`publish-update.sh` 结尾"最长 6 小时/不会自动安装"
  是 d87098a 只下载时代的陈旧文案,别被它误导);**只在清单版本严格大于本机
  版本时行动**,下载(超时 30 分钟)后必须 sha256 校验通过才备为待装。
- 安装不全自动(批 2"一键自动安装",b9d36f9):新版备好后由甲方在客户端
  **一键确认**;确认后脑先结束当前运行、等在途命令收束——超时就放弃本次,
  宁可不装也不把在途消息杀成 suspect——然后安装并重启客户端。

两条由此而来的纪律:

- **每次发布必须升版本号**。同号重传只有一个用途:修复上一次传坏/传半截的
  同版本(客户端认 sha256 不认文件名,重传安全)。
- **没有"回滚"这回事**。清单填旧版本号会被客户端直接忽略;要回到旧行为,
  用**更高的版本号**打一个基于旧代码的包再发布。

## 二、打包(引用,不复制)

基线核对、升版本号、构建、产物核对、HEAD 复核,**全部按 `recruithelper-package`
skill 执行**,本文件不重复任何细节——那份 skill 是打包知识的唯一维护点,
这里抄一份只会腐烂(本仓库吃过过时副本的亏,见 CLAUDE.md 开篇)。

要点只提醒两句:打包在主检出 `main` 上进行,前后各记一次 HEAD;升号用
`./scripts/bump-version.sh`,升号 commit 与发布对应的 commit 要能对上。

## 三、发布

```bash
./scripts/publish-update.sh
```

(可带服务器参数,默认 `8.153.161.25`;需要本机对 `root@服务器` 的 SSH 免密。)

脚本做四件事:算 sha256 → 上传安装包 → 写 `latest.json` → 回读校验(清单
版本、sha256、包可达)。顺序刻意"**包先、清单后**":反过来清单会先指向一个
还没传完的包,客户端下到半截、校验失败、退避重试,白造一段失败窗口。

清单的 `notes` 字段记**打包时刻**的基线——这是事后回溯"客户机装的到底是
哪版代码"的唯一线索。基线由 build-win.sh 写在 `release/BUILD_COMMIT` 字条,
发布脚本只读字条、不问当下 HEAD:本仓库多会话并行,构建到发布之间 main
随时可能被推进,现问会把别人的 commit 标到自己的包上(0.2.7 首发即中招:
包是 518089a,notes 错标成 cdd1621;之后才改为字条制)。发布时若提示
"包基线≠当前 HEAD",只说明打包后主线又动过,包本身没问题——确认要发的
就是这个包再答 y。字条带 `-dirty` 后缀说明包出自未提交的工作树、无法完整
追溯,这种包不要发给客户。

## 四、发布后要交代给甲方的话

1. 发布的版本号与**打包时刻**的 commit(甲方拿它对客户机;notes 若错标要
   一并说明)。
2. 生效节奏:客户端约 15 分钟内发现并后台下载校验;下好后**等甲方在客户端
   一键确认**才安装,不确认就一直备着,不用催。
3. 确认安装时脑会结束当前运行、等在途命令收束再动手;安装会重启客户端;
   插件随整包自动换代重载,不用碰 Chrome。
4. 验证方式:诊断台看版本号,或等客户反馈;不需要远程人工操作。

## 五、禁区(AGENTS 条款里与发布操作直接相关的)

- 该通道单向只读,不得复用于任何上报、遥测、控制面或配置下发。
- 更新源地址与客户标识不进 AI 请求、运营通知 webhook 与旧后台。
- 插件仍随客户端整包携带,本通道不单独下发插件。
- 客户端 sha256 校验闸是内置的,任何情况下不要想办法绕过它。
